# token-station 全量功能测试用例

- 基线分支：`feat/claude-code-anthropic-adapter`
- 基线提交：`62115dc`
- 测试目标：先证明现有功能的稳定性，修复全链路缺陷后再进入新功能迭代
- 形态红线：保留 `Tauri + React` 桌面 App；本轮不迁移网页端
- 状态定义：`待执行`、`通过`、`失败（缺陷 ID）`、`阻塞（原因）`、`不适用`

## 1. 测试策略

| 标记 | 场景 | 执行方式 | 准入要求 |
|---|---|---|---|
| A | 自动化 | Rust/TypeScript 测试、构建、静态检查、脚本化 API/E2E | 每次提交和 CI 必跑，零失败 |
| M | 人工 | 真实 macOS 窗口、系统钥匙串、客户端配置、视觉/交互、网络异常恢复 | 发布前按清单留证 |

## 3. 标准测试数据与环境

- 自动化上游使用本地 mock HTTP server，不访问真实供应商。
- 真实供应商 E2E 只使用已有的隔离配置和环境变量；密钥不得进入命令历史、文档、日志和 SQLite。
- 客户端配置写入测试专用临时目录；除人工明确验收外，不修改真实 `~/.claude`、`~/.codex`、`~/.config/opencode`。
- 端口使用 `127.0.0.1:0` 或 8787/8791 等隔离端口；失败后必须确认端口释放。
- 金丝雀：prompt、response、上游密钥、virtual key 各使用不同固定标记，便于日志和数据库原始字节检索。

## 12. 自动化门禁命令

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps

npm --prefix apps/desktop run build
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets

cargo fmt --manifest-path plugins/official/agent-anthropic/Cargo.toml -- --check
cargo fmt --manifest-path plugins/official/agent-openai/Cargo.toml -- --check
cargo fmt --manifest-path plugins/official/agent-openai-responses/Cargo.toml -- --check
cargo fmt --manifest-path plugins/official/provider-openai-compatible/Cargo.toml -- --check
```

涉及依赖或发布时追加 `cargo deny check`、`cargo audit` 和发布可复现验证；真实客户端 E2E 按对应 `docs/guides/` 的隔离目录执行。

## 13. 稳定性准入标准

只有同时满足以下条件，才允许开始新功能迭代：

1. 所有 P0 自动化用例通过；P0 人工/混合用例完成且留有可复核证据。
2. P1 无“未定位”或“无回归测试”的开放缺陷；延期项必须有负责人、原因和边界。
3. workspace、desktop、三类 agent 插件、provider 插件均通过独立构建/测试门禁。
4. Claude Code、Codex、OpenCode 至少各完成一次普通文本主链；Claude Code 与 Codex 各完成一次工具闭环。
5. prompt、response、上游 Key、virtual key 的日志/数据库泄漏检查通过。
6. App 仍为 Tauri 桌面形态，未引入网页部署或浏览器托管改造。
