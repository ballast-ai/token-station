# Agent 兼容工程总验收

日期：2026-07-20
范围：Claude Code、Codex、OpenCode、OpenClaw、NousResearch Hermes Agent 的只读发现、版本准入、Connector、配置事务、桌面交互和发布前门禁。
结论：自动化与本机受控验收通过；Windows runner 和未重复执行的真实客户端场景明确保留为 CI/发布前验收项，不伪报为本机已执行。

## 1. 红线结论

- `crates/router-core/**` 未修改；基线摘要仍为 `637c90a0988afa23e059ecf991853101abbd60ade57365645c58eed068a84a1a`。
- Connector 只在核心路由外投影配置，未增加路由算法、规则匹配、评分、选池、排序或 `RouterConfig`/`Decision` 特判。
- 扫描、未知版本和阻断版本均为零写入；程序不安装、升级、启动或修复第三方 Agent。
- 写入链固定为：服务端预览 → 用户确认 → 加密快照 → revision 复核 → 原子替换 → 解析/自检 → 归属提交；失败按阶段恢复。
- 测试使用临时目录、mock endpoint 与内存密钥，没有读取或改写用户真实 Agent 配置。

## 4. 平台矩阵

- Linux：常规 CI 执行 desktop 全量、覆盖率与安全审计。
- macOS：本机完成五 Agent 只读探测、路径模板、配置格式和隔离 E2E；CI 另跑平台 fixture 与密钥解码边界。
- Windows：CI 定向执行平台模板、原生可执行文件/脚本 shim 识别与密钥解码边界；本机未执行真实 Windows Agent。
- WSL：路径模板与环境根规则由跨平台 fixture 覆盖；本次未启动真实 WSL Agent。

macOS/Windows 定向 job 只编译并运行仓库测试，不安装第三方 CLI，不接触真实 Agent 配置，也不创建或删除真实 keychain 条目。

- 五张 Agent 卡片、安装实例、版本状态、未知保护、预览/确认/恢复入口已在深色与浅色主题检查。

## 7. Agents 页面扫描缓存第一阶段

本阶段只处理 Agents 页面扫描与切换卡顿，不包含“启动代理”操作的 Wasmtime 编译耗时和界面阻塞；后者继续由独立 Spec 处理。

- App 启动后每个进程只触发一次自动扫描；主页与 Agents 页面往返不再增加扫描次数。
- Registry 元数据通过轻量 IPC 独立加载，首次扫描期间也能展示完整 Agent 列表。
- 只有用户点击“重新扫描”才再次执行完整探测；重复请求由前后端两层单飞控制拒绝。
- 扫描、连接/断开预览复核和最终写入复核均在 Tauri 异步命令线程执行，不占用窗口事件线程。
- 扫描失败保留上一次成功展示结果，但连接、断开和快照恢复仍强制重新扫描；展示缓存不构成写入授权。
- `crates/router-core/**` 与核心路由契约未修改，红线脚本对 `origin/develop..29dc9d9` 通过。

干净提交 `29dc9d9` 的验证结果：frontend Vitest 45 passed；frontend production build 通过；desktop Rust 101 passed、1 ignored、0 failed；Rust fmt、Clippy `-D warnings`、diff-check 和 router-core 红线脚本均通过。

## 8. 发布前仍需显式执行

1. Windows 和 WSL 的真实 Agent 只读发现；
2. Codex、OpenCode 独立真实客户端经回环代理的受控 E2E；
3. 使用发布候选应用重复五 Agent 接入/断开/恢复；
4. 生产兼容目录 URL、公钥、负责人确认后，才允许启用远程目录。

这些项目不阻塞代码侧 Task 12 收口，但阻塞扩大灰度或正式发布。
