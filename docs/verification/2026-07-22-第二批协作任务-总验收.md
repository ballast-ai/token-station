## 3. 真实 App 验收

已构建隔离应用：

```text

bundle id: com.tokenstation.recoveryverify
```

隔离 Application Support 数据库注入 schema `99` 与 canary `future-row` 后，通过 Computer Use 完成启动、展开诊断、复制诊断、明确确认和原始数据导出。App 直接进入独立自救壳，未挂载业务导航；源数据库最终 SHA-256 仍为 `470ca7ea36f068ca21584612f0ce0316217ef6f8a255dd2ec69ed47338d81735`，`user_version=99` 与 canary 均未变化。

独立 bundle id 修改后已重新执行本地 ad-hoc 签名：严格 codesign、Wasmtime executable-memory entitlement、源码路径脱除和五个 builtin plugin marker 检查均通过。该操作只修复隔离调试包，不涉及生产发布签名。

实机验收同时发现并经 TDD 修复两处安全缺口：

1. 原始导出最初为默认 `0755/0644`；现已收敛为目录 `0700`、文件 `0600`，真实导出复验通过。
2. “脱敏诊断”最初仍包含用户名与绝对路径；现由后端将路径映射为 `$DATA_DIR`，前端只从后端脱敏预览生成复制内容。
