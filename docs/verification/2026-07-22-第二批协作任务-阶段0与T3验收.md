## 3. #3 实现内容

### 3.1 后端诊断事实

`DiscoveryRecord` 新增：

- `binary_source`：`homebrew/npm_global/path/known_path/env_override`；
- `modified_at_ms`：真实目标文件 mtime；
- `binary_sha256`：流式读取完整文件得到的标准 SHA-256；
- `upgrade_command`：只有来源和包名可安全确认时才生成。

来源识别规则：

- Homebrew 只接受 canonical path 中可验证的 `Cellar/<formula>/...` 布局，公式名经过保守字符校验；
- npm 全局只接受 `lib/node_modules` 或 Windows 风格 `npm/node_modules` 布局，并从受限大小的 `package.json` 读取、严格校验包名；
- 项目内普通 `node_modules` 不会被误判为 npm 全局安装；
- 不能可靠识别包管理器时保留 PATH、已知目录或环境覆盖来源，不猜测升级命令。

升级命令只作为 IPC 返回值供 UI 展示和复制；本阶段没有新增任何执行升级命令的 Tauri/CLI command。

### 3.2 前端行为

- 单安装显示当前精确 canonical path、来源、平台、mtime 和完整 SHA-256；
- 多安装选择器列出每个安装点的精确路径、版本、来源、当前 PATH 生效项、mtime 和短哈希；
- 多安装时不再自动替用户选择第一项，选择前“一键接入”保持禁用；
- 用户选择精确安装后，连接计划继续只传该次扫描返回的 canonical path；
- Homebrew/npm 升级命令可复制，复制后明确提示 Token Station 不会自动执行。

此前“隐藏完整路径”的旧 UI 断言与本批任务“必须说清接管哪一个路径”的新要求冲突，已按更新后的需求改为显式展示精确路径。
