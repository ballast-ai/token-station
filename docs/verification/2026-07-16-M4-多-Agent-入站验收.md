# M4 多 Agent 入站验收

验收日期：2026-07-16（Asia/Shanghai）

## 1. 结论与范围

本轮只覆盖用户确认的三个 Agent：

- Codex：OpenAI Responses，`POST /v1/responses`，
  `agent-openai-responses`。
- OpenCode：OpenAI-compatible Chat Completions，
  `POST /v1/chat/completions`，`agent-openai`。
- OpenClaw：OpenAI-compatible Chat Completions，
  `POST /v1/chat/completions`，`agent-openai`。

Aider、Continue 和其他 Agent 不在 M4 范围内，也没有新增其配置、代码或验收结论。

本地实现和验证已完成。本文不代表已 push、已开 PR、已获负责人批准、已合并或
已发布。

## 3. 实现门禁

### Responses 插件

`agent-openai-responses` 五族 fixture 覆盖 normalize、hint、render、stream 和
error。最终独立插件结果：

```text
agent-openai-responses: agent-protocol-v1 16/16
agent-openai:           agent-protocol-v1 16/16
provider-openai-compatible: provider-protocol-v1 22/22
```

Responses 实现覆盖：

- instructions、字符串/消息 input、文本与图片 URL；
- function tool、function call、function call output；
- 非流式 Responses 输出和 Responses 错误；
- `response.created`、`response.output_item.added`、
  `response.content_part.added`、文本/参数 delta、output item done 和 completed；
- 按 `stream_id` 隔离和清理流状态。

## 4. 真实 Agent E2E

### Codex

临时 `CODEX_HOME` 指向 8791，`wire_api = "responses"`。因当前适配器只承载
本地 function tool，临时配置关闭 Codex hosted tools、namespace tools 和个人
插件注入，并把 web search 设为 disabled。

- 普通流式：最终固定标记 `CODEX_M4_OK`。
- 工具闭环：Codex 实际执行
  `cat /tmp/token-station-m4-codex-work/marker.txt`，最终返回
  `CODEX_TOOL_M4_OK`。
- 本地错误 key：Codex 收到本地 401；服务端无 route 记录。
- 上游错误 key：单次受控请求收到“upstream rejected credential”401，退出码 1。
- 修复证据：补齐 output-item/content-part 起始事件后，Codex 不再报告
  `OutputTextDelta without active item`。

Codex metrics：4 条 HTTP 200、1 条受控上游 HTTP 401。另有 3 条 HTTP 400 是
修复/配方形成前对 `namespace` 和 `web_search` 的明确能力拒绝；没有把字段静默
丢弃，也没有进入真实上游成功链。

### OpenCode

使用 `/tmp/token-station-m4-opencode` 中的固定版本和进程级/XDG 隔离配置，
provider 为 `@ai-sdk/openai-compatible`，指向 8792。

- 普通流式：`OPENCODE_M4_OK`。
- 工具闭环：实际执行 `cat marker.txt`，最终返回
  `OPENCODE_TOOL_M4_OK`。
- 本地错误 key：本地 401，退出码 1。
- 上游错误 key：受控上游 401，退出码 1；发生有限重试，没有无限循环。

OpenCode metrics：5 条 HTTP 200、2 条受控上游 HTTP 401。

### OpenClaw

临时配置使用 `api = "openai-completions"`，同时隔离 `HOME`、
`OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH` 和 workspace，指向 8793。

- 普通流式：`OPENCLAW_M4_OK`。
- 工具闭环：`toolSummary.calls = 1`、`tools = ["read"]`、失败数 0，
  最终返回 `OPENCLAW_TOOL_M4_OK`。
- 本地错误 key：本地 401，退出码 1。
- 上游错误 key：受控上游 401，退出码 1，没有无限重试。

第一次只隔离 state/config 时，OpenClaw 自身的 legacy migration 仍把用户 HOME
下的审批文件重命名为 `.migrated`。验收立即按原路径、内容、权限和 mtime
恢复；后续命令额外隔离 HOME。结束审计确认原文件存在、`.migrated` 不存在。

OpenClaw metrics：3 条 HTTP 200、1 条受控上游 HTTP 401。

## 6. 已知边界

- Responses reasoning item、reasoning summary、computer/hosted tool、file-id 图片、
  namespace tool 和完整 Responses 事件全集尚未支持。
- Codex 当前配方必须关闭上述 hosted/namespace 工具；适配器对不支持项返回明确
  capability error。
- Codex 的文本 + 本地 function tool 通过，不等价于“完整 Responses 兼容”。
- OpenCode/OpenClaw 只验证本地 Chat Completions Agent 主链；其 MCP、远程 channel、
  浏览器、用户插件或用户 skills 不在本轮结论内。
- token usage 和价格以 token-station metrics 与上游账单为准；Agent 自己的兼容
  模型元数据不能作为计费依据。
