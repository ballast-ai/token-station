## 1. 结论

本轮完成了本机可执行范围内的稳定性前置工作：全量功能用例已固化，确认的桌面接入缺陷已补回归测试并修复，Rust workspace 与桌面端门禁通过，Claude Code、Codex、OpenCode 均通过真实 DeepSeek 普通流式和工具闭环，日志/SQLite 未检出 prompt、response 或凭证金丝雀。在此前稳定性门禁通过后，已把动态模型发现、刷新、缓存、搜索和已保存供应商模型管理迁入当前桌面 App；没有替换为网页端。

当前可判定为：**macOS 本地内核、桌面 IPC 逻辑和三 Agent 真实数据面回归通过；发布级全平台稳定性验收尚未全部关闭。** 尚未关闭的是当前工作区窗口的人工点击、Windows/Linux 安装冒烟、长稳和压力测试。因此本报告不把项目表述为“所有平台、所有人工场景全部完成”，也不据此推进新功能。

## 2. 确认并修复的缺陷

| ID | 严重度 | 根因 | 修复 | 回归证据 |
|---|---|---|---|---|
| STAB-001 | P0 | 桌面 Codex 接入仍生成已废弃的 `wire_api = "chat"` | 改为 Responses，补齐 `requires_openai_auth=false` 和有限重试配置 | `codex_connection_uses_responses_and_preserves_the_existing_config` + 真实 Codex E2E |
| STAB-002 | P0 | 桌面默认仅启用 `agent-openai`，Claude/Codex 按钮与已实现协议脱节 | 默认启用 Chat、Anthropic、Responses 三入站；旧 Chat-only 配置只在内存迁移 | template/legacy migration 单测 + 三 Agent E2E |
| STAB-003 | P0 | 发布装配只内嵌/打包两个旧插件，新 Agent 源码不会进入正式包 | builtin 和 release staging 扩为三个 Agent + 一个 Provider | `cargo check -p token-station-cli --features builtin-plugins` |
| STAB-004 | P0 | App 遇到损坏 `token-station.json` 会静默回退空模板，后续可能覆盖原文件 | 使用 `ClientConfig::load` 完整校验；失败进入只读保护，保存/启动/修改均拦截 | `a_broken_existing_config_enters_read_only_protection_without_overwrite` |
| STAB-005 | P0 | Claude/Codex/OpenCode 既有配置解析失败时会按空对象覆盖；写入也非原子 | 非法配置明确拒绝；保留其他字段；可靠备份；同目录临时文件 + rename | 5 个配置合并/损坏/幂等单测 |
| STAB-006 | P0 | `set_tier` 可经 IPC 写入不存在的供应商/模型，或用半空参数误清档 | IPC 后端验证供应商、模型和成对参数 | tier 非法输入与 1/2/3 档兜底单测 |
| STAB-007 | P1 | App 初始 `get_state` 异步失败会永久停在“加载中” | 显示真实错误并提供重试 | TypeScript/Vite build + 源码审计 |
| STAB-008 | P1 | 主页面操作没有统一防重复闸，快速连点可并发执行 IPC | `busyRef` 立即互斥并禁用相关控件 | TypeScript/Vite build + 源码审计 |
| STAB-009 | P1 | auth 关闭时 Agent 配置收到空 token，部分客户端可能在发请求前拒绝 | 使用非敏感、非空的本地占位 token；服务端 auth 关闭时不校验 | desktop 单测/代码路径审计 |
| STAB-010 | P0 | Codex 0.144.5 将 assistant 文本项插在 function call 与 output 之间；逐项转成 Chat 消息后，DeepSeek 因工具结果未紧跟工具调用而返回 400 | `agent-openai-responses` 合并相邻 assistant 输出，使内容与 tool calls 位于同一消息；未修改 Canonical IR 或 provider | fixture 16/16 + proxy 回归 + 真实 Codex 工具闭环 |
