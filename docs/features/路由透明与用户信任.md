# 路由透明与用户信任（路由器产品需求）

> 场景：**token station 作为独立路由器产品，向用户证明「我没为了省钱偷偷把你降级/换小模型」**——路由透明是路由器建立用户信任的第一产品能力。
> 本文汇总散落在两处的路由透明要求，作为 token-station 的产品需求收口：路由能力细节见本项目 [智能路由能力.md](./智能路由能力.md)；把路由透明放进更大的「防作弊/信任」框架里，见 glm5.2-platform 的 [用户信任与数据监控.md](../../../glm5.2-platform/docs/business/glm-5.2-用户信任与数据监控.md)（那是 GLM-5.2 那门生意的商业信任设计，本文只取与路由器相关的横切能力）。

---

## 一、为什么路由器必须自证清白

智能路由的本质是「替用户决定这次用哪个模型」。用户的天然疑虑是：**你会不会为了压成本，把本该给 SOTA 的请求偷偷路由到便宜模型？** 一旦这个疑虑坐实一次（被社区 benchmark 抓到静默降级），路由器的整个价值叙事崩塌。

因此 token station 的设计原则：**不是「承诺不作弊」，而是「让用户随时能自己验出没作弊」**——「我说没换模型」和「你自己能测出没换模型」是两个世界。

## 二、路由透明三件套（源自 [智能路由能力](./智能路由能力.md) 第四节）

| 能力 | 说明 | 验证强度 |
|------|------|---------|
| **决策原因可见** | 每条请求记录「路由到哪个模型 + 为什么（命中哪条规则/分类器判定）」，写进响应与账单 | 可看 |
| **反事实价格** | 「如果不路由会花多少 / 本月智能路由为你省了 $X」——省钱不可见等于没省，也是续费关键展示位 | 可看 |
| **可覆写兜底** | 用户能用声明式规则（① 层）强制覆写任一路由决策，作为「路由判错」的用户侧兜底 | 可控 |

## 三、路由器特有的透明凭证

| 凭证 | 说明 | 与 glm5.2-platform 的关系 |
|------|------|--------------------------|
| **分类器看了什么特征** | 对任一请求，用户可查「路由分类器读取了请求的哪些特征做判定」 | 对 BYOK / 本地路由用户，这同时证明**分类在本地完成、内容未上云**（见用户信任文档 §4.1） |
| **实际模型 + 精度标注** | 路由落地的真实模型、供应商、精度写进响应 header，落库不可篡改 | 与 glm5.2-platform 的模型真实性监控（§1）共用同一份 `backend·provider·精度` 标注 |
| **供给侧路由 ≠ 计费溢出** | 路由器的「换供应商/换模型」与 glm5.2-platform 内部的「GLM-5.2 产能溢出到别的 GLM-5.2 供给」是**两套机制**，各自独立打标，不混淆 | glm5.2 内部溢出的计费语义（`overflow_eligible`）留在 [计费接入架构](../../../glm5.2-platform/docs/architecture/glm-5.2-计费接入架构.md)，路由器不介入 |

## 四、边界：路由器管什么、不管什么

- **路由器管**：路由决策的产生、解释、覆写、反事实计价——即「这次为什么这么路由」的全部可解释性。
- **路由器不管**：计费对账、订阅额度、降级透明、数据留存删除凭证——这些是 glm5.2-platform 那门生意的商业信任设计，见其 [用户信任与数据监控.md](../../../glm5.2-platform/docs/business/glm-5.2-用户信任与数据监控.md)。路由器只保证「路由这一环」可验证，不承担整套平台的信任框架。
