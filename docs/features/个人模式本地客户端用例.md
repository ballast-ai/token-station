# 个人模式本地客户端用例文档

> 场景：基于[个人模式本地客户端需求](./个人模式本地客户端需求.md)（2026-07-08 收口，同日二次修订）与[概要设计](../architecture/个人模式本地客户端概要设计.md)，整理个人本地版的完整用例（Use Case），作为详细设计与测试用例的输入。
>
> 整理日期 2026-07-08。当日拍板口径已全部纳入：无账号绑定票据、设备码授权懒触发、统一 refresh token、本体版本检查匿名开放、关闭云同步已上报数据保留；**二次修订：取消本地 Web 界面与界面包、指标库默认开启、用量报表以平台网页为主 + 命令行简统计、对账改命令行命令（C3）、企业网关上游降为远期观察项**。
>
> 用例口径：主流程只写理想路径，异常与分支写入扩展流程；每个用例标注所属里程碑（C1/C2/C3，见概要设计 §八）与需求追溯。

## 一、参与者（Actor）

| 参与者 | 类型 | 说明 |
|--------|------|------|
| **个人用户** | 主参与者（人） | 下载客户端的个人开发者（开源任意下载，注册解锁云功能，2026-07-09 口径）；管理面为命令行（唯一管理面），用量报表经平台网页查看 |
| **调用方** | 次参与者（系统） | IDE / Agent / SDK，以 OpenAI 兼容协议连接本地端点，持本地虚拟 key |
| **平台服务端** | 次参与者（系统） | token-station 平台侧配套：账号注册、下载分发、OAuth 设备码授权、云同步接收、用量报表网页 |
| **模型厂商 API** | 次参与者（系统） | 自带密钥（BYOK，Bring Your Own Key）直连的官方接口（上游①） |
| **本地模型运行时** | 次参与者（系统） | Ollama / vLLM 等 OpenAI 兼容端点（上游②） |

> 企业 / 小 Team 网关（原上游④）2026-07-08 二次修订降为远期观察项，不进 C1–C3，相关用例暂不编写；届时协议上等同又一个 OpenAI 兼容上游，接入成本极小。

## 三、A 组：获取与安装

### UC-A1 下载客户端（2026-07-09 修订：开源任意下载，注册后移到云功能）

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：无（开核开源，任意下载，无需账号）
- **主流程**：
  1. 用户从官网下载页或 GitHub release 获取对应平台的官方签名安装包（匿名可下载）；
  2. 用户下载通用二进制安装包（不内嵌任何账号信息，2026-07-08 拍板无绑定票据）。
- **扩展流程**：
  - 1a. 用户从源码自行构建（Apache-2.0；可复现构建可验证官方包与源码一致）；
  - 2a. 安装包被转发给他人 → 无凭证泄露风险（通用二进制），使用云功能时各自注册（懒触发绑定，见 UC-D1）。
- **后置条件**：用户持有安装包；官方渠道下载可记录匿名版本/平台统计（供灰度分析，不关联账号）。
- **追溯**：需求 §五；概要设计 §4.1、§五「下载分发服务」。

### UC-A2 首次启动初始化

- **主参与者**：个人用户
- **前置条件**：已完成安装
- **主流程**：
  1. 用户启动客户端（命令行入口）；
  2. 客户端自动生成默认本地虚拟 key，打印到终端并写入本地配置；
  3. 客户端创建本地指标库（默认开启：仅元数据、仅存本地，2026-07-08 二次修订拍板）；
  4. 客户端就绪：监听 `127.0.0.1` 本地端点，写文件日志与指标库，零账号绑定。
- **扩展流程**：
  - 2a. 配置文件已存在（重装 / 升级）→ 沿用既有配置与指标库，不重复生成 key；
  - 3a. 用户后续经命令行关闭指标库 → 仅写文件日志（关闭期间历史缺口不回填）。
- **后置条件**：本地端点可接受携带虚拟 key 的调用；无任何数据出设备。
- **追溯**：需求 §三、§四；概要设计 §3.4、§3.6、§4.1。

### UC-A3 客户端本体升级

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：已安装客户端
- **主流程**：
  1. 用户执行命令行升级检查（版本检查接口**匿名开放**，2026-07-08 拍板，不要求登录态）；
  2. 下载分发服务返回版本信息（支持灰度）；
  3. 发现新版本 → 提示用户，用户显式确认（永不自动更新）；
  4. 下载安装包：任意下载官方签名包（2026-07-09 开源口径，无需登录；已绑定设备可凭 access token 客户端内直接下载）；
  5. 安装包签名校验（客户端内置公钥）→ 替换二进制、重启；配置、密钥库、指标库全部保留。
- **扩展流程**：
  - 5a. 签名校验失败 → 拒绝安装并告警，保持当前版本。
- **后置条件**：客户端运行新版本；内嵌小分类器权重随本体同通道更新（C3 后）。
- **追溯**：需求 §四、§五；概要设计 §4.3、§五、§六「本体分发安全」。

## 四、B 组：配置与密钥（命令行是唯一本地管理面）

> 本组本地管理用例经命令行 + 配置文件完成；个人版无本地 Web 界面（2026-07-08 二次修订拍板）。云端网页只管理非机密配置 profile，需用户显式开启远程配置后由本地主动拉取生效；key 本体永不上云。

### UC-B1 管理本地虚拟 key

- **主参与者**：个人用户
- **前置条件**：客户端已初始化（UC-A2）
- **主流程**：
  1. 用户执行 `key create / list / revoke` 管理调用方接入凭证；
  2. 客户端更新本地配置，即时生效。
- **扩展流程**：
  - 1a. 单人设备场景，用户显式关闭本地端点鉴权 → 客户端警示后放行（默认开启鉴权）；
  - 2a. revoke 后调用方仍使用旧 key → 本地端点返回鉴权失败（见 UC-C1 扩展）。
- **后置条件**：虚拟 key 集合更新；文件日志记录管理操作。
- **追溯**：概要设计 §3.6。

### UC-B2 添加自带密钥上游（BYOK 直连）

- **主参与者**：个人用户　**次参与者**：模型厂商 API
- **前置条件**：用户已在模型厂商官网自行生成个人 key
- **主流程**：
  1. 用户执行 `upstream add <provider> --key ...`；
  2. 密钥保管组件加密入库（优先操作系统钥匙串，退化为主密码加密文件）；
  3. 客户端对该上游测活（发起最小探测请求）；
  4. 上游进入可路由池，其模型出现在 `/v1/models` 聚合目录。
- **扩展流程**：
  - 2a. 钥匙串不可用且用户未设主密码 → 引导设置主密码后重试；
  - 3a. 测活失败（key 无效 / 网络不通）→ 报错并保留配置，标记该上游不可用。
- **后置条件**：key 加密存储，永不上传、不出现在日志；平台批发 key 无下发通道，本地直连只可能是个人 key（需求 §二）。
- **追溯**：需求 §一①、§二；概要设计 §3.3、§3.6、§六。

### UC-B3 配置本地模型上游

- **主参与者**：个人用户　**次参与者**：本地模型运行时
- **前置条件**：本机或局域网已运行 Ollama / vLLM 等 OpenAI 兼容服务
- **主流程**：
  1. 用户执行 `upstream add local --endpoint http://...`；
  2. 客户端测活并拉取该端点模型列表；
  3. 上游进入可路由池（隐私等级 L3：零外发）。
- **扩展流程**：
  - 2a. 端点不可达 → 报错，标记不可用，恢复探测接管（UC-C3）。
- **后置条件**：本地模型可被路由命中。
- **追溯**：需求 §一②；概要设计 §3.3。

### UC-B4 编辑路由规则

- **主参与者**：个人用户　**次参与者**：平台服务端（仅规则预设下行时）
- **前置条件**：客户端已初始化
- **主流程**：
  1. 用户编辑本地 profile 的规则文件（或经命令行修改）；
  2. 客户端校验规则语法后热加载；
  3. 后续请求按新规则路由（执行永远在本地）。
- **扩展流程**：
  - 1a. 用户显式开启远程配置并从服务端拉取规则预设（Preset）→ 仅非机密配置下行，无内容上行；需登录态（懒触发绑定，UC-D1）；远程 profile 生效时，本地 profile 暂不参与路由；
  - 1b. 用户关闭远程配置 → 回到本地 profile；云端不可达时沿用最后一次成功拉取的远程配置缓存；
  - 2a. 规则语法错误 → 拒绝加载，保留旧规则并报错。
- **后置条件**：规则文件更新；指标库记录路由决策与命中规则。
- **追溯**：概要设计 §3.2。

## 五、C 组：调用与路由（日常主路径）

### UC-C1 调用方接入本地端点

- **主参与者**：调用方（IDE / Agent / SDK）
- **前置条件**：客户端运行中；调用方持有效本地虚拟 key
- **主流程**：
  1. 调用方将 API 地址指向 `127.0.0.1` 本地端点，填入虚拟 key；
  2. 调用 `/v1/models` 获取聚合模型目录（各上游合并）；
  3. 以 OpenAI 兼容协议发起 `chat/completions`（含流式）。
- **扩展流程**：
  - 3a. 虚拟 key 无效或已吊销 → 返回鉴权错误；
  - 3b. 调用方附带路由提示（hint header，如 Agent 步骤类型）→ 传给路由引擎参与决策；
  - 3c. 调用方使用 Anthropic Messages 等其他协议 → 客户端侧维持 🟡 非首版（跟随服务端协议层规划，概要设计 §3.1）。
- **后置条件**：请求进入路由引擎（UC-C2）。
- **追溯**：概要设计 §3.1。

### UC-C2 发起一次模型请求（路由与转发）

- **主参与者**：调用方　**次参与者**：某一上游
- **前置条件**：至少一个上游可用
- **主流程**：
  1. 路由引擎按「用户规则 → hint → 启发式打分 → 内嵌小分类器」四层决策（全本地，内容不发给任何云端分类器）；
  2. 选定模型与上游，密钥保管组件取出对应凭证；
  3. 上游适配层发出请求，流式透传响应给调用方；
  4. 写文件日志（时间、模型、上游、状态码、耗时）+ 指标库元数据明细（token 数、延迟、路由决策与命中规则、成本估算；指标库默认开启）；
  5. 若云同步开启：元数据入同步队列。
- **扩展流程**：
  - 1a. 小分类器未随本体分发（C1/C2 阶段）→ 决策止于启发式层；
  - 3a. 上游请求失败 → 计入错误计数（UC-C3），向调用方透传错误；级联兜底不进个人版首版（双份调用成本个人承担，性价比差）；
  - 4a. 指标库被用户显式关闭 → 仅写文件日志；
  - 4b. 原始请求 / 响应内容：默认不落盘；仅在本地调试留存开启时限期保存（UC-E3），**任何情况下不上传**。
- **后置条件**：调用方收到响应；本地留下文件日志与指标库记录。
- **追溯**：需求 §三；概要设计 §3.2、§3.4、§4.2。

### UC-C3 上游故障切换

- **主参与者**：系统内部（健康检查）
- **前置条件**：多个上游在池
- **主流程**：
  1. 某上游超时 / 错误计数超阈值 → 临时摘除；
  2. 路由引擎将后续请求分配给其余可用上游；
  3. 恢复探测周期性访问被摘除上游，恢复后重新入池。
- **扩展流程**：
  - 2a. 无其他可路由上游 → 向调用方返回明确错误（不做服务端那套三层容灾）。
- **后置条件**：上游池状态与实际可用性一致；摘除 / 恢复事件写日志。
- **追溯**：概要设计 §3.3。

## 六、D 组：账号绑定与平台功能（懒触发）

### UC-D1 设备码授权绑定平台账号

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：用户已注册平台账号（UC-A1 已满足）
- **触发**（懒触发，2026-07-08 拍板，以下任一首次发生）：启用平台账户上游 / 开启云同步 / 使用对账命令 / 拉取规则预设
- **主流程**：
  1. 客户端向平台发起设备码授权，展示用户码与确认地址；
  2. 用户在已登录的浏览器中输码确认；
  3. 平台将设备与账号绑定，向客户端换发**统一 refresh token**（长效）；
  4. refresh token 经密钥保管组件加密存储（与个人 key 同等待遇）；
  5. 客户端后续按 scope（平台端点调用 / 账单只读 / 安装包下载 / 云同步上报）换取短效 access token，静默续期。
- **扩展流程**：
  - 2a. 用户码超时未确认 → 授权失败，可重新发起；
  - 5a. refresh token 失效（过期 / 被撤销）→ 依赖它的功能暂停并提示重新授权；纯本地功能（BYOK / 本地模型 / 文件日志 / 指标库 / 简统计）不受影响。
- **后置条件**：设备与账号绑定一次，之后平台交互无需二次绑定。
- **追溯**：需求 §五；概要设计 §4.1 绑定口径、§五「OAuth 设备码授权」。

### UC-D2 启用平台账户上游

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：已完成设备码授权（UC-D1，未授权则触发之）
- **主流程**：
  1. 用户启用平台账户上游（上游③）；
  2. 客户端以平台端点 scope 的 access token 调用平台端点；
  3. 流量经平台端点按平台订阅 / 按量计费（计费在服务端发生，客户端不参与计费）。
- **扩展流程**：
  - 3a. 平台侧额度耗尽 / 订阅到期 → 透传平台错误；订阅额度展示是否进首版为概要设计 §九待决 2。
- **后置条件**：平台模式流量对平台可见（L1），BYOK / 本地流量不受影响（L2/L3 承诺不变）。
- **追溯**：需求 §一③、§二；概要设计 §3.3。

### UC-D3 撤销账号授权

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：设备已绑定
- **主流程**：
  1. 用户在客户端执行解绑（或在平台账号页撤销该设备）；
  2. 平台吊销 refresh token；客户端删除本地存储的凭证；
  3. 平台账户上游、云同步、对账命令停用；纯本地功能不受影响。
- **扩展流程**：
  - 2a. 客户端离线时从平台侧撤销 → 客户端下次换 token 失败，按 UC-D1 扩展 5a 处理。
- **后置条件**：设备回到零绑定状态，可重新授权；已同步到服务端的历史用量数据保留（2026-07-08 拍板：不删除）。
- **追溯**：概要设计 §五（撤销粒度由统一 refresh token 保证：一处吊销、全 scope 失效）。

## 七、E 组：观测、云同步与对账

### UC-E1 查看文件日志

- **主参与者**：个人用户
- **前置条件**：客户端运行过
- **主流程**：用户直接查看本地滚动文本日志（请求时间、模型、上游、状态码、耗时）；日志本地轮转。
- **后置条件**：无状态变化；这是最底层、永远存在的记录。
- **追溯**：需求 §三；概要设计 §3.4。

### UC-E2 命令行用量简统计

- **主参与者**：个人用户
- **前置条件**：指标库开启（默认开启）
- **主流程**：
  1. 用户执行统计命令（按时间段 / 模型 / 上游过滤）；
  2. 客户端读本地指标库，终端输出用量、token 数、错误、延迟、成本估算汇总（成本基于配置通道下发的定价表本地计算）。
- **扩展流程**：
  - 1a. 指标库被关闭 → 提示无数据来源，建议开启（文件日志仍可人工查看）；
  - 2a. 定价表未获取（从未联网 / 未更新）→ 输出用量但成本列标注「定价表缺失」。
- **后置条件**：无数据出设备；完整可视化报表见平台网页（UC-E5）。
- **追溯**：需求 §四；概要设计 §3.4、§3.6。

### UC-E3 开启本地调试留存

- **主参与者**：个人用户
- **前置条件**：客户端已初始化
- **主流程**：
  1. 用户经命令行显式开启「本地调试留存」；
  2. 客户端开始在本地保存原始请求 / 响应内容，限期自动清理（默认期限与上限为概要设计 §九待决 1，建议 7 天 / 500MB）；
  3. 留存内容仅本地可查，**任何情况下不上传，无上传开关**。
- **后置条件**：调试期结束后自动清理；关闭开关即停止留存。
- **追溯**：需求 §三；概要设计 §3.4、§九待决 1。

### UC-E4 开启云同步（多设备用量管理）

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：指标库开启（默认满足）；已绑定账号（未绑定则触发 UC-D1）
- **主流程**：
  1. 用户经命令行显式开启云同步（默认关闭）；
  2. 同步模块按字段白名单（代码层硬编码，内容字段结构性不可达）上报指标库元数据聚合与明细；错误字段只上传结构化错误码与脱敏后的上游错误类别；
  3. 断点续传、批量上报；服务端按账号归集——**这是多设备用量管理的机制**：每台开启同步的设备客户端各自上报本地用量。
- **扩展流程**：
  - 2a. 网络中断 → 队列积压，恢复后续传；
  - 2b. 指标库被用户关闭 → 云同步随之无新数据可报，提示两者依赖关系；
  - 1a. 用户关闭云同步 → 立即停止上报；**已上报数据保留在服务端账号下，不删除**（2026-07-08 拍板），历史仍可在平台网页查看。上报范围本就仅限元数据白名单，保留不改变隐私边界。
- **后置条件**：平台可见范围仅限元数据白名单；上报数据永不作计费凭证（客户端上报可伪造）；不开启时平台对 BYOK / 本地模型流量全程不可见。
- **追溯**：需求 §三；概要设计 §3.7、§五、§六。

### UC-E5 平台网页查看多设备用量报表

- **主参与者**：个人用户　**次参与者**：平台服务端
- **前置条件**：至少一台设备开启云同步（UC-E4）
- **主流程**：
  1. 用户登录平台网页，进入用量报表页；
  2. 平台展示账号维度的多设备归集视图：按设备 / 模型 / 上游 / 时间段的用量、成本、错误统计（仅存储展示，不入账务系统）。
- **扩展流程**：
  - 1a. 从未开启云同步 → 报表页为空，提示在客户端开启同步；本地观测退路为命令行简统计（UC-E2）与文件日志（UC-E1）。
- **后置条件**：无。想看报表 → 必须绑定 + 同步元数据；这是有意识接受的取舍（L2「内容永不上传」承诺不变）。
- **追溯**：需求 §三、§四；概要设计 §3.7、§五「云同步接收与用量报表网页」。

### UC-E6 本地对账（命令行，C3）

- **主参与者**：个人用户　**次参与者**：平台服务端（只读账单接口）
- **前置条件**：指标库开启；已绑定账号；使用过平台账户上游（有平台账单可对）
- **主流程**：
  1. 用户执行对账命令（按账期 / 时间段）；
  2. 客户端以账单只读 scope 拉取对应平台的 Usage/Logs 账单明细；
  3. 与本地指标库（本地独立计量底账）逐条 diff；
  4. 终端输出差异报告：token 计数差异、预扣 / 结算差异。
- **扩展流程**：
  - 2a. 对应上游的只读账单接口未就绪 → 命令提示该上游不支持对账；
  - 3a. 指标库存在关闭期缺口 → 报告注明可对账区间。
- **后置条件**：用户获得独立于平台的计量核验能力——对账逻辑上不能搬到平台网页（自己验自己），故保留在本地命令行（2026-07-08 拍板）。对账对象按上游区分：token-station 平台账户上游对 token-station 自有账单；glm5.2-platform 作为被集成方时对其只读 Usage/Logs；其他上游只有在提供只读账单接口时才纳入。本命令只做账单 schema 适配、拉取 + diff + 输出。
- **追溯**：需求 §四；概要设计 §3.8、§八 C3 依赖说明。

## 九、跨用例不变式（任何用例的任何分支不得违反）

1. 原始请求 / 响应内容永不上传，无开关（UC-C2、UC-E3、UC-E4 的结构性约束）；
2. 路由决策全部本地完成，内容不发给任何云端分类器（UC-C2）；
3. 本地直连只用个人 key，平台批发 key 永不下发（UC-B2）；
4. 指标库数据仅存本地，未开云同步不出设备；同步范围限于代码层硬编码的元数据白名单，错误正文、prompt 片段、response 片段、密钥与用户自定义 header 不得进入同步路径（UC-A2、UC-E4）；
5. 本体安装包签名分发 + 可复现构建，升级永远显式确认（UC-A1、UC-A3；2026-07-09 修订：开源任意下载，注册解锁云功能）；
6. 纯本地功能（BYOK / 本地模型 / 文件日志 / 指标库 / 简统计 / 路由）永不因账号、授权或网络问题不可用（UC-D1 扩展 5a、UC-D3）。
7. 安装包签名只证明发布者与包完整性；L2/L3 信任以源码公开 + 可复现构建为主验证（2026-07-09 开核开源口径），网络边界、本地审计输出、同步字段白名单与离线可用保留为纵深验收。
