## 零、用户人群与商业目的（2026-07-08 拍板）

> 本节口径由 token-station 自身定义，不依附 glm5.2-platform 的服务模式叙事。

### 用户人群：三类核心 + 一条边界

| # | 人群 | 核心诉求 | 隐私等级 |
|---|------|---------|---------|
| 1 | **BYOK 多上游开发者** | 手里已有多家厂商个人 key，要多模型切换、混合路由、统一用量视图——「本地的 OpenRouter」 | L2 |
| 2 | **本地模型玩家 / 隐私敏感者** | 跑 Ollama/vLLM，要求内容零外发；对「路由全本地、内容永不上传」最敏感，也是命令行 + 文件日志形态的天然受众 | L3 |
| 3 | **平台潜在轻量用户** | 经注册漏斗进来先裸用 BYOK，未来被转化为 token-station 平台端点付费用户——**商业上最重要的一类** | L2 → L1 |

**边界**：「多设备统一接入、key 只存一处、成员管理」不属于个人版，属网关类产品形态；个人版云同步只解决「多设备**看**用量」（§三）。

### 商业目的：免费产品的三重角色

个人版免费、不直接产生收入，其商业角色是：

1. **注册漏斗**（获客，2026-07-09 五次修订：注册后移）：开源任意下载，云功能（平台账户上游 / 云同步 / 云端配置 / 多设备报表）解锁时注册（§五）——注册者是已激活用户，个人端是其留存工具；
2. **平台端点的转化触点**（变现主路径之一）：客户端是能把 L2 用户温和转化为平台付费（token-station 服务端订阅 / credits）的入口——BYOK 用户可能因「更稳定的上游可用性 / 统一限额 / 免管 key / 统一账单」把部分流量切到平台账户上游（§一③），开始产生平台收入；
3. **信任资产**：本地独立计量 + 对账命令是「平台账单可被独立核验」的证明，反哺平台端点的信誉。

> 原「企业 license 转化桥」（统一接入端、入职不换工具）随上游④降为远期观察项，**不列为当前商业目的**，见下方切换口径。

### 模式切换口径（2026-07-08 拍板）

客户端内的「切换」不是迁移，是**加上游 + 路由分流**：

- **个人 → 平台**：客户端内完成（C2 就绪）——设备码授权 → 启用平台账户上游 → 路由规则决定哪些请求走平台端点。BYOK 与平台上游**并存于账户维度，不并存于同一条请求**；计费边界清晰（经平台端点才计费，§二）。反向随时关掉上游③，零迁移成本。
- **个人 → 企业 / 小 Team 网关**：**换端点切换**——调用方直接指向网关端点（其本身即 OpenAI 兼容端点），个人客户端退出数据路径，本地混合路由与计量连续性随之放弃。「客户端内挂企业网关（上游④）、无需换工具」为**远期愿景，不构成当前承诺**（2026-07-08 拍板：接受换端点，④保持远期观察项）。

## 一、三类当前上游 + 一类远期观察（2026-07-08 四次修订）

个人客户端当前支持按模型/供应商**混合路由**到三类上游，同一客户端内可并存：

| # | 上游 | 数据路径 | 计费 | 隐私等级 |
|---|------|---------|------|---------|
| ① | 自带密钥（BYOK，Bring Your Own Key）直连官方 API | 本地 → 模型厂商 | 用户直接与厂商结算，客户端免费 | L2 |
| ② | 本地部署模型（Ollama / vLLM 等） | 零外发 | 免费 | L3 |
| ③ | 平台账户（glm5.2-platform 等平台模式端点） | 本地 → 平台端点 | 走平台订阅 / 按量 | L1 |

**远期观察：企业 / 小 Team 网关（成员身份接入）**。其产品含义是「统一接入端——个人用户入职后在客户端里挂上企业网关端点、无需换工具」，但不构成当前承诺，不进 C1–C3 里程碑；当前的个人 → 企业切换方式是换端点直连网关（见 §零 切换口径）。协议上它只是又一个 OpenAI 兼容上游，视企业网关产品线进展再排期。

> 接入平台账户（③）沿用已拍板的 OAuth 设备码授权 + 只读 Usage/Logs API 集成方式（见服务模式定位 §二）。

## 二、密钥边界：平台批发 key 永不下发到本地

- 个人模式的本地直连路径（上游 ①）**只能使用用户个人的 key**；平台采购的批发 / 低价 key 一律不下发到客户端。
- **对称约束（2026-07-08 拍板）**：用户的 BYOK key **永不上传云端**。云端可管理的配置仅含非机密部分（路由规则、上游定义、配额），key 本体只经本地 CLI 录入、本地存储，云端配置中仅存引用名（见[业务模式与定价划分 §三](./业务模式与定价划分.md)）。
- 想享受平台价格 → 流量必须切到平台端点（上游 ③），按平台模式计费。
- 原则同源于服务模式定位 §三「谁看得见请求，谁才能按量收费」：平台看不见的流量，平台既不参与计费，也不承担自有 key 外泄与滥用的风险。

### 开核开源下的信任验收（2026-07-09 五次修订，替代原「闭源分发下的信任验收」）

> 原闭源口径存在自证循环硬伤（用客户端自己的命令证明自己没作恶，见[开源策略讨论 §一](./个人本地版开源策略讨论.md)），已作废。现行口径：客户端开核开源（Apache-2.0），L2/L3 信任以**源码公开 + 可复现构建**为主验证手段——路由引擎、上游适配、云同步客户端侧代码全部开源，「同步字段白名单结构性不可达」从承诺变为任何人可读源码验证的事实；官方二进制可验证由公开源码编出。以下机制保留为**纵深防御与用户自查手段**：

- **网络边界可查**：提供本地命令导出最近网络目的地与用途；BYOK / 本地模型请求路径只允许访问用户配置的上游、本地模型端点、匿名版本检查、用户显式开启的云同步 / 远程配置 / 对账接口。
- **离线可用**：关闭云同步与远程配置后，BYOK / 本地模型 / 本地路由 / 文件日志 / 指标库 / 简统计不依赖平台网络。
- **同步字段白名单**：云同步路径只允许上报 §三列出的元数据白名单；原始请求 / 响应内容在同步代码路径中结构性不可达。
- **本地审计输出**：提供命令导出本地配置摘要、启用的云端功能、同步字段版本、最近 N 条路由决策与外联摘要，供用户自查或第三方审计。
- **签名与开源的分工**：安装包签名只证明发布者与包完整性，可复现构建负责证明「官方二进制 == 公开源码编译产物」，二者配合才构成完整信任链（签名私钥与发布流水线在闭源侧，见[代码仓库规划 §四#5](../architecture/代码仓库规划.md)）。

## 三、日志与数据面（2026-07-08 二次修订拍板：指标库默认开启；云同步可选、默认关闭）

> 原「检测数据随界面包启用」的两态设计随界面包取消而作废（见 §四）。现行口径：

| 数据 | 形态 |
|------|------|
| 文件日志 | 始终写（滚动文本），本地轮转 |
| 检测数据（本地指标库：用量、token 数、延迟、路由决策、错误统计） | 随客户端本体内置，**首启即建、默认开启**（仅元数据、仅存本地）；命令行可关。默认开启的理由：数据不出设备、隐私代价低且可被用户删除 / 关闭，同时为云同步与对账保证历史完整 |
| 原始请求 / 响应内容 | 默认不落盘；可开本地调试留存（仅本地、限期自动清理）；**永不上传，无开关** |

云同步建立在指标库之上（指标库默认开启，故无额外前提；开启云同步需绑定账号）——这是**多设备用量管理的机制**：各设备客户端把本地用量元数据同步到云端，按账号归集：

| 数据 | 默认 | 可选 |
|------|------|------|
| 检测数据 | 仅存本地 | 用户主动开启「云同步」后按字段白名单上报服务器，换取多设备查看用量 |
| 原始请求 / 响应内容（提示词与回复正文） | 仅存本地 | **永不上传，不提供开关** |

- 云同步**默认关闭**，由用户主动开启；不开启时，平台对 BYOK / 本地模型流量全程不可见——既有的 L2 隐私承诺不变。
- 客户端上报的数据**永不作为计费凭证**（客户端上报可伪造，见服务模式定位 §二），仅供用户自查与多设备汇总。
- 云同步白名单字段：设备匿名标识、时间段、上游引用名、模型名、token 数、延迟、状态码 / 错误码、路由命中规则 ID、成本估算、客户端版本。错误字段只允许结构化错误码与脱敏后的上游错误类别，不上传错误正文、prompt 片段、response 片段、header 中的密钥或用户自定义内容。

## 四、管理面形态：无本地 Web 界面（2026-07-08 二次修订拍板）

> 原「本地 Web 界面 + 界面中心化分发」方案作废：个人版**不提供本地 Web 管理界面，取消界面包机制**。

- **命令行是唯一本地管理面**：虚拟 key、BYOK key、指标库开关、云同步开关、远程配置开关、本地配置 profile 均只能经命令行 + 配置文件管理；另提供简单用量统计命令（用量 / 错误 / 延迟 / 成本汇总，读本地指标库）。
- **云端网页可管理非机密配置**（2026-07-08 三次修订）：路由规则、上游定义、配额可在云端网页编辑，配置由本地系统主动拉取生效；key 本体仍只经本地 CLI 管理、永不上云。配置冲突规则：默认使用本地 profile；用户显式开启远程配置后，云端 profile 成为非机密配置的生效来源，本地只保留密钥映射与最后一次成功拉取的远程配置缓存。用户可随时关闭远程配置并回到本地 profile；云端不可达时沿用最后一次缓存，数据面照常工作但不能拉取新配置。云端配置必须版本化、可回滚、可导出。
- **用量报表在平台网页**：绑定账号并开启云同步后，多设备用量元数据在服务端归集，经平台网页查看（仅元数据，见 §三）。想看报表 → 必须绑定 + 同步，这同时强化注册留存漏斗；不同步的用户保留命令行简统计与文件日志。
- **本地对账工具改为命令行命令**：拉取只读账单 → 与本地指标库 diff → 终端输出差异报告。对账的意义是独立于平台的核验，故不能搬到平台网页（自己验自己）。对账对象按上游区分：token-station 平台账户上游对 token-station 自有账单；glm5.2-platform 作为被集成方时对其只读 Usage/Logs；其他上游只有在提供只读账单接口时才纳入。客户端负责适配账单 schema、diff 与输出，不定义各平台账单真实性规则。
- **取消界面包的安全收益**：「服务器下发远程界面代码」的风险面整体消失，原界面包签名 / 版本锁定机制不再需要；客户端本体仍要求安装包签名 + 用户显式升级（本体升级永远显式确认，安装包经私钥签名、客户端内置公钥校验）。注意：签名是分发安全机制，不等于 L2/L3 隐私证明，隐私证明见 §二「开核开源下的信任验收」。

## 五、获取与分发：开核开源、注册解锁云功能（2026-07-09 五次修订，替代原「注册前置下载」拍板）

- 客户端（社区版）**开核开源（Apache-2.0，已拍板 2026-07-09），任意下载、可自行构建**；官方安装包由闭源流水线签名发布，**可复现构建**保证官方二进制可验证由公开源码编出（版本检查接口匿名开放，下载不再要求登录态）。
- **注册门槛后移到云功能**：纯 BYOK / 本地模型的全部本地功能零账号可用；云同步、云端网页管配置、平台账户上游、多设备报表须绑定账号——这些功能设计上本就必须有账号，是天然注册钩子（Tailscale 模式）。注册账号天然打通 OAuth 设备码授权与可选云同步，无需二次绑定。
- 获客漏斗口径：从「注册前置 → 下载」改为「**用出价值 → 自然注册**」，注册者是已激活用户，转化质量更高；开源仓即客户端与内核的开发主战场（upstream-first，禁止内部开发定期导出），开源边界与仓库落地见[代码仓库规划](../architecture/代码仓库规划.md)，决策依据见[开源策略讨论](./个人本地版开源策略讨论.md)。
