## 一、当前闭源方案的逻辑漏洞：自证循环

[个人模式本地客户端需求 §二](./个人模式本地客户端需求.md#开核开源下的信任验收2026-07-09-五次修订替代原闭源分发下的信任验收)原「闭源分发下的信任验收」（已按采纳结论改写）存在循环论证：**用客户端自己的命令，证明客户端自己没作恶。**

- 「本地命令导出最近网络目的地」——若客户端真想偷传内容，它导出的报告同样可以撒谎。自证清白的工具不能是被怀疑对象本身。
- 「原始内容在同步代码路径中结构性不可达」——这是**关于代码结构的断言**，闭源下用户无法验证，退化为「承诺」。

这违反了 [路由透明与用户信任](./路由透明与用户信任.md) 自己立的设计原则：「不是承诺不作弊，而是让用户随时能自己验出没作弊」。路由决策做到了可验证，但「内容不出设备」这个更根本的承诺，闭源方案只做到了承诺级。

独立验证手段（Little Snitch、抓包）不依赖客户端提供的命令——但用户一旦开启云同步，外部只能看到一条到服务器的加密连接，**没有源码就无法区分传的是元数据白名单还是 prompt 正文**。这是开源能解决、闭源审计命令解决不了的一环。

## 二、信任维度：开源对目标人群接近刚需

对照 [个人模式本地客户端需求 §零](./个人模式本地客户端需求.md#零用户人群与商业目的2026-07-08-拍板) 的三类人群：

| 人群 | 对闭源的接受度 |
|------|--------------|
| ① BYOK 多上游开发者（L2） | 低——同类工具（LiteLLM、one-api/new-api、OpenRouter 生态）几乎全开源，闭源新进入者缺乏采纳理由 |
| ② 本地模型玩家 / 隐私敏感者（L3） | 极低——「对内容零外发最敏感」的人群，装闭源二进制做全流量代理的概率接近零 |
| ③ 平台潜在轻量用户 | 中性——但此人群经①②的社区口碑漏斗进来，上游枯竭则漏斗为空 |

**竞争现实**：一个闭源、免费、注册才能下载的本地路由器，在这个赛道的采纳率预期接近于零。闭源保护的转化率再高，乘以趋近于零的流量，漏斗仍是空的。

两点反面校准，避免把开源当银弹：

1. **开源本身不等于信任**。没人真读源码；信任来自「源码公开 + 可复现构建（官方二进制可被验证由公开源码编出）+ 社区盯守」。开源但官方包不可复现，怀疑者会说「二进制和仓库代码未必是一回事」，等于白开。
2. **开源不自动带来推广**。GitHub 上无人问津的开源网关一抓一把。开源给的是入场券（HN/V2EX/Reddit 传播渠道、awesome-list、被集成可能），不是流量本身。

## 三、推广维度：商业结构天然适合开源

关键事实：**个人版本来就免费，变现在平台端点**（见需求文档 §零「免费产品的三重角色」）。护城河不在客户端代码，而在平台侧的供给、价格与服务——免费漏斗型产品最适合开源的结构。他人 fork 客户端拿走的是成本中心（一个免费产品的代码），拿不走平台生意。

真正的冲突只有一个：§五 的「注册前置」。OSI 开源意味着可自行构建，下载注册门槛形同虚设（需求文档自己已指出）。**解法不是守住下载门槛，而是把注册触发点从「获取产品」后移到「获取价值」**：

- 客户端开源、任意下载；纯本地功能（BYOK 直连、本地模型、本地路由、文件日志、指标库）无需账号；
- 云同步、云端网页管配置、平台账户上游、多设备报表——设计上**本就必须绑账号**，是天然的注册钩子。

即 Tailscale 模式：客户端开源，账号换云服务。漏斗从「先注册才能下载」变为「用出感觉了自然注册」，注册者是已激活用户而非被门槛逼着填表的人，转化质量更高。

## 四、建议方案：开核，而不是全开

| 模块 | 建议 | 理由 |
|------|------|------|
| 本地数据面（路由引擎、上游适配、指标库、审计命令） | **开源（Apache-2.0 / MIT）** | 信任承诺的全部载体；「内容不出设备」「白名单结构性不可达」只有在此开源才可验证 |
| 云同步 / 远程配置的客户端侧代码 | **开源** | 恰是最需要被检查的部分——用户要看的就是「同步到底传了什么」 |
| 平台服务端、计费、批发供给管理 | **闭源** | 商业核心；用户信任问题不在此处（平台账单靠已设计的本地对账命令独立核验，逻辑自洽） |
| 若担心被云厂商 / 竞品直接商用 | 退一档用 **source-available（BSL/FSL 类）** | 信任验证价值保留约九成，但损失部分开源社区传播善意，L3 人群中部分人不认 |

配套两件必做事项，否则开源的信任价值不成立：

1. **可复现构建**（reproducible build）；
2. 保留既有安装包签名机制（开源 ≠ 不签名，见需求文档 §四）。

需接受的代价（不粉饰）：公开仓库的维护成本（issue、PR、发版节奏暴露）；roadmap 半公开；会有人 fork 掉注册引导——但 fork 者拿走的是成本中心，不是收入。

## 五、推广如何借开源发力

1. **定位语现成**：「本地的 OpenRouter，内容永不出设备，源码可查」——需求文档的产品叙事直接可作开源发布文案；
2. 首发渠道对准人群：HN「Show HN」、r/LocalLLaMA（人群②大本营）、V2EX / 即刻（国内 BYOK 人群）；
3. 把「路由透明三件套 + 反事实省钱账单」做成 README 首屏截图——「本月路由为你省了 $X」是天然传播素材（见 [路由透明与用户信任 §二](./路由透明与用户信任.md)）；
4. 让被集成成为渠道：向 Ollama / vLLM 社区提集成 PR 或进其生态列表，比自发帖有效。

## 六、结论与待决事项

**一句话收口**：闭源方案在「信任」上有自证循环的硬伤，在「推广」上放弃了赛道最主要的分发渠道，而它保护的东西（下载注册门槛）价值低于代价。建议重启开源议题，口径定为「**本地客户端开核开源 + 注册后移到云功能 + 可复现构建**」。
