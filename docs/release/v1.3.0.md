# Token Station v1.3.0

Draft. This release moves every southbound provider translation onto the South provider components
(`token-station-south`, `provider-adapter-v2`) and removes the v1 provider plugin path.

## Southbound: South components only

- The v1 `provider-adapter-v1` WASM ABI, the `provider-openai-compatible` v1 package, the shadow-comparison
  lane, and the per-upstream `south_component` setting are gone. Every upstream dialect is translated by the
  South component that declares it: `provider-openai-compatible` (`openai-compatible`, `azure-openai-v1`)
  and `provider-anthropic` (`anthropic`), both built in to official binaries.
- `plugins-dist/` is flat: agent adapters ship `manifest.json` + `adapter.wasm`, South components ship
  `manifest.json` + `component.wasm`. The plugin directory scan reads `api_version` first and dispatches to
  the matching loader. Existing configs that map `openai-compatible` to a `provider-openai-compatible`
  directory should point at `provider-openai-compatible-v2` (or drop the entry on an official binary, where
  the builtin package wins).
- `plugin install` admits agent packages only. A South component's conformance runs where it is built;
  drop the package into `plugins.dir` and vouch for it with `plugins.providers` or `plugins.allow_unsigned`.
- `plugin new`, `plugin build`, and `plugin test` are removed together with the v1 scaffold.
- `token-station-plugin-api` 0.2.0 carries the northbound ABI only.

## Behavior changes on the translated path

These follow the South component's ruled behavior and replace the v1 plugin's:

- `redacted_thinking` blocks are dropped silently instead of rejected with `capability` (400).
- A bare `reasoning` field (Qwen, OpenWebUI) is surfaced as thinking output, streaming and non-streaming,
  instead of being discarded.
- The OpenAI first-frame `delta: {role: "assistant", content: ""}` no longer produces an empty text block,
  so streamed block indexes match the provider's.
- Text-only message content rendered after the host's media fallback is sent as a one-part `content`
  array (`[{"type": "text", ...}]`) rather than a plain string. OpenAI-compatible upstreams accept both.
- Empty `content` / `tool_calls` shapes follow the component's convention: `null`, absent, and `[]` are
  not interchangeable.

## Transport: South by default

- `provider_call` now defaults to `south_v1_buffered_streaming_header_auth`: buffered and streaming calls,
  Bearer credentials, and Azure OpenAI v1's fixed `api-key` header all run on the South transport. A
  config that never named an engine switches over on upgrade; `"provider_call": "legacy"` pins an
  upstream to the legacy engine and survives a round trip.
- A call South cannot carry falls back to legacy before any credential is read, and the attempt receipt
  (`requests.log`, `metrics.sqlite` schema v11) records `south_fallback_reason`: `configured_legacy`,
  `buffered_mode_cannot_stream`, `unauthenticated_upstream`, `no_provider_runtime`,
  `credential_resolver`, `provider_dialect`, `provider_package_unapproved`, `api_dialect`, `egress`,
  `streaming`, `method`, `auth`, `body`, `secret_source`, `response_metadata`, or `headers`.
- The desktop Provider details replace the four-way runtime selector with a read-only transport row
  (`South active` / `Legacy fallback` + reason / `Legacy (pinned in configuration)`); saving details no
  longer touches the engine.
- `upstream test` probes over South by default; `--transport legacy` probes the fallback path.
- The never-wired `RolloutDisabled` eligibility gate is removed.

Rollback is a release rollback: there is no runtime switch back to the v1 path.
