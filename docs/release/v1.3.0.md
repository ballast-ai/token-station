# Token Station v1.3.0

This release moves every southbound provider translation onto the South provider components
(`token-station-south` 0.16.0, `provider-adapter-v2`), removes the v1 provider plugin path, and makes the
South transport the default engine.

## Before you upgrade

Three configuration shapes stop loading or change meaning. Check your config before installing:

- An upstream with `api_dialect: anthropic-native` must also say `provider: anthropic`. A config that pairs
  `anthropic-native` with `provider: openai-compatible` is refused at load; the error names the fix.
- A v1 `provider-openai-compatible` directory left in `plugins.dir` **fails startup**, whether or not
  `plugins.providers` still points at it: the scan reads every manifest and refuses an `api_version` it
  does not load, naming the file and the version. It is a refusal rather than a skip on purpose — a
  silently ignored package is a config that looks applied and is not. Point the entry at a
  `provider-openai-compatible-v2` package, or drop both the entry and the directory on an official binary,
  where the builtin component wins. A stale `plugins-dist/` from an earlier build is the likeliest source,
  and the error names the file rather than the staleness, so check the path it prints.
- A per-upstream `south_component` setting is dropped while the file is read, with a line naming the
  upstream, and is gone from the next save. (It is genuinely ignored now: because `deny_unknown_fields`
  rejects retired keys before any later migration can see them, this one runs on the JSON.) An upstream that never
  named a `provider_call` engine now runs on South; add `"provider_call": "legacy"` to keep it on the legacy
  engine.

There is no runtime switch back to the v1 provider path. Rolling back means installing v1.2.4 again; the
metrics store written by v1.3.0 (schema v12) is not readable by v1.2.4, so back it up first if you need
the history both ways.

## Desktop workflow improvements

- Home now includes **Test model**. Select an exact configured Provider and model, then send an ephemeral
  multi-turn test conversation. Replies stream into the console with first-text and total latency. Each
  send is a real Provider request and can incur Provider charges.
- The model test console bounds conversation input, visible output, raw Provider responses, and emitted
  stream events. Stop, close, clear, and target changes wait for cancellation acknowledgement before the
  interface reports completion or permits another request.
- Agent routing navigation and Provider management use clearer scope labels and more compact controls.
- Settings keyboard navigation keeps focus and selection aligned after pointer or keyboard activation.
  The content pane keeps independent scrolling at supported desktop widths and resets to the top when the
  selected section changes.

## Southbound: South components only

- The v1 `provider-adapter-v1` WASM ABI, the `provider-openai-compatible` v1 package, the shadow-comparison
  lane, and the per-upstream `south_component` setting are gone. Every upstream dialect is translated by the
  South component that declares it: `provider-openai-compatible` (`openai-compatible`, `azure-openai-v1`)
  and `provider-anthropic` (`anthropic`), both built in to official binaries.
- `plugins-dist/` is flat: agent adapters ship `manifest.json` + `adapter.wasm`, South components ship
  `manifest.json` + `component.wasm`. The plugin directory scan reads `api_version` first and dispatches to
  the matching loader. Existing configs that map `openai-compatible` to a `provider-openai-compatible`
  directory should point at `provider-openai-compatible-v2` (or drop the entry on an official binary, where
  the builtin package wins).
- `plugin install` admits agent packages only. A South component's conformance runs where it is built;
  drop the package into `plugins.dir` and vouch for it with `plugins.providers` or `plugins.allow_unsigned`.
- `plugin new`, `plugin build`, and `plugin test` are removed together with the v1 scaffold.
- `token-station-plugin-api` 0.2.0 carries the northbound ABI only.

## Behavior changes on the translated path

These follow the South component's ruled behavior and replace the v1 plugin's:

- `redacted_thinking` blocks are dropped silently instead of rejected with `capability` (400).
- A bare `reasoning` field (Qwen, OpenWebUI) is surfaced as thinking output, streaming and non-streaming,
  instead of being discarded.
- The OpenAI first-frame `delta: {role: "assistant", content: ""}` no longer produces an empty text block,
  so streamed block indexes match the provider's.
- Text-only message content rendered after the host's media fallback is sent as a one-part `content`
  array (`[{"type": "text", ...}]`) rather than a plain string. OpenAI-compatible upstreams accept both.
- Empty `content` / `tool_calls` shapes follow the component's convention: `null`, absent, and `[]` are
  not interchangeable.

## Transport: South by default

- `provider_call` now defaults to `south_v1_buffered_streaming_header_auth`: buffered and streaming calls
  run on the South transport for every dialect an admitted component declares it can authenticate. That
  is decided by the component's manifest rather than by a list of provider names, so Anthropic's
  `x-api-key` travels over South alongside Bearer credentials and Azure OpenAI v1's `api-key` — the name
  list had not been extended for it, so the Anthropic component could translate a request the transport
  then refused to send. A config that never named an engine switches over on upgrade;
  `"provider_call": "legacy"` pins an upstream to the legacy engine and survives a round trip.
- A call South cannot carry falls back to legacy before any credential is read, and the attempt receipt
  (`requests.log`, `metrics.sqlite` schema v12) records `south_fallback_reason`: `configured_legacy`,
  `buffered_mode_cannot_stream`, `unauthenticated_upstream`, `no_provider_runtime`,
  `credential_resolver`, `api_dialect`, `egress`, `streaming`, `method`, `auth`, `body`,
  `secret_source`, or `headers`. Three reasons this release can no longer produce —
  `provider_dialect`, `provider_package_unapproved`, `response_metadata` — went with the judgement
  behind them: eligibility no longer matches a provider's *name* against a list, re-decides whether an
  admitted component's package is approved, or asks about response metadata. A component that passed
  admission is judged on its descriptor and the auth arms its manifest declares. Attempts v1.2.4
  recorded under those three reasons still read and still group; the store keeps them parseable.
- The desktop Provider details replace the four-way runtime selector with a read-only transport row
  (`South active` / `Legacy fallback` + reason / `Legacy (pinned in configuration)`); saving details no
  longer touches the engine.
- `upstream test` probes over South by default; `--transport legacy` probes the fallback path.
- `stats --by engine` and `stats --by fallback` group receipts by the engine of the attempt that settled
  each request and by its fallback reason (`(south)` when none). The admin `stats` endpoint and the desktop
  usage view accept the same two groupings.
- The never-wired `RolloutDisabled` eligibility gate is removed.

## Anthropic: translated by default, passthrough only for server tools

- `agent-anthropic` no longer refuses content blocks it does not model (`server_tool_use`,
  `web_search_tool_result`, `document`, `search_result`, …): they ride through the IR verbatim. Routed to
  an Anthropic upstream they round-trip unchanged; routed to an OpenAI-compatible or Gemini upstream the
  provider component refuses them by name at render time (south 0.16.0), with the same `capability`
  (400) class as before but attributed to the renderer that cannot express them.
- A forced `tool_choice: {type: tool, name}` is carried instead of degraded to `auto`.
- A `document` block (PDF attachment) reaches a `provider: anthropic` upstream unchanged, so the upstream
  reads the file itself. Local PDF text extraction, and the "attachment not read" marker for anything
  else, now happen per attempt and only for upstreams whose dialect cannot carry the block
  (OpenAI-compatible, Azure, Gemini). Before, every translated route extracted locally.
- `api_dialect: anthropic-native` is now the server-tool escape hatch: only a request declaring a tool the
  upstream executes itself is forwarded verbatim; everything else takes the translated path through the
  Anthropic provider component. Such an upstream must be `provider: anthropic` — configs that paired
  `anthropic-native` with `provider: openai-compatible` are rejected at load with a message naming the fix.

## Fixes on the passthrough path

- A `anthropic-native` turn now reports the tokens the upstream billed. It reported none, so its cost
  was unknown, budgets counted it as free, and — the one that matters for routing — the quota ledger
  never saw the consumption, so Quota-first kept choosing an account it had just spent. Buffered and
  streamed turns are both counted; Anthropic reports usage in two halves of a stream and both are read.
  Turns recorded by earlier versions keep their blank counts and stay uncosted: the repricing pass
  only visits rows that already have a token count, so there is nothing for it to price.
- A streamed native reply no longer corrupts characters that the network splits across two reads.
  Each read was decoded on its own, so a multi-byte character straddling a boundary became `U+FFFD` —
  reliably, on any long answer in Chinese, Japanese, or containing emoji. The bytes are relayed
  unchanged now, which is what the passthrough always claimed to do.
- A native attempt that never reaches its upstream is recorded under the `native` engine rather than
  `unknown`, so `stats --by engine` shows the failures as well as the successes.
- A 5xx or a rate limit from an `anthropic-native` upstream is retried against the rest of the pool, as
  the translated path already did. If every upstream fails, the client receives the **last** one's
  status and body byte for byte rather than a token-station envelope. Before, the first failure was
  relayed and the request ended there, so one upstream's outage was survivable on the translated route
  and fatal on this one. Ejection is unchanged: an upstream that keeps failing stops being routed to.

## Known behaviour, not a bug

- A 4xx from an `anthropic-native` upstream reaches the client verbatim and the pool's next upstream is
  not tried: the same request fails the same way on every upstream, and Claude Code reads the original
  error body to repair itself, which a wrapped envelope would break.
- An upstream whose credential comes from a key file rather than the credential store runs on the legacy
  engine, with `south_fallback_reason: secret_source`. South carries stored credentials only.

## Update and installation

An official v1.2.4 preview can check for v1.3.0 and install it inside the App. The updater verifies the
signed payload before installation.

For a manual installation, download `token-station_1.3.0_aarch64_UNSIGNED-UNNOTARIZED.dmg` and its
`.sha256` file. Verify the checksum, drag the App to Applications, and follow the README in the DMG if
macOS blocks it.

This preview supports Apple Silicon only. The DMG and App are ad-hoc signed, unsigned by Apple, and not
notarized. The updater signature protects the update payload, but it does not provide Apple Developer ID
identity or an Apple notarization ticket.
