## Show HN

**标题**：Show HN: Token-station – a local LLM router that never sees your prompts (Rust, WASM plugins)

**正文**：

I built a loopback proxy that routes LLM requests between my own API keys and
local models — rules first, then agent hints, then a scoring heuristic. The
part I care about: routing is a local decision. Nothing about the prompt
leaves the machine that wasn't already going to the provider you configured.

Some design choices that were fun to defend with tests:

- The metrics store *structurally* cannot hold content: every column comes
  from a record of numbers, closed enums, and operator-configured names. An
  integration test sends a canary through message content, tool definitions
  and headers, then greps the raw SQLite bytes.
- Provider adapters are sandboxed WASM components with no network and no
  secrets. An "exfiltration gate" validates each outbound request against the
  configured endpoint *before* any credential resolves — a malicious adapter
  can build a request to evil.example, but the key never attaches.
- Keys live in the OS keychain, resolved per request; a key pasted into a
  base URL is rejected by the type that parses URLs.
- Releases are reproducible (pinned toolchain, remapped paths,
  SOURCE_DATE_EPOCH, deterministic tar) and the manifest is Ed25519-signed —
  CI rebuilds from a clean tree on every release and byte-compares. The
  signature proves the publisher; the rebuild proves the source.

Works today with OpenAI-compatible upstreams (incl. Ollama/vLLM). Anthropic
and Gemini native adapters are next, based on what people actually need.

Apache-2.0, open core. I'd love scrutiny on the exfiltration gate and the
content-free metrics claim — both have tests designed to be attacked.

https://github.com/GlimpseEngine/token-station

## r/LocalLLaMA

**标题**：I made a local router that mixes my BYOK keys with Ollama by rules — and provably can't log prompts

**正文**：

Point your IDE at `127.0.0.1`, write rules like "tools → GPT, long context →
the big model, everything else → llama on Ollama", and it just routes. Ask for
model `auto` and the router decides; ask for a concrete model and you get it.

Highlights for this crowd:

- Fully offline-capable: no account, no telemetry; the only non-upstream
  connection is a version check *you* trigger with `upgrade`.
- The metrics store (SQLite, local) records model/tokens/latency/decision —
  and physically has no column for content. Tests grep the raw DB bytes for a
  canary to keep it that way.
- Failing upstreams get ejected and probed back in; streams survive awkward
  TCP splits (there are tests that cut SSE frames mid-multibyte-char).
- `upstream test` sends one max_tokens=1 completion per model so you know a
  key works before your agent does.
- Reproducible builds + signed releases, or just `cargo build` it yourself.

OpenAI-compatible upstreams today (Ollama, vLLM, most BYOK). Tell me which
native adapters you want first.

## V2EX（/go/create 或 /go/programmer）

**标题**：做了个本地 LLM 路由器 token-station：路由决策不出本机，指标库结构上装不下 prompt

**正文**：

把 IDE / Agent 指到 `127.0.0.1`，按规则在自己的 BYOK key 和本地 Ollama 之间
路由：带工具的走 GPT、长上下文走大模型、其余走本地。请求 `auto` 由路由器
决策，请求具体模型就直通。

几个设计点：

- 零账号、可断网用；外联只有你配置的上游 + 你手动触发的版本检查。
- 指标库（本地 SQLite）只有数字、闭集枚举和你自己配置里的名字——没有列能
  装下 prompt，集成测试拿金丝雀 grep 数据库原始字节来验证。
- provider adapter 是 WASM 沙箱：无网络、拿不到明文 key；外泄闸门在凭据
  解析前核对出站端点。
- key 进 OS 钥匙串；粘进 URL 的 key 在配置解析层直接拒绝。
- 可复现构建 + Ed25519 签名发布：签名证明发布者，重建证明源码；也可以
  完全不信任二进制，自己 `cargo build`。

Rust 写的，Apache-2.0，开核。欢迎来挑战外泄闸门和「内容进不了磁盘」这两个
断言——测试就是照着被攻击设计的。
