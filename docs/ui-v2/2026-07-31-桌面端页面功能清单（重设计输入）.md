# Token Station 桌面端页面功能清单（重设计输入）

> 目的：作为桌面端 UI 重新设计（高保真原型）的输入素材，完整记录当前实现（`apps/desktop/src`）的模块、操作、字段，便于对照取舍。
> 范围：仅覆盖前端 UI 层（页面 + 复用组件），不涉及 Rust 内核实现细节。
> 关联：`docs/design/2026-07-28-桌面端UI重构与发布门禁设计.md`（如有交叉，以该文档的门禁约束为准）。

## 0. 核心概念与全局状态

Token Station 管理五类核心对象：

- **Provider（供应商）**：上游 AI 服务商配置（Base URL、API Key、可用模型、模型能力、目录、额度计划）。
- **Agent（智能体）**：本地检测到的 CLI 工具（如 Claude Code、Codex 等），可被"接管"（改写其配置指向本地代理）。
- **Tier（三档路由）**：high / mid / low 三档，每档绑定一个 Provider + Model，供主页与各 Agent 路由使用。
- **Profile（策略组）**：一组三档配置的命名快照，可在多个 Agent 间复用挂载。
- **Quota（额度）**：两套机制并存——「额度优先」路由模式（按队列轮换账户）与「实时额度监控」（只读展示）。

全局状态 `StateView` 的关键字段（详见 `apps/desktop/src/api.ts`）：

| 字段 | 说明 |
|---|---|
| `providers[]` / `deleted_providers[]` | 供应商列表 / 回收站 |
| `tiers` | 主页三档配置（`Record<TierSlot, TierView>`） |
| `keywords` | 各档关键词库 |
| `agent_routes` | 各 Agent 的路由配置（`AgentRouteView`） |
| `profiles[]` | 已存策略组名 |
| `local_only` / `allow_cloud_fallback` | 只走本地开关及云端兜底子开关 |
| `routing_mode` | 全局路由模式：`tiered`（三档）/ `quota_first`（额度优先） |
| `quota_accounts[]` | 额度优先模式的轮换账户队列 |
| `serve` | 代理运行态（`ServeView`：phase/app_runtime/listener_reachable/virtual_key 等） |
| `draft_revision` / `saved_revision` / `config_dirty` / `config_error` | 草稿-保存-应用的三段版本状态 |
| `settings` | 鉴权、出站代理、本地指标等系统设置 |

**保存/应用模型**：几乎所有配置改动都遵循"改草稿 → 保存并应用（重启代理生效）"两段式，`config_dirty` / `saved_revision` / `serve.running_revision` 三者的关系决定了顶部的保存状态文案（"有未保存更改" / "已保存尚未应用" / "运行中 revision N"）。这是贯穿所有配置类页面的核心心智模型，重设计时需要保留或显式替代。

## 1. 整体信息架构

```
AppShell（外壳：左侧导航 + 顶部工具条）
├─ HomePage（主页路由，默认视图）
├─ Agent 路由页 × N（每个已注册 Agent 一个，左侧导航列出）
├─ Stats（用量统计，顶部图标入口）
├─ QuotaUsagePage（实时额度，从 HomePage/AgentRoutePage 的"实时额度"按钮跳转）
├─ SettingsHub（设置，顶部图标入口）
│  ├─ general：VirtualKeyCard + Settings
│  ├─ router：RouterTable
│  ├─ plugins：Plugins
│  ├─ appearance：外观（主题）
│  ├─ language：语言
│  └─ about：About
├─ AddProviderPage（添加供应商，顶部"+"入口）
│  └─ FreeProviderConfigPage（选中免费供应商后的验证配置子页）
└─ RecoveryShell（异常自救兜底，非常规路径，覆盖全屏）
```

**AppShell 导航栏**：
- 左侧：Home + Agent 列表（每项带状态点：connected 绿 / blocked 红 / detected 蓝 / idle 灰）+ "重新扫描"按钮
- 顶部：代理运行指示灯 + 状态文案（未知状态/运行中/启动中/停止中/重试/启动代理）+ Agent 连接状态 + 启停按钮 + 路由模式切换（仅 home/agent 视图，tiered ⇄ quota_first）+ 用量入口 + 设置入口 + "添加供应商"按钮

## 3. Agent 路由页 — `/pages/AgentRoutePage.tsx`

每个已注册 Agent（Claude Code / Codex 等）一个实例，管理"是否接管该 Agent 的配置"与"该 Agent 的路由是否独立于主页"。

### 3.1 状态徽章（statusCopy）
| tone | 文案 | 触发条件 |
|---|---|---|
| idle | 未发现 | 无可管理安装 |
| idle | 待选择（多安装） | 检测到多份安装但未选定 |
| success | 已接入 | installation.connected |
| danger | 需修复 | 已接管但运行态不一致 |
| ready | 可接入 | 精确匹配或兼容 |
| danger | 暂不可接入 | 兼容性判定非 DETECTED_VERIFIED |

### 3.2 接入操作区
| 元素 | 说明 |
|---|---|
| InstallationPicker | 多安装时的选择下拉（见 §11.7） |
| 主操作按钮 | 已接管→"恢复 Agent 原始配置"；未接管→"一键接入"；处理中→"处理中…" |
| 「强制断开」 | 仅已接管时出现的小按钮，附 tooltip：仅在正常恢复因密钥/快照不可用而失败时使用 |
| 首次接入 diff 卡片 | 仅首次接入后出现一次（localStorage 记忆），列出关键改动字段（URL/Key/Endpoint 等优先，最多 3 条+"另有 N 项"汇总），「知道了」关闭 |
| 未启动代理提示 | `!serveRunning && !managed` 时的 inline 提示 |

### 3.3 路由区（按 `route.routing_mode` 二选一）
- `quota_first` → QuotaPriorityPanel
- `tiered` → 三档路由区：
  - 模式单选：跟随主页（inherit）/ 独立路由（custom）/ 挂载策略组（profile）
  - profile 模式下出现策略组下拉
  - TierRouteEditor（非 custom 时只读）
  - custom 模式：「保存并重启」（禁用：有配置错误）+「恢复主页路由」
  - profile/inherit 模式：说明性文案（当前跟随的策略组名 / 会自动跟随主页最新配置）
  - `config_error` 时的错误提示

## 10. 跨页面共性规则（重设计时必须保留的约束）

1. **双语文案**：所有文案通过 `copy(en, zh)` 或 `t(key)` 提供中英双语，由 LanguageProvider 统一切换。
2. **忙碌态锁定**：几乎所有表单/按钮遵循复合禁用逻辑（`busy || saving || refreshing || applying`），防止并发写操作冲突。
3. **金额输入统一规则**：价格/预算类数字输入统一用正则 `^\d+(?:\.\d{1,6})?$`，上限 90 亿，内部换算为微单位整数。
4. **三态成本展示**：`cost_kind` 统一分 `actual`（实际）/ `estimated`（估算）/ `unknown`（未知）三态着色，贯穿回执、日志、统计三处。
5. **预算仅观测**：预算功能明确定位为"仅提醒，不影响实际路由决策"，UI 上必须保留 OBSERVE ONLY 类似的显式声明，避免用户误以为预算会限流。
6. **保存-应用两段式**：配置类改动先写草稿，「保存并应用」才重启代理生效；重设计时无论如何调整交互，都需要让用户清楚区分"改了" vs "生效了"。

## 12. 重设计需要重点关注的现有问题（供设计评审参考）

以下是从字段清单反推出的、当前实现里比较明显的信息架构/交互负担，供重新设计时权衡取舍（非结论，仅供讨论）：

1. **Stats 页面单页承载过多**：筛选、总览、趋势图、明细表、日志、预算表单、价格编辑器七个模块挤在一个可滚动长页里，折叠面板（"预算与定价管理"）掩盖了重要功能的可发现性。
2. **"保存草稿 / 保存并应用"两段式贯穿全局**，但视觉提示（`config-save-status` 文案）比较弱，容易让用户以为改了就生效。
3. **quota_first 与 tiered 两种路由模式在 HomePage 和 AgentRoutePage 上各自复制了一套完全不同的 UI**（一个是三档编辑器，一个是队列面板），概念上是否需要合并或至少统一视觉语言值得讨论。
4. **SettingsHub 的"router"分区（RouterTable）是纯只读调试信息**，和其余偏用户配置的分区混在一起，信息密度/受众都不一样。
5. **首次接入 diff 卡片、预算 OBSERVE ONLY 声明等"信任类"提示分散在各页面**，没有统一的视觉语言来区分"只读说明" vs "可操作项"。
