## 一、定位与范围

**一句话定位**：本地的 OpenRouter——单二进制、`127.0.0.1` 本地代理，多上游混合路由（BYOK 直连 / 本地模型 / 平台账户），内容永不出设备，源码可查。

**商业角色**（免费产品，不直接收入）：注册漏斗（注册解锁云功能）、平台端点转化触点、信任资产（本地独立计量 + 对账）。

| 范围内（本仓承载） | 范围外 |
|--------------------|--------|
| `crates/*` 公共地基：protocol / router-core / plugin-api / plugin-runtime / conformance / metrics | 服务端网关与平台服务（闭源仓 `token-station-server`） |
| `apps/cli`：客户端本体（本地代理 + CLI 管理面） | 本地 Web 界面 / 界面包（已拍板取消） |
| `plugins/official/*`：OpenAI-compatible 双端样板 adapter | 企业/小 Team 网关上游（远期观察项，不进 C1–C3） |
| 云同步 / 设备码授权 / 远程配置的**客户端侧**代码与协议 schema | 云同步接收、下载分发、报表网页等平台侧配套（闭源仓） |
| ONNX 小分类器的加载与推理 | 分类器训练管线与数据飞轮（闭源仓） |

**设计红线**（已拍板，任何阶段不得违反）：

1. 本地直连只用个人 key，平台批发 key 永不下发；BYOK key 永不上传（对称约束）；
2. 路由决策全部本地完成，内容不发给任何云端分类器；
3. 原始请求/响应内容永不上传，无开关；
4. 指标库默认开启、仅存本地，未开云同步不出设备；
5. 云同步字段白名单在代码层硬编码，内容字段结构性不可达；
6. 开源仓必须能独立编译出完整社区版，不得 import 任何闭源模块（依赖只许闭源 → 开源单向）。

## 三、阶段详表

### C0 — 公共地基（与服务端 P1 同窗口共建）

**目标**：抽出双线共用的路由内核与插件 ABI，本仓即开发主战场（upstream-first）。crate API 设计评审必须服务端、客户端两线共同参与——配置源抽象（trait）从第一天就双实现（服务端 DB / 客户端本地文件）。

| # | 任务 | 说明 | 粗估 |
|---|------|------|------|
| 1 | `protocol`：Canonical IR + AgentHint + 基础协议类型 | 双端 adapter 的公共中间表示 | 与 #3 合计 4 人周（= P1#7） |
| 2 | `router-core` 骨架（无 IO 依赖）+ 本地文件配置源 | 先覆盖规则/启发式最小子集；配置源 trait 抽象 | 2 人周（= P1#6） |
| 3 | `plugin-api` / `plugin-runtime`：`agent-adapter-v1` / `provider-adapter-v1` WASM Component ABI、manifest schema、安全加载 | 官方与第三方 adapter 统一走此机制 | （并入 #1） |
| 4 | `conformance`：双端准入测试 runner + fixtures | 插件包必须带 manifest、签名与 conformance fixtures | （并入 #1） |
| 5 | 官方样板插件：OpenAI-compatible agent-adapter / provider-adapter 各一 | 每插件独立 manifest、fixtures、CODEOWNERS | （并入 #1） |
| 6 | CI 门禁：fmt → clippy(-D warnings) → test → cargo deny → cargo audit | 本仓已有 ci.yml，补 deny.toml 等缺项 | 0.5 人周内随手 |

**出口标准**：`router-core` 最小 API 可被 CLI 调用；OpenAI-compatible 双端 WASM 插件通过 conformance 并可本地加载；配置源 trait 有本地文件实现与测试。

### C1 — 最小可用（纯本地，零账号）

**目标**：BYOK / 本地模型用户全程零绑定可用；出口即开源首发。

| # | 任务 | 说明 | 粗估 |
|---|------|------|------|
| 1 | 本地端点：`127.0.0.1` OpenAI 兼容 `chat/completions`（含流式）+ `/v1/models` 聚合目录 | 经 agent-adapter 插件 normalize；接受 hint header | 1.5 人周 |
| 2 | 上游适配：BYOK 直连（OpenAI / Anthropic / Gemini 等 provider-adapter）+ 本地模型（Ollama / vLLM 直通） | 简化版健康检查：超时/错误计数 → 临时摘除 → 恢复探测 | 2 人周 |
| 3 | 本地路由：规则 → hint → 启发式（复用 `router-core`），决策记录入指标库 | 级联兜底（④层）不进个人版 | 1 人周 |
| 4 | 密钥保管：OS 钥匙串优先，退化主密码加密文件；key 不进日志 | 本地虚拟 key 首启自动生成、默认开鉴权 | 1 人周 |
| 5 | 数据层：文件日志（始终写、轮转）+ 指标库（SQLite，首启即建、默认开启、可关）；调试留存默认关、限期自动清理 | 指标库存元数据明细：模型/token/延迟/决策/错误/成本估算 | 1 人周 |
| 6 | CLI 管理面：`key` / `upstream`（增删测活）/ 规则编辑 / 各开关 / 简统计命令（用量/错误/延迟/成本，读指标库） | 命令行是唯一本地管理面 | 1.5 人周 |
| 7 | 开源首发工程：可复现构建、安装包签名（Ed25519 manifest，私钥在闭源流水线）、匿名版本检查 + 显式确认升级、README 与发布文案 | 开源信任价值的成立前提（已回写 V2 计划 C1 估算） | 1 人周 |

**出口标准**（= V2 验收表 C1 行，口径按开核修正）：

- IDE / Agent 指向 `127.0.0.1` 可用，流式正常；
- BYOK / 本地模型混合路由生效；断网（关云同步/远程配置后）完整可用；
- key 不进日志；指标库默认开启；外联目的地可解释（仅用户配置的上游 + 匿名版本检查）；
- ~~注册下载~~ → **任意下载、开源可自行构建**；官方二进制可验证由公开源码编出（可复现构建）；
- 通过后进入：个人版本地试用 + 开源社区首发（Show HN / r/LocalLLaMA / V2EX）。

### C2 — 账号与云端观测

**前置**：闭源侧 P3a#9 配套就绪（设备码授权、云同步接收、用量报表网页、最小远程配置服务、下载分发 + 签名流水线）。

| # | 任务 | 说明 | 粗估 |
|---|------|------|------|
| 1 | 设备码授权（RFC 8628，懒触发）：首次启用平台上游 / 云同步 / 对账 / 拉预设时才要求绑定 | 统一 refresh token 加密存储，按 scope 换短效 access token | 1 人周 |
| 2 | 平台账户上游：OAuth token 接入平台端点，与 BYOK 并存于账户维度（不并存于同一请求） | 反向随时可关，零迁移 | 1 人周 |
| 3 | 云同步（默认关）：字段白名单硬编码、断点续传、批量上报 | 白名单：设备匿名标识/时间段/上游引用名/模型名/token 数/延迟/状态码/命中规则 ID/成本估算/客户端版本 | 1.5 人周 |
| 4 | 定价表下发与成本估算：配置通道数据下行，本地计算 | 逐请求成本估算写指标库 | 0.5 人周 |
| 5 | 远程配置 profile 拉取（默认关）：开启后云端 profile 对非机密配置生效；本地保留密钥映射 + 最后一次成功缓存；关闭即回本地 profile | 云端不可达沿用缓存，数据面照常 | 1 人周 |

**出口标准**（= V2 验收表 C2 行）：设备码懒触发绑定；平台账户上游可切换；云同步字段抽样无 prompt / response / header secret；平台网页可看多设备用量；远程配置离线缓存可回退。

### C3 — 完整形态

**前置**：闭源侧 P4#4 蒸馏产出 ONNX 权重；对账依赖只读账单 API（token-station 自有账单；glm5.2-platform 作为被集成方的只读 Usage/Logs）。

| # | 任务 | 说明 | 粗估 |
|---|------|------|------|
| 1 | 本地对账命令：拉只读账单 → 与指标库逐条 diff → 终端差异报告（token 计数、预扣/结算差异） | 独立于平台的核验，只能在本地做；负责账单 schema 适配，不定义真实性规则 | 1.5 人周 |
| 2 | 内嵌 ONNX 小分类器：权重随 release 发布（不进 git），本地推理进路由第四级 | 推理开源、训练闭源；权重更新走本体升级同一签名通道 | 1.5 人周 |
| 3 | 本地审计输出：命令导出配置摘要、启用的云端功能、同步字段版本、最近 N 条路由决策与外联摘要 | 开源后审计命令从「自证」升级为「可对照源码验证」 | 1 人周 |

**出口标准**（= V2 验收表 C3 行）：对账命令可拉账单并 diff 出报告；ONNX 分类器本地推理 <10ms 且附离线评测报告；审计输出四要素齐全。

## 四、与服务端主线的同步点

| 同步点 | 时机 | 约束 |
|--------|------|------|
| `router-core` API 设计评审 | C0 启动时 | 两线共审；配置源 trait 双实现（DB / 本地文件）从第一天开始，防止各自 fork |
| 双端 adapter ABI 冻结节奏 | C0–C1 | breaking change 必须走 `-v2` 并存期；官方插件与 conformance 同步变更 |
| C2 启动闸门 | P3a 出口 | P3a#9 五项配套验收通过才启动 C2，不得客户端先行 mock 上线 |
| C3 启动闸门 | P4#4 产出 | 分类器必须过离线评测门槛；未达标则 C3#2 顺延，C3#1/#3 可先行 |
| 决策记录字段 | C0 | 指标库决策字段按未来训练特征需求设计（与服务端 P1#1 同构），晚埋则返工 |

## 六、通用门禁（每阶段出口必过）

| 门禁 | 验收方式 |
|------|----------|
| 工程质量 | `cargo fmt --check`、`clippy -D warnings`、`cargo test --workspace`、cargo deny、cargo audit 全绿 |
| 安全边界 | secret 不进日志；内容不上云约束未破（同步路径代码审查 + 抽样）；错误不泄内部细节 |
| 隐私可验证 | 关闭云功能后外联目的地清单可解释且可独立抓包验证 |
| 开源纪律 | 本仓独立可编译；无闭源依赖；PR / issue / CI 全公开（upstream-first，禁止内部开发定期导出） |
| 文档同步 | 新增能力同步到需求、概要设计、README 与用户可见口径 |

## 七、风险登记

| # | 风险 | 缓解 |
|---|------|------|
| 1 | `router-core` 双端 API 设计不当 → 服务端与客户端各自 fork | C0 两线共审；配置源 trait 第一天双实现（继承 V2 风险 #2） |
| 2 | C2/C3 被服务端 P3a/P4 进度卡死，客户端人力空转 | 闸门空窗排入社区运营与 adapter 生态工作（§五）；C3#1 对账不依赖分类器，可与 #2 解耦先行 |
| 3 | 可复现构建在 Rust 工具链下有非确定性因素（路径、时间戳、平台差异） | C1#7 提前验证；锁 rust-toolchain；发布用容器化构建环境；做不到全平台先保 Linux 单平台可复现 |
| 4 | 开源首发即巅峰、后继乏力（GitHub 无人问津） | 首发素材按开源策略 §五准备（定位语、透明三件套截图）；被集成渠道（Ollama / vLLM 生态列表）比自发帖优先 |
| 5 | 白名单约束在迭代中被无意破坏（新字段绕过白名单） | 同步路径字段以类型系统收口（白名单 struct 之外无序列化路径）+ conformance 级测试断言 |
| 6 | ONNX 分类器不达标 | 继承 V2 风险 #3：不达标不替换判官级决策，C3 按 #1/#3 先交付 |
