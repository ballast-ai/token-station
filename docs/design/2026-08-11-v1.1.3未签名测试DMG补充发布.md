# v1.1.3 未签名测试 DMG 补充发布设计

## 1. 问题与决策

v1.1.3 已以仅源码方式发布。用户后续明确要求 GitHub Release 必须提供
DMG，并接受“未签名、未公证”的测试包。当前 Mac 没有有效的 Developer ID
身份，GitHub 仓库也没有 Apple 签名或公证凭据，因此不能把该 DMG 表述为
正式 macOS 安装包。

本次把 DMG 定义为稳定 Release 下的显式测试资产，不移动已公开的
`v1.1.3` 标签，不启用正式二进制工作流。

## 2. 目标

1. 为 Apple Silicon 生成
   `token-station_1.1.3_aarch64_UNSIGNED-UNNOTARIZED.dmg`。
2. 同时发布对应的 `.sha256` 文件。
3. App 可执行代码来自 `v1.1.3` 标签；DMG 安装物料来自已合并的打包
   修订提交，两个提交都写入 `构建来源.txt`。
4. DMG 文件名、根目录警告、安装说明、安装脚本和 Release 正文都必须
   明确写出“未签名、未公证、仅供测试”。
5. 正式 DMG 的 Developer ID、Gatekeeper、Apple 公证和票据审计保持原样，
   测试模式不得降级正式路径。

## 3. 范围与非目标

范围：

- 新增独立的 `--unsigned-test` 打包和审计模式。
- 新增测试包安装说明、可见警告标记和构建来源文件。
- 让现有安装脚本在测试标记存在时明确提示风险，并允许用户继续。
- 更新 v1.1.3 发布说明和公开回归测试。

非目标：

- 不生成 Developer ID 签名或 Apple 公证声明。
- 不提供 Intel DMG、Windows 安装包、CLI 二进制或 Updater 载荷。
- 不移动、删除或重建 `v1.1.3` 标签。
- 不将本机 App、用户配置、凭据、Token、缓存、日志或未跟踪文件放入 DMG。

## 4. 安全与数据红线

1. 测试模式必须由显式 `--unsigned-test` 参数启用；默认仍是正式模式。
2. 正式模式仍必须要求 DMG 签名、Apple 公证、票据装订、Gatekeeper 和完整审计。
3. 测试模式只接受 ad-hoc 签名且 bundle id 为 `com.tokenstation.desktop` 的 App。
4. 安装脚本仍只能操作 `/Applications/token-station.app` 和带固定前缀的随机
   临时目录，并保留明确确认、目标验证、备份和回滚。
5. 不得关闭 Gatekeeper、修改 SIP，或对宽泛路径移除 quarantine。
6. 不得把开发机用户名、绝对路径、GitHub Token、Apple 凭据、业务配置或未跟踪文件
   写入 App、DMG、校验文件或 Release 正文。
7. 资产在隐藏临时目录中生成和审计，通过后才以无覆盖方式发布到输出路径。

## 5. 用户可见交互与失败处理

DMG 根目录包含：

1. `token-station.app`
2. `Applications`（精确指向 `/Applications`）
3. `安装前必读.md`
4. `安装 Token Station.command`
5. `AGENTS.md`
6. `未签名测试版.txt`
7. `构建来源.txt`

安装脚本在测试标记存在时，必须先说明 App 未通过 Apple 身份验证和公证，
建议仅在确认 GitHub Release 来源和 SHA-256 后继续。测试模式不把 Gatekeeper
拒绝当作损坏，但仍验证 ad-hoc 代码签名、bundle id、安装目标和安装后 App。
其他输入除 `y` 或 `Y` 外均取消，不修改系统。

所有失败必须说明是来源 App、测试标记、bundle id、ad-hoc 签名、复制、替换、启动
还是回滚失败，不只输出工具原始错误。

## 6. 响应式、键盘和可访问性

本次不修改 App UI。Finder 根目录警告和安装文件名可直接由键盘选择；终端
提示不依赖颜色、鼠标或图形弹窗。风险提示使用纯文本，结果可被屏幕阅读器和
终端历史读取。

## 7. 状态变化

`设计已更新` → `公开测试先失败` → `测试打包模式已实现` → `全量回归通过` →
`修订 PR 已合并` → `从 v1.1.3 构建 App` → `最终 DMG 挂载审计通过` →
`上传 DMG 和 SHA-256` → `远端下载回验通过`。

任一阶段失败都不得上传产物。正式模式门禁失败时，不得用测试模式替代正式包；
本次只因用户明确指定测试 DMG 才使用测试路径。

## 8. 公开测试边界

- 正式模式缺少签名身份或公证凭据时仍失败。
- 测试模式必须同时要求警告文件、测试安装说明和两个构建提交。
- 测试 DMG 文件名必须含 `UNSIGNED-UNNOTARIZED`，正式 DMG 文件名不得包含该后缀。
- 挂载审计要求七个根目录入口、精确 bundle id、1.1.3 版本、arm64 架构、
  ad-hoc App 签名、未签名 DMG、无公证票据、精确 Applications 链接和可执行安装脚本。
- 安装说明、脚本和 Release 正文不得声称已签名或已公证。
- DMG 内容和 App 可执行文件不得包含开发机用户名、`/Users/` 路径、凭据、
  未跟踪文件名或本地配置。
- 最终上传后必须重新下载 DMG，比对 SHA-256，再挂载执行同一审计。

## 9. 验收标准

1. 修订提交只包含设计、测试、打包/审计脚本、安装物料和发布说明。
2. 前端、Rust 工作区、桌面 Rust、静态发布门禁和生产构建全部通过。
3. 打包修订 PR 合入 `develop`，且 App 源码与 `v1.1.3` 标签的 `apps/`、
   `crates/` 和 `plugins/` 完全一致。
4. 最终 DMG 和校验文件通过本地审计，Release 页面明确警告安全边界。
5. 远端资产列表只新增精确命名的 DMG 和 `.sha256`，不包含其他本地文件。
6. 远端下载回验的哈希、挂载内容、App 版本、架构和测试标识全部一致。

## 10. 实现落点与遗留项

- 打包：`scripts/package-macos-dmg.sh`。
- 挂载审计：`scripts/audit-macos-dmg.sh`。
- 安装脚本：`packaging/macos/安装 Token Station.command`。
- 测试说明：`packaging/macos/未签名测试版安装前必读.md`。
- 静态门禁：`scripts/check-macos-dmg-packaging.mjs`、`tests/unsigned-test-dmg.mjs`。
- 发布说明：`docs/release/v1.1.3.md`。

已知遗留：Gatekeeper 会拒绝该测试 App，用户需要通过 DMG 内安装脚本或
Finder 右键“打开”流程安装。正式 DMG 仍需 Developer ID 签名和 Apple 公证，
不能从测试 DMG 推导出正式发布已就绪。
