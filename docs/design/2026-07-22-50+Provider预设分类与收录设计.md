# 50+ Provider 预设分类与收录设计

- 日期：2026-07-22
- 范围：`apps/desktop/src/catalog.ts` 与添加供应商页面
- 协议边界：当前仅收录能由 `provider-openai-compatible` 发送 `POST <baseUrl>/chat/completions` 的服务

## 1. 收录规则

默认目录必须同时满足：

1. Base URL、Chat Completions 路径、鉴权方式和示例模型可由供应商或项目官方资料证明；
2. 固定 Base URL 不含账号、部署 ID、区域资源名等占位符；
3. 使用 Bearer Key，或本机回环地址无需 Key，能适配当前凭据与出站契约；
4. 区域、普通按量 API 与 Coding/订阅计划使用独立预设，避免凭据跨边界误发；
5. 商业中转/聚合路由不因竞品目录存在而进入默认目录。

托管多模型推理平台只有在官方直接提供推理 API、用户直接与平台建立凭据关系时，才标记为 `managed_inference`；把请求继续路由给第三方 Provider 的商业聚合服务标记为 `aggregator`，只保留在候选数组。

## 2. 数据契约

`ProviderPreset` 在原有 `label/baseUrl/models/needsKey/note` 之外增加：

- `protocol`：固定为 `openai_chat_completions`；
- `region`：中国、全球、美国、新加坡或本机；
- `subscription`：按量 API、Coding Plan、托管推理或自托管等；
- `serviceClass`：`first_party | managed_inference | self_hosted | aggregator`；
- `officialDocs`、`modelDocs`、`verifiedAt`：接入与模型证据及核验日期。

添加供应商页面使用“协议 · 区域 · 订阅”组合标签生成 `optgroup`，选择后展示官方接入文档。默认目录与聚合候选为两个独立导出，防止 UI 调用方误把候选混入。

## 3. 明确排除

| 候选 | 原因 | 处理 |
| --- | --- | --- |
| Anthropic 原生 API | 使用 `/v1/messages`，当前出站插件固定发送 Chat Completions | 不收录；需要独立 Provider 协议实现 |
| Azure OpenAI / Azure AI Foundry 部署 | Base URL 含用户资源名或部署 ID，无法提供无占位符的固定预设 | 继续使用自定义供应商 |
| Perplexity Agent API | 当前官方 OpenAI 兼容主路径为 Responses API，不满足本目录 Chat Completions 契约 | 不收录 |
| OpenRouter | 商业聚合路由 | 放入 `AGGREGATOR_CANDIDATES`，未经确认不进入默认目录 |
| Hugging Face Inference Providers Router | 会在多个第三方推理商之间服务端选路 | 不收录默认目录 |
| 需要动态部署 URL 的云端专属 Endpoint | 无法给出用户可直接使用的固定 Base URL | 使用自定义供应商 |

## 4. 不变量

- 模型清单仍是可编辑建议；运行时 `/models` 发现优先，目录不承诺模型对任意账号始终有权限。
- 收录不等于真实付费 E2E 已通过；无 Key 自动验收只证明路径、分类和静态证据正确。
- 本地服务只使用官方默认回环地址；改过端口或启用本地鉴权时使用自定义供应商。
- 目录变更不修改 Router、Canonical IR、Provider WASM 或用户已有配置。

## 5. 验证

目录测试必须证明：默认项不少于 50、ID/模型唯一、远端 URL 为 HTTPS、本地 URL 仅回环、每项有接入和模型证据、聚合候选与默认目录隔离、三级分组渲染正确。

逐项证据与 fresh-run 结果见 `docs/verification/2026-07-22-第二批协作任务-T10供应商预设验收.md`。
