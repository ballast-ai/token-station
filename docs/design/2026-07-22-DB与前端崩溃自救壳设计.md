# DB 与前端崩溃自救壳设计

> 日期：2026-07-22
> 对应任务：第二批协作任务 #7
> 状态：实现与自动化门禁通过；真实 App 验收待 Mac 解锁

## 1. 背景

旧实现能拒绝过新 metrics schema，前端也有最小 ErrorBoundary，但两者都是“报错后停住”：应用启动前没有独立的兼容性分流，渲染异常只显示原始 stack，没有持久诊断、脱敏预算、确认导出和有限自救动作。

自救能力必须独立于业务 metrics DB。若数据库无法打开或来自未来版本，任何依赖 `SqliteStore`、业务 `AppState` 或 Agent 写命令的方案都不是真正的自救壳。

## 2. 目标

1. 应用挂载业务 UI 前，只读检查 `PRAGMA user_version`；不创建、不迁移、不修改源库。
2. schema 过新或数据库不可读时，仅注册基于应用路径和文件系统的自救状态，不注册正常业务/Agent 状态。
3. 自救壳提供检查更新、只读导出、打开备份位置、复制脱敏诊断和重新检测。
4. React render error、`window.error`、`unhandledrejection` 进入同一自救壳并持久化本地结构化日志。
5. 日志采用字段白名单、单字段长度预算、文件总量预算、写入脱敏和读取/导出二次脱敏。
6. 不自动上传；原始本地配置/指标数据只有用户勾选确认后才导出。

## 3. 启动与隔离模型

```text
Tauri setup
  └─ 注册 DesktopPaths（无 DB 依赖）
      └─ read-only inspect_schema(metrics.sqlite)
          ├─ missing/current/older → 注册 AppState + AgentCommandState
          └─ newer/unreadable     → 不注册业务状态，仅保留 recovery IPC

React bootstrap
  └─ get_recovery_state
      ├─ normal → mount App
      └─ safe   → mount RecoveryShell

RecoveryBoundary / global events
  └─ record_frontend_diagnostic → local JSONL → RecoveryShell
```

`SchemaCompatibility` 是 typed 结果：`Missing`、`Current`、`Older`、`Newer`。`Older` 仍允许正常启动，由既有写侧迁移链处理；`Newer` 只读进入 safe mode。

## 4. 诊断与隐私契约

- Renderer 只提交 `kind/message/stack/component_stack`，IPC 类型拒绝未知字段。
- 合法 kind 为 `render_error`、`window_error`、`unhandled_rejection`；其他输入归一化为 `runtime_error`。
- Renderer 先做大小限制和常见 secret 脱敏；后端写入前再次执行权威脱敏与 UTF-8 安全截断。
- 后端读取和导出时执行第二次脱敏，防止旧日志或外部篡改日志绕过写入规则。
- 日志上限 256 KiB，返回最近 50 条；每个字段有独立预算。
- 日志文件在 Unix 上收紧为 `0600`；诊断仅本地保存，`auto_upload=false`。
- 导出包含原始配置/指标时必须传入显式 `confirmed=true`；UI 在用户勾选前禁用导出按钮。

## 5. 只读导出

1. 对可打开的 metrics DB 使用 SQLite online backup 生成一致快照，不解释或迁移 schema，未来版本也可复制。
2. 若 DB 已损坏到 SQLite 无法打开，则保留 raw fallback，并连同 WAL/SHM sidecar 导出，供离线修复。
3. 原始配置按敏感数据处理；前端诊断以二次脱敏 JSONL 写入。
4. manifest 明示 `local_only=true`、`auto_upload=false`、`contains_raw_local_data=true` 和实际文件清单。
5. 导出只写到应用数据目录的 `recovery-exports/`，不修改源文件。

## 7. 退出条件

- 成功：未来 schema 和可控 render crash 均能进入自救壳；导出可用且源文件字节不变；日志不含测试 secret；全量门禁与真实 App 证据通过。
- 阻塞：宿主机锁屏或 OS 拒绝启动独立 Debug App 时，保留自动化结果并把实机验收移入最终门，不伪造完成结论。
- 失败：safe mode 仍注册正常写状态、必须打开业务 DB 才能显示、自动上传诊断，或未经确认即可导出原始数据。
