# 关键词路由与概览空间优化

- 日期：2026-08-04
- 状态：已实现并完成本机验收
- 范围：`apps/desktop`
- 用户确认：关键词档位保持“强模型 → 中模型 → 弱模型”的纵向排列

## 1. 问题

### 1.1 关键词路由

- 三个已配置档位在空状态下重复展示“这一档还没有关键词。添加关键词后，匹配的请求会固定到这一档。”，同一信息连续出现三次，削弱扫描效率。
- 档位卡片相对整个面板偏窄、偏矮，强、中、弱三档的优先级主线不够突出。
- 关键词输入框随剩余列无限拉长，在宽屏上远超关键词的合理输入长度，按钮也被推到页面最右侧。
- 用户已明确否决三档横排方案；档位顺序必须与原版一致，继续纵向排列。

### 1.2 概览

- 概览的两层卡片均使用固定最小高度，在高分辨率窗口中只占据页面上半部，下半部留下大面积无意义空白。
- 当前内容本身已经足够，不需要为了填满页面新增指标、图表或操作；问题是视口空间分配，不是信息缺失。

## 2. 目标

1. 关键词空状态说明只在页面标题区出现一次，不在每档重复。
2. 强、中、弱模型继续严格纵排，档位卡片成为更清晰的视觉主线。
3. 关键词输入区限制为适合短词输入的宽度，并在窄窗口中自然收缩。
4. 概览在常见桌面高度中铺满导航栏下方的可用视口，两层卡片边缘对齐并接近页面底部。
5. 不改变任何路由、关键词、统计、导航或持久化行为。

## 3. 范围与非目标

### 3.1 范围

- 调整 `TierKeywords` 的空状态渲染和可访问结构。
- 调整关键词区的网格、卡片尺寸、输入区宽度和响应式规则。
- 调整概览根布局、摘要卡和下方两张主卡的视口高度分配。
- 增加覆盖公开文案、档位顺序和现有交互的前端测试。

### 3.2 非目标

- 不改变关键词匹配、跨档优先级、保存并应用或内核规则。
- 不将三档改为横排，不改变“强 → 中 → 弱”的 DOM 和视觉顺序。
- 不新增概览指标、图表、快捷入口或后端读取。
- 不改变 Tauri command、Rust 数据结构、前后端契约或发布渠道。
- 不重做全局视觉系统，不引入新字体、颜色或组件库。

## 4. 安全与数据红线

- 不读取、记录或展示 prompt、response、API Key、虚拟密钥或其他敏感正文。
- 不自动添加或删除关键词，不保存草稿，不应用路由，不启停代理。
- 不改变 `keywords.high/mid/low` 的数据结构和回调语义。
- 概览继续只读取现有本地状态和 24 小时聚合统计；布局变化不得触发新的网络或 IPC 请求。
- 构建失败时保留当前 `/Applications/token-station.app`，安装脚本只允许替换 bundle id 为 `com.tokenstation.desktop` 的目标 App。

## 5. 视觉与布局决策

### 5.1 设计基线

- 产品对象：本机 LLM Agent 路由控制台。
- 主要用户：需要快速判断实际路由并修改下一版配置的 AI 工程师。
- 颜色继续使用现有变量：`--canvas`、`--surface`、`--surface-2`、`--ink`、`--muted`、`--line`、`--signal`。
- 标题和正文继续使用 IBM Plex Sans；优先级 eyebrow、revision、端点和模型使用 IBM Plex Mono。
- 唯一强化元素是纵向优先级轨道：三张放大的档位卡自上而下表达匹配优先级，不额外增加装饰。

### 5.2 关键词路由

宽屏布局：

```text
关键词路由 · 你说了算                                      最高优先级
自动分档不称心？……说明只保留在这里一次

┌强模型 约 280–320w / 92h┐  ┌已有关键词，可换行，最大约 680w────┐
│ ● 命中这些词 → 最强档  │  │ 输入关键词，回车加入          添加 │
└────────────────────────┘  └───────────────────────────────────┘

┌中模型──────────────────┐  ┌───────────────────────────────────┐
│ ● 命中这些词 → 中档    │  │ 输入关键词，回车加入          添加 │
└────────────────────────┘  └───────────────────────────────────┘

┌弱模型──────────────────┐  ┌───────────────────────────────────┐
│ ○ 命中这些词 → 便宜快档│  │ 输入关键词，回车加入          添加 │
└────────────────────────┘  └───────────────────────────────────┘
```

- `.keyword-grid` 保持单列行序，每个 `.keyword-row` 自身使用两列网格；不再使用 `display: contents` 组织整个区域。
- 档位卡桌面宽度约 280–320px、最小高度约 92px；关键词工作区最大宽度约 680px，不再占满整个面板。
- 已配置但没有关键词时，关键词列表保持视觉空白，不重复说明。未配置时由禁用输入框的“该档未配置模型”直接说明原因。
- 已有关键词继续显示可删除 chip；输入框回车和“添加”按钮行为保持不变。

### 5.3 概览

```text
RUNTIME STATUS / 概览 / 说明

┌代理状态────────┐ ┌今日成本────────┐ ┌已接管 Agent────┐ ┌供应商─────────┐
│ 随第一层分配高度，四卡等高并保持内容不裁切                                      │
└────────────────┘ └────────────────┘ └────────────────┘ └───────────────┘

┌当前路由快照 + revision，填充剩余高度──────┐ ┌快捷键，填充剩余高度────────────┐
│ 三档路由行均匀分布                         │ │ 三个入口均匀分布               │
└────────────────────────────────────────────┘ └───────────────────────────────┘
```

- `.overview-page` 使用视口内的三行网格：标题、摘要层、主内容层；根节点最小高度为内容容器的 100%。
- 摘要层和主内容层使用 `minmax()` 分配可用高度，避免固定高度导致下半屏空白。
- 下方两张卡填满主内容层；卡内列表通过弹性分配拉开，不新增信息。
- 当内容高度小于安全最小值时页面仍由既有主容器滚动，不压缩到文字重叠。

### 5.4 自检

- 没有采用通用三列卡片模板，因为用户明确要求三档纵排，且优先级本身就是顺序信息。
- 没有通过新增图表填空；概览只重新分配现有真实内容的空间。
- 没有新增渐变、阴影或强调色；视觉变化集中在尺寸、比例和留白。

## 6. 用户可见状态与失败处理

- 关键词为空且档位已配置：不显示重复空文案，输入框可用。
- 档位未配置：输入框和添加按钮继续禁用，输入框显示“该档未配置模型”。
- 输入只有空格：添加按钮继续禁用，回车不提交。
- 添加成功：输入框继续清空；添加失败由现有上层错误链处理，本轮不改变反馈。
- 统计加载中、不可用或没有请求：概览继续使用现有占位和失败文案；布局不能隐藏或覆盖这些状态。
- 窗口高度不足：允许概览主容器纵向滚动，不裁切底部操作。

## 7. 响应式、键盘与可访问性

- 980px 以下概览摘要继续折为两列；主内容在项目最小桌面宽度内保持两列，文字不得横向溢出。
- 760px 以下关键词行折为单列，档位卡与输入区都占满可用宽度；强、中、弱顺序不变。
- 每档关键词容器提供与档位关联的可访问名称；空容器不通过可见重复文案占位。
- 输入框、添加按钮和删除按钮保持原有 Tab 顺序；Enter 添加、按钮点击和删除的键盘行为不变。
- 可见焦点继续使用现有 `:focus` 样式；颜色不是区分三档的唯一信息，标题和顺序始终可见。
- 本轮不新增动画；`prefers-reduced-motion` 行为不变。
