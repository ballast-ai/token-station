文档V1P1P2

Token Station API 参考。统一身份验证：Authorization: Bearer gw-YOUR_KEY。参见模型目录与决策记录。

快速接入 V1

把任意兼容 OpenAI 的 SDK 或 HTTP 客户端指向网关地址，改一下 model 字段即可切换提供商——网关自动完成格式转换与路由。

Base URL：https://api.tokenstation.example/v1　密钥前缀：gw-（在 API 密钥 页创建）

curl -X POST https://api.tokenstation.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer gw-YOUR_KEY" \
  -d '{
    "model": "glm-5.2",
    "messages": [
      {"role": "system", "content": "You are helpful."},
      {"role": "user", "content": "你好!"}
    ],
    "stream": true
  }'

把 model 换成 claude-sonnet、claude-haiku、gpt-5-mini、deepseek-v4，或者交给路由：填 auto（见路由控制）或 @acme/code-review（见 Preset 引用）。每个响应都带 X-Routed-Model / X-Routed-Reason / X-Cost 三个响应头，可在决策记录按 request_id 回查。

SDK P1

官方 SDK 是对 OpenAI SDK 的薄封装：预置 base_url、错误码类型化、内建路由响应头解析〔V2-P1-9〕。

Python

pip install token-station
from token_station import TokenStation

client = TokenStation(api_key="gw-YOUR_KEY")

resp = client.chat.completions.create(
    model="glm-5.2",
    messages=[{"role": "user", "content": "你好!"}],
)
print(resp.choices[0].message.content)
print(resp.routed_model, resp.routed_reason, resp.cost)  # 路由三件套已解析

JavaScript / TypeScript

npm install @token-station/sdk
import TokenStation from "@token-station/sdk";

const client = new TokenStation({ apiKey: "gw-YOUR_KEY" });

const resp = await client.chat.completions.create({
  model: "claude-haiku",
  messages: [{ role: "user", content: "你好!" }],
});
console.log(resp.choices[0].message.content);

直接用 OpenAI SDK

from openai import OpenAI

client = OpenAI(
    base_url="https://api.tokenstation.example/v1",
    api_key="gw-YOUR_KEY",
)

错误码 P1 P4

所有错误响应的 error 对象内都有稳定的 code（跨版本不变，供程序分支）以及 request_id / trace_id（供决策记录与日志关联）〔V2-P1-2〕。message 仅供人读，不要对其做字符串匹配。

HTTP/1.1 402 Payment Required
{
  "error": {
    "code": "insufficient_balance",
    "message": "余额不足,请充值后重试。",
    "request_id": "req_01j9x7v2m3",
    "trace_id": "tr_8f24bd01"
  }
}
codeHTTP语义建议处理
invalid_request400请求体不合法（缺字段/参数越界）修正请求，不重试
invalid_api_key401key 不存在、已过期或已吊销检查 密钥状态与轮换宽限期
insufficient_balance402余额不足充值后重试
model_not_allowed403被治理策略（白/黑名单/数据策略）拒绝联系 org admin 或换模型
budget_exceeded403任一层级预算超 hard 限额（逐层 AND）等待周期重置或调预算
rate_limited429RPM/TPM 超限，响应带 limit/remaining/reset 头按 reset 退避重试
upstream_unavailable502上游容量故障且 fallback 链耗尽指数退避重试

按 code 分支的示例：

try:
    resp = client.chat.completions.create(model="auto", messages=msgs)
except TokenStationError as e:
    if e.code == "rate_limited":
        time.sleep(e.reset_after)      # 响应头 reset
    elif e.code == "insufficient_balance":
        notify_billing(e.request_id)   # 带 request_id 便于回查
    else:
        raise

P4 错误文案（message）随 Accept-Language 提供五语言版本（EN/简/繁/日/韩）；code 恒为英文标识符，不受语言影响〔V2-P4-7〕。

模型后缀 P1

在模型名后追加后缀声明形态偏好：glm-5.2-thinking（要求思维链档）、claude-sonnet-high（要求高推理力度）。后缀的解析结果会写入决策记录〔V2-P1-10〕。

路由控制 P2

请求级供给控制：provider 偏好（order / only / ignore）、sort（价格/吞吐/延迟）、约束参数（max_price、require_parameters、quantizations、data_collection、zdr），以及 model: "auto" 逻辑模型（①用户规则 + ②启发式的默认组合）〔V2-P2-5/6/7/11〕。

hint header P2

Agent 框架可用 X-Hint-Step 请求头声明步骤类型（planning / execution / summarize …），第②层路由据此选档；无 hint 的流量归「未声明」并走启发式打分〔V2-P2-4〕。

Preset 引用 P4

把 model 写成 @preset/ 别名（如 "model": "@acme/code-review"）即引用整套「模型 + 参数 + provider 偏好 + 路由策略」，改配置不改代码，版本可回滚〔V2-P4-1〕。管理入口见预设 Preset。
