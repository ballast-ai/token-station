# v1.1.3 DMG 拖拽布局修复

## 问题、目标、范围与非目标

已发布的 v1.1.3 未签名测试 DMG 可以手动把 `token-station.app` 拖到
`Applications`，但打包脚本只把暂存目录直接压成只读 DMG，没有写入 Finder 的窗口和
图标布局。Finder 因此自动排列七个根目录项目，应用与 `Applications` 快捷方式不在同一
主视觉区域，用户无法一眼识别标准拖拽安装路径。

v1.1.2 Release DMG 是本次行为基线：它使用 660×400 的图标视图、128 px 图标，
`token-station.app` 位于 `(180, 170)`，`Applications` 位于 `(480, 170)`。本次目标是
恢复相同的双入口关系和 300 px 水平间距，同时为 v1.1.3 必须保留的安装、安全与构建来源
文件提供整齐的次级区域。

范围包括 macOS DMG 打包脚本、挂载审计、公开行为测试、v1.1.3 发布说明和 GitHub
Release 中同名 DMG 及校验文件的替换。非目标包括修改 App 二进制、版本号、标签、签名或
公证状态；本次仍发布明确标记为未签名、未公证的测试 DMG。

## 安全与数据红线

1. DMG 仍只能从显式 App bundle 和仓库内受控打包文件构建，不能复制用户目录、配置、
   密钥、日志、数据库、缓存、下载目录或任意未跟踪文件。
2. 根目录继续包含 `token-station.app`、精确指向 `/Applications` 的快捷方式、
   `安装前必读.md`、可双击安装脚本、`AGENTS.md`、未签名警告和构建来源。
3. 安装脚本的事务边界、bundle id 校验、精确目标路径和 quarantine 限制不变；不得关闭
   系统 Gatekeeper，也不得扩大到其他 App 或系统目录。
4. 不改写 v1.1.3 标签和 App 源码；构建来源必须继续记录 App 标签提交与打包源码提交。
5. 新 DMG 完成挂载审计、隐私扫描和真实 Finder 验收前，不覆盖 GitHub Release 资产。
   替换后必须重新下载并按 SHA-256 和挂载内容回读。

## 用户可见交互、状态变化与失败处理

DMG 打开后使用 920×600 的 Finder 图标视图，隐藏工具栏、侧边栏、路径栏和状态栏，
保持 v1.1.2 的 128 px 图标尺寸。主安装区把 `token-station.app` 与 `Applications`
保持 300 px 水平间距并放在同一行；五个必需的说明与辅助文件整齐放在下方一行。
用户可直接把 App 拖到 `Applications`，也可阅读说明后双击安装脚本。

打包流程改为“解码仓库内已验收的 `.DS_Store` 模板 → 创建可写镜像 → 挂载并清理 macOS
临时索引 → 确认布局元数据存在 → 卸载 → 压缩为最终只读 DMG”。不在打包时现场操作
Finder，因为开发机的“显示隐藏文件”偏好会把已经删除的 `.fseventsd` 临时目录写进布局
元数据，导致产物依赖个人设置。布局模板必须固定 SHA-256，并在最终只读 DMG 上由 Finder
回读。模板解码失败、`.DS_Store` 缺失、图标坐标不符、临时目录残留、卸载失败或压缩失败
时都必须停止发布，并用中文说明具体失败环节和下一步；不得产出看似成功的 DMG。

## 响应式、键盘操作与可访问性

Finder DMG 窗口不是网页响应式界面。920×600 的固定窗口需要在常见 Mac 屏幕上完整
显示；用户仍可缩放、移动窗口或使用列表视图。所有项目必须保留真实文件名和系统图标，
支持方向键选择、Return 打开、Command+C/Command+V 复制，以及 VoiceOver 按名称读取。
布局不能依赖只在背景图中出现的箭头或文字来传达唯一操作，因此不新增背景图；应用与
`Applications` 的同排位置和真实名称本身就是可访问的安装提示。

## 公开测试边界、验收标准与真实 App 检查项

公开测试必须先证明旧打包脚本缺少 Finder 布局步骤，并覆盖以下契约：

1. 打包脚本校验并解码受控 `.DS_Store` 模板，创建可写镜像、清理 `.fseventsd` 后再压缩。
2. 布局定义使用图标视图、128 px 图标、关闭自动排列，并为七个根目录项目设置固定坐标；
   模板二进制 SHA-256 固定为 `bd345bfc5b70ac1d47fa48c620d04d085b22cbe453dc0ed3542cad0403cc3f38`。
3. 挂载审计要求 `.DS_Store` 存在，并通过 Finder 回读窗口尺寸、视图、图标大小和两个
   主入口坐标；不能只检查文件存在。
4. 原有文件白名单、签名、公证、架构、版本、安装脚本和危险命令门禁继续通过。

真实验收需要挂载最终 DMG，打开 Finder，确认应用在上方左侧、`Applications` 在上方
右侧、说明文件在下方且无重叠；实际拖动可由复制语义验证，不覆盖本机已安装 App。因为本次
不修改 App bundle 或可执行行为，不运行 `scripts/install-local-desktop.sh`，但仍复用已经
通过 bundle id、架构和代码签名审计的 v1.1.3 App。

## 实现落点、已知遗留项与发布要求

- `scripts/package-macos-dmg.sh`：解码受控布局模板、创建可写 HFS+ 镜像、清理系统临时项
  并压缩。
- `packaging/macos/dmg-layout.dsstore.base64`：保存不含机器临时项的已验收 Finder 布局。
- `packaging/macos/configure-dmg-layout.applescript`：维护布局坐标并负责最终挂载回读，源码
  注释统一为英文。
- `scripts/audit-macos-dmg.sh`：挂载后回读 Finder 布局并保留原有安全审计。
- `scripts/check-macos-dmg-packaging.mjs`、`tests/unsigned-test-dmg.mjs`：增加公开布局契约。
- `docs/release/v1.1.3.md`：记录替换后的资产哈希和验收结果。

发布仍使用标签 `v1.1.3` 和现有同名资产。代码必须以中文提交说明进入 `develop`；合并且
CI 通过后，才允许用新 DMG 和匹配的 `.sha256` 同时替换 GitHub Release 资产。替换后从
GitHub 重新下载，验证字节哈希、Finder 布局、根目录白名单和无本地数据。实施与验收状态
将在构建完成后回写本文件。
