# 额度优先路由 · 生产化实施计划（面向开源 Release）

> 状态：待评审 / P0① 即将开工
> 前置：额度路由 MVP（引擎 QuotaFirst + 账本 + 在途租约 + 账户持久化 + 各 Agent 独立模式）已完成并全绿，位于 `quota-routing-wip` 分支（未提交）。

## 1. 背景与目标

额度优先路由即将随产品收尾开源，会有真实用户接入自己的付费 / 免费额度。面向真实用户，「完美」的标准不是功能最多，而是四条底线：

1. **可信**：绝不把请求持续发给一个实际已耗尽的账户（否则 429 风暴、体验崩）。
2. **不超发**：高并发下不因「同时都看到某账户有余量」而一起涌入、击穿其速率限制。
3. **安全**：真实用户的真实密钥必须走钥匙串、默认不外发。
4. **诚实**：任何「剩余额度」的展示都要如实标注是「供应商权威值」还是「本地估算」，并说明估算的盲区。

排序算法本身（`quota_rank`）已定稿且经用户确认——**不改**：`remaining` 只当耗尽闸门；主排序按最快 reset；同 reset 时段内用速率余量把负载**分散**到最空闲账户（外加会话粘性 / 速率压力）。分散正是对「竞态」的直接解法，因此**不做 fill-first**。

本计划解决的是排序之外、让它「名副其实且不坑用户」的部分：**额度信号的真实性 + 并发正确性 + 安全 + 诚实呈现**。

## 2. 现状盘点（可复用基础设施 / 缺口）

已在代码中、可直接复用：

- `ErrorEnvelope.retry_after_ms`（`crates/protocol/src/error.rs`）——已由 `provider-openai-compatible` 适配器从真实 `retry-after` 响应头解析（`plugins/.../provider-openai-compatible/src/lib.rs:618`）。**通用 429 信号已在流。**
- `Gateway::observe(upstream, model, outcome)`（`apps/cli/src/gateway.rs:1709`）——每次尝试的成败已喂给 health / ejection，429 已能触发健康层摘除。
- `Gateway::settle_quota(...)`（`gateway.rs:2179`）——每次额度请求收尾时释放在途租约、记录用量、记住会话账户。**目前只处理成功路径，失败路径未反馈给 quota——这是 P0① 的缺口。**
- `QuotaTracker`（`apps/cli/src/quota_tracker.rs`）公开 API：`quota_state / grant / release / record(usage) / last_account / remember`。**没有「标记耗尽 / 冷却」入口**——exhausted 目前只能由「记录用量 vs plan 窗口」推算，plan 未配则永远推不出耗尽。
- Retry-After 已有单请求上限（`gateway.rs:70`），防止一个 upstream 用超长 Retry-After 长时间占位。

关键缺口：**upstream 说「你超了」的真实信号，没有反馈到额度层**。这是数据可信度的第一道、也是最便宜的一道闸。

## 3. 数据可信度分层架构

额度数据按可信度分三层，**以真实反馈为准**：

| 层 | 来源 | 准确性 | 说明 |
|---|---|---|---|
| **L1 反馈闭环（通用）** | upstream 的 429/402 + `Retry-After` | 高（事后真相） | 任何供应商通用；upstream 一旦拒绝就立即冷却该账户。复用现有解析，成本最低。**P0①。** |
| **L2 权威摄取（每家适配）** | 供应商额度/限流响应头或查询端点 | 最高（无盲区） | Anthropic：每响应带 `anthropic-ratelimit-*`（含 unified-5h 窗）；OpenAI：`x-ratelimit-remaining/reset-*`；OpenRouter：错误响应带 `X-RateLimit-*` + `GET /api/v1/key`。**它统计的是全部用量，无本地盲区。P1。** |
| **L3 本地账本估算（兜底）** | 用户配的 plan 窗口 + 经本网关观测的流量 | 中，有盲区 | ⚠️只看得到经过 token-station 的流量；用户在别处用同一 key 会**高估剩余**。仅用于无任何权威信号的供应商，且 UI 必须标注「估算·仅本网关」。P1。 |

**根本限制（须在文档与 UI 诚实告知）**：L3 本地账本无法感知网关外的消耗（其它机器、直连、别的工具）。缓解手段就是尽量用 L2（权威头无盲区）+ L1（真实反馈兜底纠偏）。

## 5. P0① 详细设计（开工项）

**目标**：任一 upstream 返回额度类拒绝（429/402，或供应商标记的额度耗尽），立即把该账户在额度层标记冷却，直到 `Retry-After`（无则默认冷却时长）过去；冷却期内 `quota_rank` 将其视为耗尽、踢出轮换；到期自动恢复。全程纯宿主态，`router-core` 不变（仍读 `QuotaState`）。

### 5.1 引擎侧（不变）
`quota_rank` 已在 `state.exhausted` 时返回 `None`（踢出）。P0① 只需让 `QuotaState.exhausted` 在冷却期为真——**router-core 零改动**，保持纯函数不变量。

### 5.2 账本侧（`apps/cli/src/quota_tracker.rs`）
- 新增每 upstream 的 `cooling_until_ms: HashMap<String, u64>`（或并入现有账户结构）。
- 新增：
  ```rust
  pub fn note_rate_limited(&mut self, upstream: &str, now_ms: u64, cooldown_ms: u64)
  ```
  写入 `cooling_until_ms[upstream] = now_ms + cooldown_ms.min(MAX_QUOTA_COOLDOWN_MS)`。
- `quota_state(upstream, now_ms)`：折入冷却——若 `now_ms < cooling_until` 则返回 `exhausted = true`（其余字段照常计算）；到期后自然失效。
- 常量：`DEFAULT_QUOTA_COOLDOWN_MS`（无 Retry-After 时，如 60_000）、`MAX_QUOTA_COOLDOWN_MS`（冷却上限，复用/对齐现有 Retry-After 上限，防长时间占位）。

### 5.3 网关接线（`apps/cli/src/gateway.rs`）
- 在**失败尝试已知 upstream + error 的位置**（`dispatch` 循环内失败分支，或 `observe` 旁）识别额度类错误：复用 `classify_provider_error` / `ErrorCode`（`RateLimited` 等）判定。
- 命中则：`self.quota.lock().note_rate_limited(upstream, now_ms, error.retry_after_ms.unwrap_or(DEFAULT_QUOTA_COOLDOWN_MS))`。
- 只在 QuotaFirst 模式支付该成本（tiered 路径不受影响）；`now_ms` 复用 `quota_preamble` 的单次时钟读，避免额外读钟。
- 与 health/ejection 并存互补：health 是跨模式的通用摘除，quota 冷却是额度语义的「这份额度用完了、等它 reset」。

### 5.4 测试
- **单元（quota_tracker）**：`note_rate_limited` 后 `quota_state` 在到期前 `exhausted=true`、到期后恢复；冷却时长被 `MAX` 截断。
- **单元（router-core 已有）**：`exhausted` 账户被 `quota_rank` 踢出（已覆盖，无需新增）。
- **集成（gateway proxy 测试）**：mock 一个 upstream 返回 429 + `Retry-After` → 该账户被冷却 → 下一请求路由到别家 → 冷却到期后重新参与。断言无超发、无对死账户连发。

### 5.5 验收标准
- upstream 返回 429/402 后，额度路由在 `Retry-After`（或默认冷却）内**不再选中**该账户，到期自动恢复。
- tiered 模式行为与性能不变。
- router-core 无改动、保持纯函数。
- 全工作区测试绿（router-core / cli lib+proxy / desktop / 前端 / plugin-runtime）。
