# PR #88 合并阻断修复设计

日期：2026-08-14
状态：实现完成，本地全量验证与真实 App 验收通过

## 1. 问题、目标、范围与非目标

PR #88 当前不能合并到 `develop`：三个文件存在内容冲突；OpenAI 兼容流仍输出
`usage -> finish_reason -> [DONE]`；Cursor 启动失败时可能在恢复失败后删除活动记录；
Cursor 状态只检查 `cloudflared` 进程而不验证实际数据库配置；固定的
`cloudflared 2026.8.0` 已被上游标记为不应继续使用。

本修复目标：

- 合并最新 `develop`，同时保留 #89 与 #88 的公开行为。
- 将最终 OpenAI SSE 顺序固定为 `finish_reason -> usage -> [DONE]`。
- Cursor 配置或启动失败时失败闭合：恢复失败不得删除活动记录或丢失恢复入口。
- Cursor 状态同时核验隧道进程与数据库接管字段；配置漂移必须显示“需修复”。
- 取得 Quick Tunnel URL 后确认子进程仍存活，再修改 Cursor 配置。
- 升级到上游未标记为已知坏版本的固定 `cloudflared`，继续校验大小与 SHA-256。

范围包括 #88 已修改的桌面端、OpenAI Provider/Agent 插件、对应公开测试和设计验收记录。
非目标：不扩展公网路径、不改变全局虚拟 Key、不发布 DMG、不修改其他 Agent 的配置所有权。

## 2. 安全与数据红线

- 公网桥接仍只接受每次连接新生成的 Cursor 临时令牌和既有三条路径白名单。
- Token Station 全局虚拟 Key 不写入磁盘、Cursor 数据库或日志。
- `cloudflared` 仍只连接随机 loopback 桥接端口，下载包和二进制均校验固定摘要。
- 任一配置写入、启动或回滚步骤失败，必须保留可重试恢复状态；不得报告“未接入”掩盖残留配置。
- Cursor Base URL、BYOK 开关或模型选择发生漂移时，不得继续报告“已接入”。
- 不强制退出 Cursor，不删除用户原始配置备份。

## 3. 用户可见行为、状态与失败处理

- 正常接入成功后仍显示“已接入”，并自动启动 Cursor。
- 隧道仍运行但 Cursor 数据库已漂移时显示“需修复”，同时提供重新接入和恢复官方配置。
- Cursor 启动失败且原配置恢复成功时，清理本次活动记录并返回明确错误。
- Cursor 启动失败且恢复失败时，保留活动记录和备份，停止临时隧道并返回包含恢复失败原因的错误。
- Quick Tunnel 在输出 URL 后立即退出时，接入失败且不得写入 Cursor 数据库。
- WorkBuddy 收到的终止序列必须是 `finish_reason`、最终 `usage`、`[DONE]`。

## 4. 响应式、键盘与可访问性

本修复不新增页面、控件或焦点顺序。现有“需修复”文字、按钮键盘行为、禁用态和 Toast
live region 保持不变；状态不能仅通过颜色表达。
