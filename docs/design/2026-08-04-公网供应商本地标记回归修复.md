## 1. 问题、目标、范围和非目标

### 问题

添加 DeepSeek 等公网供应商时，界面仍允许勾选“本地模型”。提交后后端安全校验拒绝写入：

```text
upstream `deepseek` is marked local but its base_url is not a loopback endpoint
```

### 目标

- 公网 Base URL 的“本地模型”复选框保持未选中且不可操作。
- `localhost`、`127.0.0.1` 等后端认定的回环端点仍可标记为本地模型。
- Base URL 从回环地址切换为公网地址时立即清除前端 `local` 状态。
- 提交层再次收敛参数，公网端点不能构造 `local: true`。

### 范围

- 扩展 Provider 端点预览契约，返回后端统一计算的 `loopback`。
- 调整添加供应商页面的状态、复选框和辅助说明。
- 增加前端公开行为测试与 Rust 端点判定测试。

### 非目标

- 不放宽后端 `validate_local_identity` 安全校验。
- 不把局域网地址、自托管公网域名或“密钥保存在本机”解释为本地模型。
- 不迁移或改写现有有效配置，不修改路由算法。

## 2. 安全与数据红线

- loopback 资格必须由 Rust `ProviderEndpoint::is_loopback()` 计算，前端不复制 URL 安全规则。
- 后端保存校验继续作为不可绕过的最终边界。
- 不读取、输出或迁移 API Key；端点预览只处理 Base URL。
- 修复过程中不得覆盖工作区无关改动，不得删除当前已安装 App；只有新 App 构建审计成功后才替换。

## 3. 用户交互、状态变化和失败处理

- 选择 DeepSeek、GLM、OpenAI 等公网预设后，端点预览返回 `loopback: false`，复选框自动取消并禁用，显示“云端地址不能标记为本地模型”。
- 选择本地 Ollama 后，预览返回 `loopback: true`，复选框可用并保留预设默认值。
- 端点解析中、Base URL 为空或解析失败时，复选框禁用；保存按钮继续沿用端点预览门禁。
- URL 资格由 true 变为 false 时清除已勾选状态，提交参数使用 `local && endpointPreview.loopback`。
- 旧前端或绕过 UI 的调用仍收到后端明确拒绝，不静默降级安全语义。

## 4. 响应式、键盘与可访问性

- 不改变现有表单布局和响应式断点。
- 使用原生 `disabled` 阻止鼠标和键盘切换不合格的复选框。
- 资格说明通过 `aria-describedby` 关联复选框，并使用 `aria-live="polite"` 通知状态变化。
- 禁用原因必须有中英文文本，不只依赖颜色。
