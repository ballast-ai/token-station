# 后台常驻与 Agent 接入完整性修复设计

日期：2026-08-12
状态：已实现、已安装并完成真实 App 验收

## 1. 问题与事实基线

本设计处理四个已经分别复现的缺陷。它们在用户侧同时表现为“Agent 接入不稳定”，
但根因并不相同，不能用一个兜底重试或一个前端提示掩盖。

1. **关闭主窗口后代理消失。** 桌面端代理运行时与 Tauri 主进程同生共死；当前关闭
   唯一窗口会退出进程，因此 `8787` 监听器和 Agent 连接一起消失。真实安装 App 已复现
   “关窗前可达、关窗后进程与端口同时消失”。
2. **Cursor 显示接入成功但没有走代理。** 当前连接器写入了 `openAIBaseUrl` 和密钥，
   却没有把 Cursor `applicationUser` 中的 `useOpenAIKey` 打开，也没有在成功前验证它。
   当前本机数据库的实际值为 `false`，因此现有成功提示是假阳性。
3. **OpenCode 无上下文与费用信息。** 当前本地 `/models` 只返回
   `id/object/owned_by`，OpenCode 连接器也只写入附件和模态信息。OpenCode 1.18.2 会把
   缺失的 `limit.context`、`limit.output` 和 `cost` 解析为零；其中 context 为零时自动压缩
   直接失效。供应商 `/models` 中已有的 context、output、modality 与 cost 信息还会在
   Token Station 的模型目录解析阶段被主动丢弃。
4. **重启后出现 `invalid type: null, expected a map`。** 历史配置中的
   `agent_routes`、`profiles` 或 `agent_budgets` 若显式为 `null`，会在 Serde 结构解析阶段
   失败，早于加载迁移；桌面端随后进入只读保护，所以启动代理与全局路由一起被锁。
   字段完全缺失已兼容，但“字段存在且为 null”尚未兼容。

以上四项是事实。尚不能从当前已经恢复合法的正式配置反推出历史上具体是哪一个可选
映射曾被写成 `null`；实现必须只兼容已经确认可选的三个映射，不能把必需映射的
`null` 也静默吞掉。

## 2. 目标、范围与非目标

### 2.1 目标

- 红色关闭按钮只隐藏主窗口，Token Station 进程及当前代理状态保持不变。
- macOS 菜单栏提供常驻入口、真实代理状态、启动/停止操作和显式退出操作；Dock 再次
  点击也能恢复同一个主窗口。
- Cursor 只有在 Base URL、密钥和 `useOpenAIKey=true` 三项均已事务性写入并回读通过后，
  才报告连接成功。
- 建立一个规范化模型元数据边界，保留供应商提供的 context、最大输出、模态与费用信息；
  本地 `/models` 和 OpenCode 配置从该边界投影，不再各自猜测。
- OpenCode 至少获得非零、保守且可解释的 context 上限，使自动压缩恢复工作；只有在
  当前 Agent 路由的所有可达目标价格一致或路由确定为单一目标时，才写入静态 cost，
  避免把估算值伪装成实际花费。
- 历史三个可选映射的显式 `null` 兼容为空映射；必需映射继续严格拒绝。

### 2.2 范围

- Tauri 窗口生命周期、菜单栏原生菜单及状态同步。
- Cursor SQLite 连接器的写入、验证、备份与恢复契约。
- 模型目录缓存、供应商 `/models` 解析、模型能力配置、本地 `/models` 输出及 OpenCode
  连接器投影。
- ClientConfig 的字段级旧数据兼容。
- 对应单元、集成、桌面公开行为与真实安装 App 验收。

### 2.3 非目标

- 本轮不把代理拆为 launchd、sidecar 或跨进程守护服务；显式退出、用户登出、系统重启
  后不保证代理继续运行。
- 本轮不新增开机自启、崩溃拉起或自动更新重启协调。
- 不承诺 Cursor 的全部自有模型、Auto/Composer 都支持 BYOK。连接成功只表示 Cursor 的
  OpenAI BYOK 通道已正确指向 Token Station；用户仍需选择兼容该通道的模型。
- 不伪造跨供应商动态路由的精确 OpenCode `Spent`。Token Station 自身按实际上游响应
  统计的费用仍是权威值。
- 不修改本轮并行进行的 React/CSS 前端优化。

## 3. 安全与数据红线

1. 不在日志、菜单、错误提示或测试快照中暴露代理令牌、供应商密钥或 Cursor 密钥。
2. Cursor 写入继续使用现有完整记录备份与单个 SQLite 事务；任一写入或回读失败必须
   回滚，不能留下 URL 已改、开关未开或密钥半写入的状态。恢复必须恢复原始完整 JSON，
   包括原始 `useOpenAIKey` 值。
3. 只对 `agent_routes`、`profiles`、`agent_budgets` 三个历史可选映射执行
   `null -> empty map`。`upstreams`、`router.pools` 等必需结构的 `null` 必须继续失败关闭。
4. 启动加载旧配置只在内存规范化，不因读取而改写用户文件；只有下一次明确保存才以
   当前格式写回。
5. 菜单栏“启动/停止代理”必须复用唯一后端生命周期协调器，不能绕过保存前校验、revision
   防并发和 drain 逻辑，也不能维护第二份推测状态。
6. 供应商模型元数据只接受有限、经过类型与范围校验的字段。未知字段不直接进入可执行
   配置；非法、负数、非有限费用及零/负 token 上限一律忽略并保留诊断，不覆盖已有合法值。
7. 不以某一个供应商或某一个模型（例如反馈样例中的 Wecoding `glm-5.2`）冒充动态
   `tokenstation/auto` 的全局能力与价格。

## 4. 统一模型元数据契约

### 4.1 规范化字段

模型目录为每个 `upstream/model` 保留下列可选元数据：

- `context_window`：可接受的总上下文 token 数，必须大于零；
- `max_output_tokens`：单次最大输出 token 数，必须大于零且不大于 context；
- `input_modalities` / `output_modalities`：当前至少规范化 text/image；
- `image_input`：由 capabilities、modalities 或现有显式字段共同解析，但“未知”不得提升为
  “已验证支持”；
- `cost`：按百万 token 的 input、output、cache read、cache write、reasoning/think 价格，
  input/output 必须同时合法才形成可结算价格；供应商省略某一 cache 类表示该类未单独
  计费并按 0 处理，显式存在但类型错误、负数、非有限或越界则整组价格保持 unknown；
  reasoning/think 可选且单独保留；
- 元数据来源与更新时间，供陈旧缓存和现场诊断使用。

解析兼容供应商常见的平铺字段以及反馈样例中的 `limit`、`modalities`、`capabilities`、
`cost` 结构。目录缓存版本升级，但必须读旧版本；旧缓存缺少新字段时保持 unknown，不能
捏造默认值。

### 4.2 写入模型配置

用户在供应商模型目录中更新已选模型时：

- 目录中合法的 context 与 max output 只填补对应 `ModelCapability` 的 unknown；由于旧配置
  尚无字段级来源标记，任何已有非零值一律视为用户拥有，刷新不得静默升高或降低它；
- 目录的 unknown 不得清空已有值；若未来需要持续跟随供应商变化，必须先新增来源标记和
  可见冲突确认，不能仅凭数值猜测所有权；
- 费用按 `upstream/model` 保持供应商作用域，避免相同模型 ID 在不同供应商价格不同而
  相互覆盖；目录价格只填补不存在的 scoped key，不能覆盖版本化定价编辑器中的现有值；
  旧的仅 model ID 价格只用于结算兼容，不得被 OpenCode 当作供应商精确价；
- 本轮不让一次“刷新目录”自动改写尚未被用户选中的模型。

### 4.3 本地 `/models` 投影

Agent 命名空间的 `/v1/models` 对每个实际可达模型返回兼容 OpenAI 的基础字段，并在已知时
补充：

- `context_window`；
- `max_output_tokens` 与 `limit.context/output`；
- `capabilities.image_input/input_modalities/output_modalities`；
- `modalities.input/output`；
- `cost`。

未知字段省略，不返回零来冒充已知上限或价格。费用使用当前上游作用域价格；不得把另一
同名模型的价格串过来。

### 4.4 OpenCode 的 `tokenstation/auto`

OpenCode 静态 provider 配置需要一个虚拟模型。其快照按连接时该 Agent 的有效路由计算：

- context 使用所有可达目标中**最小的已知合法上限**；如果任一可达目标未知，则使用
  当前配置可证明安全的最小值；完全无法证明时连接失败并说明需要补全模型上限，不能再
  静默写入零导致压缩关闭；
- max output 必须对每个可达目标已知；任一目标未知即拒绝接入，因为 OpenCode 会把省略
  解析为零/内部回退，Token Station 无法据此证明安全的压缩输入预算；
- 模态取可达目标的交集；
- cost 仅在路由确定为单一目标，或所有可达目标的完整 scoped 价格相同时写入；若已知
  reasoning/think 价格与 output 不同，也必须省略，因为 OpenCode 1.18.2 无法独立表达它。
  其他情况省略并在连接结果中说明实际费用查看 Token Station；
- 路由或模型能力之后发生变化时，连接视图标记需要刷新 OpenCode 配置。本轮以重新执行
  “连接”生成新快照，不在后台静默改写第三方配置。

## 5. 用户可见交互与状态

### 5.1 关闭、恢复与退出

- 点击红色关闭按钮：阻止销毁并隐藏主窗口，不修改代理状态。
- 点击 Dock 图标且没有可见窗口：显示、取消最小化并聚焦现有主窗口。
- 菜单栏图标采用透明、单色 template glyph，适配浅色/深色系统菜单栏，不依赖颜色表达
  状态。tooltip 提供“Token Station · 当前状态”。
- 菜单由上至下显示：
  1. 禁用的状态行（已停止、正在启动、运行中、正在停止或错误）；
  2. 禁用的监听地址行；
  3. “打开 Token Station”；
  4. “启动代理”或“停止代理”，过渡态及只读恢复模式中禁用；
  5. “退出 Token Station”。
- 监听地址必须来自可信的当前运行态或已加载配置。数据恢复安全模式不读取
  业务配置，普通配置损坏的只读保护也只持有展示模板；两者的菜单地址都必须
  显示“不可用”及对应原因，不得把模板 `127.0.0.1:8787` 冒充为用户的真实地址。
- `⌘Q`、应用菜单退出与菜单栏“退出”是真退出，允许进程和端口终止；关闭隐藏逻辑不得
  拦截它们。

### 5.2 Cursor 连接

- Cursor 正在运行时继续拒绝写入，提示用户彻底退出后重试。
- 成功条件升级为 URL、密钥、`useOpenAIKey=true` 三项全部回读通过。
- 成功文案继续明确“下次启动 Cursor 生效”，并补充必须选择 OpenAI BYOK 兼容模型；
  不能宣称 Cursor 所有模型都会被代理。
- 失败时显示具体阶段，但不显示密钥内容；事务回滚后仍保留可重试状态。

### 5.3 OpenCode 连接

- 连接成功结果说明保守 context 已写入，以及 cost 是精确快照还是因动态异价而不写入；
  本轮不新增独立的 Web 预览面板。
- 缺少安全 context 时不允许生成一个会禁用压缩的零值配置；提示用户先补全供应商模型
  上限或选择能力已知的确定路由。
- 动态价格无法精确表达时，连接仍可成功，但结果明确提示 OpenCode `Spent` 不作为权威值。

### 5.4 Agent 路由热更新与运行快照

- “保存并重启此 Agent”只能把路由热更新到当前已发布的 `RunningServer`；路由中的
  每个 Provider/模型目标必须存在于该运行实例的 serving snapshot。只在最新草稿存在的目标
  必须拒绝热更新，明确提示先完成全量应用；不得返回成功后再让请求失败。
- `Starting` / `Applying` 期间候选配置已固定，本轮不实现排队重放。此时保存并重启
  Agent 路由必须以 `apply_in_progress` 拒绝，不得仅保存新 revision 却向用户报告已生效。
- Running 态热更新使用三阶段事务边界：先在内存中构建并完整验证目标与
  `Router`（可失败、不改磁盘与 Gateway），再持久化配置（可失败、不改 Gateway），
  最后安装已验证的 opaque plan（无可恢复的 `Result` 失败路径）。不得先保存再构建
  Router，否则热更新失败会留下“磁盘新路由、运行时旧路由”的分裂。
- 热更新成功后记录的 `agent_router_overrides` 仅描述该运行实例真正接受的路由；
  全量替换新实例时重建，应用失败回退旧实例时保留，停止时随运行实例一同销毁。

## 6. 响应式、键盘与可访问性

- 本轮不新增 Web 前端布局，因此沿用现有响应式断点。
- 菜单栏菜单必须可用键盘和 VoiceOver 逐项读取；状态与地址项使用语义清楚的文字，不用
  单独颜色或图标表达。
- 主窗口恢复后保留原有焦点顺序；若窗口曾最小化，先取消最小化再聚焦。
- 菜单项在 Starting/Applying/Stopping/只读恢复模式下使用原生 disabled 状态，避免重复
  操作；状态文字同步说明原因。
- template 图标在浅色与深色菜单栏下均需肉眼验收，至少保留 18pt 视觉尺寸所需的透明
  留白和清晰轮廓。

## 7. 公开测试边界与验收标准

### 7.1 配置兼容

- 三个历史可选映射分别及同时为 `null` 时，CLI 与 Desktop 完整加载成功并规范化为空 map。
- 启动加载不改写源文件；显式保存后空 map 按现有规则省略。
- `upstreams: null` 与 `router.pools: null` 继续产生结构错误。
- 字段完全缺失的现有回归保持通过。

### 7.2 Cursor

- 原 `useOpenAIKey=false` 的隔离数据库连接后变为 true，URL/密钥正确，备份仍含原始 false。
- 任一回读不一致时不返回成功；事务失败不留下部分更新。
- restore 恢复原始完整 applicationUser 与密钥。

### 7.3 模型元数据与 OpenCode

- 用反馈中的 Wecoding `/models` 样例做公开解析测试，验证 context=257550、output=32768、
  image modality 与各费用字段不丢失。
- 旧目录缓存可读；刷新/选择模型后合法元数据进入配置，人工值不被 unknown 覆盖。
- Agent `/v1/models` 集成测试验证已知字段完整、未知字段省略、同名跨供应商价格不串用。
- 将连接器生成配置交给本机 OpenCode 1.18.2 解析，验证 `limit.context > 0`；确定单路由时
  cost 非零，动态异价路由时 cost 省略。
- streaming 与 non-streaming 响应中的 usage 继续穿透，Token Station 请求记录以实际模型
  计费；静态元数据测试不能代替 runtime usage 测试。

### 7.4 桌面生命周期与菜单栏

- 纯状态映射测试覆盖 stopped/starting/running/stopping/failed/read-only 的菜单文字、动作和
  enabled 状态。
- 窗口 CloseRequested 公开 seam 验证“prevent + hide”；Dock reopen 与菜单 Open 复用同一
  显示函数。
- 菜单 Start/Stop 复用现有生命周期，并在状态发布时更新菜单。
- 显式 Quit 不被 close-to-hide 拦截。
- 数据恢复安全模式与损坏配置只读保护的地址行均验证为不可用，且提示原因可区分。

### 7.5 Agent 路由热更新

- 当草稿新增的 Provider/模型尚未全量应用到运行实例时，单 Agent 热更新拒绝并保持
  已保存 revision、Gateway 和 `agent_router_overrides` 不变。
- 生命周期为 `Applying` 时，`restart_agent_route` 返回 `apply_in_progress`，不保存新
  revision，不修改旧实例或已固定的候选实例。
- 目标存在但 Router 结构本身不可路由时，opaque plan 的 prepare 阶段必须在保存前拒绝，
  已保存 revision、配置文件、Gateway 和 override 均不变。
- 只引用当前 serving snapshot 中 Provider/模型的路由可热更新成功，且运行态模型契约
  与 Gateway 实际路由保持同一快照。

### 7.6 真实安装 App 门禁

执行统一安装脚本后，在 `/Applications/token-station.app` 验证：

1. 启动代理并确认带鉴权的 `/agents/opencode/v1/models` 可达且返回丰富元数据；
2. 关闭窗口，确认窗口隐藏但同一 PID 和 `8787` 仍存在；
3. 从 Dock 和菜单栏分别恢复同一窗口，不重复启动代理；
4. 菜单栏停止/启动代理，端口、菜单状态与主界面一致；
5. 浅色/深色菜单栏图标清晰，VoiceOver 能读出菜单文字；
6. 对隔离数据库验证 Cursor 三字段写入；如操作正式 Cursor 配置，必须先确认 Cursor 已退出
   且保留现有备份；
7. 用 OpenCode 实际读取生成配置，context 非零且压缩边界可用；
8. `⌘Q` 和菜单栏退出后 PID 消失、端口释放。

## 8. 实现落点

- `apps/cli/src/config.rs`：字段级 `null_to_default`，严格限制到三个可选映射。
- `crates/protocol/src/capability.rs`：补充可选最大输出等规范化能力字段；保持旧配置兼容。
- `apps/cli/src/pricing.rs`：提供上游作用域优先、模型 ID 回退的只读价格解析边界。
- `apps/cli/src/gateway.rs`：丰富 `/models` 投影并保持未知字段省略。
- `apps/desktop/src-tauri/src/model_catalog.rs`：目录缓存版本迁移及供应商元数据解析/合并。
- `apps/desktop/src-tauri/src/agent_integration/commands.rs`：Cursor toggle 原子写入/验证；计算
  OpenCode Agent 的保守虚拟模型元数据。
- `apps/desktop/src-tauri/src/agent_integration/connectors/opencode.rs`：写入规范化 limit、modalities
  与满足真实性条件的 cost。
- 新建独立原生 shell/tray 模块：菜单构建、纯状态映射、窗口恢复及菜单事件；`lib.rs` 只做
  最小生命周期接线和统一状态发布，减少与并行前端工作的冲突。
- `apps/desktop/src-tauri/Cargo.toml` 与原生图标资产：启用 Tauri tray/png 特性并加入 template
  图标。

## 9. 已知遗留项与发布要求

- 进程崩溃、显式退出、登出或重启后的守护能力留待独立 sidecar/launchd 设计。
- 动态异价路由无法由 OpenCode 的单个静态虚拟模型精确表达；本轮选择不伪造。若未来需要
  OpenCode 精确 Spent，应暴露真实模型身份及逐模型配置，或由 OpenCode 支持响应级价格。
- 已连接第三方配置不会在每次 Token Station 路由变化后自动改写；需要可见的“需刷新”
  状态和重新连接操作。
- 内置免费 Provider 的静态目录尚无可核实的 `max_output_tokens`。本轮不猜测上限，因而
  OpenCode 在免费模型进入可达集合时会明确拒绝生成不安全配置；后续应在免费模型验证流程
  中读取其 `/models`，仅接受同 ID 的合法输出上限。
- 本轮 Agent 热更新定向验收已完成：`restarting_one_agent_route` 4/4 通过，
  覆盖 Applying 拒绝、草稿独有目标拒绝、Router 预构建失败不落盘、合法 plan
  持久化并安装；`hot_agent_router` 2/2 通过，验证 serving snapshot 边界与
  override 记录。原生 shell 定向测试 6/6 通过，包含 ConfigReadOnly 与 RecoverySafe
  地址不可用契约。
- `quota_first` 路由核心目前没有执行 `local_only` 过滤，这是既有路由语义问题；本轮只保证
  OpenCode 虚拟模型契约在严格 `local_only && !allow_cloud_fallback` 时不纳入云目标，路由
  核心本身的统一语义留待独立修复。

## 10. 实现与验收记录

### 10.1 已落地实现

- macOS 主窗口关闭改为 `prevent_close + hide`；Dock reopen 与状态栏“打开 Token Station”
  恢复同一窗口。状态栏菜单由后端真实生命周期驱动，可启动、停止和显式退出；异常任务
  退出会被轮询纠正，启动失败会显示错误并恢复主窗口。
- Cursor 接入现在同一事务写入 URL、密钥和 `useOpenAIKey=true`，提交后的打开、查询、值
  不一致等任一验证失败均恢复完整原始记录；成功提示明确要求重启 Cursor 并选择 OpenAI
  BYOK 兼容模型。
- 模型目录缓存升级并解析 context、max output、模态与 scoped price；刷新失败会把持久缓存
  标记为 `Stale`，后续模型选择不得把陈旧 rich facts 投影进可执行配置。目录只填补未知能力
  和不存在的 scoped price，不覆盖用户已有值。磁盘缓存跨进程默认不可信；只有当前进程按
  `data_dir + provider + base URL` 完成 live 拉取并成功提交缓存后，rich facts 才可执行。
- OpenCode 连接器按实际 serving snapshot 计算保守虚拟模型契约：只枚举可达目标，严格
  local-only 时剔除云端目标，要求所有目标都具备 context/output，按最小可用输入预算计算
  limit；只有完整 scoped 价格一致且 reasoning 可表达时才写 cost。具体缺失原因原样返回，
  不再写零值或通用估算冒充精确事实。
- Agent 路由热更新改为“预构建并验证 -> 保存 -> 无失败安装”三阶段；Starting/Applying、
  草稿独有目标和非法 Router 均在落盘前拒绝。
- Agent OpenAI 适配器在流式与非流式 usage 中保留 cache read/write、reasoning 和 total tokens；
  历史费用回填按已记录 upstream 使用 scoped price。
- 三个历史可选 map 使用字段级 `null -> default`；必需 map 仍严格报错，加载本身不改写文件。
