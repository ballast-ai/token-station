# 旧版零并发配置兼容迁移设计

> 日期：2026-07-28
> 基线：`develop@b292696`
> 状态：已实现、已验证、已安装本地 App

## 1. 问题

历史 v1 配置把并发限制 `0` 定义为“不限制”，并通过派生的 `Default` 将
`concurrency.global/per_agent/per_provider` 默认写成 `0`。安全收紧提交
`5694347` 将默认值改为有限的 `64/16/16`，同时禁止任何并发限制为 `0`，但没有为已
落盘的 v1 文件提供读取迁移。

升级后的桌面 App 因此把曾经合法的配置误判为损坏配置，进入只读保护：

```text
concurrency.global, concurrency.per_agent and concurrency.per_provider
must all be greater than zero
```

## 2. 目标

1. 历史 v1 JSON 中的零并发值在读取时迁移为当前有限默认值。
2. 桌面 App 启动后不再因该历史值进入只读保护。
3. CLI、桌面和其他 `ClientConfig::load` 调用方获得一致的兼容行为。
4. 新配置或内存配置保存时仍拒绝 `0`，不重新开放“无限并发”语义。
5. 不改变 Provider、路由、Agent、凭据引用或其他用户配置。

## 3. 范围与非目标

### 3.1 包含

- `ClientConfig::load` 的 v1 零并发兼容迁移。
- 桌面真实配置加载和只读保护行为。
- CLI 配置公开加载测试、桌面公开加载测试。
- 本机配置的备份、迁移和真实 App 验收。

### 3.2 非目标

- 不放宽 `ClientConfig::save` 和 `validate` 对零并发值的拒绝。
- 不自动修复无效 JSON、未知字段、非回环监听地址或其他配置错误。
- 不修改配置版本号或引入新的磁盘字段。
- 不调整并发默认值和并发门控算法。

## 4. 安全与数据红线

1. 迁移后的值必须是有限默认值：global `64`、per Agent `16`、per Provider `16`。
2. 只迁移 `concurrency` 的零值；非零值原样保留。
3. 读取迁移只发生在内存中，不在 App 启动阶段静默覆盖用户文件。
4. 本机磁盘配置落盘前必须创建可恢复备份，并使用既有原子保存路径。
5. Provider API Key、请求正文和响应正文不得出现在日志、测试输出或设计文档。
6. 其他结构错误仍必须进入只读保护，禁止用模板覆盖原文件。

## 5. 状态与失败处理

### 5.1 读取

1. 从磁盘反序列化 v1 `ClientConfig`。
2. 对 `concurrency` 三个字段分别执行兼容迁移：
   - `global == 0` → `64`
   - `per_agent == 0` → `16`
   - `per_provider == 0` → `16`
3. 执行现有完整结构和安全校验。
4. 校验成功后向调用方返回迁移后的内存配置。

### 5.2 保存

- `ClientConfig::save` 仍直接校验当前内存配置；任一并发值为 `0` 时拒绝写盘。
- 桌面 App 后续正常保存时，内存中的有限值会通过既有原子写盘路径持久化。

### 5.3 失败

- JSON 反序列化失败：保持只读保护。
- 迁移后仍有其他校验错误：保持只读保护。
- 本机备份失败：不得修改真实配置。
- 本机保存或重装失败：保留旧配置与当前已安装 App，并如实报告。

## 6. 用户可见交互

- 用户不需要理解或手动编辑 concurrency。
- 历史零并发配置启动后，首页不再显示该只读保护错误。
- 模型刷新、Provider 管理、主页路由和 Agent 路由恢复正常可写。
- 本次不新增弹窗、按钮或设置项。

## 7. 响应式、键盘与可访问性

本次不改变界面结构、焦点顺序、键盘操作或响应式布局。错误消失后恢复既有可操作控件；
其他配置错误仍使用现有文本错误区域，不依赖颜色传达。
