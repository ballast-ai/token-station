# macOS 状态栏菜单视觉层级优化设计

- 日期：2026-08-13
- 状态：已实现并安装；自动化与运行事实验收通过，原生状态项视觉/VoiceOver 待人工补验
- 范围：macOS 状态栏原生菜单的信息层级、代理开关表达、状态文案与真实 App 验收
- 不涉及：React 前端页面、路由与代理数据面、用户配置格式、托盘图标资产、DMG 或远端发布

本文档自实现起替代 `2026-08-12-后台常驻与Agent接入完整性修复设计.md` §5.1 中的旧菜单顺序；
旧文档保留为当时实现和验收的历史记录。

## 1. 问题、事实基线与错误前提检查

当前截图中的弹层不是 Web 前端，而是 Tauri/muda 创建的原生 `NSMenu`。圆角、背景、字体、
高亮和系统间距由 macOS 控制，不能通过 React/CSS 调整；因此“直接改前端样式”是错误前提。

现有菜单把“代理已停止”和“监听地址”都创建为 disabled item，再分别提供“打开”和“启动代理”。
这造成三个可确认的问题：

1. 首屏连续两行低对比度灰字，状态看起来像不可用的调试信息，而不是产品状态。
2. “代理已停止”与“启动代理”重复表达同一开关，扫描成本高、主次不清。
3. “监听地址：”前缀占据宽度，但在代理控制项下没有新增语义。

## 2. 目标与成功口径

1. 使用标准 macOS 菜单语义表达“打开 App、切换本地代理、查看地址、退出”四个任务。
2. 稳定运行态和停止态不再依赖禁用状态文字；用原生 check item 的勾选状态表达开关。
3. 保留启动、运行中应用、同端口监听切换、停止等真实生命周期，以及只读保护与恢复安全模式；
   不把过渡态显示成可操作状态。旧监听仍可达时保持勾选，旧 socket 已释放且新监听尚未接管时
   必须取消勾选并明确“暂时不可用”。
4. 菜单在深色和浅色系统外观下均由系统颜色、字体和焦点样式渲染，不引入自绘浮层。
5. 不触碰并行窗口正在修改的前端文件；实现收敛到原生 shell 模块与本设计文档。

## 3. 范围与非目标

### 3.1 范围

- 调整原生菜单顺序、分组和用户可见文案。
- 将代理控制改为 Tauri `CheckMenuItem`，权威生命周期更新时同步 text、enabled 和 checked。
- 将“首次启动”“旧监听仍可达的运行中应用”和“监听交接窗口”映射为不同菜单 phase，更新
  纯状态映射测试，覆盖七态及
  两种保护模式。
- 所有菜单发布在 macOS 主线程执行时重新读取权威后端状态，避免并发通知乱序覆盖。
- 运行全量测试、构建、本地 App 安装与真实菜单验收。

### 3.2 非目标

- 不自绘 popover，不修改 macOS 原生圆角、材质、阴影、字体或行高。
- 不增加彩色圆点、品牌 Logo、渐变、远程字体或额外设置入口。
- 不改变代理启停、失败恢复、关窗常驻、Dock reopen 或显式退出语义。
- 不改 `apps/desktop/src/**`、前端依赖或另一窗口的设计文档。
- 不创建、修改或发布 DMG。

## 4. 安全与数据红线

1. 菜单事件只能继续进入现有生命周期协调器，不绕过配置验证、generation 或启动失败处理。
2. Starting 与 Stopping 必须禁用代理控制，避免重复命令；Failed 仅允许走既有 Start 重试。
   Applying 也必须禁用控制；旧运行实例存活且监听仍可达时继续勾选，不得误报为已停止。
   若 Applying 的旧任务仍存活但 listener 已不可达，则进入 Switching：保持禁用但取消勾选，
   不能声称代理仍在服务。
3. ConfigReadOnly 与 RecoverySafe 中代理控制必须禁用，不能通过勾选项产生写入或启动。
4. 监听地址只来自可信运行态或已加载配置；两种保护模式继续显示地址不可用，不能展示模板地址。
5. tooltip、菜单和主界面必须来自同一权威生命周期；不能为了视觉效果伪造“运行中”。
   菜单快照同时携带 generation；启停动作必须在生命周期锁内复核 generation 与允许的源 phase，
   陈旧点击只能忽略并刷新，不能应用配置或停止更新后的实例。
6. 不读取、显示或记录 API Key、prompt、response、第三方 Agent 配置或其他敏感数据。
7. 本地安装只允许替换 bundle id 为 `com.tokenstation.desktop` 的精确 App 路径。

## 5. 用户可见交互、状态与失败处理

### 5.1 菜单结构

```text
┌──────────────────────────────┐
│ 打开 Token Station           │
├──────────────────────────────┤
│ ✓  运行本地代理              │  ← 点按切换；勾选表示运行中
│    地址 · 127.0.0.1:8787     │  ← 只读辅助信息
├──────────────────────────────┤
│ 退出 Token Station           │
└──────────────────────────────┘
```

- “打开 Token Station”置顶，恢复、取消最小化并聚焦已有主窗口。
- 稳定态代理项固定使用“运行本地代理”；未勾选点按启动，已勾选点按停止。
- 地址使用名词性“地址 · host:port”，不在停止态误导用户认为端口正在监听；该行保持 disabled，
  明确不可编辑。
- “退出 Token Station”独立置底并继续执行真实退出。

### 5.2 生命周期映射

| 生命周期 | 代理项文字 | 勾选 | 可操作 | 点按结果 |
|---|---|---:|---:|---|
| Stopped | 运行本地代理 | 否 | 是 | 启动 |
| Starting | 正在启动本地代理… | 否 | 否 | 无 |
| Applying | 正在更新本地代理… | 是 | 否 | 无；旧监听仍可达 |
| Switching | 正在切换本地代理… | 否 | 否 | 无；同端口交接暂时不可用 |
| Running | 运行本地代理 | 是 | 是 | 停止 |
| Stopping | 正在停止本地代理… | 是 | 否 | 无 |
| Failed | 重试启动本地代理 | 否 | 是 | 重新启动 |

ConfigReadOnly 显示“本地代理不可用 · 只读保护”和“地址不可用 · 配置损坏”；RecoverySafe
显示“本地代理不可用 · 安全模式”和“地址不可用 · 安全模式”。两者均不勾选、不可操作。
tooltip 继续使用“Token Station · 当前真实状态”。

### 5.3 失败处理

- 启动失败后不自动勾选，代理项清楚提供“重试”；点按仍走既有启动错误处理并恢复主窗口。
- 原生菜单任一状态更新失败时禁用代理项，避免视觉状态与可执行动作分叉，并记录不含敏感数据的错误。
- 配置损坏或恢复安全模式不提供伪地址，也不把保护状态隐藏成普通停止态。
- 生命周期通知、运行态查询和每秒纠偏可能来自不同线程；它们只请求刷新，不携带待应用快照。
  真正的 phase、地址、勾选与可用性必须在主线程刷新任务执行时从 `AppState` 重新读取并一次连续
  应用，菜单事件不能观察到“新样式 + 旧动作 phase”的中间组合。
- `ServerLifecycle::Applying` 不能只看任务 alive：任务 alive 且 server control 仍 accepting 才映射
  Applying；stop-accepting 已发出或任务退出时映射 Switching，tooltip 显示“正在切换代理 · 暂时
  不可用”。此判定读取内存控制状态，不在主线程持全局锁发起最长 200ms 的 TCP 探针。
- 菜单 action 携带刚渲染快照的 generation。Start 只允许同 generation 的 Stopped/Failed，Stop
  只允许同 generation 的 Running；检查和状态转移必须处于同一个 `AppState` 临界区。任何不匹配
  都视为状态已前进，忽略动作并请求刷新，不显示错误、不改配置。

## 6. 视觉、响应式、键盘与可访问性

### 6.1 视觉方向

- 产品与受众：面向 AI 工程师的本机路由控制台；菜单的单一任务是快速确认并控制本地代理。
- 色彩：不设置固定 Hex token，继承 macOS 动态 `menuBackground`、`labelColor`、
  `secondaryLabelColor`、`selectedMenuItemTextColor` 与系统 accent，保证深浅色和高对比度适配。
- 字体：继承系统菜单字体（San Francisco）；不覆盖字号、字重或字距。
- 布局：三个原生分组；主窗口动作、代理控制、显式退出各自只有一个主任务。
- 视觉签名：原生 checkmark 同时承担运行状态与开关语义，减少重复文案而不引入装饰。

自检后放弃彩色状态点、每行动作图标和自绘品牌标题：它们会同时争夺注意力，且无法比系统勾选
更准确地表达二态控制。过渡态和失败态通过短文案补足二态模型无法表达的信息。

### 6.2 响应式与系统适配

- 原生 NSMenu 由 macOS 根据屏幕边缘、缩放、语言和系统外观自动定位、裁切与翻转。
- 文案保持单行和短长度；保护模式不拼接未经约束的系统错误，避免菜单异常变宽。
- 不依赖颜色表达运行状态；勾选、文字和 enabled 状态共同提供冗余语义。

### 6.3 键盘与可访问性

- 保留 macOS 原生上下方向键、Return、Escape、鼠标和触控板操作，不截获键盘事件。
- check item 让 VoiceOver 直接朗读选中/未选中；过渡态与保护态朗读禁用状态和明确文案。
- disabled 地址仍作为可朗读静态信息；“打开”和“退出”保持完整产品名称，避免动作歧义。
- 焦点、高对比度、Reduce Transparency 和系统字号行为全部交给原生菜单，不自绘替代。

## 7. 公开测试边界与验收标准

### 7.1 自动化公开行为

1. Stopped/Running 都显示“运行本地代理”，checked 分别为 false/true，且控制可用。
2. Starting/Stopping 使用明确过渡文案、保持符合当前进程存活事实的 checked 值，并禁用控制。
   Applying 单独显示“正在更新本地代理…”，旧监听可达时保持勾选且禁用；Switching 显示
   “正在切换本地代理…”，取消勾选且禁用，证明端口交接窗口不会伪报可用。
3. Failed 显示“重试启动本地代理”，未勾选且可走 Start；tooltip 保留失败事实。
4. 普通模式地址仅显示可信的名词性“地址 · `host:port`”，不把停止态表述成正在监听。
5. ConfigReadOnly/RecoverySafe 使用短保护文案、地址不可用、未勾选且禁用。
6. 只有稳定可写态和 Failed 会派发代理动作；打开、代理、退出菜单 ID 继续互不混淆。
7. 关窗隐藏与 Dock/菜单恢复策略不变。
8. 多个乱序刷新请求不能把旧快照覆盖到新状态；菜单事件使用同一次主线程权威读取的 phase。
9. 用 generation 回归测试证明：陈旧 Start 不会把 Running 误转为 Applying，陈旧 Stop 不会停止
   新 generation 的实例。

原生 NSMenu 的真实字体、间距、勾选绘制、VoiceOver 朗读和菜单点击不能由纯 Rust 单测证明，
必须通过安装后的真实 App 验收。

### 7.2 验收标准

- 菜单顺序与 §5.1 一致，首屏不再出现两行连续的灰色状态说明。
- 停止态未勾选，点按后出现过渡态并最终勾选；再次点按后最终取消勾选。
- 地址、tooltip、主界面和端口可达性在每次状态变化后保持一致。
- 浅色、深色下文字和系统勾选均清楚；键盘与 VoiceOver 不丢失动作语义。
- 打开恢复同一窗口；退出终止 PID 并释放监听端口。

## 10. 实现与验收记录

### 10.1 已实现

- 原生菜单已调整为“打开 → 分隔 → `CheckMenuItem` 代理控制 → 禁用地址辅助行 → 分隔 → 退出”；
  不再以两行连续 disabled 状态文字开场。
- 七态文案、checked、enabled、tooltip 和保护模式已收敛到纯映射；macOS 自动翻转 check item 后，
  菜单事件会立即重读并恢复后端权威状态，再决定是否派发动作。
- 刷新请求不再携带待发布快照，而是在 macOS 主线程执行时读取当前 `AppState`，消除了旧通知晚到覆盖
  新状态的问题。
- `ServerControl` 增加只读 `is_accepting` 事实。Applying 只有在旧任务存活且仍 accepting 时勾选；
  stop-accepting 后会在候选 bind 前立即刷新为 Switching，不等待一秒轮询。
- 菜单快照携带 generation；Start/Stop 在同一个 `AppState` 临界区同时复核 generation 与当前允许
  action。陈旧点击只触发菜单刷新，不能误应用配置或停止新代实例。
