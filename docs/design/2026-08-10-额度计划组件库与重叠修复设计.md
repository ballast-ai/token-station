# 额度计划组件库与重叠修复设计

- 日期：2026-08-10
- 状态：已实现并完成本机验收
- 范围：`apps/desktop/src/components/QuotaPriorityPanel.tsx`、`apps/desktop/src/App.css`、`apps/desktop/src/components/ui/field.tsx`、`apps/desktop/src/components/ui/label.tsx`

## 问题、目标、范围和非目标

额度优先面板中的“额度计划(可选)”行仍使用原生 `select`、`input` 和自定义 `.btn/.select/.input` 样式，没有使用项目已经接入的 shadcn/ui 组件库。当前 CSS 使用固定四列布局，在面板可用宽度不足、中文占位符较长或数字输入框出现浏览器 stepper 时，刷新窗口、额度上限、单位三块控件会相互挤压和重叠。

目标是把额度计划行迁移到项目已有的 shadcn `Field`、`Select`、`Input`、`Separator` 基础组件，并让供应商名与三个控件在桌面和窄窗口下都有稳定间距。用户应能继续按供应商声明刷新窗口、额度上限和单位，现有自动保存行为保持不变。

本次只修复额度计划子区的控件来源和布局，不重做额度优先模式整体信息架构，不改动额度账户列表、实时额度页、后端 `set_quota_plan` 契约或路由选择算法。

## 安全与数据红线

不读取、不展示、不写入 API Key、请求正文或供应商隐私数据。额度计划仍只写入用户主动填写的 `upstream.quota_plan` 草稿字段。清空或输入非数字上限时继续按现有行为清除计划，不能凭空估算或补默认上限。

## 用户可见交互、状态变化和失败处理

每个已参与轮换的供应商展示一行额度计划：供应商名、刷新窗口、额度上限、单位。刷新窗口和单位选择后立即调用 `onSavePlan`；额度上限输入时只更新本地字段，失焦后提交。`busy` 状态下所有控件禁用。

如果已保存计划发生变化，行内字段继续同步后端返回的 `plan`。空上限、非法数字或小于 0 的值继续提交为 0，由现有后端清除计划。没有参与轮换供应商时不显示额度计划区。

## 响应式、键盘和可访问性要求

控件必须使用组件库焦点态和禁用态。`SelectItem` 必须置于 `SelectGroup` 内。每个控件保留供应商相关 `aria-label`，键盘用户可 Tab 进入窗口、上限和单位控件，并通过 Radix Select 键盘交互选择项。

布局上供应商名不得挤压三个控件。宽窗口下供应商名和控件同排；空间不足时，供应商名占满一行，三个控件进入自适应网格并允许换行。控件最小宽度要保证“额度上限”、`requests` 和最长窗口文案不相互覆盖。

## 公开测试边界、验收标准和真实 App 检查项

公开行为测试覆盖：

1. 额度计划行渲染 shadcn `Select`、`Input`、`Separator` 数据槽，不再渲染原生 `select`。
2. 窄容器下额度计划行暴露响应式结构，供应商名和控件组分离，控件组使用可换行网格。
3. 改变刷新窗口、单位和上限仍按原参数调用 `onSavePlan`。

真实 App 检查：

1. 在额度优先模式添加 deepseek 模型后，“额度计划(可选)”行使用统一组件库样式。
2. 900×600 左右窗口宽度下，刷新窗口、额度上限、单位三块控件不重叠、不遮挡文字。
3. 控件可键盘聚焦，禁用态不丢失可读性。
