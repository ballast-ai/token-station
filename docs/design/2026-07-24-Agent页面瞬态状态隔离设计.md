# Agent 页面瞬态状态隔离设计

日期：2026-07-24
状态：已实现并通过自动化验收

## 1. 问题

桌面 App 使用同一个 `AgentRoutePage` 组件展示 Claude Code、OpenCode、Codex 等 Agent。
当前仅替换组件 props，React 会复用同一个组件实例，因此上一个 Agent 页面产生的局部状态可能出现在下一个 Agent 页面。

已确认的用户可见症状：

- Claude Code 完成接入或恢复后出现成功提示；
- 切换到 OpenCode 或其他 Agent；
- 页面标题和路由数据已经属于新 Agent，但成功提示仍来自 Claude Code。

该问题是前端页面状态串用，不代表后端 ownership、安装记录或 Connector 发生串用。

## 2. 状态边界

### 2.1 持久业务状态

以下状态由 App 或后端按 `agent_id` 提供，不应因页面重建而丢失：

- Registry 元数据；
- Agent 安装发现与兼容状态；
- connected / managed 状态；
- 三档路由及模式；
- Provider 和模型目录。

### 2.2 页面瞬态状态

以下状态只属于当前 Agent 页面实例，不得跨 `agent_id` 复用：

- 当前安装选择 `selectedPath`；
- 操作中状态 `busy`；
- 成功提示 `notice`；
- 错误提示 `error`；
- 待确认配置计划 `pendingPlan`；
- 首次接入差异卡片 `connectDiff`。

## 3. 设计决策

以 `metadata.agent_id` 作为 `AgentRoutePage` 的 React identity：

```tsx
<AgentRoutePage key={metadata.agent_id} ... />
```

当用户从一个 Agent 切换到另一个 Agent 时，旧页面实例卸载，新页面实例以空白瞬态状态创建。

不使用扫描序号、安装路径或 connected 状态作为 key，避免同一 Agent 在重新扫描、状态刷新或选择安装实例时被无意义重建。

不把 `notice`、`error` 或 `pendingPlan` 提升到 App 全局层；它们不是跨页面业务状态。

## 4. 操作语义

- 切换 Agent 会丢弃尚未确认的前端计划展示；后端短时计划保持不可复用并按 TTL 过期。
- 已经确认并开始执行的事务仍绑定原始 `agent_id`、安装路径和 operation ID，不因页面切换改写目标。
- 页面重建只清理 UI 瞬态状态，不修改 Agent 配置、ownership 或路由草稿。

## 5. 验收条件

1. Claude Code 显示“Agent 已接入”后切换 OpenCode，OpenCode 页面不得显示该提示。
2. Claude Code 显示“已恢复接入前的 Agent 配置”后切换 OpenCode，OpenCode 页面不得显示该提示。
3. 任一 Agent 的错误提示不得出现在其他 Agent 页面。
4. 任一 Agent 的配置改动确认面板不得在切换后出现在其他 Agent 页面。
5. 同一 Agent 重新扫描或状态刷新时，不因 key 变化丢失正常页面上下文。
6. 后端扫描得到的 managed / connected 状态仍分别按 Agent 展示。

## 6. 回归测试

在 `apps/desktop/src/App.test.tsx` 使用真实 App 导航边界：

1. 完成 Claude Code 恢复并生成成功提示；
2. 点击主导航进入 OpenCode；
3. 确认一级标题为 OpenCode；
4. 断言 Claude Code 的恢复提示不存在。

该测试直接覆盖用户报告的跨 Agent 页面提示串用，不以内部 state 或组件实现细节作为断言。
