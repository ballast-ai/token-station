# macOS 状态栏 Agent 快切与快捷操作设计

- 日期：2026-08-14
- 状态：已实现并安装；自动化、构建与主窗口启动验收通过，原生子菜单视觉/VoiceOver 待人工补验
- 范围：macOS 原生状态栏菜单、已接入 Agent 展示、主窗口页面快切、常用页面快捷入口
- 不涉及：Agent 接入/断开写操作、Agent 路由配置变更、代理数据面、托盘图标、Windows/Linux、DMG 或远端发布

## 1. 问题、事实与目标

### 1.1 当前事实

当前状态栏菜单只有“打开 Token Station”、代理开关、监听地址和退出。它能表达代理状态，
但不能回答“哪些 Agent 已由 Token Station 接管”，也不能直达某个 Agent 的管理页。

Token Station 支持多个 Agent 同时接入；系统里不存在互斥的“全局当前 Agent”。因此本设计中的
“切换 Agent”严格定义为：**切换主窗口当前展示和管理的 Agent 上下文**，不得暗示或修改代理层
的全局 Agent、路由或接管状态。

### 1.2 目标

1. 在状态栏菜单中展示当前由 Token Station 接管的 Agent。
2. 点选 Agent 后恢复已有主窗口，并直达该 Agent 的管理页。
3. 提供添加供应商、请求日志和设置三个高频快捷入口。
4. 保留现有代理开关、真实监听地址、后台常驻和显式退出语义。
5. 菜单状态来自后端已有扫描与接管事实，不从图标、进程名或前端猜测。

### 1.3 非目标

- 不在菜单内直接接入、断开、重启 Agent，避免绕过现有预览、确认和恢复流程。
- 不在菜单内修改 Agent 路由、供应商或模型。
- 不把“已检测到但未接管”的 Agent 冒充为“已接入”。
- 不新增常驻的全局 Agent 选择状态。
- 不制作自绘弹窗；继续使用 macOS 原生菜单。

## 2. 安全与数据红线

1. 菜单读取 Agent 状态时只使用已有服务端扫描缓存与 ownership/连接校验；不得扫描任意新路径。
2. 菜单事件只能携带预定义页面 ID 或 Registry 中的 Agent ID；不得接受文件路径、命令或配置内容。
3. Agent 项点击只恢复窗口并发送页面导航事件，不写配置、不启动外部程序、不读取或展示密钥。
4. 配置损坏只读模式与恢复安全模式不读取业务配置，不展示虚假的 Agent 列表。
5. 代理控制继续通过 generation 校验和既有生命周期协调器执行，不因菜单扩展降低并发保护。
6. 菜单刷新失败时保留旧的只读展示并记录错误；不得把未知状态显示成“已接入”。

## 3. 信息架构与视觉计划

### 3.1 设计基调

这是面向 AI 工程研发的本机调度入口，单一任务是“快速确认运行事实并跳到要处理的上下文”。
继续采用 AppKit 原生菜单的系统字体、动态颜色、焦点、对比度和 reduced-motion 行为，不额外模拟
网页视觉。视觉层级由真实结构而非装饰编码：Agent 舰队、代理运行、工作区动作三组信息。

由于原生菜单不允许安全控制色板与字体，token 由系统提供：

- 背景：`NSMenu` dynamic material。
- 主文字：`labelColor`。
- 辅助/禁用文字：`secondaryLabelColor` / disabled state。
- 选中与键盘焦点：系统 accent color。
- 字体：系统 menu font；不加载自定义字体。

### 3.2 结构草图

```text
┌──────────────────────────────┐
│ 打开 Token Station           │
├──────────────────────────────┤
│ 已接入 Agent · 2           › │
│   Codex                      │  ← 恢复窗口并打开 Codex 管理页
│   Claude Code                │
│   ─────────────────────────  │
│   管理 Agent…                │  ← 打开主页 Agent 工作区
├──────────────────────────────┤
│ ✓ 运行本地代理               │
│   地址 · 127.0.0.1:8787      │
├──────────────────────────────┤
│ 快捷操作                   › │
│   添加供应商…                │
│   查看请求日志               │
│   打开设置                   │
├──────────────────────────────┤
│ 退出 Token Station           │
└──────────────────────────────┘
```

### 3.3 签名元素与取舍

签名元素是“已接入 Agent · N”舰队入口：数量在一级菜单可扫读，具体 Agent 收入二级菜单，避免在
状态栏有限宽度里堆叠。它对应 Token Station 的多 Agent 本质，而不是通用应用菜单模板。

自检后移除了“当前 Agent 勾选”和“重新扫描”两个初稿元素：前者会制造不存在的全局选择语义；
后者可能在用户只想打开菜单时触发有成本的磁盘/版本探测。菜单只消费已有扫描缓存，完整扫描继续
由主窗口现有流程负责。

## 4. 用户可见交互、状态与失败处理

### 4.1 Agent 分组

- 纳入条件：某 Agent 至少一个已发现安装的 `managed == true`；代理运行时仍以现有 `connected`
  校验补充真实性，但代理停止不抹掉已接管事实。
- 同一 Agent 多安装只显示一个 Registry `display_name`，按 `ui_order` 排序。
- 有接入项：一级标题为“已接入 Agent · N”，子菜单列出 Agent，底部保留“管理 Agent…”。
- 无接入项或尚无扫描缓存：一级标题为“已接入 Agent · 0”；子菜单显示禁用提示
  “暂无已接入 Agent”，并保留“管理 Agent…”。
- 点击 Agent：立即恢复、取消最小化并聚焦已有主窗口，然后发出受限导航事件
  `agent:<registry-id>`。
- 点击“管理 Agent…”：恢复窗口并打开主页 Agent 工作区 `home`。

### 4.2 快捷操作

- “添加供应商…”导航到 `add-provider`。
- “查看请求日志”导航到 `logs`。
- “打开设置”导航到 `settings`。
- 所有动作复用已有单窗口，不创建重复窗口。

### 4.3 代理与退出

- 代理开关、地址、过渡态、失败态和只读保护语义保持
  `2026-08-13-macOS状态栏菜单视觉层级优化设计.md` 的约定。
- “退出 Token Station”继续直接退出进程，不被 close-to-hide 拦截。

### 4.4 失败处理

- Agent 菜单快照不可用：显示“已接入 Agent · 0 / 暂无已接入 Agent”，不阻塞代理控制。
- 前端尚未完成启动：导航事件可先恢复窗口；前端监听建立后只处理之后的用户点击，不缓存过期动作。
- Agent 已在菜单生成后被移除：前端可见 Agent 边界拒绝该导航事件并保留当前页面。
- 原生菜单更新失败：记录到标准错误，保留上一次已成功渲染的内容。

## 5. 响应式、键盘与可访问性

- 原生菜单由 macOS 负责屏幕边界避让、缩放、深浅色、高对比度和菜单滚动。
- 一级和二级菜单必须可用方向键、Return/Space 与 Escape 操作，不绑定仅鼠标可用的交互。
- 菜单项使用完整动作名称；只读状态使用禁用菜单项，不仅依赖颜色区分。
- Agent 数量是可读文本的一部分，不用徽标或图形单独表达。
- 不新增动画；遵循系统 reduced-motion。
- 中英文前端均能正确响应导航；本轮原生菜单沿用当前中文产品文案。

## 6. 公开测试边界与验收标准

### 6.1 纯行为测试

1. managed Agent 去重、排序并生成安全菜单 ID；未接管和纯检测 Agent 不进入列表。
2. Agent 菜单 ID 只解析 Registry 允许的受限 ID；未知 ID 必须 Ignore。
3. 快捷操作 ID 分别映射到 `home`、`add-provider`、`logs`、`settings`。
4. Agent/快捷操作与 Open 一样恢复窗口；只有合法导航动作才发送事件。
5. 原有代理各阶段、只读模式、退出和窗口恢复测试继续通过。
6. 前端收到状态栏导航事件后切换到目标视图；无效 Agent 回退主页。

### 6.2 验收标准

- 菜单一级可直接看到已接入 Agent 数量。
- 二级菜单只显示实际已接管 Agent，名称与 Agent Registry 一致。
- 连续点选两个 Agent 时，主窗口分别切到对应页面，代理和配置不发生变化。
- 三个快捷操作均打开正确页面，隐藏/最小化窗口均能恢复并聚焦。
- 停止代理后，managed Agent 仍保留在列表；代理控制仍可独立启停。
- 配置损坏或恢复安全模式不展示业务 Agent，不泄漏路径或配置。

### 6.3 真实 App 检查项

1. 构建并安装 `/Applications/token-station.app`，校验 bundle id 与代码签名。
2. 状态栏左键打开菜单，核对分组、数量、子菜单方向和系统深浅色。
3. 隐藏和最小化主窗口后分别测试 Agent、添加供应商、日志、设置入口。
4. 通过接入/断开一个 Agent 后重新打开菜单，核对列表更新。
5. 启停代理并确认监听端口、菜单勾选、地址与 Agent 列表互不混淆。
6. 用键盘完整遍历菜单，必要时补做 VoiceOver 读屏检查。

### 7.2 已知遗留项

- 原生菜单暂不显示每个 Agent 的模型或路由摘要；这些信息可能较长且存在未保存/未应用状态，继续留在
  Agent 页面展示。
- Cursor 的专用 SQLite 接入不使用通用 ownership 索引；若现有 Agent 视图无法提供稳定 managed 事实，
  本轮不得为菜单单独猜测 Cursor 状态，后续应统一其接管索引。
- 本轮不为快捷操作添加全局键盘快捷键，避免与 Agent 工具和系统快捷键冲突。

## 8. 实现与验收记录（2026-08-14）

### 8.1 已实现

- 原生菜单新增“已接入 Agent · N”子菜单；空态显示禁用提示并保留“管理 Agent…”。
- Agent 列表来自服务端最后一次扫描与 ownership 接管索引，按 Registry `ui_order` 排序、按 ID
  去重；代理停止不会抹掉已接管事实。
- Agent 菜单 ID 仅接受 1–64 位小写字母、数字和连字符，并且必须存在于当前菜单快照；未知 ID
  和路径式 ID 被忽略。
- 新增“快捷操作”子菜单：添加供应商、查看请求日志、打开设置。
- 菜单点击先恢复已有主窗口，再发送受限 `status-menu-navigate` 事件；前端只接受四个固定页面或
  当前可见 Registry Agent。
- Agent 子菜单只在扫描、接入、断开或强制解除接管后刷新，不加入每秒代理轮询，避免无变化时
  重读 ownership 文件；代理开关仍按原频率读取权威生命周期。
- 恢复安全模式继续只安装空 Agent 快照，不读取业务配置。
