# Agent 显示跟随检测与手动覆盖设计

## 问题、目标、范围与非目标

### 问题

当前“设置 → Agent 显示”与主页使用了两套互相冲突的可见性判断：

- 设置开关只检查 Agent 是否存在于“隐藏 ID”列表，因此 Registry 中所有 Agent 默认都显示为开启；
- 主页又要求 Agent 必须在本次启动扫描中被检测到，因此未检测 Agent 即使在设置中开启也不会出现。

结果是：本机没有安装 Gemini CLI 时，设置仍显示开启；用户关闭再开启也无法在主页看到它。

### 目标

1. 启动扫描检测到的 Agent 默认开启；未检测到的 Agent 默认关闭。
2. 用户可以显式覆盖默认值：隐藏已检测 Agent，或显示未检测 Agent。
3. 未检测 Agent 被手动显示后，立即出现在主页 Agent 列表中，并使用与“多实例”等状态相同层级的“未检测”标签。
4. 打开未检测 Agent 后，详情区明确说明本机未发现可管理安装，接入操作保持禁用。
5. 显式选择跨启动保存；已存在的“隐藏 Agent”偏好继续兼容。

### 范围

- Agent 显示偏好的本地存储与兼容读取。
- 设置页开关的有效状态与计数。
- 主页 Agent 列表的可见性和未检测状态文案。
- 对应公开行为测试、组件测试、本地 App 构建与真实界面验收。

### 非目标

- 不改变 Agent 扫描候选、版本探测或 Connector 行为。
- 不因用户显示未检测 Agent 而创建配置文件、安装 CLI 或执行重新扫描。
- 不改变“多实例”“异常”“已接入”等已有状态判断。
- 不新增自动安装入口。

## 安全与数据红线

1. 显示开关仅写浏览器本地 UI 偏好，不写 Agent 配置、Token Station 路由配置或密钥。
2. 手动显示未检测 Agent 不得伪造发现记录，不得启用“一键接入”。
3. 扫描失败不得当作“全部未检测”；继续使用现有启动失败保护界面。
4. 存储内容只允许规范化 Agent ID 和布尔显示意图；忽略畸形、超长和非法 ID。
5. 本地存储读写失败只影响偏好持久化，不阻断导航；继续通过现有错误 Toast 告知。

## 用户可见交互、状态变化与失败处理

### 有效显示状态

每个 Agent 的有效显示状态按以下优先级计算：

1. 用户显式设为显示：开启；
2. 用户显式设为隐藏：关闭；
3. 无显式选择：本次启动检测到则开启，未检测到则关闭。

旧版隐藏 ID 数组迁移为“显式隐藏”；未出现在旧数组中的 Agent 不被错误解释为“显式显示”。

### 设置页

- 已检测、无覆盖：开关开启。
- 未检测、无覆盖：开关关闭。
- 用户切换后立即更新当前会话的主页列表，并保存显式覆盖。
- 状态计数展示有效开启数，而不是 Registry 总量或旧隐藏集合的差值。
- 存储写入失败时，本次会话仍生效，并显示现有错误 Toast。

### 主页

- 手动开启未检测 Agent 后，它立即进入主页列表，不触发重新扫描。
- 列表右侧状态标签显示“未检测”（英文为 “Not found”），不使用容易被理解为运行状态的“离线”。
- 点击后详情区显示“未发现 / 没有在本机发现可管理的安装”，一键接入按钮禁用。
- 在设置中关闭当前打开的 Agent 后，返回主页全局路由，避免保留不可达详情。

## 响应式、键盘与可访问性

1. 复用现有 Radix Switch，不改变触控目标、焦点样式与 Space/Enter 键行为。
2. 开关继续使用 Agent 名称作为可访问名称；计数继续使用 `role=status` 和 `aria-live=polite`。
3. 主页状态继续使用文本标签，不只依赖颜色表达“未检测”。
4. 不新增固定宽度或额外布局层，沿用现有窄窗口滚动与主从栏响应式行为。

## 公开测试边界与验收标准

### 自动化测试

1. 仅检测 Claude Code 时，设置中 Claude Code 开启、Gemini CLI 关闭，计数为 `1 / N`。
2. 开启未检测 Gemini CLI 后，无重新扫描，主页立即出现 Gemini CLI，状态标签为“未检测”。
3. 点击 Gemini CLI 后显示未发现说明且接入按钮禁用。
4. 重新挂载后，显式显示的未检测 Agent 仍显示。
5. 旧版隐藏数组仍按显式隐藏迁移；畸形新版偏好安全回退。
6. 已检测 Agent 的隐藏/恢复、键盘操作、存储失败和当前 Agent 自动关闭行为继续通过。

### 真实 App 检查

在本机未安装 Gemini CLI 的前提下：

1. 设置 → Agent 显示中 Gemini CLI 默认关闭。
2. 开启后主页立即出现 Gemini CLI，右侧显示“未检测”。
3. 打开后显示未发现说明且“一键接入”不可点击。
4. 关闭再返回主页后 Gemini CLI 消失。

## 实现落点、遗留项与发布要求

### 实现落点

- `apps/desktop/src/components/AgentVisibilityPreferences.ts`：显式显示/隐藏覆盖、旧格式兼容与持久化。
- `apps/desktop/src/App.tsx`：基于启动检测事实和显式覆盖计算有效显示集合。
- `apps/desktop/src/pages/SettingsHub.tsx`：直接接收有效显示集合。
- `apps/desktop/src/pages/AgentsPage.tsx`：未检测状态标签文案。
- 对应 `.test.ts` / `.test.tsx`：公开行为与存储边界回归。

### 已知遗留项

- 显示偏好仍是当前设备本地偏好，不跨设备同步。
- 本次启动后新安装 CLI 不会自动改变检测默认值；沿用产品现有“每次启动扫描一次”合同。

### 发布要求

完成全量前端测试与构建后，执行 `scripts/install-local-desktop.sh`；只在官方构建、审计、bundle id 与签名校验成功后替换 `/Applications/token-station.app`。真实界面验收结果回写本文，最后使用规定 Git 身份和中文提交说明创建本地 commit。
