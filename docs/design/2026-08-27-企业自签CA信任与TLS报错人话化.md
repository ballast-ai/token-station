## 1. 问题 / 目标 / 范围 / 非目标

### 问题

企业内网部署的 Token Station 服务(token-station-server 企业档)用私有 CA 签发
TLS 证书。桌面端所有对上游的 HTTPS 请求走 ureq 3.3(rustls),根证书**只有**
Mozilla webpki-roots——没有 platform-verifier 特性、没有任何自定义 CA 加载代码。
后果:

1. 桌面端**完全无法连接**自签证书的内网服务(`UnknownIssuer`),把企业 CA 导入
   macOS 钥匙串也无效(ureq 不读系统信任库)。
2. TLS 失败对用户是天书:`模型目录请求失败：io: invalid peer certificate:
   UnknownIssuer` 一类的原文直出,前端兜底文案又把它笼统归为「无法连接,请检查
   网络、Base URL 和代理设置」,方向性误导(问题在证书信任,不在网络)。
3. 附带的不一致:同一 App 里 reqwest(仅 loopback Cursor 桥接用)走系统钥匙串,
   ureq 走 webpki-roots。用户导入钥匙串后「有的通有的不通」加剧困惑。本设计不
   改 reqwest(它不碰用户填的地址),但把这一事实记录在案。

服务端侧的前置修复(token-station-server `25d94fee`)已把部署脚本从「单张
CA:TRUE 证书直接当服务器证书」改为「私有 CA + serverAuth 叶子」,rustls 的
结构性拒绝已解除;剩下的就是信任链注入,即本设计。

### 目标

1. 用户可配置**一个额外信任的 CA 证书文件(PEM)**,对所有出站上游请求生效
   (网关转发、健康探测、可取消请求、模型目录发现)。
2. 语义是**追加**:webpki-roots 全量保留,公网 Provider 不受影响。
3. TLS 证书类失败给出**可行动的中文报错**:未信任(去配置 CA)/域名不匹配
   (SAN 问题)/过期/用途不符(部署方证书签错),不再落进「检查网络」兜底。

### 范围

- `apps/cli`:`EgressConfig` 新增 `extra_ca_file` 字段 + CA 加载/合并 +
  `EgressPolicy` TLS 注入 + `map_transport_error` TLS 细分 + 公开分类助手。
- `apps/desktop`:设置页新增 CA 路径输入、`set_settings` 透传、模型目录发现
  应用同一信任配置、TLS 报错映射中文、前端兜底文案表新增证书类条目。

### 非目标

- 不做 per-Provider CA(`EgressPolicy` 是 per-gateway 的,改造面大;单文件可以
  放多张 PEM,已覆盖多套内网部署并存的场景)。
- 不做文件选择器(不引入 tauri-plugin-dialog;沿用凭据 file 模式的「绝对路径
  文本框」先例)。
- 不提供跳过证书校验的开关(`disable_verification` 明确排除:凭据会暴露给
  中间人)。
- 不改 reqwest / cursor_tunnel(仅 loopback,不涉及企业地址)。
- 不做证书内容管理(查看/导入/过期提醒);只引用文件路径,与凭据 file 模式
  同口径。

## 2. 安全与数据红线

- **只加根、不减校验**:自定义 CA 是追加进信任库,主机名校验、有效期校验、
  用途校验全部保持 rustls 默认行为。永不引入 `danger_accept_invalid` 等旁路。
- 配置里只存**文件路径**,不存证书内容;证书是公开材料(不含私钥),路径落
  `token-station.json` 无泄密面。
- CA 文件解析失败/为空必须**显式报错**,绝不静默降级成「只剩 webpki-roots」
  (ureq 的 `add_parsable_certificates` 会静默跳过坏证书,加载层自己先校验
  「至少 1 张」再交给 ureq)。
- 出站代理的 no-redirect / no-env-proxy 红线(P1-6)不受影响。

## 3. 用户可见交互与失败处理

### 设置页(与出站策略同区块)

「出站策略」区块内、出口模式之下新增一行:

- 标签:「自定义 CA 证书(PEM 文件绝对路径)」,说明文案:「连接使用自签名
  证书的内网服务时,填入部署方提供的 CA 证书文件;留空表示仅信任公共证书
  颁发机构。文件可包含多张证书。」
- 纯文本输入(mono),placeholder `/absolute/path/ca.pem`;保存时后端校验:
  文件存在、可读、至少解析出 1 张证书,失败以字段级错误回显(aria-invalid +
  role=alert,同 egress_proxy_url 先例)。
- 该字段独立于出口模式:direct 模式下同样生效(内网直连正是主场景)。

### 失败处理(TLS 报错人话化)

| 场景 | rustls 错误 | 中文文案(桌面) |
|---|---|---|
| 未配置 CA / CA 对不上 | `UnknownIssuer` | 服务端证书不在信任链中。若是自签名部署,请在「设置 → 出站策略」填入部署方提供的 CA 证书文件;已配置的,请核对该 CA 是否签发了服务端证书。 |
| SAN 不含访问地址 | `NotValidForName` | 服务端证书与访问地址不匹配(证书未包含当前主机名或 IP)。请改用证书覆盖的地址访问,或请部署方重新签发。 |
| 证书过期 | `Expired` | 服务端证书已过期,请联系部署方重新签发。 |
| 证书未生效 | `NotValidYet` | 服务端证书尚未生效,请检查本机时间或联系部署方。 |
| 证书用途不符 | `InvalidPurpose` | 服务端证书用途不符(可能把 CA 证书直接当服务器证书使用),请联系部署方重新签发。 |

- 网关面(`map_transport_error`)同维度细分,报文保持英文(面向 API 客户端),
  code 仍是 `UpstreamUnavailable`。
- 前端 `errors.ts` 兜底表在通用网络条目**之前**加证书类条目,以上述中文文案
  的特征子串匹配,避免被「检查网络」吞掉。

## 4. 响应式与可访问性

- 新输入行沿用 `.setting-row` / `label` + `Input` 现有布局,窄窗口下与代理
  URL 行为一致(纵向堆叠)。
- `aria-label`、字段级错误 `aria-invalid` + `aria-describedby` + `role=alert`,
  照抄 egress_proxy_url 的实现。
- 三语(简中/繁中/英文)文案齐全,key 收在 LanguageProvider。

## 5. 公开测试边界与验收标准

公开行为(测什么):

1. **配置层**:`extra_ca_file` 序列化往返;文件缺失/空文件/无证书 PEM →
   `validate()` 报错;多张证书的 bundle 全部加载(张数正确)。
2. **信任合并**:配置 CA 后,信任库 = webpki-roots 全量 + 用户证书(公网根
   不丢;合并逻辑集中在 `extra_tls_config`,由 e2e 的成功握手与 bundle
   张数断言共同覆盖)。
3. **真实握手 e2e**:本地起 rustls TLS 服务(测试夹具:私有 CA 签发的
   localhost 叶子),(a) 未配 CA → 失败且分类为「未信任」;(b) 配了 CA →
   请求成功。夹具证书入库(公开材料,有效期 100 年,含生成命令说明)。
4. **报错分类**:对 `UnknownIssuer` / `NotValidForName` / `Expired` /
   `NotValidYet` / `InvalidPurpose` 各断言分类结果;分类走
   `io::Error → rustls::Error` downcast(ureq 3.3 的握手失败落在
   `Error::Io`,不是 `Error::Rustls`——测试钉住这个行为)。
5. **设置命令**:`set_settings` 携带 CA 路径保存/清空往返;坏路径 → 字段级
   错误(`egress_extra_ca_file`)。
6. **前端**:errors.ts 新条目命中优先于通用网络条目(vitest)。

验收标准:上述测试全绿;`cargo test -p token-station-cli` 与
`cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml` 通过;
`npm test` 通过;真实界面验收(设置页填 CA → 添加自签内网 Provider →
模型发现成功;删掉 CA → 报「不在信任链」文案)。

## 6. 实现落点与遗留项

### 落点

| 层 | 位置 | 内容 |
|---|---|---|
| 配置 | `apps/cli/src/config.rs` `EgressConfig` | `extra_ca_file: Option<String>`(`#[serde(default)]`);`load_extra_cas()` / `extra_tls_config()`;`validate()` 接入 |
| 依赖 | `apps/cli/Cargo.toml` | `webpki-root-certs`(完整 DER 的 Mozilla 根,rustls 官方;CDLA-Permissive-2.0 已在 deny 允许表)、`rustls`(显式声明既有传递依赖以做错误 downcast) |
| 注入 | `apps/cli/src/gateway.rs` `EgressPolicy::config` | `tls_config(...)`;`DefaultConnector` 链里的 `RustlsConnector` 从 `Config.tls_config` 取配置,`cancel_aware_agent` 同步生效,无需碰 connector |
| 分类 | `apps/cli/src/tls_trust.rs`(新) | `pub fn classify_tls_failure(&ureq::Error) -> Option<TlsFailure>` |
| 网关报错 | `apps/cli/src/gateway.rs` `map_transport_error` | TLS 细分 arm |
| 发现 | `apps/desktop/src-tauri/src/model_catalog.rs` | agent 应用 `extra_tls_config()`;报错走分类映射中文 |
| 设置命令 | `apps/desktop/src-tauri/src/lib.rs` | `SettingsView.egress_extra_ca_file`、`set_settings` 新参数(egress JSON 整体重写路径必须带上它,否则保存代理设置会抹掉 CA 配置)、`classify_settings_error` 新分支 |
| 前端 | `Settings.tsx` / `api.ts` / `LanguageProvider.tsx` / `errors.ts` | 输入行、透传、三语 key、兜底文案条目 |

### 遗留项

- ureq 与 reqwest 信任库不一致(webpki vs 系统钥匙串)未统一;若未来 ureq 侧
  开 `platform-verifier` 特性可整体切换,需过 deny 审计。
- 单一 CA 文件(可多张)而非 per-Provider;有真实需求再升级。
- CLI(`apps/cli`)的 config 面没有暴露 `key set` 之外的编辑命令,CA 字段
  暂只能通过桌面设置页或直接编辑 `token-station.json` 配置。
