# Agent 切换后保留版本选择设计

## 问题

同一 Agent 存在多个安装版本时，用户选定一个版本后切换到其他 Agent，再返回原 Agent，版本选择会被清空。“一键接入”因此重新进入不可用状态。

## 目标

在当前 Token Station 进程内按 Agent 保留已选安装路径。用户切换 Agent 卡片后返回，原版本仍保持选中。

## 范围

- 将安装路径选择状态提升到 Agent 页面上层，按 Agent ID 分别保存。
- Agent 页面继续支持独立渲染，未提供上层状态时使用组件内状态。
- 将安装选择入口文案改为“选择版本”。
- 扫描结果不再包含原安装路径时，删除对应选择，避免使用失效路径。

## 非目标

- 不把版本选择写入本地持久化存储。
- 不修改 Agent 的连接流程和路由策略。
- 不改变单安装 Agent 的自动选择行为。

## 安全与数据边界

状态只保存在前端内存中。代码不写入 Agent 配置，也不触发连接或断开操作。重新扫描后只接受当前扫描结果中仍然存在的规范路径。

## 用户可见行为

用户为多安装 Agent 选择版本后，可以切换到其他 Agent。返回原 Agent 时，选择器继续显示原版本，“一键接入”保持可用。原版本被卸载或扫描不到时，界面清除该选择，并要求用户重新选择。

## 可访问性

选择器继续使用现有按钮和列表框语义。选中项继续通过 `aria-selected` 表示，不改变键盘操作方式。

## 实现位置

- `apps/desktop/src/App.tsx`：按 Agent ID 保存并清理安装路径选择。
- `apps/desktop/src/pages/AgentRoutePage.tsx`：支持受控安装路径，同时保留独立测试所需的本地状态。
- `apps/desktop/src/components/InstallationPicker.tsx`：显示“选择版本”。
- 对应测试覆盖跨 Agent 切换后的选择保留。

## 验收标准

1. 多安装 Agent 选定版本后切换到其他 Agent，再返回时仍保持原选择。
2. 返回后“一键接入”仍可使用。
3. 选择器中的原版本仍标记为已选中。
4. 扫描结果删除原路径后，旧选择不会继续生效。
5. Agent 页面测试和桌面前端构建通过。
