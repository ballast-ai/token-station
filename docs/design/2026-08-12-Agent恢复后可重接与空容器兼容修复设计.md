# Agent 恢复后可重接与空容器兼容修复设计

日期：2026-08-12
状态：代码、自动化、7 Agent 生产命令闭环、压力验收、最终 App 重装与只读 UI 复验通过
范围：Desktop Agent Integration 的配置 codec、连接计划、恢复官方配置与回归测试

## 1. 问题

Hermes 已接入 Token Station 后，点击“恢复官方配置并断开”会移除
`model.default`、`model.provider`、`model.base_url`、`model.api_key` 和
`model.api_mode`。当 `model` 下没有其他字段时，lossless YAML 删除器会保留：

```yaml
model:
```

该 YAML 合法，但语义是 `model: null`。再次接入时，Hermes Connector 在生成计划前要求
`model` 是对象，于是拒绝 Token Station 自己留下的配置。界面随后把结构错误归类成配置语法
错误，用户无法完成“接入 → 恢复 → 再接入”的正常生命周期。

这次修复不能只给 Hermes 增加例外。所有内置通用 Connector 都必须满足同一条产品合同：

```text
首次接入 → 恢复官方配置并断开 → 再次接入
```

整个闭环必须可重复执行，不得因为前一次 Token Station 写入或删除留下的空容器而阻断。

## 2. 目标与非目标

目标：

1. 对声明为 owned path 的写入，如果其祖先是精确的空值 `null`，连接计划可把该祖先安全提升为
   空对象后继续写入。
2. YAML 的裸空值、显式 `null`、`~` 和空 flow mapping `{}` 都能安全进入块映射写入；注释、
   相邻字段和未拥有字段保留。
3. 八个内置通用 Connector 统一满足“接入 → 删除受管内容 → 再接入”的生命周期合同：
   Claude Code、Claude Desktop、Codex、Gemini CLI、Hermes、OpenClaw、OpenCode、WorkBuddy。
4. “恢复官方配置并断开”在写盘前执行一次通用重接 dry-run；若删除结果不能再次通过同一个
   Connector 的连接与投影复验，则拒绝该次写入，也不清除 ownership。
5. Hermes 当前真实的 `model:` 配置可由新版 App 直接重新接入，不要求用户手工删 Token Station
   数据或整份恢复旧备份。

非目标：

- 不把字符串、数组、非空 flow mapping、YAML anchor/tag/alias 等不明确结构自动改成对象。
- 不删除空父容器。强制断开没有可依赖的明文基线，递归删除父容器可能误删用户注释或接入后
  新增的未知字段。
- 不改变 Connector 的 owned paths、Agent 协议、路由算法或虚拟 Key 生成规则。
- 不承诺 `force_forget` 精确还原接入前被覆盖的值；精确还原仍由正常快照恢复负责。
- Cursor 使用独立 SQLite 接入且当前没有通用 ownership/断开流程，不套用本次配置文件合同；
  继续由其 SQLite 备份与事务测试覆盖。

## 3. 安全与数据红线

1. 只允许提升 declared owned path 的严格祖先；不允许借兼容逻辑扩大 Connector 所有权。
2. 只有语义为 `null` 的祖先可以提升为空对象。已有对象保持原样；字符串、数字、布尔、数组和
   非空歧义结构继续 fail closed。
3. YAML 只转换可证明安全的空表示：裸值、大小写无关的 `null`、`~` 和 `{}`。不解析或重写
   anchor、tag、alias、merge key、重复键、多文档及非空 flow mapping。
4. 原始配置字节仍作为加密快照事实源。连接前兼容只发生在计划内存副本和最终受控投影中，
   不改变快照内容。
5. 所有写入继续经过 revision 绑定、patch ownership 校验、脱敏 diff、原子替换、写后重解析和
   Connector 自检；任何失败不得回显 API Key 或配置原文。
6. 非 owned 字段、注释、字段顺序和未触碰的标量样式必须保留。兼容处理不得整份序列化 YAML
   或 JSON5。
7. 强制断开重接 dry-run 使用固定的内存占位 Key，不读取或输出真实用户凭据，不发送网络请求。
8. ownership 的 managed revision 必须绑定写盘后的真实字节、权限和 owner；只有三者均未变化时，
   才能把接入前不存在且投影为空的文件删除。仅 owner 变化也视为用户/外部修改并保留文件。
9. companion owned path 若表示“共享集合中的 Token Station 成员”而非整个集合，force-forget
   必须使用 Connector 的动态过滤合同；不得以删除整个 owned path 的方式误删其他成员。Claude
   Desktop `_meta.json.entries` 只允许移除固定 Token Station profile ID。

## 4. 用户可见行为、状态与失败处理

### 4.1 再次接入

当 Agent 配置的 owned ancestor 是空值时，用户点击“一键接入”后仍按现有流程生成计划并立即
应用。成功状态、首次改动摘要和 Agent 路由页面不增加新步骤。

真正不安全的父级类型继续在创建快照和写盘前失败。例如 `model: []`、`env: "manual"` 或
`provider: 1` 不会被自动覆盖；错误必须表示结构不兼容，而不是声称 Token Station 已完成接入。

### 4.2 恢复官方配置并断开

删除受管字段后，后端先在内存中验证结果可被相同 Connector 再次接入。验证成功才逐文件执行
revision-bound 原子替换并清除 ownership；准备期验证失败时不写任何文件，写入期失败时尽力
回滚本次已替换文件并保留 ownership。跨文件无法获得操作系统级单事务原子性；若磁盘或权限
故障叠加回滚失败，仍需依赖加密快照恢复。

为保护注释和无法证明来源的父容器，恢复结果可以保留空对象或 YAML 空父节点。产品合同是
“可安全重接”，不是“强制删除所有空容器”。

### 4.3 响应式、键盘与可访问性

本次不增加或重排 UI 控件，不改变按钮文案、焦点顺序、键盘操作、Toast live region、窗口尺寸
或响应式断点。现有“一键接入”和“恢复官方配置并断开”按钮的可访问名称保持不变。

## 5. 跨格式行为

| 格式 | 涉及 Agent | 空祖先处理 |
|---|---|---|
| JSON | Claude Code、Claude Desktop、OpenCode、WorkBuddy、部分 companion | `null` 可提升为 `{}`；其他类型拒绝 |
| JSON5 | OpenClaw | `null` 可提升为空对象并保留 round-trip trivia |
| TOML | Codex | TOML 无 null；继续保留空表并验证可重接 |
| YAML | Hermes | 裸值、`null`、`~`、`{}` 可转为可写块映射；歧义结构拒绝 |
| dotenv | Gemini CLI | 无嵌套容器；继续按键删除与重写 |

Gemini CLI 和 Claude Desktop 的 companion 文件继续使用持久化的显式格式合同；主配置生命周期
矩阵之外，既有 companion 恢复测试必须继续通过。Gemini `settings.json` 的 `security` 或
`security.auth` 为 `null` 时，也使用同一祖先提升与反向投影合同。

## 6. 公开测试边界与验收标准

测试只通过公开的配置 codec、Connector 和连接计划边界观察行为，不断言私有 helper 调用次数。

1. **YAML codec 边界**：对 `model:`、`model: null`、`model: ~`、`model: {}` 分别执行真实
   owned child 写入，结果必须是对象并保留根注释、行内注释和相邻字段；字符串、数组、非空
   flow mapping、重复键、merge key、多文档继续拒绝。
2. **连接计划边界**：Hermes 的真实故障输入 `model:\nfallback_providers: []` 必须成功生成
   脱敏、可逆且写后可复验的连接计划。
3. **Connector 生命周期矩阵**：八个内置通用 Connector 从最小合法配置执行 connect patch、
   disconnect/force-forget patch、再 connect，第二次投影必须通过 `validate_projected`，且敏感值
   不进入错误或公开摘要。
4. **真实 force-forget 边界**：Hermes 经真实 `AgentCommandState` 接入后执行 force-forget，
   ownership 被清除、未知字段保留，随后可再次生成连接计划。
5. **companion 回归**：Gemini CLI 与 Claude Desktop 的 companion 格式、未知字段和恢复行为
   继续通过。
6. 现有非法结构、跨 owned path、重复键、merge key、多文档、revision 冲突、写后自检和回滚
   测试全部继续通过。
7. **生产命令闭环矩阵**：在隔离临时目录中，Claude Code、Claude Desktop、Gemini CLI、
   Hermes、OpenClaw、OpenCode、WorkBuddy 必须经过真实 `AgentCommandState` 计划/确认、
   `TransactionEngine` 写盘、force-forget、再次计划并再次写盘；最后清理 ownership。Codex 因
   用户当前正在使用，明确不纳入本机真实操作；隔离测试虽无副作用，本次新增矩阵也按用户要求
   排除。Cursor 没有通用可逆断开合同，继续排除。
8. **显式压力入口**：上述 7 个生产命令闭环支持重复多轮运行，并增加同一目标多计划并发竞争
   测试；任何一轮只能有一个提交成功，其余必须由 revision/ownership 边界拒绝，且配置始终
   可解析、敏感值不进入错误。该入口默认忽略，发布验收时显式执行并记录轮数、耗时与结果，
   不把普通测试并行执行误称为压力测试。

公开验收命令至少包含定向 Rust 测试、Desktop Rust 全量测试、前端全量测试、TypeScript 构建、
workspace 全量测试/构建、格式检查、Clippy 和 `git diff --check`。

## 8. 实现与自动化验收结果

已实现：

1. 配置 codec 对 JSON、JSON5、YAML 的 owned null ancestor 做受限提升，并把结构性反向操作
   纳入公开计划；TOML、dotenv 保持原有严格语义。
2. 主文件和 companion 都在计划阶段执行同一可写准备；Gemini 的 null companion 已由真实
   `build_connection_plan` 回归覆盖。
3. force-forget 先完成全部文件投影与同 Connector 重接 dry-run，再执行 revision-bound 写入；
   写入失败按写后 revision 做尽力回滚，WorkBuddy 主配置和 Claude Desktop companion 的动态数组
   patch 都与各自同一次源读取绑定。
4. 正常连接事务在写后保存包含真实 owner 的 full revision；接入前不存在的文件仅在完整
   revision 未漂移时恢复为不存在，owner-only 漂移不会触发删除。
5. 连接竞态中未获胜且未替换目标的事务会取消固定它刚创建的主文件和
   companion 快照，不会因 CAS/ownership 拒绝留下永久 pinned 快照。
6. 快照从 pinned 转为 unpinned 时立即重新执行每 Agent/每目标保留策略，长期重复
   接入/断开后也严格保留最新 5 份未固定快照。
7. 写后校验失败需要恢复配置时，事务先从仍为 pinned 的基线快照恢复全部已写文件，再解除
   固定并执行保留策略；避免恢复读快照前被裁剪成 `RepairRequired`。

## 10. 已知遗留项

- force-forget 仍是无基线的应急恢复，不会还原被覆盖的原值；UI 的“恢复官方配置”语义后续可
  单独评估是否应重新优先使用加密快照。
- 当前 YAML lossless patch 只支持受控的两段标量路径。未来 Agent 若需要更深 YAML 或复杂
  collection，必须新增版本化 codec/Connector 合同，不能复用本次空容器兼容绕过。
- Cursor 若未来加入通用断开能力，必须先建立 ownership、备份和独立生命周期测试，再纳入矩阵。
