# Cursor 公网隧道一键接入修复设计

日期：2026-08-13
状态：实现完成，真实重新接入已通过

## 1. 问题与事实基线

Token Station 当前把 `http://127.0.0.1:8787/agents/cursor/v1` 和虚拟 Key 直接写入
Cursor 的 `state.vscdb`。这条路径有三个已经实测的缺陷：

1. Cursor 3.15.19 使用 Electron `safeStorage` 读取
   `secret://cursorAuth/openAIKey`。Token Station 写入明文后，Cursor 启动日志报告解密
   失败并丢弃该 Key。
2. Cursor 原生 Agent 的 BYOK 请求经过 Cursor 云端。云端拒绝 localhost 和私网地址，
   返回 `Access to private networks is forbidden`，请求不会抵达 Token Station。
3. Cursor 没有通用 Connector 或 ownership。后端写完 SQLite 后，前端只能弹成功 Toast，
   `managed` 仍为 false，所以按钮不会切换为“恢复官方配置”。
4. cloudflared 启动日志同时包含 `https://api.trycloudflare.com`。旧解析器把该 Cloudflare
   API 主机误当成了随机 Quick Tunnel 地址，导致 Cursor 收到 HTTP 405，请求没有进入
   Token Station。Token Station 重启后，界面只提供恢复按钮，用户无法直接重建隧道。

2026-08-13 的真实验证证明下面的链路可用：

```text
Cursor Agent
  -> Cursor 云端
  -> 随机 HTTPS Quick Tunnel
  -> 仅允许 Cursor 路径的本地桥接
  -> Token Station /agents/cursor/v1
  -> wec/glm-5.2
```

Cursor 使用 `zai-org/GLM-5.2` 发送带 20 个工具定义的真实 Agent 请求后，界面返回
`CURSOR_TUNNEL_OK`。Token Station 请求库新增 `agent_id=cursor`、HTTP 200、
`openai-chat-completions`、`wec/glm-5.2`、`attempts=1` 的回执。因此公网隧道已经通过
真实 Agent 门禁，不是普通 curl 或模型列表探针。

## 2. 目标、范围与非目标

### 2.1 目标

- Cursor 一键接入时建立可供 Cursor 云端访问的 HTTPS 地址。
- 公网入口只接受 Cursor 专用临时令牌，只允许 Cursor models、Chat Completions 和
  Responses 路径。Token Station 全局虚拟 Key不离开本机桥接。
- 使用 Cursor `safeStorage` 兼容密文保存临时令牌，不向 SQLite 写明文 Key。
- 接入成功后按钮切换为“恢复官方配置”。恢复动作停止隧道并恢复接入前的完整 Cursor
  设置。
- 成功定义包含公网鉴权探针和真实 Cursor Agent 回执。SQLite 回读不能单独构成成功。
- Quick Tunnel 地址解析必须拒绝 `api.trycloudflare.com` 等 Cloudflare 保留主机。
- 上次隧道失效时同时提供“重新接入并启动”和“恢复官方配置并断开”。重新接入继续要求
  Cursor 已完全退出。

### 2.2 范围

- macOS Cursor 3.15 的专用配置、隧道和恢复生命周期。
- Cursor 专用 Tauri 命令与前端状态。
- 官方 `cloudflared` 的固定版本下载、SHA-256 校验和私有缓存。
- Cursor 路由的本地路径白名单与临时令牌。

### 2.3 非目标

- 不修改 Codex、Claude、OpenCode、WorkBuddy 或其他 Agent 的发现、Connector、路由和
  ownership。
- 不把 Token Station 的 8787 端口直接暴露到公网。
- 不把 Quick Tunnel 描述为有 SLA 的生产网络。Cloudflare 官方将其定位为开发和测试
  功能。稳定域名和 SLA 需要后续设计命名隧道或 Token Station 托管中继。
- 本轮不实现 Windows/Linux Safe Storage 和 cloudflared 资产矩阵。非 macOS 平台继续
  返回明确的不支持错误。

## 3. 安全与数据红线

1. 每次连接生成新的 256 位 Cursor 临时令牌。公网桥接只接受该令牌，不能接受 Token
   Station 全局虚拟 Key。
2. 桥接在恒定时间比较临时令牌，验证通过后才在本机内存中注入全局虚拟 Key。日志只记录
   方法、路径和状态，不记录 Header、Key、请求正文或响应正文。
3. 桥接只允许：
   - `GET /agents/cursor/v1/models`
   - `POST /agents/cursor/v1/chat/completions`
   - `POST /agents/cursor/v1/responses`
4. cloudflared 只连接桥接的随机 loopback 端口，不能连接 8787。桥接和隧道任一失败时，
   都必须停止已启动的另一半。
5. cloudflared 使用固定官方版本和固定 SHA-256。摘要不一致时禁止解压或执行。
6. Cursor Key使用登录 Keychain 中的 `Cursor Safe Storage` 主密码，按 macOS Chromium
   OSCrypt 的 `PBKDF2-HMAC-SHA1(1003) + AES-128-CBC + v10` 格式加密。Keychain 读取失败
   时禁止降级为明文。
7. 接入前完整备份 `applicationUser` 和原加密 Key。恢复保留备份文件，只恢复原值和清理
   Token Station 自己的活动状态。
8. Token Station 显式退出或隧道异常退出时立即撤销公网入口。失效的 Cursor Base URL
   不能继续显示“已接入”。

## 4. 用户可见状态与交互

### 4.1 未接入

- 状态显示“可接入”。
- 主按钮显示“一键接入”。
- 点击后若 Cursor 正在运行，继续提示用户自行退出。Token Station 不强制关闭 Cursor。

### 4.2 正在接入

- 按钮禁用并显示进行中状态。
- 顺序固定为：启动本地桥接、准备 cloudflared、建立 HTTPS 隧道、验证公网鉴权、备份并
  写入 Cursor Safe Storage、记录活动状态。
- 任一步失败时停止桥接和隧道。Cursor 写入已经开始时恢复原配置。

### 4.3 已接入

- 状态显示“已接入”，详情说明 Cursor 请求通过 Token Station。
- 主按钮显示“恢复官方配置”。
- 接入成功 Toast 显示 HTTPS 隧道已经建立，并提示启动 Cursor 后选择
  `tokenstation/auto`。

### 4.4 恢复官方配置

- Cursor 正在运行时拒绝恢复，提示用户退出 Cursor。
- 停止 cloudflared 和本地桥接，恢复完整 `applicationUser` 与原加密 Key，清除活动状态。
- 恢复失败时保留活动状态和备份，显示可重试错误；不能把按钮提前切回“一键接入”。

### 4.5 失效与重启

- 本轮 Quick Tunnel URL 随进程变化。Token Station 重启后不能把磁盘状态冒充为活动隧道。
- 如果发现上次接入记录但当前没有隧道，状态显示“需修复”。主按钮显示“重新接入并启动”，
  并保留“恢复官方配置并断开”按钮。
- 重新接入沿用最初保存的官方配置备份，只替换 Token Station 管理的隧道地址和临时密钥。
  Cursor 正在运行时继续拒绝改写。

## 5. 响应式、键盘与可访问性

- 不新增页面或弹窗，沿用现有 Agent 路由页响应式布局和焦点顺序。
- 状态不能只用颜色表示。`可接入`、`已接入`、`需修复` 必须有文字。
- 忙碌状态禁用重复操作，Toast 使用现有 live region。
- “恢复官方配置”保持现有按钮语义，可用键盘触发。

## 6. 公开测试边界与验收标准

### 6.1 桥接

- 临时令牌访问允许路径成功。
- 全局虚拟 Key、错误令牌和无令牌都返回 401。
- 未列入白名单的路径返回 404，不能到达 8787。
- 请求与响应支持 OpenAI 流式传输，断开后释放连接。

### 6.2 cloudflared

- 固定资产摘要通过后才可执行。
- 摘要不一致、下载中断、URL 解析超时和进程提前退出都关闭桥接。
- 只接受随机分配的 `https://*.trycloudflare.com`，明确拒绝
  `https://api.trycloudflare.com` 和日志中的其他 URL。

### 6.3 Cursor Safe Storage

- 固定主密码和明文夹具产生可由参考算法解密的 `v10` Buffer JSON。
- 数据库中不出现临时令牌明文。
- 连接写入 Base URL、`useOpenAIKey=true`、加密 Key 和 `tokenstation/auto`。
- 恢复精确还原原始 `applicationUser` 与原加密 Key。

### 6.4 前端

- Cursor 活动状态为 true 时显示“恢复官方配置”。
- 未接入时显示“一键接入”。
- 残留记录但无活动隧道时显示“需修复”，不能显示“已接入”。此状态必须同时提供重新接入
  和恢复官方配置两个动作。
- 其他 Agent 的现有用例不得变化。

### 6.5 真实 App

1. 执行 `scripts/install-local-desktop.sh`。
2. 完全退出 Cursor 后点击一键接入。
3. 启动 Cursor，确认 Key 和 Base URL 跨启动保留。
4. 选择 `tokenstation/auto`，发送包含工具定义的 Agent 请求。
5. Cursor 得到有效回复，Token Station 请求库新增 `agent_id=cursor` 且状态 200。
6. 退出 Cursor，点击“恢复官方配置”，确认官方 Base URL 和原 Key恢复。
7. 确认 cloudflared、桥接端口和公网地址全部失效。

- 原 `configure_cursor_database` 明文写入路径删除或改为只接受已经加密的 Secret。

## 8. 已知遗留项与发布要求

- Quick Tunnel 没有 SLA，URL 每次变化。它适合先恢复 Cursor 原生 Agent 可用性，不能作为
  长期稳定企业方案。后续应评估命名 Cloudflare Tunnel 或 Token Station 托管 Cursor Relay。
- Cursor 子 Agent 可能不继承自定义 Base URL，这是 Cursor 当前公开缺陷。本轮验收只覆盖
  主 Agent；界面不能承诺子 Agent 可用。
- Cursor 可能主动关闭 BYOK 开关。活动状态扫描必须发现该漂移并显示“需修复”。自动改写
  运行中 Cursor 留待扩展辅助方案，当前不能后台反复写 SQLite。
- 发布前必须完成全量测试、桌面构建、本地安装和真实 Cursor 回执验收。实现只允许修改本
  文列出的 Cursor 文件与必要的 Cursor 专用接线。
