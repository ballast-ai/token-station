每个逻辑名称（例如 claude-sonnet-4-5）都会路由到一个或多个通道。一个通道只是指定一个已注册的模型——网关会根据该模型推导出提供商，并为每个请求从该提供商的凭证池中选取一个凭证（按提供商的 credential_strategy 排序：round_robin 按凭证权重分摊，failover 按权重从高到低遍历）。当有多个通道符合条件时，由策略决定选取哪个通道；遇到上游瞬时错误（5xx、408 Request Timeout、429 Too Many Requests、401 凭证被拒）时，故障转移会按优先级顺序走到下一个通道，并优先轮换该提供商的各个凭证。

同一组内的各通道可以指向不同的上游模型，甚至不同的提供商——例如，一个 Anthropic 直连作为主通道、一个 AWS Bedrock 作为故障转移、一个 Claude Code 订阅作为第三通道，三者共同服务于同一个逻辑名称。运行时会为每次尝试修补请求体中的 model 字段，使每个上游都收到正确的线路模型 id。同一组内的所有通道必须共享相同的出站线路形态（Anthropic Messages、OpenAI Chat、OpenAI Responses 或 Gemini-native）——不支持传输途中的请求体转换；如需另一种形态，请新建一个独立的组。
