# Agent 预算预警设计

> 日期：2026-07-22
> 状态：已实现并通过专项验收
> 范围：`apps/cli` 的预算/统计契约、Desktop IPC、用量页预算配置与提示
> 核心边界：第一版只观察和提示，任何预算状态都不得参与准入、路由、重试或 Provider 选择

## 1. 背景

Token Station 已把每次请求的 Agent、用量、成本、`cost_kind` 和 `price_version` 固化到本地 Receipt，但此前缺少面向 Agent 的预算配置与阈值提示。用户能看到历史请求，却不能回答“某个 Agent 当前周期用了多少、是否接近额度、何时到期”。

第二批任务 #8 要求补齐 per-Agent 预算和到期/额度告警，并复用既有版本化价格与 Receipt；第一版必须是展示型能力，接近或超额都不能阻断请求。

## 2. 目标

1. 为任意合法 Agent ID 保存独立预算上限、预警百分比、可选统计周期和到期预警天数。
2. 从已落库 Receipt 聚合每个 Agent 在预算周期内的历史成本，不回算、不改写历史价格。
3. 明确区分健康、接近、超额和含未知价格四种用量状态，以及未设周期、有效、即将到期、已到期四种期限状态。
4. 在 Desktop 用量页提供预算设置、删除、黄条/徽章和按 Agent 聚合入口。
5. 通过结构与真实代理集成测试证明所有预算状态都是 `observe_only`，且 `routing_affected=false`。

## 3. 非目标

- 不拒绝、暂停或降级任何请求。
- 不改变路由、fallback、重试次数或 Provider 选择。
- 不自动续期、重置预算周期或调用订阅平台 API。
- 不把未知价格当作零成本。
- 不修改旧 Receipt 的 `cost_micros` 或 `price_version`。
- 不在本阶段实现价格编辑器；该能力属于任务 #9。

## 4. 数据与状态契约

### 4.1 配置

`ClientConfig.agent_budgets` 是以 Agent ID 为键的映射，每项包含：

| 字段 | 语义 | 校验 |
|---|---|---|
| `limit_micros` | 预算上限，单位为微单位 | `1..=9_000_000_000_000_000` |
| `warning_percent` | 接近预算的阈值 | `1..=100`，默认 80 |
| `period_start_ms` | 统计周期开始 | 可空 |
| `period_end_ms` | 统计周期结束 | 可空；与开始同时存在时必须更晚 |
| `expiry_warning_days` | 到期前多少天提示 | `0..=365`，默认 7 |

Desktop 写命令只接受 Registry 中 `admission=supported` 的 Agent；CLI 配置层允许语法合法的未来 Agent ID，以保留 Registry 扩展性。

### 4.2 Receipt 聚合

- 聚合按 `requests.agent_id` 分组，只读取本地 SQLite 元数据，不读取 prompt 或 response。
- 固定周期采用半开区间 `[period_start_ms, period_end_ms)`，避免周期结束后的新请求污染旧周期。
- 成本直接求和 Receipt 已保存的 `cost_micros`。旧请求继续绑定其原 `price_version`，预算读取不会触发重算。
- `cost_micros IS NULL` 单独计入 `unpriced_requests`；只要尚未确定超额且存在未知价格，请求状态为 `unknown`，界面说明用量不完整。
- `priced_requests` 和 `unpriced_requests` 同时进入用量聚合视图，成本透明度可被用户核对。

### 4.3 用量与期限状态

| 状态 | 条件 | 展示 |
|---|---|---|
| `healthy` | 已知用量低于阈值且无未知价格 | 普通信息条 |
| `approaching` | 已知用量达到预警百分比但未到上限 | 黄色提示 |
| `exceeded` | 已知用量达到或超过上限 | 超额提示；仍不阻断 |
| `unknown` | 未确定超额且存在未定价请求 | 黄色“不完整”提示 |

期限状态为 `none / active / expiring / expired`。`expiring` 和 `expired` 均追加期限提示，但不改变用量状态，也不产生执行权限。

所有返回状态固定包含：

```json
{
  "enforcement": "observe_only",
  "routing_affected": false
}
```

## 5. 接口与界面

Desktop 提供三个命名参数 IPC：

- `get_agent_budgets`
- `set_agent_budget(agentId, limitMicros, warningPercent, periodStartMs, periodEndMs, expiryWarningDays)`
- `remove_agent_budget(agentId)`

设置和删除均经过完整 `ClientConfig` 校验并原子保存；保存失败必须返回错误，前端不得显示“已保存”。

用量页新增：

- “按 Agent”聚合维度；
- 只列可写支持 Agent 的预算选择器；
- 金额、阈值、周期、到期预警配置；
- 健康/接近/超额/未知价格/到期状态条；
- 固定的“仅提醒 · 不影响路由”徽章；
- 已定价与未定价请求计数。

## 7. 退出条件

### 7.1 成功退出

仅当第 8 节全部通过、专项设计与验收证据已保存，且没有预算影响路由的代码路径时，#8 才可标记完成并进入 #9。

### 7.2 暂停退出

出现以下任一情况时暂停并报告最小阻塞：

- Receipt 缺少稳定 Agent 或成本字段，无法做可信聚合；
- 配置无法原子持久化；
- 必需测试环境不可用，且 fixture 不能替代结论；
- 发现旧价格会被预算读取或编辑流程回算。

### 7.3 失败退出

发现预算状态会拒绝请求、改变路由/重试/Provider，或未知价格被静默计为零时，立即停止扩大改动，保留复现证据并修复红线后重新验收。

## 8. 通过条件

- 能为某个支持的 Agent 设置、读取、修改和删除预算，重载配置后仍存在。
- 健康、接近、超额、未知价格、即将到期和已到期状态可由确定输入复现。
- 固定周期只统计 `[start, end)` 内的 Receipt。
- 预算成本来自 Receipt 已保存的版本化价格，不改写旧请求。
- 接近和超额在界面有明确提示，且固定显示“仅提醒，不影响路由”。
- 超额预算下的真实代理请求仍返回成功并命中上游。
- CLI、Desktop Rust、Vitest、TypeScript/Vite、clippy、fmt 和 diff check 全绿。
