# 模型目录读取失败误报本地文件

- 日期：2026-08-14
- 状态：已实现；测试、构建、本地安装通过；真实 Key 重试由用户执行
- 范围：Desktop 错误归类与模型目录刷新失败提示

## 1. 问题、目标、范围和非目标

用户在添加供应商时刷新模型目录，DeepSeek 的 401/403 错误原文包含“读取模型目录的权限”，
界面因匹配到“权限”二字而将它归类为“无法访问所需的本地文件”，导致用户错误排查磁盘。
底层网络/响应读取错误中的 `failed to read` 也存在同类误分类风险。

目标：模型目录请求或响应读取失败必须展示供应商目录获取失败提示；只有明确的本地文件读写、
权限或只读错误才能展示本地文件提示。

范围仅包含错误分类顺序与匹配边界，以及对应公开行为测试。不修改模型目录网络请求、缓存格式、
供应商协议或重试策略。

## 2. 安全与数据红线

1. 用户提示不得暴露 API Key、响应正文、本机路径或底层库错误详情。
2. 不因错误归类变化而自动重试、保存凭据或改变供应商配置。
3. 不放宽模型目录响应大小、重定向、鉴权或跨主机凭据转发限制。

## 3. 用户可见交互、状态变化和失败处理

- 模型目录 401/403：明确提示 API Key 无效或账号无权读取模型目录。
- 其他模型目录请求、响应读取、解析或缓存降级失败：保留“获取失败”状态，提示“暂时无法获取最新的供应商数据”。
- 明确的本地配置、数据库或缓存文件权限失败：继续提示检查本地文件权限和磁盘空间。
- 错误仍通过现有 Toast 与原位目录状态展示，不新增交互步骤。

## 4. 响应式、键盘操作和可访问性

不改变布局、焦点、键盘操作和 ARIA 结构。修复后的提示继续由现有可关闭 Toast 和目录状态区域
播报，保持当前响应式行为。

## 5. 公开测试边界、验收标准和真实 App 检查项

公开行为测试覆盖：

1. 包含“读取模型目录失败”且底层含 `failed to read` 的错误必须归类为供应商目录失败。
2. 后端 401/403 原文“Key 无效，或当前账号没有读取模型目录的权限”必须显示 Key/账号权限提示。
3. 明确的 `permission denied` 本地文件错误仍归类为本地文件失败。
4. 中英文提示均符合现有脱敏文案。

验收标准：定向测试、Desktop 全量测试与构建通过；安装本地 App 后，在真实添加供应商界面刷新
模型目录，失败时不再误报本地文件权限。

## 6. 实现落点与已知遗留项

- `apps/desktop/src/errors.ts`：收窄或调整错误指导匹配优先级。
- `apps/desktop/src/errors.test.ts`：增加模型目录响应读取失败回归测试。

已知遗留：前端当前只展示脱敏文案，无法从 UI 直接查看原始错误；本次不新增诊断日志入口。

## 7. 发布要求

该改动影响用户可见错误提示。完成测试与构建后必须运行 `scripts/install-local-desktop.sh`，
在本地 App 真实验收并回写本文状态、结果与遗留项，最后使用规定 Git 身份和中文提交说明创建
本地 commit。

## 8. 实现与验收结果

- 已将模型目录 401/403 与本地文件权限错误分开，提示 API Key 无效或账号目录权限不足。
- `errors.test.ts` 18/18、Desktop 全量 379/379、生产构建、Rust workspace 全量测试通过。
- `scripts/install-local-desktop.sh` 构建、审计、签名校验、安装与启动通过。
- 未代替用户再次发送 API Key；最终真实刷新结果需用户自行点击验证。
