# Token Station 应用图标设计

## 问题、目标与范围

现有图标由黄、蓝两段环形和两个圆点构成，能表达循环与流动，但在 Dock、侧栏和 32px 小图标里容易被读成同步、阴阳或通用连接图形。新图标要让人先看到一个干净、可靠的开发者工具标记，再从中央分流关系读出“本机路由站”：请求进入 Token Station，由本机规则切换到不同模型上游。

本轮只产出可复用的 SVG、PNG 源资产和验证证据，不替换 Tauri 正在使用的图标，不生成或声称已经完成平台原生打包，也不改变产品界面、状态模型、前后端契约或发布行为。

非目标包括：照抄 Claude、Codex、Gemini 等第三方标志；在图标中加入 `TS`、终端提示符、模型名称或可读文字；用复杂窗口、网络节点图或发光材质解释全部产品能力。

## 安全与数据红线

图标不得暗示请求被上传到 Token Station 托管云。视觉隐喻必须符合产品事实：路由决策发生在本机，云端请求只发往用户配置的上游。不得使用第三方商标轮廓、模型 Logo 拼贴或来源不明的公开 SVG 作为交付资产。

用户给出的 Agent 列表截图只作为“小尺寸、强轮廓、少细节”的风格证据；现有项目图标只作为品牌历史与配色参考，不直接嵌入生成包。

## 用户可见设计与失败处理

主方向采用 `black-stage-mark`：近黑蓝底色承接当前深色控制台气质；中央是一枚奶白色圆角菱形站台牌，深色对角通道从左下贯穿到右上；一个电蓝圆形 token 位于入口，一个琥珀圆角方形 token 位于出口，保留现有蓝黄品牌记忆。图标不使用文字、描边、阴影、辉光、玻璃高光、细小电路线或真实透明孔洞。

中央标记必须在 64px 清晰，在 32px 仍能读出一个入口和两个方向的切换关系。如果生成概念出现 Git 分支图标、分享按钮、Wi-Fi、同步箭头、地铁地图或三节点拱门的既视感，就回到语义层重画，而不是用更多装饰掩盖问题。

## 响应式、键盘与可访问性

图标本身没有键盘交互。前景与背景使用高亮度反差，关键信息不只依赖蓝黄颜色区分；即使转为灰度，轨道轮廓和分流关系也必须成立。验收覆盖 1024px、64px 和 32px 视觉检查，并检查圆角预览与未圆角源画布。

## 公开测试边界与验收标准

交付目录必须包含 `.preview.svg`、`.preview.png`、`.svg`、`.png`、语义分层源文件、当前 `spec.json` 和验证报告。生成概念存在时保留一份 `.origin.png` 作为来源证据，但不得把整张生成图当作唯一源层。

验收标准：

1. 轮廓在 64px 与 32px 不糊成圆环、字母或节点网。
2. 不出现文字、水印、第三方品牌标记、阴影、辉光、材质噪声或细小 UI。
3. 前景由少量语义明确的 SVG 层构成，背景与前景可独立复用。
4. `author-icon` 与 `verify` 通过，SVG 材质警告和包级警告为空。
5. 在浅色 Finder/Dock 背景与深色产品界面旁观察，图标仍有清楚边界。

真实 App 检查不属于本轮，因为本轮不替换 `apps/desktop/src-tauri/icons/`。若用户确认采用，再单独完成 Tauri 图标集替换、`scripts/install-local-desktop.sh`、Finder/Dock/应用切换器检查和发布记录。

## 实现落点、遗留项与发布要求

源资产写入 `apps/desktop/branding/token-station-icon/`，该目录是本轮唯一生成根。生成过程的候选、设计 JSON、遮罩和比较图全部留在其 `tmp/work/` 下。

本轮遗留项是用户对最终方向的主观确认，以及后续平台原生导出和 App 集成。只有确认采用后，才允许改动现有 Tauri 图标、更新本机桌面 App 并创建发布相关提交。

## 实现与验收状态

- 状态：通用 SVG/PNG 源资产已经生成并通过验证；尚未替换正在使用的 App 图标。
- 联网研究结论：同类开发者工具最有效的图标普遍依赖一个直接隐喻、强轮廓和小尺寸专门校验；堆叠终端窗口、文字和复杂节点虽然解释得更多，但辨识度更差。
- 最终资产：`apps/desktop/branding/token-station-icon/` 下的 SVG、PNG、圆角预览、五个语义 SVG 层、生成概念来源图、规范和验证报告。
- 验证结果：`author-icon` 与 `verify` 通过，`route_status` 为 `generic_assets_ready`，警告和失败均为空。已人工检查 1024px、64px 和 32px 预览；小尺寸仍能分辨白色站台、蓝色入口 token 与琥珀出口 token。
- 遗留项：等待用户确认是否采用；确认后再生成平台原生图标集、替换 Tauri 资产、安装本机 App 并完成 Finder、Dock 和应用切换器验收。

## 暖白底岔路与车站候选探索

用户进一步明确图标应围绕两种同源视觉：一是输入和输出顺序不同的分岔/重排，例如 `1→b、2→a、3→d、4→c`；二是火车站咽喉区，多条轨道和站台被中央的大站房或雨棚统一组织。新一轮不使用图像生成，直接绘制三枚可编辑 SVG 候选，以便先比较轮廓和隐喻。

三枚候选统一采用暖白背景、近黑主体、琥珀色选中线路和少量电蓝信号。候选分别强调：中央大架子遮住复杂调度、裸露的编组场分岔、以及将线路重新排序的站台交换矩阵。所有线路使用填充路径而非细描边，不画枕木、列车、站名、数字、箭头、节点网络或透视场景。

本轮只新增独立候选源资产，不覆盖上一版探索，不替换 Tauri 图标，也不安装桌面 App。验收重点是 1024px、64px 和 32px 下的轮廓差异，以及 SVG 分层、材质警告和包级警告。

三枚候选均已生成通用 SVG/PNG 源资产并通过 `verify`，警告和失败为空。1024px、64px 和 32px 检查后的判断是：`01-gantry-yard` 最像真实车站但细节最多；`02-switch-fan` 的小尺寸轮廓最强，也最直接表达输入输出重排；`03-platform-matrix` 最像交换矩阵，但存在被读成芯片或路由器的风险。三者都保留为待用户选择的概念，不进入平台原生导出和 App 集成。

根据“必须同时表达路由中转站并保持简洁”的反馈，新增 `04-route-station` 收敛方向：只保留两条输入输出顺序互换的粗线路、一座覆盖调度区的中央站房拱架，以及一个蓝色入口信号。琥珀色线路从较低入口穿过站房后由较高出口离开；另一条近黑线路反向交叉。中央站房负责把裸露分岔变成“中转站”，两条线路的限制负责避免第一版站房候选的视觉拥挤。

`04-route-station` 已通过通用资产验证，警告和失败为空。1024px、64px 和 32px 检查确认中央站房、琥珀色穿站线路和反向近黑线路都能保留；相比前三版，它同时具备明确中转建筑、输入输出换位和较低元素数量。当前仍是候选，不替换 App 图标。

## ImageGen 结构保持探索

在用户明确要求调用图像生成后，以 `04-route-station.preview.png` 作为构图参考进行一次非破坏性概念生成。输入图是参考图，不是需要逐像素修改的正式源资产。生成必须保留暖白背景、两条线路在中央站体内交换上下顺序、琥珀色主线路由左下进入并由右上离开、中央站体明显覆盖调度区，以及不使用文字和第三方标志。

ImageGen 只允许探索站体比例、建筑辨识度、线路曲率和整体留白，不得增加轨道数量、列车、枕木、站名、箭头、网络节点、透视场景、阴影、玻璃、辉光或复杂材质。生成结果保存为独立概念证据，不覆盖任何 SVG，也不直接进入 App 图标集；只有用户选择后才重建为语义 SVG。

ImageGen 第一轮结果保存为 `04-route-station/tmp/work/imagegen-station-v1.png`。它保留了两条线路的上下换位，并通过屋顶和三跨站厅显著增强了“火车站”辨识度；但同时引入了不需要的柔和渐变、阴影和较具体的建筑细节。该图只作为下一轮 SVG 收敛参考，不能直接作为正式图标或 PNG 前景层。若采用这一方向，应保留屋顶/站厅的建筑暗示，把三跨缩减为一至两跨，并恢复纯色语义层。
