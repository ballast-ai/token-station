# PR #84 合并阻断修复设计

## 问题、目标、范围和非目标

PR #84 的最终复审发现五类合并阻断：Codex/Hermes 在模型元数据未知时可能删除用户原有限制；WorkBuddy 顶层数组 ownership 将用户后来添加的非受管模型误判为漂移；诊断正文脱敏可被分号或换行绕过；Gateway 仍可能发布部分价格并遮蔽完整配置价格；Agent 元数据聚合把能力、价格与 limits 整体门控，任一候选缺少 limit 时会丢弃已验证的 vision/tool/reasoning/price。

本次目标是在不扩大 PR 功能范围的前提下修复上述问题，并补齐公开行为回归。范围仅包含 Agent 配置生命周期、诊断持久化/预览和 Agent 模型目录价格投影。非目标包括新增 Agent、改变路由算法、创建 DMG 或重构无关模块。

## 安全与数据红线

1. metadata unknown 不得删除首次接入前由用户提供的限制字段；只允许移除上一 revision 确由 Token Station 写入并通过 HMAC 验证的 stale 值。
2. WorkBuddy ownership 必须绑定 `tokenstation-auto` 的完整受管值，但不得把其他模型或 `availableModels` 中的其他成员纳入受管范围。
3. 诊断不得持久化或展示请求正文、prompt、content、input、工具参数或搜索词；分号、换行和嵌套 JSON 不能绕过脱敏。
4. 只有同时具有有效 input/output 的完整价格才能发布或遮蔽配置价格；部分价格视为 unknown。
5. limits、能力与价格必须独立聚合；不完整 limits 不得产生零值或猜测值，也不得清除独立验证的能力与价格。
6. 不读取、打印或提交真实凭据；测试只使用显式虚构标记。

## 用户可见行为、状态和失败处理

- Codex/Hermes：首次接入时若 metadata unknown，保留用户限制；之后 metadata 仍 unknown 时继续保留。由 Token Station 写入的限制在后续变为 unknown 时才安全移除。
- WorkBuddy：用户接入后新增或修改非 `tokenstation-auto` 模型，refresh/disconnect 仍可执行并保留该模型；修改受管模型仍返回 `owned_values_changed` 且不写磁盘。
- 诊断：敏感内容整体显示为 `[REDACTED]`，失败时宁可多隐藏正文，不回退为原文。
- `/agents/<agent>/v1/models`：部分 catalog cost 不出现，并允许回退到完整配置价格。
- Agent 原生配置：limits 不完整时不写 limit 字段，但继续投影统一且已验证的 vision/tool/reasoning/price。

## 响应式、键盘和可访问性

本次不改变布局、焦点顺序、快捷键或交互控件。诊断预览仍使用现有可复制文本区域；仅减少敏感正文，不改变可访问名称与键盘行为。

## 公开测试边界与验收标准

1. Agent 配置生命周期：通过 connector/transaction 公共行为覆盖 connect → refresh → disconnect。
2. 诊断边界：通过前端 `diagnosticInput`、后端 `record_frontend_diagnostic` 与恢复预览覆盖持久化和展示前的双层脱敏。
3. 模型目录：通过 Gateway `models_for` 覆盖部分价格、完整配置价格和 Agent-scoped 输出。
4. Agent 元数据：覆盖 limits 不完整但能力和价格完整的聚合与各原生配置投影，断言不出现零 limit。
5. 每个修复先出现失败测试，再写最小实现使其通过。
6. 定向测试、workspace/desktop 全量测试、Clippy、前端测试和生产构建必须通过。
7. 执行 `scripts/install-local-desktop.sh`，核验 bundle id、签名、启动健康状态；真实 App 检查 Agent 页面、路由保存和诊断预览无回归。
