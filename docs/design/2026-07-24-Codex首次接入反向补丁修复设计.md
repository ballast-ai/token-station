# Codex 首次接入反向补丁修复设计

日期：2026-07-24
状态：已实现并通过自动化验收
范围：Desktop Agent Integration 的连接计划与结构化配置反向补丁

## 1. 问题

当 `~/.codex/config.toml` 不含 `model_providers.tokenstation` 时，Codex 首次接入会在连接计划阶段失败：

```text
Connector 反向 patch 无法恢复接管前受管字段
```

`codex-v1` 将 `base_url`、`name` 等字段逐项写入 `model_providers.tokenstation`。现有 `apply_patch_with_reverse` 仅为每个叶子字段生成反向 `Remove`。回放后会留下空的 `model_providers.tokenstation` 表，而基线中该受管路径不存在，因此 `verify_reverse_projection` 正确拒绝签发计划。

失败发生于计划构建和写盘事务之前；不得把它解释为 Codex 未安装、网关不可用或用户配置语法无效。

## 2. 目标与非目标

目标：

- 首次创建嵌套受管配置时，反向 patch 将对应新建的最深父路径一并删除，使受管路径恢复为不存在。
- 保留已有父表、已有 provider 中未被 Connector 修改的字段、配置注释和无关路径。
- 修复必须覆盖 `build_connection_plan`，即桌面端“预览接入”的服务端边界。

非目标：

- 不改 Codex Connector 的 owned paths、配置协议或 UI 文案。
- 不降低反向投影校验，也不以跳过 `verify_reverse_projection` 规避错误。
- 不改变实际断开/恢复使用加密快照与 ownership 投影作为事实源的机制。

## 3. 设计

对每个 `Add` / `Replace` 操作，应用前读取目标路径的完整父路径：

1. 若该父路径不存在，说明本操作会创建这条嵌套结构；记录一个反向 `Remove`，路径为该最深父路径。
2. 继续按现有逻辑记录该叶子操作的旧值并应用正向操作。
3. 反向操作整体逆序回放。叶子字段先恢复，随后删除仅因本次投影创建的父路径。

以 Codex 为例，写入 `/model_providers/tokenstation/base_url` 前不存在 `/model_providers/tokenstation`，因此反向链额外包含：

```text
Remove /model_providers/tokenstation
```

此操作只删除 Connector 已声明拥有的 provider 子树；它不删除 `model_providers` 的其他 provider，也不覆盖接入后在无关路径新增的内容。

## 4. 验收

- 对包含 `model = "..."`、但不含 `model_provider` 和 `model_providers.tokenstation` 的 Codex TOML，`build_connection_plan` 成功。
- 计划中的反向投影能将 `/model`、`/model_provider` 和 `/model_providers/tokenstation` 还原至基线语义值。
- 现有跨格式反向补丁、Connector 归属和计划测试继续通过。
- 格式、clippy 与 diff 检查通过。

## 5. 实施顺序

1. 在 `build_connection_plan` 的 Codex 首次接入场景补充失败回归测试。
2. 在 `apply_patch_with_reverse` 中最小化生成父路径清理操作。
3. 运行定向测试、Desktop Rust 测试与静态检查，并更新验收记录。
