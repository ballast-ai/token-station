# 左上角品牌图标与模型选择顺序修复

## 问题、目标、范围和非目标

当前桌面端左上角使用 `lucide` 的 Route 图标，和 Token Station 应用图标不一致。暗色界面也没有使用现有 App icon 的黑白反转版本。

供应商管理中的模型选择器会把已选模型提到列表前面并按首字母排序。用户每点击一次，按钮位置就会变化，连续选择多个模型时很难确认刚才点的是哪一项。

本次目标是：

1. 左上角直接显示现有 `public/icon.png`，和 App icon 使用同一份资产。
2. 暗色模式对同一份 App icon 做黑白反转，并随实际生效主题自动切换。
3. 模型选择器在当前页面生命周期内保持目录顺序。点击勾选或取消勾选只改变选中状态，不改变模型位置。

非目标：不改变模型保存顺序、供应商目录接口、搜索过滤规则和模型去重规则，也不重新设计应用图标本身。

## 安全与数据红线

- 只修改前端展示和选择状态，不读取、写入或迁移 API Key、凭据和供应商配置。
- 不改变模型保存接口传入的 `selected` 顺序。
- 不使用远程图片或外部资源加载品牌图标。

## 用户可见交互、状态变化和失败处理

- 主题为浅色时，左上角加载 `/icon.png`。
- 主题为深色时，左上角继续使用 `/icon.png`，通过 `filter: invert(1)` 反转黑白视觉。
- 系统主题模式下，`ThemeProvider` 的 `resolvedTheme` 变化后，图标立即更新。
- 模型按钮点击后只切换 `aria-pressed`、勾选标记和上层 `selected` 值，其他模型的 DOM 顺序保持不变。
- 模型搜索仍按当前目录顺序显示过滤结果。无匹配时继续显示现有空状态。
- 图标加载失败时保留可见的品牌容器，不影响导航和主题按钮。

## 响应式、键盘和可访问性

- 品牌图标使用带空 `alt` 的装饰性图片，品牌文字继续作为按钮的可访问名称。
- 模型按钮继续使用原生 `button`、`aria-pressed` 和键盘焦点行为。
- 不新增仅依赖颜色的状态表达，已选状态继续保留勾选符号和现有样式。
- 图标尺寸沿用现有 28px 头部布局，不改变窄窗口导航布局。

## 公开测试边界和验收标准

公开测试至少覆盖：

1. `AppShell` 在浅色和深色 `resolvedTheme` 下分别引用对应品牌图标。
2. 模型列表初始顺序保持传入顺序。
3. 点击一个未选模型后，该模型仍在原位置，后续模型不被顶到前面。
4. 点击已选模型取消后，列表顺序仍不变。
5. 搜索过滤和自定义模型入口仍可用。

真实 App 检查项：切换浅色、深色和系统主题，确认左上角图标同步变化；进入供应商管理，连续点击示例模型，确认列表不跳动，再保存并重新进入确认保存逻辑不受影响。
