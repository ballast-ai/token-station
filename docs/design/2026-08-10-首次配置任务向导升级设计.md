# 首次配置聚光灯任务向导设计

- 日期：2026-08-10
- 状态：已实现、安装并完成真实 App 验收
- 前置设计：[`首次进入聚光灯引导设计`](2026-08-10-首次进入聚光灯引导设计.md)
- 正式范围：`apps/desktop`

## 1. 问题

第一版首次引导使用遮罩、聚光灯和教学卡片指出真实界面位置，用户能直观看到“在哪里操作”，但它只讲解
页面，没有带用户完成配置。随后实现的三步任务条接入了供应商、路由和 Agent 的真实完成信号，却把教学
退化成了页面顶部的状态提示：它只说明“要做什么”，没有把“在哪里点、现在配什么”绑定到真实控件。

真实 App 验收已经确认，任务条方案不满足“手把手教学”。本次设计废弃任务条，保留真实完成判定，将两版
的有效部分合并成“聚光灯微步骤 + 真实任务推进”。

依赖顺序保持不变：

```text
添加一个包含模型的供应商
  → 配置、保存并真实应用全局路由
  → 接入一个已检测 Agent，或在未检测到 Agent 时明确跳过
```

## 2. 目标

1. 使用第一版的全屏遮罩、真实控件高亮和锚定教学卡片，让用户知道每一步在哪里操作。
2. 将三个业务阶段拆成多个微步骤；操作型步骤由用户点击真实控件推进，而不是点击通用“下一步”。
3. 供应商只在真实保存成功后进入路由；路由只在目标 revision 真实运行后进入 Agent。
4. Agent 只在重新扫描得到 `CONNECTED` 后完成；没有可管理安装时允许明确跳过。
5. 关闭或 Escape 只暂停；重启或重新查看时从真实 App 状态恢复到第一个未完成业务阶段。
6. 保留用户自由选择供应商、模型、路由模式、安装路径和是否接入，不代替用户作配置决策。

## 3. 范围与非目标

### 3.1 范围

- 将现有三步任务条替换为跨页面聚光灯教学层。
- 为首页入口、供应商选择/配置/保存、路由配置/应用、Agent 选择/安装/接入建立稳定目标。
- 在 `StationApp` 编排业务阶段、微步骤、页面导航、暂停、永久结束和真实完成信号。
- 复用 `AddProviderPage.onAdded`、路由 revision 运行态和 Agent 重扫结果。
- 升级引导版本标记，使见过任务条试制版的用户能够看到新的聚光灯版本。
- 覆盖中英文、浅色/深色、窄窗口、键盘、失败停留、已有配置和无 Agent 分支。

### 3.2 非目标

- 不自动填写或读取 API Key，不自动选择供应商、模型、路由模式或 Agent 安装。
- 不因引导自动发起 Provider 连接/生成测试；这类请求可能访问外网并消耗额度。
- 不因单击“保存并应用”或 Tauri command 返回就认定路由已运行。
- 不因 `applyAgentPlan` 返回就认定 Agent 已接入。
- 不要求已有有效配置的用户重复完成业务操作。
- 不新增 Rust/Tauri command、数据库表、配置字段或网络协议。
- 不为每一种供应商制作独立脚本；可选字段差异通过目标存在性和步骤跳过处理。

## 4. 安全与数据红线

- 引导不读取、展示、复制、记录或传输 API Key、虚拟 Key、提示词、响应正文和请求 body。
- 聚光灯只测量目标元素的边界和可见性，不读取输入框值、选项文本或本地文件内容。
- `localStorage` 只保存引导版本与“已结束”状态，不保存供应商、模型、Agent 路径、revision 或完成时间。
- 凭据继续使用现有 store/env/file 语义；引导层不接触明文凭据。
- Agent 接入继续使用现有计划、确认 token、备份、ownership 与恢复门禁。
- 命令失败时留在当前业务阶段并复用页面错误；不得自动重试任何写操作。
- 暂停、永久结束和跳过 Agent 都不能撤销或伪造真实配置状态。

## 5. 交互模型

### 5.1 教学层

- 教学层由全屏半透明遮罩、透明聚光孔、目标描边和锚定教学卡片组成。
- 遮罩阻止目标外的鼠标操作；高亮目标和教学卡片保持可操作。
- 教学卡片展示业务阶段进度（例如“添加供应商 · 2/5”）、当前动作、完成说明、暂停和不再提示。
- 操作型步骤不显示通用“下一步”；用户点击真实目标或真实操作成功后推进。
- 说明/配置区域没有单一完成事件时，允许使用“配置好了，继续”进入下一个目标，但不能借此完成业务阶段。
- 目标不在视口时先滚动到可见区域，再展示聚光灯；减少动态效果时使用立即滚动。供应商列表在窄窗口
  中高于视口时，先将工作区复位到顶部，为教学卡片保留独立空间，不能把卡片压到供应商卡片上。
- 目标临时不存在时显示同一阶段的等待卡片，不出现落在左上角或覆盖错误控件的高亮框。

### 5.2 阶段一：供应商与模型

| 微步骤 | 聚光灯目标 | 推进条件 |
|---|---|---|
| `provider-entry` | 全局“添加供应商”按钮 | 用户点击真实按钮并进入添加页 |
| `provider-choice` | 供应商选择区域 | 用户选择真实供应商/免费方案 |
| `provider-credential` | 当前表单的凭据区域 | 可选；用户填写后点击教学卡片“下一项” |
| `provider-models` | 当前表单的模型配置区域 | 用户选择模型后点击“去保存” |
| `provider-save` | 当前表单的真实保存按钮 | `onAdded` 返回成功且状态中存在含模型的供应商 |

- 无凭据方案不渲染 `provider-credential` 目标时直接进入模型步骤。
- 如果当前表单把模型与凭据合并在一个区域，允许合并两个说明型微步骤，但保存仍是独立真实目标。
- 保存失败继续高亮保存区域或页面错误附近，不导航、不推进业务阶段。
- 保存成功显示短暂成功说明，自动进入全局路由页。

### 5.3 阶段二：配置并启动路由

| 微步骤 | 聚光灯目标 | 推进条件 |
|---|---|---|
| `route-entry` | 主导航“路由” | 冷启动/重新查看时用户点击真实导航；供应商保存后的自动跳转视为已完成 |
| `route-mode` | 路由模式选择区域 | 用户选择模式，或明确沿用当前模式 |
| `route-config` | 当前模式的主要配置区域 | 用户配置后点击“去应用” |
| `route-apply` | “保存并应用”按钮 | 用户点击真实按钮，并等待权威运行态 |

路由阶段完成必须同时满足：

- 当前引导记录了本次显式保存并应用的目标 revision，或重新查看时真实状态已经有效运行；
- `app_runtime === "running"`；
- `listener_reachable === true`；
- `serve.error === null`；
- `running_revision === saved_revision`，且等于本次目标 revision（存在目标时）；
- `config_dirty === false` 且 `config_error === null`。

command 返回、旧 revision 仍在运行、监听不可达、启动失败或回滚都必须停留在 `route-apply`。真实运行成功后
显示短暂成功说明并自动进入 Agent 页。

### 5.4 阶段三：接入 Agent

Agent 微步骤按扫描结果动态分支：

| 条件 | 聚光灯目标与顺序 |
|---|---|
| 冷启动/重新查看 | 主导航“Agent”；路由成功后的自动跳转视为已完成 |
| 有可管理安装 | Agent 列表 → 可接入 Agent → “一键接入” |
| 同一 Agent 有多份安装 | Agent 列表 → “选择安装” → “一键接入” |
| 正在扫描 | “重新扫描”区域的等待卡片，不提供伪完成 |
| 没有检测到安装 | “重新扫描” → 教学卡片中的“暂不接入，完成设置” |
| 已连接 | 直接进入完成态，不重复写配置 |

- 现有 Agent 接入流程会先生成计划再直接应用，并在首次接入后展示差异卡片；引导只高亮真实“一键接入”，
  不额外制造一个与产品现状不符的确认步骤。
- `applyAgentPlan` 成功只表示写操作完成；必须在后续重扫中看到 Agent 或安装状态为 `CONNECTED` 才完成。
- 检测到但不可接入、安装冲突、版本阻断或 Cursor 正在运行时，继续展示现有页面原因，不提供伪成功跳转。
- “暂不接入”只在一次完整扫描结束且结果确实为空时出现；完成页必须写明 Agent 尚未接入。

### 5.5 完成、暂停、永久结束与重新查看

- Agent 连接成功或无安装时明确跳过后，写入新版本标记并展示完成态。
- 完成态提供“返回概览”，并说明可从“设置 → 关于”重新查看。
- 关闭按钮和 Escape 只暂停当前会话，不写入标记；下次冷启动从真实未完成阶段恢复。
- “不再提示”明确写入标记并结束教学，不撤销已完成配置。
- 关于页重新查看只在当前会话打开教学，不清除持久标记，不导致下次启动再次打扰。

## 6. 状态模型

```text
provider-entry
  → provider-choice
  → provider-credential? → provider-models → provider-save
  → [Provider 保存成功]
route-entry? → route-mode → route-config → route-apply
  → [目标 revision 真实运行]
agent-entry? → agent-select → agent-installation? → agent-connect
  → [重扫 CONNECTED] → complete-connected

agent-scan-empty → explicit-skip → complete-skipped

任一步 --Close / Escape--> paused
任一步 --不再提示--> dismissed
任一写操作失败----------> 保持当前业务阶段
```

- `businessStage` 由 `StateView + scanAgents` 派生，真实配置是阶段恢复的唯一真相。
- `microStep` 是当前会话内的教学状态；冷启动从未完成阶段的入口微步骤开始，不持久化字段级历史。
- 路由推进复用 `pendingApplyRevisionRef` 的目标 revision，拒绝普通启动和迟到轮询误推进。
- Agent 推进观察重扫结果，不观察按钮文案或 `applyAgentPlan` 返回值。
- 教学版本从任务条试制版升级为新的聚光灯版本，避免旧标记屏蔽改版。

## 7. 聚光灯目标与定位约束

- 目标通过稳定、语义化的 `data-onboarding-target` 标识；不能依赖文本、CSS 层级或数组下标定位。
- 页面组件只暴露目标和必要的用户动作通知，不把凭据值、表单 state 或保存实现交给引导层。
- 目标测量监听窗口 resize、滚动、`ResizeObserver` 和页面切换；卸载时清理属性与监听器。
- 目标使用描边/阴影高亮，不复制 DOM，不克隆表单，不生成第二个可点击按钮。
- 教学卡片优先放在目标下方或侧边，空间不足时夹取到安全边距；不得遮挡目标。
- 900×600 下卡片和目标必须同时可见；长表单允许自动滚动，不产生横向溢出。
- 目标尺寸为零、被卸载或超出页面时进入等待态，不能沿用上一目标的旧坐标。

## 8. 键盘、可访问性与响应式

- 当前目标使用 `aria-describedby` 关联教学卡片，卡片有可见标题和阶段进度。
- 微步骤切换后把焦点移动到真实目标；说明型步骤的继续按钮进入正常 Tab 顺序。
- 教学激活时 Tab 范围限制在真实目标与教学卡片操作之间，目标外内容不可聚焦、不可点击。
- Enter/Space 触发真实按钮自身行为；引导不能通过键盘代理执行写操作。
- Escape 暂停并恢复到打开教学前的合理焦点；重新打开后重新测量目标。
- 进度不能只依赖颜色，必须包含业务阶段和微步骤数字/标题。
- 浅色、深色和高对比下目标描边均可辨认；`prefers-reduced-motion` 禁用卡片位移和滚动动画。
- 中英文文案变化不能改变目标定位逻辑。

## 9. 已确认的公开测试边界

测试缝隙固定为用户可观察的 App UI、可访问关系、真实控件点击、页面导航和既有 IPC 返回。测试不读取组件
内部 state，不断言私有目标计算、遮罩坐标、CSS 像素或事件监听器数量。视觉定位由真实 App 验收负责。

按 red → green 的垂直切片覆盖：

1. 新用户看到“添加供应商 · `1/5`”聚光灯教学；真实“添加供应商”是当前目标，点击它进入添加页。
2. 供应商选择后依次出现配置/模型/保存目标；保存失败不推进，真实保存成功才进入路由。
3. 路由模式、配置区和“保存并应用”按顺序成为目标；command 返回和旧 revision 不推进。
4. 只有目标 revision 运行、监听可达且配置干净时，才进入 Agent 阶段。
5. Agent 列表、安装选择和“一键接入”根据扫描结果出现；写入后、重扫前不完成。
6. 重扫得到 `CONNECTED` 后完成；空扫描提供重新扫描和明确跳过，并如实显示未接入完成态。
7. 已有配置从第一个未完成业务阶段开始；全部完成时显示完成态。
8. Escape/关闭只暂停且恢复焦点；“不再提示”持久结束；关于页可重新查看。
9. 普通非引导操作不受影响，供应商、路由和 Agent 的原有错误与确认流程仍可使用。

## 12. 已知权衡

- 字段逐个高亮会被供应商差异、可选字段和动态目录放大维护成本；本版以凭据区、模型区和真实保存按钮为
  教学粒度，兼顾手把手感与稳定性。
- 说明型“配置好了，继续”只切换教学目标，不代表配置有效；业务阶段仍由保存/运行/重扫的真实结果完成。
- 全屏教学层比任务条更强制，因此关闭必须是低成本暂停，不能等价于永久结束。
- 目标跨多个滚动容器和确认弹窗，定位与焦点管理是主要前端复杂度；不通过复制 DOM 规避该问题。

## 16. 滚动恢复后的聚光灯边界一致性（18:39 补充）

### 16.1 新证据与反馈环

### 16.3 已确认根因与最小修复

- 反馈环稳定复现：工作区最终恢复到 `scrollTop = 0`，但描边由初始 `top 93 / height 414` 变为

  `scrollTop` 设回锁定值；浏览器不保证再产生一个可供测量的 scroll 事件，因此 React 保留了过期矩形。
- 最小修复是在工作区位置确实被恢复后，立即基于恢复后的真实 DOM 再执行一次 `measure`。不改变聚光灯
  clamp、不改三档 DOM，也不扩大滚动锁范围。
