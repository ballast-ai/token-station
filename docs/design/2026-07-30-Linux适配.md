# Linux 适配 · 构建、依赖与验证

面向三平台开源 release(Windows / macOS / Linux)。本文记录 Linux 侧的适配结论、构建方式、系统依赖与验证清单。macOS 侧已基本完成,Windows 由另一位负责。

## 结论:Linux 适配主要是「数据 + 打包 + 脚本」,几乎无平台专属逻辑要写

项目本就跨平台(Rust + Tauri),核心代码的平台差异几乎全部走 `#[cfg(unix)]`(macOS 与 Linux **共享同一份**),没有「macOS 专属而 Linux 缺失」的运行时逻辑。适配工作集中在:注册表 Linux 路径、Tauri Linux 打包、构建脚本放开 Linux。

## 构建 Linux 版

### 1. CLI 二进制(`token-station-cli`)

脚本本就 target 参数化,直接传 Linux triple:

```bash
scripts/build-release.sh x86_64-unknown-linux-gnu
# 或 aarch64-unknown-linux-gnu
```

产物:`token-station-cli-<version>-<target>` tar.gz(内含二进制 + 内嵌插件 dist)。

### 2. 桌面应用(deb / AppImage / rpm)

**必须在 Linux 机器上构建**(Tauri 桌面打包依赖 Linux 系统库 webkit2gtk,无法从 macOS 交叉编译)。

```bash
scripts/build-desktop.sh --production        # 或 --local(本地免签名)
```

Linux 包不做代码签名(与 macOS/Windows 不同),脚本的 Linux 分支不需要签名环境变量。

## Linux 构建机系统依赖

Tauri 2 桌面打包在 Linux 需要(Debian/Ubuntu 包名,其它发行版对应等价包):

```bash
sudo apt-get install -y \
  libwebkit2gtk-4.1-dev \
  libgtk-3-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev \
  build-essential curl wget file \
  libssl-dev libxdo-dev pkg-config
# AppImage 打包会自动下载 linuxdeploy 等工具;rpm 打包需 rpmbuild(rpm 包)
```

Rust target:`rustup target add x86_64-unknown-linux-gnu`(或 aarch64)+ `wasm32-wasip2`(插件)。

## 已做的验证(在 macOS 开发机)

- **cross-check**:`cargo check --target x86_64-unknown-linux-gnu` 对纯 Rust crate(protocol / metrics / router-core)**全部编译干净**,证明 cfg 逻辑对 Linux 成立。
  - cli / plugin-runtime 的 cross-check 卡在 `zstd-sys`(C 依赖,来自 wasmtime 的 cache feature)缺 macOS→Linux 的 C 交叉链接器 —— 这是 C 工具链问题、非 Rust 代码问题(我的 crate 都编过才撞到它);zstd 在真 Linux 上是 ubiquitous 库、必然可编。
  - cli/plugin-runtime 无任何 macos-only Rust 分支(平台代码仅 `cfg(unix)` mac/linux 共享 + upgrade.rs 多平台),故 macOS 能编 ⇒ Linux 能编。
- **测试**:全套件在 macOS 绿(router-core 89 / cli lib 198 / desktop lib 210 含新增 Linux registry 覆盖测试)。跨平台逻辑测试(platform-paths、discovery、registry)通过 `Platform` 枚举在 macOS 上就覆盖了 Linux 代码路径。
