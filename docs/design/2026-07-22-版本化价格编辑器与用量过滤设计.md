# 版本化价格编辑器与用量过滤设计

> 日期：2026-07-22
> 状态：已实现并通过专项验收
> 范围：版本化单模型价格编辑、历史 Receipt 不回算、Agent/入站协议来源过滤
> 核心边界：价格编辑只产生当前配置的新版本；历史 Receipt 的成本和 `price_version` 永不更新

## 1. 背景

Token Station 已有 `PriceTable.version`、按模型的五类 token 价格，以及在请求结算时固化 `cost_micros / cost_kind / price_version` 的内核。此前只能手工编辑配置，没有 Desktop 编辑器、并发版本保护和 Agent/来源过滤。

任务 #9 要求用户能编辑单模型价格并生成新版本，同时证明旧请求不会按新价回算；用量视图还要支持按 Agent 和来源过滤。

## 2. 目标

1. 在 Desktop 中读取、添加、修改和删除单模型价格。
2. 每次实际变化把当前 `PriceTable.version` 精确增加 1；无变化编辑不生成空版本。
3. 写命令携带 `expected_version`，拒绝基于陈旧页面覆盖新版本。
4. 支持输入、输出、缓存读、缓存写和可选推理价格；推理价格为空时沿用输出价格。
5. 显式全零价格代表免费，模型缺失才代表未知成本。
6. 价格更新后新请求使用新版本，旧 Receipt 的成本和版本保持不变。
7. 用量查询可按 Agent namespace 和入站协议来源精确过滤，两个条件可组合。

## 3. 非目标

- 不批量回算或 UPDATE 历史 Receipt。
- 不从外部 Provider 自动同步价格。
- 不推断账户货币；界面沿用“账户货币 / 1M tokens”的中性单位。
- 不让浏览器侧通过 HTTP 写价格；配置写入仍只走 Tauri IPC。
- 不在运行代理中静默热替换价格。保存后需重新应用配置，新请求才使用新版本。
- 不把 Provider、模型或 Agent 名称写入特判路由。

## 4. 契约

### 4.1 单模型价格

每个模型保存：

| 字段 | 单位 | 语义 |
|---|---|---|
| `input_per_mtok` | 微单位 / 1M tokens | 输入 token |
| `output_per_mtok` | 微单位 / 1M tokens | 输出 token |
| `cache_read_per_mtok` | 微单位 / 1M tokens | 缓存读取 |
| `cache_write_per_mtok` | 微单位 / 1M tokens | 缓存写入 |
| `reasoning_per_mtok` | 微单位 / 1M tokens，可空 | 推理 token；空时跟随输出价 |

界面用账户货币单位输入，最多 6 位小数，再精确换算成微单位。`0` 是合法的明确免费价格；缺少模型条目才返回 `None/unknown`。

### 4.2 追加版本

领域方法不原地修改旧表，而是从当前表返回克隆后的下一版本：

```text
current(version=N, models) + actual change
  -> next(version=N+1, copied models with one change)
```

- 相同值编辑拒绝为 no-op。
- 删除不存在模型拒绝。
- `u32::MAX` 后拒绝继续递增。
- 旧的手工 `version=0` 非空表保持可读；首次编辑升级为 v1，避免新增启动回归。

Desktop 写命令包含 `expected_version`。只有 `expected_version == current.version` 才保存，否则提示刷新，防止两个页面发生 lost update。

### 4.3 Receipt 不变量

网关在请求结算时只计算一次成本，并把当时价格版本写入同一 Receipt。编辑器只写配置文件，没有 SQL UPDATE 能力。

跨版本运行态 fixture 必须证明：

```text
请求 A：price v1 -> cost 3
应用新价格
请求 B：price v2 -> cost 6
再次读取请求 A：仍为 price v1 / cost 3
```

### 4.4 零价兼容修正

旧存储归一化把 `Estimated + cost=0 + price_version` 错误降级为未知，与 `ModelPrice` 的“零价是免费”公开契约冲突。本阶段将该旧测试判定为已被领域契约取代：

- `cost >= 0` 且 Estimated 携带版本：保留数值和版本；
- Actual 的非负数值：保留；
- 负数、Estimated 缺版本或未知形状：归一化为 unknown；
- v3→v4 迁移同样保留带版本零价，未版本化旧成本保持 unknown。

### 4.5 用量过滤

`StatsFilter` 在聚合前做参数化精确匹配：

- `agent_id`：Receipt 的 Agent namespace；
- `source`：Receipt 的入站适配器协议，即 `protocol` 字段，例如 `openai-responses`，不是请求 header/body。

时间、Agent、source 可组合；SQL 使用绑定参数，统计仍以只读方式打开 SQLite。过滤贯通 CLI `stats --agent/--source`、`/admin/stats?agent=&source=`、Desktop IPC 和前端选择器。

## 5. 执行步骤

1. 扫描现有价格、存储和旧测试契约，识别零价冲突。
2. 用 RED 测试定义不可变下一版本、no-op、删除、零价和版本耗尽。
3. 实现领域级 `next_with_model / next_without_model`。
4. 修正零价存储与 v3 迁移语义，保留负值/缺版本 fail-closed。
5. 添加 Desktop get/set/remove price IPC、完整配置校验、原子持久化和 expected-version 检查。
6. 用历史 Receipt fixture 证明配置编辑不写旧成本。
7. 扩展 Stats Agent/source 组合过滤，并贯通 CLI、HTTP、IPC、前端。
8. 实现价格表、编辑表单、版本徽章、删除入口和重新应用提示。
9. 扩展真实运行态 apply 测试，证明新请求使用 v2、旧请求仍为 v1。
10. 执行全量测试、TypeScript、clippy、fmt 和 diff check，固化验收证据。

## 6. 退出条件

### 6.1 成功退出

仅当第 7 节全部通过、专项设计与 fresh verification 已保存，且 diff 中不存在历史成本更新语句，#9 才可关闭并进入 #10。

### 6.2 暂停退出

- 当前配置的价格语义无法无损映射到编辑表单；
- 运行态无法可靠区分保存版本与实际生效版本；
- Receipt 缺少稳定 `price_version`，无法证明不回算；
- Agent/source 过滤需要读取正文或非白名单字段。

### 6.3 失败退出

发现改价会更新旧 Receipt、零价被误判未知、缺价格被误判免费、陈旧页面能覆盖新版本，或过滤读取 prompt/response 时，立即停止扩大改动并修复红线后重新验收。

## 7. 通过条件

- 能添加、编辑、删除单模型价格，五类价格 round-trip 正确。
- 每次实际变化生成 `version+1`；并发旧版本写入被拒绝。
- 显式零价以数值 0 和价格版本落库；缺失模型仍为 unknown。
- 跨版本真实代理请求分别使用 v1/v2，旧 Receipt 成本和版本不变。
- 用量可按 Agent、source 及两者组合过滤；未命名请求不会误归属某 Agent。
- HTTP 数据面仍只读，价格写入只走受限 IPC。
- CLI、Desktop Rust、Vitest、TypeScript/Vite、clippy、fmt 和 diff check 全绿。
