# 英文代码注释与人话错误提示

## 问题、目标与范围

代码中仍有大量中文注释，跨语言协作时需要反复翻译。部分路由配置错误直接暴露内部字段和实现口吻，例如没有路由池时只说明“无法路由”，却没有告诉用户怎样继续。

本次改动做两件事：把本 PR 修改的非冻结源码注释改成含义一致的英文；在桌面端显示边界把现有配置错误字符串转成直接、可操作的人话。`crates/router-core/**` 受冻结 tree 红线保护，本 PR 不修改其错误类型或文案。改动不调整控制流、路由规则、配置格式或默认值。

## 非目标与安全红线

- 不修改业务逻辑、协议错误码、后端命令契约、日志字段、请求收据结构或持久化格式。
- 不修改受保护的 `crates/router-core/**` tree；其既有中文注释是已知基线例外，不再声称全仓扫描为 0。
- 不吞掉供应商名、模型名、路由池名、规则 ID 等诊断信息。
- 不把密钥、请求正文或其他敏感数据加入错误提示。
- 只能通过 `scripts/install-local-desktop.sh` 替换 bundle id 为 `com.tokenstation.desktop` 的本机 App；构建失败时不得删除旧 App。

## 用户可见行为与失败处理

配置校验仍在原来的位置失败，错误类型也保持不变。桌面端 formatter 精确识别已有 `ConfigError` 显示文本，先说明当前缺少或冲突的内容，再给出可以执行的下一步。例如没有路由池时提示用户先创建至少一个路由池，然后才能启动 Token Station。

错误仍保留相关字段值。未知路由池会显示路由池名和引用它的配置项；重复规则会显示规则 ID。这样用户能处理问题，开发者也能继续定位原始配置。

## 响应式、键盘与可访问性

本次不改变组件结构、焦点顺序、键盘操作或布局。错误文本继续使用现有错误区域和可访问性语义。较长提示必须允许现有容器自然换行，不能依赖悬浮提示才能读全。

## 测试边界与验收标准

- 路由配置错误类型和触发条件保持不变。
- `NoPools` 文案明确说明必须先设置路由池才能启动。
- 真实的空 pool 和未知 pool 文本包含具体 pool/rule 标识和可执行下一步。
- 模型目录 warning 和更新检查 message 也经过同一 formatter，英文界面不直接显示中文或底层错误。
- 本 PR 新增或修改的非冻结源码注释不出现中文字符；用户界面文案和测试 fixture 不在此项检查范围内。
- 完成本地构建和产物审计后，必须执行 `scripts/install-local-desktop.sh` 并启动真实 App 验收。

## 实现落点、遗留项与发布要求

错误显示适配位于 `apps/desktop/src/errors.ts`，并由模型目录和 About 页调用。注释翻译覆盖本 PR 修改的非冻结 Rust、TypeScript、TSX、CSS、Shell、TOML 和 CI YAML 代码。现有结构化请求错误翻译保持不变。

本次不创建 DMG。全量门禁和真实 App 验收通过后，按仓库约定创建中文提交并更新 PR。

## 实现与验收结果

已完成。真实 `NoPools`、空 pool、未知 pool 文本和成功结果内 warning/message 均有中英文公开测试，未知错误走安全兜底；最终前端 29 个测试文件、268 项全部通过，生产构建通过。workspace 格式、Clippy、全量测试和 `-D warnings` 文档构建通过，桌面端 Clippy 与 251 项 lib 测试（另 1 项只读真机探测按设计忽略）、10 项更新测试、2 项安装测试、3 项 YAML 回归测试全部通过。

`scripts/install-local-desktop.sh` 已完成构建、审计、安装与启动。真实 App 的英文和简体中文 About 页都把“缺少官方更新公钥”显示成对应语言的可执行提示，没有暴露底层任意字符串或本地路径；未知错误兜底通过公开组件测试验证，没有为制造错误破坏用户配置。受保护的 `crates/router-core/**` 既有中文注释仍是明确基线例外，无其他已知遗留项。
