# 英文代码注释与人话错误提示

## 问题、目标与范围

代码中仍有大量中文注释，跨语言协作时需要反复翻译。部分路由配置错误直接暴露内部字段和实现口吻，例如没有路由池时只说明“无法路由”，却没有告诉用户怎样继续。

本次改动只做两件事：把代码文件中的中文注释改成含义一致的英文；把现有配置错误字符串改成直接、可操作的人话。改动不调整控制流、数据结构、路由规则、配置格式或默认值。

## 非目标与安全红线

- 不修改业务逻辑、协议错误码、日志字段、请求收据结构或持久化格式。
- 不吞掉供应商名、模型名、路由池名、规则 ID 等诊断信息。
- 不把密钥、请求正文或其他敏感数据加入错误提示。
- 不安装或替换 `/Applications/token-station.app`。本次构建和运行都留在独立工作树。

## 用户可见行为与失败处理

配置校验仍在原来的位置失败，错误类型也保持不变。变化仅限错误的显示文字。每条提示先说明当前缺少或冲突的内容，再给出可以执行的下一步。例如没有路由池时提示用户先创建至少一个路由池，然后才能启动 Token Station。

错误仍保留相关字段值。未知路由池会显示路由池名和引用它的配置项；重复规则会显示规则 ID。这样用户能处理问题，开发者也能继续定位原始配置。

## 响应式、键盘与可访问性

本次不改变组件结构、焦点顺序、键盘操作或布局。错误文本继续使用现有错误区域和可访问性语义。较长提示必须允许现有容器自然换行，不能依赖悬浮提示才能读全。

## 测试边界与验收标准

- 路由配置错误类型和触发条件保持不变。
- `NoPools` 文案明确说明必须先设置路由池才能启动。
- 其他配置错误包含具体对象和可执行下一步。
- 代码注释中不再出现中文字符；用户界面本身的中英文文案不在此项检查范围内。
- 桌面端在独立工作树中完成本地构建，产物审计通过，并从构建目录启动。
- `/Applications/token-station.app` 不被替换。

## 实现落点、遗留项与发布要求

错误文案位于 `crates/router-core/src/config.rs` 的 `ConfigError` 显示实现。注释翻译覆盖 Rust、TypeScript、TSX、CSS、Shell 和 TOML 代码文件。现有结构化请求错误翻译保持不变，因为它已经按错误码提供用户建议。

本次不创建 DMG，不安装 App，也不提交或推送。后续发布可按正常桌面发布流程纳入这些纯文本变化。
