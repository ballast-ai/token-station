状态：安全／格式修复及本机自动验证完成，官方 App 已更新；未验证平台和 UI 边界单列。社区基线 `9e699fe`，server 已完成 `c667b1f0` 的严格矩阵；不修改共享核心或 South 组件 runtime 身份。

## 目标与边界

修复上一轮已确认的社区依赖安全失败和格式门，重新执行真实任务、旧插件、桌面及前端验证，并按官方脚本更新本地 App。glib 采用官方 0.18.5 完整发布包加上游两行回补，校验完整文件集与实际依赖，并以原 registry 身份持续审计；原过期例外仅保留历史，不续期。此次不迁移 M4 文本与剩余供应商，不改 UI、数据模型、计费或 CI 触发器。

## 已有失败与最小方案

- 根／桌面两个锁分别包含 rustls 0.23.41／0.23.42，以及 Wasmtime 46.0.2 和已撤回的 chacha20 0.10.1。采用上游修复补丁版本并检查锁差异，不进行全树无差别更新。
- 根四个 Rust 文件、桌面一个旧文件的 rustfmt 差异已在原基线复现，本轮仅接受 rustfmt 的格式修改。
- RUSTSEC-2024-0429 的 glib 0.18.5 例外已过期；Tauri 仍依赖 GTK 0.18，不能直接切到 glib 0.20。精确回补上游修复，保留 API、版本与许可证，详见[回补来源与门禁](../security/glib-0.18.5回补.md)。
- 界面检查曾被系统拒绝；安装后重试现有能力，不修改系统安全设置。无法取得的证据明确保留。

## 可验证目标

1. 保留当前安全／格式／例外失败日志；修复后同命令通过，或精确报告不能消除的外部限制。
2. 依赖变更仅涉及目标包及必需的同版本族；共享 task-core 与正式组件身份不漂移。
3. Rust 1.96 的 workspace／独立 desktop clippy、测试、文档、格式；Node 22 的前端测试／构建；正式任务组件 CLI 专腿均验证。单例不超过 55 秒，先编译再控制并发。
4. 根与桌面 deny、audit 和例外期限门分别执行；不同平台未运行的检查不计绿。
5. 官方 App 构建、审计、签名、替换、启动完成后回写实际结果；旧 App 在构建失败时保留。

## 产品行为与验收

用户入口、CLI JSON、桌面交互和可访问性均不改变。TLS 验证与插件沙箱应使用上游修复实现；现有 TLS 错误分类、正常代理启动、任务恢复及精确 pin 回归继续通过。无新增界面，因此不引入新的响应式或键盘规则。

参考：[rustls 通告](https://rustsec.org/advisories/RUSTSEC-2026-0285)、[Wasmtime 官方安全通告](https://github.com/bytecodealliance/wasmtime/security/advisories)、[glib 通告](https://rustsec.org/advisories/RUSTSEC-2024-0429)。
