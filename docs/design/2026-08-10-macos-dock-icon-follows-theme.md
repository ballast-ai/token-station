# macOS Dock 图标跟随主题

## 问题与目标

Token Station 的窗口界面已经支持浅色、深色和跟随系统三种主题，但 macOS Dock
一直显示安装包里的固定图标。用户切到深色主题后，Dock 仍保留浅色图标，应用内外的
视觉状态不一致。

本次改动让正在运行的 macOS App 根据最终生效的主题切换 Dock 图标。浅色模式继续使用
当前打包图标。深色模式从当前 Dock 图标生成 1024 x 1024 资源：米白与黑色部分反色，
橙色斜长条保持原色。跟随系统模式不增加第四种状态，而是使用系统当前解析出的浅色或深色结果。

## 范围与非目标

范围只包括 macOS 运行期间的 Dock 图标切换、主题到原生层的桥接、公开行为测试和图标资源。
Windows 与 Linux 接收同一个命令时保持无操作，现有窗口主题逻辑不变。

本功能不替换安装包的默认图标，不修改 Finder 中的 App 图标，也不改左上角品牌图标。
它与本分支已有的英文注释和双语错误提示一起交付，但两部分实现保持独立。

## 安全与数据红线

- 图标只从编译进 App 的静态资源读取，不读取用户文件或网络资源。
- 命令只接受 `light` 和 `dark`，其他值直接返回错误。
- 图标切换失败不能阻止主题切换、窗口显示或 App 启动。
- 不替换 `/Applications/token-station.app`，除非后续获得明确安装授权。

## 用户可见行为与失败处理

用户选择浅色或深色主题后，页面先按现有逻辑更新，随后原生层在 AppKit 主线程更新 Dock
图标。用户选择跟随系统时，系统外观变化会重新计算最终主题，并触发同一条更新链路。

如果运行环境不是 Tauri，前端不调用原生命令。如果原生命令不可用或调用失败，前端忽略该
错误并保留已经生效的页面主题，避免一个装饰性功能影响主要操作。

## 响应式、键盘与可访问性

本功能没有新增控件，不改变现有响应式布局、键盘路径和屏幕阅读器信息。主题选择器原有的
交互与可访问性行为保持不变。深色图标保留品牌形状和强调色，并使用深底浅形提高 Dock 中的
辨识度。

## 测试边界与验收标准

- 公开行为测试确认最终主题为深色时发送 `dark`，切换到浅色后发送 `light`。
- Rust 单元测试确认只接受两种主题，并确认两张嵌入图标具有 PNG 文件头。
- 前端测试、Rust 测试和桌面构建通过。
- 真实 App 检查项：启动 App 后分别选择浅色、深色和跟随系统，Dock 图标应与最终主题一致；
  系统外观变化后无需重启 App。

自动测试只能证明主题值和原生命令链路，不能替代 macOS Dock 的肉眼检查。本 PR 不安装或
替换 `/Applications` 中的 App；验收时直接运行构建目录里的 App，检查真实 Dock。

## 实现落点、遗留项与发布要求

- `ThemeProvider` 在现有主题副作用中调用 `set_dock_theme_icon`。
- Tauri Rust 层校验主题，并通过 AppKit 的 `setApplicationIconImage` 更新 Dock 图标。
- 浅色和深色运行时资源均为 1024 x 1024，使用同一套透明圆角和图形位置。浅色资源不再
  复用会在 `setApplicationIconImage` 下显示成方框的打包 `icon.png`。
- 深色资源来源包保存在 `apps/desktop/branding/token-station-dock-dark/`。
- 旧的蓝点与橙色方块图标资产已经删除，不能再作为 Dock 图标来源。
- 打包图标保持不变，所以完全退出 App 后，Finder 与未运行状态仍显示默认图标，这是本次明确的
  非目标。
- 合并前创建独立功能分支和面向 `develop` 的 PR，不直接推送 `develop`。
