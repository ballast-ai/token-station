# 额度优先模式 · 工作原理与限制(用户向)

额度优先(Quota-First)模式把请求优先发给「最接近刷新、且仍有余量」的账户,让每一份会过期的额度在刷新前尽量用尽,而不是白白清零。本文说明它**怎么判断余量**,以及一个必须诚实告知的**限制**。

## 余量从哪来:三层数据,以真实反馈为准

额度余量按可信度分三层,系统尽量取最准的一层:

1. **供应商权威值(最准,无盲区)** —— 直接读供应商在**响应头**里上报的剩余额度与重置时间(如 Anthropic 的 `anthropic-ratelimit-*`、OpenAI 的 `x-ratelimit-*`)。这些数字统计的是该密钥的**全部**用量,不管在哪台机器、哪个工具产生。查看页标注为「供应商权威」。

2. **本地账本估算(有盲区,见下)** —— 供应商没有上报时,按你为该供应商声明的「额度计划」(刷新窗口 + 额度上限)在本地累计经过本网关的流量来估算。查看页标注为「本地估算」。

3. **实时反馈兜底(自愈)** —— 无论上面哪层,只要供应商真的回了 429/402(额度/限流拒绝),该账户会立即被冷却(按 `Retry-After`),路由随即跳过它直到恢复。这是最后一道保证「不会持续把请求发给已耗尽账户」的闸。

## ⚠️ 必须知道的限制:本地估算只看得到「本机、经本网关」的流量

**「本地估算」层只统计经过这台机器上这个 token-station 网关的请求。** 如果你在**别的地方也用同一个密钥** —— 另一台机器、直连供应商不经本网关、别的工具 —— 本地账本**看不到**那部分消耗,于是会**高估剩余额度**,可能把请求发给一个实际已经快用完的账户。

**缓解手段(按优先级)**:

- **优先让路由用「供应商权威值」**:对会在响应头上报额度的供应商(Anthropic / OpenAI 等),系统自动读头,**没有盲区**,不受多机影响。这类账户无需你声明额度计划。
- **实时反馈自愈**:即便本地估算高估了,一旦真的超了,供应商的 429/402 会立即冷却该账户,路由自动绕开 —— 不会长时间对着一个空账户硬发。
- **多机场景的建议**:如果你在多台机器/多个入口共用同一批密钥,**不要只依赖「本地估算」**;尽量用会上报额度的供应商,或把「额度计划」的上限设保守一些。

**目前不提供跨机器的额度对账**(多台机器各自的本地账本不互通)。这是已知限制;跨机对账需要一个共享的额度账本服务,不在当前版本范围内。查看页用「本地估算 / 供应商权威」徽章如实区分来源,不会把估算值伪装成权威值。

## 其它说明

- **额度优先模式不做「只走本地」(local_only)**:额度模式本身就是在多个(通常是云)账户之间轮换榨额度,与「数据不出本机」互斥。两者不能同时用;需要本地隐私时请用三档智能路由的「只走本地」。
- **额度模式默认关闭**:需要在主页或某个 Agent 页显式切换到「额度优先」才启用;每个 Agent 可独立选择模式。
- **密钥安全**:账户密钥存在操作系统钥匙串里,配置文件只存槽位引用、从不含密钥明文。
