# Agent 导航显示偏好设计

- 日期：2026-07-31
- 状态：已实现并完成本机验收
- 范围：`apps/desktop`
- 交互参考：[shadcn/ui Switch](https://ui.shadcn.com/docs/components/base/switch)

## 1. 问题

桌面端左侧导航会展示 Agent Registry 中所有 `supported` Agent。用户通常只使用其中
一部分，但当前无法收起不需要的入口；Agent 数量增加后，导航噪声和滚动压力会持续上升。

用户提供的 cc-Switch 参考使用一组可独立开关的品牌按钮选择主页项目。Token Station
需要提供同类能力，同时遵守现有 shadcn 风格的低阴影、清晰边框与可见焦点语言，不能把
“隐藏入口”误做成卸载、断开或停止扫描。

首版真实 App 预览暴露出明确的视觉问题：高反差白色大卡片、英文 eyebrow、右侧计数和
状态圆点共同制造了过多视觉噪声；多列应用按钮也与 Token Station 现有设置页的纵向表单
语言割裂。本次修订改为单列设置行，每行右侧使用 shadcn Switch 语义展示开关状态。

## 2. 目标

- 在设置中增加独立的“Agent 显示”分区。
- 动态展示当前 Registry 中全部 `supported` Agent，不硬编码固定数量或名称。
- 每个 Agent 可独立切换显示或隐藏，修改后立即反映到左侧导航，无需保存或重启。
- 偏好写入本机非敏感存储，重新打开 App 后保持。
- 当前和未来新加入 Registry 的受支持 Agent 默认显示。
- 浅色、深色、常规侧栏和折叠侧栏都保持清晰。

## 3. 范围与非目标

### 3.1 范围

- 设置导航和 Agent 显示面板。
- Agent 显示偏好的读取、会话内状态和本地持久化。
- 左侧 Agent 导航的可见性过滤。
- 隐藏当前历史 Agent 后的返回导航保护。
- 中英文文案、键盘操作、响应式和深色主题。

### 3.2 非目标

- 不卸载、断开、禁用或删除 Agent。
- 不停止 `scan_agents`，不改变扫描频率、Registry 排序或 admission 规则。
- 不过滤 Agent 路由、用量筛选、预算、Receipt、配置快照或后台状态。
- 不修改 `StateView`、Tauri command、Rust 配置结构或前后端数据契约。
- 不提供“全部显示”或“全部隐藏”批量按钮；本轮只提供明确的逐项选择。
- 不跨设备同步偏好，不处理多窗口之间的实时同步。

## 4. 安全与数据红线

- 只允许写入新的本地展示偏好键，不读取或修改供应商 API Key、虚拟 Key、Agent 配置、
  路由草稿、SQLite 数据或 `token-station.state.json`。
- 显示偏好不得参与 Agent 扫描、兼容性判断、接入事务、运行态或路由计算。
- 不因 Agent 被隐藏而删除其 `agent_routes`、预算、快照或历史用量。
- 不把绝对路径、凭据或扫描诊断写入显示偏好。
- 本地 App 安装仍只允许精确替换 bundle id 为 `com.tokenstation.desktop` 的
  `/Applications/token-station.app`。

## 5. 用户可见交互

### 5.1 信息架构

设置左侧新增“Agent 显示 / Agent visibility”，位于“通用”之后。进入后展示一个面板：

```text
Agent 显示
选择显示在左侧导航中的 Agent。

┌──────────────────────────────────────────────┐
│ [图标] Claude Code                         ◉ │
├──────────────────────────────────────────────┤
│ [图标] Claude Desktop                       ○ │
├──────────────────────────────────────────────┤
│ [图标] Codex                               ◉ │
└──────────────────────────────────────────────┘
```

列表来自已经按 `ui_order` 排序并过滤为 `supported` 的完整 Registry。品牌图标继续复用
`AgentIcon`，没有官方图标时沿用现有首字母或自带图片回退。

### 5.2 Switch 列表语义

面板采用 shadcn Switch 的独立布尔设置语义：

- 每一行是原生 `button role="switch"`，以 `aria-checked=true` 表示“显示”；整行可点击，
  右侧轨道和滑块提供熟悉的开关视觉。
- 按下已显示项目后变为隐藏；按下已隐藏项目后恢复显示。
- 修改立即生效，不出现额外“保存”按钮，也不触发代理重启提示。
- 允许隐藏全部 Agent；主页、用量和设置入口始终保留，因此用户仍可返回设置恢复。
- 显示数量仍以 `role=status` 的 live region 向读屏器播报，但使用视觉隐藏文本，避免与
  每个 Toggle 的状态重复表达。

### 5.3 视觉方向

沿用现有 shadcn 风格令牌与字体，不引入新的品牌色：

| 角色 | 浅色 | 深色 |
|---|---:|---:|
| 画布 / 主表面 | `#ffffff` | `#09090b` |
| 次级表面 | `#f4f4f5` | `#18181b` |
| 主文字 | `#09090b` | `#fafafa` |
| 次级文字 | `#71717a` | `#a1a1aa` |
| 边框 | `#e4e4e7` | `#27272a` |
| Switch 显示态轨道 | `#09090b` | `#fafafa` |
| Switch 隐藏态轨道 | `#d4d4d8` | `#3f3f46` |

字体继续使用 Geist Sans 和系统字体。删除英文 eyebrow、可见状态圆点和视觉计数。
标题与说明直接位于设置内容区，不再额外套用外层 `panel` 卡片。项目放在一个主表面底色、
细边框、8 px 圆角的单列分组容器中；每行高度 52 px，以细
分隔线相连。品牌图标与名称左对齐，32×18 px Switch 右对齐；行悬停只使用次级表面底色，
不把整行填成高反差卡片。“显示”态仅将 Switch 轨道切换为主文字色，“隐藏”态使用中性轨道；焦点
轮廓和 `aria-checked` 共同表达状态。品牌图标是唯一附加识别元素，不增加渐变、投影或
装饰动画。

### 5.4 导航边界

- 左侧导航只接收可见 Registry；扫描结果仍按完整 Agent ID 映射状态。
- 从 Agent 页面进入设置、随后隐藏该 Agent 时，设置页保持不跳转。
- 此时点击“返回”不得重新打开已隐藏 Agent，应返回主页。
- 已经隐藏的 Agent 没有其他界面入口可直接导航时，不创建未知 Agent 或错误状态。

### 5.5 失败处理

- 偏好键缺失时视为没有隐藏项，即全部受支持 Agent 可见。
- 偏好 JSON 无效或不是数组时安全回退为空集合；数组中的非字符串、空字符串和不符合
  Agent ID 格式的条目逐项忽略。
- 本地存储读取失败时使用“全部显示”作为初始状态，但不得在挂载阶段回写空数组覆盖原值；
  只有用户明确切换项目时才尝试持久化。
- 本地存储写入失败时，本次会话内切换仍立即生效；不显示会阻断操作的错误横幅。
- Registry 暂时不包含某个格式合法的已隐藏 ID 时保留该 ID；该 Agent 恢复后仍遵守
  用户偏好。这里的未知 ID 不是无效项，不能因一次 Registry 缩减而删除用户选择。
- Agent ID 与 Registry 一致，使用最长 64 字节的 lower-kebab ASCII：仅小写字母、数字和
  单个连字符，不允许首尾连字符或连续连字符；重复项去重，最多保留 64 项。
- 持久化数组按 Agent ID 的 Unicode 字典序升序写入，不依赖当前 Registry `ui_order`。
- 集合已经达到 64 项时，用户最新明确隐藏的 Agent 必须保留，并淘汰当前集合中字典序
  最大的旧 ID；会话内集合与实际写入集合必须完全一致。
- 写入失败不显示成功或失败提示；控件状态明确代表“当前会话已生效”，持久化属于尽力而为
  的非关键界面偏好。

## 6. 状态模型与持久化

新增本地键：

```text
token-station-hidden-agent-ids
```

值为去重、稳定排序后的 JSON 字符串数组。持久化隐藏集合而不是可见集合，原因是：

1. 缺省空数组天然兼容现有用户。
2. Registry 新增 `supported` Agent 时默认显示，不会被旧的“可见白名单”永久漏掉。
3. 偏好只表达用户明确隐藏过的项目。

`StationApp` 保留两份派生数据：

- `orderedRegistry`：完整的 `supported` Registry，用于设置、页面解析和所有业务行为。
- `visibleRegistry`：从完整 Registry 排除隐藏 ID，只传给 `AppShell` 绘制导航。

扫描、路由和后端状态不读取 `visibleRegistry`。

偏好必须在 `StationApp` 首次渲染前作为 state initializer 读取。首次可观察到的导航直接
使用隐藏集合，不允许先显示全部 Agent 再异步收起。挂载本身不写偏好；写入只发生在用户
切换后，从而避免一次临时读取失败破坏已有值。

## 7. 响应式、键盘与可访问性

- 项目容器始终单列；长名称区域允许收缩并省略，右侧 Switch 不压缩、不换行。
- 每个设置行最小高度为 52 px，品牌图标为 22 px，Switch 为 32×18 px。
- 原生按钮支持 Tab 聚焦、Enter 与 Space 切换；保留全局可见焦点轮廓。
- `aria-checked` 是显示状态的机器可读来源，视觉隐藏的计数文本提供整体状态播报。
- 项目容器使用 `role="group"` 和本地化 `aria-label`；计数使用
  `role="status" aria-live="polite" aria-atomic="true"` 宣告变化。
- 颜色不是唯一状态提示：按钮同时通过填充、边框和可访问属性区分。
- 动效只使用现有短过渡，并在 `prefers-reduced-motion` 下关闭。
- 980 px 折叠侧栏中，只隐藏用户取消选择的 Agent；可见 Agent 继续保留 `title`。
- 760 px 以下现有移动布局会隐藏全部 Agent 导航，本设置仍可操作且不改变持久化状态。

## 8. 公开测试边界

App 集成测试只观察公开 UI、本地存储和 IPC 调用；偏好模块另用聚焦单元测试验证
localStorage 输入输出、格式边界和容量策略，不测试 React 内部状态、DOM 层级或组件快照：

1. 无偏好时按 Registry 顺序展示全部 `supported` Agent，`discovery_only` 不出现。
2. 设置中展示同一完整列表，所有项目初始为 `role=switch aria-checked=true`。
3. 关闭一个 Agent 后，该项目变为未按下、左侧入口立即消失、计数更新且偏好持久化。
4. 重新打开同一 Agent 后，左侧入口恢复且持久化集合移除该 ID。
5. 重新挂载 App 后恢复隐藏偏好；未来新增的 Registry Agent 默认显示。
6. 隐藏不减少或新增 `scan_agents` 调用，不改变完整 Agent 业务数据。
7. 从 Agent 进入设置并隐藏它后，“返回”落到主页。
8. 无效 JSON、非数组、非法条目、重复项、超过上限、读取异常和写入异常按状态模型容错；
   格式合法但当前未知的 ID 保留。
9. 键盘可聚焦并用 Enter、Space 切换，状态可通过 `aria-checked` 读取；组和视觉隐藏计数具有
   可访问名称与状态播报语义。
10. 隐藏全部 Agent 后，左侧仍保留主页、用量和设置入口；设置面板仍展示全部项目并可恢复。
11. 默认英文和切换后的简体中文都展示完整、对应的标题、说明与可访问名称，并保留本地化
    的隐藏状态播报。
12. 切换时不调用 `set_settings`、serve、路由、接入、断开或其他写业务状态的 IPC；
    `scan_agents` 调用数不变，设置中的完整 Agent 列表不变。
13. 带隐藏偏好重新挂载时，首次出现的导航已经过滤，不发生“全部显示”闪现。

不创建整页快照，不断言具体 DOM 层级或 CSS 类名。
