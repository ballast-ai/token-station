# T4：出站路径显式与红线测试设计

> 日期：2026-07-22
> 范围：网关生产请求与 Provider probe 的 HTTP 出站边界；不包含 Agent Skill 用量。

## 1. 安全不变量

1. 所有携带 Provider 凭据的出站请求只能连接配置中经 `ProviderEndpoint` 授权的第一跳。
2. 3xx 一律不跟随，并在 Provider adapter 解析响应前归类为 `UpstreamUnavailable`；`Location` 与凭据都不得进入客户端错误或日志。
3. `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及大小写变体不能改变生产请求或 probe 的网络路径。
4. 生产请求、分层 probe、普通 probe 与取消感知 transport 必须复用同一 `EgressPolicy` 配置，禁止旁路构造默认 HTTP client。

## 2. 实现边界

`EgressPolicy` 是无状态的 fail-closed 构造器：

- `config(timeout)` 显式设置 `max_redirects(0)`、`proxy(None)` 与统一超时；
- `agent(timeout)` 用于 probe；
- 生产请求的 `cancel_aware_agent` 使用同一 config，只替换为可取消 connector；
- `reject_redirect(status)` 在凭据已发送到授权第一跳、但响应尚未进入 Provider plugin 前拒绝全部 3xx。

不实现“安全重定向白名单”。同域重定向也拒绝，因为重定向后的路径不再是用户保存并预览过的最终 URL。

## 3. CI 红线

1. 第一跳返回 302，`Location` 分别模拟其它主机名、loopback 与 metadata；客户端得到 typed 502，第二跳监听器 0 hit，凭据不出现在响应。
2. 普通 probe 与分层 probe 遇到 302 同样失败，不能把端口可达误报为模型健康。
3. 在隔离子进程中同时设置恶意 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY` 及小写变体：生产与 probe 都必须直连测试目标，代理捕获器 0 hit。子进程隔离避免并行测试修改全局环境变量。

这些测试只连接测试进程创建的本地监听器。metadata 用例保留标准 `/latest/meta-data/...` 路径与原始 IP 标记，但网络目标指向本地 canary；若重定向保护回归，canary 会确定性报 hit，测试不会访问真实 link-local metadata 服务。
