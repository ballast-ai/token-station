## 2. 目标

1. 隔离版本探测子进程时注入平台最小非敏感环境（含绝对路径 `HOME` / `USERPROFILE`），使官方 `~/.local/bin/claude` 包装入口可完成 `--version`。
2. 主页 `router.pools` 为空时，启动入口在写盘和异步 `gateway_init` 前失败，并给出可操作的中文说明。
3. Agent 页按 `reason_code` 区分状态标题，并在探测类失败时提供「重新扫描」。
4. OpenClaw 支持安全发现自定义 npm global prefix 或用户明确选择的安装入口，并区分 Node 缺失、版本过低和版本探测失败。
5. 已有接管但运行态不一致时，精确区分凭据失配、外部漂移、网关未启动和适配器不可用；仅凭据失配可进入确认式同步，外部漂移可查看不含值的字段级诊断。
6. ownership installation identity 变化时，在一次索引锁和一次原子写入内完成 CAS rebind；任一失败保持配置、ownership 与快照的事务前状态。
7. 补齐未落盘草稿提示、配置 revision 冲突保护、空主页配置深链和配置解析诊断。

## 3. 范围

### 3.1 包含

- `ScanEnvironment.child_environment` 最小变量注入与探测回归测试。
- `begin_serve_start` / 启动 UI 的主页 pools 前置校验与错误文案。
- `AgentRoutePage` 状态标题映射与重新扫描入口。
- `RuntimeResolutionSource::ProcessPath`、npm global prefix / 用户选择入口、OpenClaw Node 最低版本诊断。
- managed 且未连接时的凭据同步交互（单个 `SyncCredentials` preview/apply 事务）。
- ownership 原子 CAS rebind 和迁移前 MAC、Connector、目标路径、基线快照校验。
- 配置 revision 冲突保护、草稿/已落盘状态文案、空主页配置深链和配置解析诊断。

### 3.2 非目标

- 不把完整父进程环境或密钥透传给探测子进程。
- 不支持「主页 pools 为空、仅 Agent 独立路由即可启动」的 Agent-only 网关语义（产品未决，保持 fail-closed）。
- 不新增可静默覆盖用户 Agent 配置的后台任务。
- 不自动批量重投影网关凭据；只标记需修复并要求用户预览、确认。

## 4. 安全与数据红线

1. 版本探测继续 `env_clear()`；仅允许注入白名单绝对路径变量：`PATH`（受限构造）、`HOME`/`USERPROFILE`（绝对路径）、Windows `SYSTEMROOT`/`WINDIR`。
2. 禁止把 `ANTHROPIC_*`、Provider API Key、虚拟 Key、代理鉴权头或任意完整父进程环境注入探测进程。
3. 虚拟 Key、Agent 配置正文、受管字段明文不得进入日志、错误 banner、UI 摘要或测试输出。
4. 同步网关凭据必须走单个 preview/apply 事务，只允许更新 Connector 声明的敏感 owned path；非敏感 owned path 有漂移时必须 fail-closed。
5. ownership rebind 必须在一次索引锁和一次原子磁盘写入中完成；写入失败不得先删除旧记录，回滚不得丢失 ownership 或快照。
6. 不删除、不迁移、不覆盖用户未授权的 `~/.claude/settings.json` / OpenClaw 配置 / 磁盘 `token-station.json`。
7. Node 运行时解析必须：绝对路径、原生可执行校验、canonical 二次校验、多候选同优先级 fail-closed。
8. 启动前置校验不得绕过鉴权默认开启、loopback 监听和虚拟 Key 常量时间比较。
9. 测试只能使用临时 HOME / 临时配置副本，结束后清理，不触碰真实用户 Agent 配置。

## 5. 用户可见交互与状态

### 5.1 Claude 版本探测（问题二）

- 成功：官方入口探测为 `DETECTED_VERIFIED`（版本在兼容范围内时）。
- 失败：继续返回精确 `reason_code`；前端不再用笼统「暂不可接入」掩盖。

### 5.2 空主页启动（问题五）

- 主页 pools 为空时：
  - 顶部「启动」仍可点击或禁用均可，但点击后必须同步返回中文错误，不得进入 `phase=error` 的 `gateway_init: a router with no pools...`。
  - 错误文案：`请先在主页路由中至少配置一个档位（供应商 + 模型），再启动代理。`
- 「保存并应用」与「启动」共用“至少一档”规则；本批仍要求主页兜底，不启用 Agent-only 启动。

### 5.3 Agent 状态标题（问题一）

| reason_code / 条件 | 标题 | 操作 |
|---|---|---|
| 未发现安装 | 未发现 | 重新扫描 |
| 多安装未选择 | 待选择 | 选择精确路径 |
| `CONNECTED` / connected | 已接入 | 恢复原始配置 |
| managed 且未连接 | 需修复 | 同步网关凭据、恢复原始配置 |
| `BlockedVersionMatch` | 当前版本已被阻止 | 重新扫描 |
| `VersionProbeTimeout` | 版本检测超时 | 重新扫描 |
| `VersionProbeExitFailure` | 无法检测版本 | 重新扫描 |
| `ExecutableNotRunnable` | 安装入口无法运行 | 重新扫描 |
| `ConfigReadFailed` / `ConfigParseFailed` / 预检失败 | 配置预检未通过 | 重新扫描 |
| 其他非 verified | 暂不可接入 | 重新扫描（如适用） |
| verified | 可接入 | 一键接入 |

详情继续优先展示后端 `compatibility.message`；不得展示密钥或完整配置。

### 5.4 OpenClaw / Node（问题三）

- 自动扫描已知路径、受约束 PATH 和 npm global prefix；没有找到时允许用户明确选择绝对安装入口。
- `env_shebang` 仅解析唯一、绝对、原生可执行且 canonical 后仍满足约束的 Node。
- Node 不存在显示「未找到可用 Node.js」；低于 `22.19.0` 显示当前版本和最低要求；不得统称 OpenClaw 未安装。

### 5.5 同步网关凭据（问题六）

用户路径：

1. 代理已启动，Agent 显示「需修复」。
2. 用户点击「同步网关凭据」。
3. 后端生成一个 `SyncCredentials` 计划，只包含敏感 owned path；非敏感路径漂移、网关未启动或适配器不可用时拒绝生成。
4. 用户确认后执行一次 apply；如需 installation identity rebind，与 ownership 更新在同一原子索引事务中完成。
5. 成功后重新扫描，期望 `connected=true`。
6. 任一步失败时配置、ownership 和快照保持事务前状态；不输出凭据。

副操作「恢复 Agent 原始配置」仍只断开不重接。

## 6. 响应式、键盘与可访问性

- 状态标题不依赖颜色 alone：保留文字 label + tone class。
- 启动失败错误进入现有全局/页面错误区域，读屏可读。

## 7. 公开测试边界与验收标准

### 7.1 自动化

1. **HOME 探测**：构造依赖 `$HOME` 的包装入口；`env_clear` 后仅注入 child_environment；断言可解析版本或至少不因缺失 HOME 得到 `/local/bin/...` 类失败。
2. **空 pools 启动**：空主页配置调用 `serve_start` / `begin_serve_start` 立即错误，且错误含中文“至少配置一个档位”；不进入异步 gateway_init fixture。
3. **状态映射**：前端测试覆盖若干 `reason_code` 标题与 managed 失配文案/按钮。
4. **OpenClaw 发现与运行时**：临时 npm prefix / 用户选择入口可发现；唯一 Node 可解析；多 Node fail-closed；Node 低版本返回精确诊断。Unix 与 Windows 路径规则分别有平台夹具。
5. **同步凭据**：通过公开 command/transaction 接口验证只有敏感路径失配才生成计划；外部漂移、网关未启动和适配器不可用分别返回稳定状态。
6. **原子 rebind**：通过 OwnershipStore 公开接口和完整 apply 事务验证成功只写一个新身份；写入失败、revision 冲突、MAC/基线无效时旧 ownership、配置、快照均不变。
7. **草稿与并发**：未落盘 Provider 显示草稿；第二 revision 写入失败并提示重新加载，不静默覆盖。
8. **诊断与深链**：配置解析失败显示专用标题/操作；空主页启动错误可跳转主页档位。

### 7.2 真实 App 检查项

1. 安装本地 App 后，对官方 Claude 入口重新扫描，不应仅因缺 HOME 被判 broken（本机若安装）。
2. 清空主页三档后点启动，应看到中文前置错误，而非 `gateway_init: a router with no pools...`。
3. 使用隔离临时数据目录构造 managed 凭据失配，应看到「同步网关凭据」预览和确认，不修改真实 Agent 配置。
4. OpenClaw 未发现、Node 缺失/过低、配置解析失败均显示可操作诊断。
