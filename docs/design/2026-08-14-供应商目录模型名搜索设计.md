# 供应商目录模型名搜索设计

## 1. 问题、目标、范围与非目标

添加供应商页的搜索框文案声明可搜索“供应商、模型或标签”，源码也把模型字段放进了
搜索文本，但当前采用整段字符串匹配。用户按自然写法输入模型名（例如把
`gpt-5.6-sol` 写成 `gpt 5.6 sol`）时无法命中，且缺少公开行为测试，已存在的模型
搜索能力容易回归。

本次目标：常规 API 与免费 API 目录都能按模型 ID 或模型显示名筛选供应商；搜索忽略
大小写，并把空格、`-`、`.`、`/` 等分隔符视为等价分词边界。多个搜索词必须都能在
同一供应商的可搜索元数据中找到。

范围仅限添加供应商目录的前端搜索和对应测试。非目标：不修改供应商/模型目录数据，
不做拼写纠错或网络搜索，不搜索用户已经保存但不在当前预设目录中的动态模型，也不
改变地区、免费类型筛选规则。

## 2. 安全与数据红线

- 搜索只读取当前已加载的公开预设元数据，不读取、记录或发送 API Key。
- 不发起额外网络请求，不把搜索词写入配置、日志或遥测。
- 不改变供应商选择、凭据保存、免费额度和付费回退边界。

## 3. 用户交互、状态与失败处理

- 输入供应商名、模型 ID、免费模型显示名或现有标签时，目录实时保留匹配供应商。
- 搜索大小写不敏感；标点和空格差异不影响模型名匹配。
- 多个词按 AND 语义匹配，避免任一短词造成大量无关结果。
- 搜索无结果时沿用现有空状态和“清除筛选”入口；清空搜索恢复目录。
- 地区及免费类型筛选继续与搜索条件同时生效。

## 4. 响应式、键盘与可访问性

不改变现有布局和断点。搜索框继续使用原生 `type="search"`，保留可访问名称、键盘
输入和浏览器清除行为；结果仍使用带可访问名称的列表。

## 5. 测试边界与验收标准

公开行为测试覆盖：

1. 常规目录输入带空格/标点差异的模型名，只显示提供该模型的供应商。
2. 免费目录按模型显示名或模型 ID 搜索，只显示对应供应商。
3. 原有供应商名、标签、地区和免费类型筛选测试继续通过。

真实 App 检查项：进入“添加供应商”，分别搜索 `gpt 5.6 sol` 与一个免费目录模型名，
确认结果卡片正确、清空后恢复；全程不选择或保存供应商。

## 6. 实现落点、遗留与发布要求

- `apps/desktop/src/pages/AddProviderPage.tsx`：统一搜索文本归一化与多词匹配。
- `apps/desktop/src/pages/AddProviderPage.test.tsx`：固化常规及免费模型搜索行为。
- 按仓库门禁执行前端/全量测试与构建，运行 `scripts/install-local-desktop.sh`，在真实 App
  验收后回写本文状态并创建中文本地提交。

## 7. 实现与验收结果

- 已增加统一搜索匹配：Unicode NFKC 归一化、大小写不敏感、常见分隔符等价、多个词
  采用 AND 语义；常规与免费目录共用相同行为。
- 页面测试通过：`AddProviderPage.test.tsx` 15 项全部通过，其中覆盖
  `gpt 5.6 sol` → `gpt-5.6-sol`，以及 `gpt oss 120b` → 免费模型目录。
- 全量前端测试通过：35 个测试文件、372 项测试；`npm run build` 通过。Vite 仅报告
  既有的大 chunk 提示，不影响构建成功。
- `cargo test --workspace --quiet` 全量通过；1 项既有真机只读用例按设计忽略。
- `scripts/install-local-desktop.sh` 已完成隔离 bundled-plugin 门禁、release 构建、产物
  审计、ad-hoc 签名、固定 bundle id 替换和启动。
- 真实 App 验收通过：常规目录输入 `gpt 5.6 sol` 后只显示 OpenAI；免费目录输入
  `gpt oss 120b` 后显示实际提供该模型的 Groq、SambaNova 与 NVIDIA。已清空搜索，
  未选择或保存供应商，用户配置未变更。

实现状态：已完成，无本次已知遗留项。
