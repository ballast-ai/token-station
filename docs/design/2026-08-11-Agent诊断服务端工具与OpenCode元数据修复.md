# Agent Diagnostics, Server Tools, and OpenCode Metadata Fixes

## Problem and Goals

This change fixes UX-005, UX-006, and UX-007 from the manual testing ledger. It also fixes the global read-only lock that occurred after an app restart when a legacy configuration contained `profiles: null`.

1. When a request failed during local inbound normalization, the recent-request receipt still described `invalid_request` as an upstream rejection even when `attempts=0`.
2. Anthropic server tools such as `web_search_*` were converted into empty-schema functions on translated routes. The resulting request no longer failed because of a missing `input_schema`, but no executor, result, citation, or usage data existed. The UI and client could incorrectly treat this conversion as an equivalent search execution.
3. The `tokenstation/auto` model generated by the OpenCode connector had no context window, maximum output limit, or pricing. OpenCode could not calculate Context or Spent correctly, and a zero context window disabled proactive context compaction.
4. The local configuration serialized an empty `profiles` field as explicit `null`. Serde can apply a default when a field is absent, but it rejects a present `null` value when a map is required. After a restart, this error put the complete configuration into read-only protection and blocked the proxy and global routing.

The goal is to keep each boundary honest: local failures must be identified as local, server tools that cannot be translated must fail before the upstream request, and OpenCode must receive only model metadata that the current effective route can prove safely.

## Scope and Non-goals

The scope includes recent-request diagnostics, the Anthropic Messages translation adapter, provider `/models` catalog parsing and caching, effective OpenCode route metadata projection, the OpenCode connector configuration, gateway `/models` output, and safe loading of legacy optional maps.

Configuration compatibility applies only to `agent_routes`, `profiles`, and `agent_budgets`, whose omitted value already means an empty map. Required structures such as `upstreams` and `router.pools` remain strict. A `null` value in a required structure must still fail closed instead of hiding a damaged configuration.

This change does not implement a web-search executor inside Token Station. It does not present an ordinary OpenAI-compatible provider as an Anthropic server-tool provider. The native `anthropic-native` route continues to pass the original request through unchanged. This change also does not assign a false exact price to `tokenstation/auto` when reachable candidates have different prices.

## Safety and Data Boundaries

1. Receipt diagnostics use only existing finite enums, stages, decision presence, and attempt counts. They must not display request bodies, field values, tool input, search terms, search results, or credentials.
2. Provider catalog parsing accepts only bounded responses, bounded model counts, and nonnegative numeric values within validated limits. Invalid or out-of-range metadata remains unknown and must not enter the configuration.
3. OpenCode projection writes only the connector-owned `provider.tokenstation` path. It must preserve other providers, the top-level model, themes, and unrelated user settings.
4. When a route can reach multiple models, context and output limits use the minimum value across all known candidates. If any candidate lacks a required limit, the connector does not claim a complete `limit`. A `cost` is written only when all candidates have identical pricing.
5. The upstream `think` price must not be mapped silently to an OpenCode field. The current OpenCode model schema has no separate reasoning-price field, so only proven input, output, cache-read, and cache-write prices can be projected.

## User-visible Behavior and Failure Handling

### Legacy Configuration Recovery After Restart

If a legacy configuration stores `agent_routes`, `profiles`, or `agent_budgets` as `null`, the loader treats it as the same empty map used when the field is absent. The configuration no longer enters read-only protection for these values. Empty maps remain omitted when the configuration is serialized. A `null` value in another required object still produces a structure error and keeps read-only protection active.

If an existing OpenCode configuration has an object at `provider` but contains the legacy value `provider.tokenstation: null`, reconnecting replaces only that connector-owned value with a complete provider map. The top-level `model` and unrelated user fields remain unchanged.

### Recent-request Receipts

When `inbound_normalize` fails before a routing decision and no upstream attempt exists, the diagnosis states that local request conversion failed and that the request was not sent upstream. If a finite conversion reason is available, the UI identifies the category, such as JSON syntax, request shape, capability, or unsupported tool type. A real upstream `invalid_request` after an upstream attempt continues to be described as an upstream rejection.

The empty states for Decision and Attempts explain that the request stopped at an earlier stage instead of showing only that no record exists. English and Chinese UI text must have equivalent meaning.

### Anthropic Server Tools

When a translated route receives `web_search_*`, `web_fetch_*`, `code_execution_*`, `tool_search_*`, `mcp_*`, or `advisor_*`, inbound normalization returns HTTP 400 with error code `capability`. The message contains only the safe tool category and explains that a native provider with Anthropic server-tool support is required. The receipt records `provider_tool_unsupported` and a finite tool category, with `attempts=0`.

Client-executed tools such as `bash_*`, `text_editor_*`, `computer_*`, and `memory_*` continue to become canonical function tools. Custom functions retain the existing strict `input_schema` validation. The `anthropic-native` path continues to bypass canonical translation and preserves the original server-tool request.

### OpenCode

Provider `/models` responses can supply these compatible fields:

- Context window: `context_window` or `limit.context`.
- Maximum output: `max_output_tokens` or `limit.output`.
- Pricing: `cost.input`, `cost.output`, `cost.cache_read`, and `cost.cache_write`.

Refreshing a provider catalog writes these verified facts into the model capabilities and pricing data. The catalog cache version is incremented so old entries expire safely instead of being treated as complete metadata.

When OpenCode is connected, the backend collects every candidate reachable through the current effective OpenCode route. If all candidates have known limits, `tokenstation/auto.limit` contains the minimum context and output limits. If all candidate prices are identical, the connector also writes `cost`. Unknown or mixed pricing leaves `cost` absent, and the success message explains why no precise price was projected. The gateway endpoint `/agents/opencode/v1/models` returns the same available `context_window`, `max_output_tokens`, `limit`, and `cost` fields for compatible clients.

## Responsive Design, Keyboard Use, and Accessibility

This change does not alter navigation or form layout. Diagnostics continue to use semantic sections, headings, and text. Local and upstream failures are not distinguished by color alone. Keyboard reading order remains Diagnosis, Decision, Attempts, and Conversions.

## Public Test Boundaries and Acceptance Criteria

1. Frontend component tests distinguish a local `inbound_normalize` failure with `attempts=0` from a real upstream HTTP 400 and verify that no sensitive details are rendered.
2. Anthropic plugin tests cover server-tool rejection, continued client-tool conversion, and strict schema validation for custom tools.
3. Gateway integration tests prove that translated routes reject server tools before an upstream attempt and record `provider_tool_unsupported/web_search`. Native Anthropic routes preserve the original request.
4. Model catalog tests use the Wecoding response supplied by the tester and cover nested fields, invalid values, cache versions, and merge behavior.
5. OpenCode connector tests cover complete limits and prices, omission of mixed prices, replacement of only connector-owned configuration, recovery from `provider.tokenstation: null`, and idempotent reconnects.
6. Gateway `/models` tests cover model metadata output.
7. Full tests, the desktop production build, and the artifact audit must pass. The installed `/Applications/token-station.app` must start, run the proxy, and open the Agent and recent-request pages.
8. Connector unit tests use an isolated home directory. The authorized real-app validation reconnects the existing OpenCode configuration and confirms that only `provider.tokenstation` changes while the top-level model and unrelated fields remain intact.

## Implementation Locations

- `apps/desktop/src/errors.ts` and `apps/desktop/src/components/RecentReceipts.tsx`: receipt-aware diagnostics and explanatory empty states.
- `plugins/official/agent-anthropic/src/lib.rs`: server-tool and client-tool separation.
- `apps/desktop/src-tauri/src/model_catalog.rs` and `apps/desktop/src-tauri/src/lib.rs`: model-limit and pricing discovery, caching, and persistence.
- `apps/desktop/src-tauri/src/agent_integration/commands.rs`, `connectors/mod.rs`, and `connectors/opencode.rs`: effective-route metadata calculation and OpenCode configuration projection.
- `apps/cli/src/gateway.rs`: `/models` metadata output.

## Implementation Status, Real-app Validation, and Remaining Limitations

Status: implementation and validation are complete. The full Rust workspace test suite passed. All 287 tests across 30 desktop frontend test files passed. Desktop Rust tests passed with 257 successful tests and one existing conditional test ignored. The production frontend build, official local desktop build, and artifact audit passed.

Real-app validation used the newly installed `/Applications/token-station.app`:

1. The app loaded the real legacy configuration containing `profiles: null` without entering read-only protection. The empty field was omitted after the next save.
2. The proxy started and the global routing entry remained available. Quitting the app stopped the proxy. Reopening the app produced no structure error, and the proxy restarted successfully on `127.0.0.1:8787`.
3. Refreshing the Wecoding catalog stored `context_window=257550`, `max_output_tokens=32768`, and prices `input=0.2`, `output=0.6`, and `cache_read=0.04` for `glm-5.2`.
4. Reconnecting OpenCode replaced the real legacy `provider.tokenstation: null` value with an object and preserved the top-level `model=tokenstation/auto`. The connector wrote the verified values to `models.auto.limit` and `cost`.
5. After the restart, `/agents/opencode/v1/models` returned the same `context_window`, `max_output_tokens`, `limit`, and `cost` values.
6. The Agent page showed Claude Desktop, OpenCode, and WorkBuddy as connected. Proxy integration tests continue to cover adaptive-thinking translation and native pass-through.

Remaining limitation: OpenCode has no separate reasoning-price field. When smart-routing candidates have different prices, one static `tokenstation/auto.cost` cannot describe every dynamic routing decision accurately, so the price remains unknown instead of being fabricated. Observing automatic compaction near the threshold still requires a real long-running conversation, but this change fixes and verifies its prerequisite: a correct, nonzero context window and output limit.
