# Gate B：错误预算与 SSE 字节终态设计

> 日期：2026-07-22
> 决策来源：`2026-07-21-Agent与网关-开发任务书.md` 的 T5、T6 与 Contract A/B。
> 范围：语言模型同步 JSON / SSE 链路；不包含 Agent Skill 用量、异步媒体任务或分类器。

## 1. 不变量

1. 处理顺序固定为：传输完整性 → HTTP 状态 → 2xx Provider 协议终态 → `settle`。
2. 只有 `StreamOutcome::Complete` 可以落 200；取消落 499，半截响应不得成为成功。
3. SSE 网络字节必须先完整分帧，再做 UTF-8 解码；半个字符和半个帧都留在 host tail。
4. 首个可输出事件前不向客户端提交流；此检查点前的可重试失败允许换候选，提交后禁止透明重放。
5. fallback 同时受次数、总耗时、单次超时与可选成本上限约束；等待 `Retry-After` 也消费总耗时。

## 2. T5：统一错误终态与 AttemptBudget

`ErrorCode` 使用协议 crate 的唯一枚举，并固化以下分类：

| 输入事实 | ErrorCode | 是否可换 Provider |
|---|---|---|
| HTTP 402 | `PaymentRequired` | 否 |
| HTTP 429 | `RateLimit` | 是 |
| HTTP 529 | `Capacity` | 是 |
| 连接/读取中断且未提交输出 | `TransportTruncated` | 是 |
| 2xx 非法 JSON、`error` 对象、空 choices | `ProviderProtocolError` | 是 |
| context-length Provider code | `ContextLength` | 否 |
| HTTP 404 / 普通 4xx 请求错误 | `InvalidRequest` | 否 |

`AttemptBudget` 在候选取得本地 Provider 准入、真正发起上游调用前原子消费一次 attempt。它持有
`max_attempts / max_elapsed / per_attempt_timeout / max_cost` 以及本请求的起点和已消费值。
默认成本上限为空；一旦配置成本上限，无法得到可信成本估计的候选必须 fail-closed，不能按 0 成本放行。

`Retry-After` 只允许等待：响应要求、剩余 `max_elapsed`、RequestContext 剩余时间三者的最小值；等待后必须重新检查取消和预算。

## 3. T6：host 字节分帧 + adapter 事件解析

host 的 `SseFrameDecoder` 只做三件事：

1. 累积原始字节；识别 `\n\n` 与 `\r\n\r\n` 帧边界；
2. 完整帧才校验 UTF-8，并把 CRLF 规范化为 LF；
3. EOF 时若仍有非空 tail，返回 `TransportTruncated`。

完整帧以 `StreamChunk` 交给 Provider adapter。OpenAI-compatible adapter 继续兼容独立增量调用，并按 SSE 规则处理 `data:`（有无空格）、多行 data、注释行和 `event:error`。`[DONE]` 始终产生终态 `Done`；顶层 error 或非法 JSON 产生 `ProviderProtocolError`。

`finish_reason` 先暂存，避免在其后的 usage 帧到达前让 Agent renderer 提前关闭流；usage 或 `[DONE]` 会连同终态一起交付。若 Provider 以 `finish_reason` 后的干净 EOF 收尾，host 调用 `StreamParser::finish()`；v1 WIT 以网络 read 不可能产生的空 `StreamChunk` 表示这个 EOF flush，不把普通空事件混作成功。

`relay_stream` 在首个有效事件前缓冲，不发送 `BeginStream`。检查点前失败返回 `Err(ErrorEnvelope)` 给 dispatch；首个渲染事件发出后，任何读取、UTF-8、解析或终态错误均返回 `FailedAfterPartial`。干净 EOF 但没有 `Done` 也属于截断失败。

## 4. 验收矩阵

最少固定以下 12 类：

1. LF 帧；2. CRLF 帧；3. `data:` 无空格；4. 多行 data；
5. 中文三字节跨 read；6. emoji 四字节跨 read；7. 多帧同 read；
8. 半帧跨 read；9. `event:error`；10. 首事件非法 JSON + fallback；
11. 一个 delta 后 EOF；12. `[DONE]` 正常终态。

另跑 T5 矩阵：`200+error / 空 choices / 429+Retry-After / 402 / 404 / 529 / 半截 / 非法 JSON`，以及 20 个 503 不得超过 attempt 上限。所有用例同时断言 receipt 状态和 `ErrorCode`，避免只验证客户端表象。
