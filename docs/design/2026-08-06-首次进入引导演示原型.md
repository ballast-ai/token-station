# 首次进入引导演示原型

- 日期：2026-08-06
- 状态：原型设计，未进入正式 App
- 范围：`apps/desktop/prototypes/first-run-onboarding-prototype.html`
- 原型问题：首次进入时，哪种引导结构最容易让用户理解 Token Station 的核心操作顺序？

## 1. 问题、目标、范围与非目标

### 问题

新用户第一次进入 Token Station 时，面对运行状态、供应商、Agent 和路由等多个入口，缺少一条明确的
起步路径，容易不知道先做什么，以及每一步完成后会得到什么结果。

### 目标

1. 用可交互 HTML 演示首次进入引导，而不是直接修改正式 App。
2. 围绕真实起步顺序表达三个动作：启动本地代理、添加供应商、接入 Agent。
3. 提供三种结构差异明显的方案，便于选择信息层级和交互方式。
4. 保持 Token Station 当前 IBM Plex、冷灰画布、蓝色运行信号和紧凑桌面端密度。

### 范围

- 方案 A：站点路线图式居中弹窗，用“车站线路”表达操作顺序。
- 方案 B：聚光灯式逐步讲解，直接指向 App 内对应控件。
- 方案 C：右侧快速开始面板，用可勾选清单弱化阻断感。
- 通过 `?variant=a|b|c`、底部按钮或键盘左右键切换方案。
- 演示下一步、上一步、跳过、重新开始和完成反馈。

### 非目标

- 不接入 React、Tauri、后端状态或真实导航。
- 不使用 `localStorage`、文件或数据库记录首次进入状态。
- 不修改供应商、Agent、路由或代理运行状态。
- 不进入正式桌面 App 构建，不执行本地 App 替换安装。

## 2. 安全与数据红线

- 原型只使用静态假数据，不读取或展示用户 API Key、提示词、响应正文或本机配置。
- 所有操作只更新当前页面内存中的演示状态，刷新后恢复。
- 不调用网络接口，不触发真实启动、添加供应商、接入 Agent 或保存配置。
- 原型必须明确标注“交互演示 · 不会修改配置”。

## 3. 用户交互、状态和失败处理

- 初始状态：当前方案处于第一步，背景展示静态 Token Station 概览。
- 下一步/上一步：在方案内部切换步骤，更新标题、说明、进度和高亮目标。
- 完成：展示简短成功状态，并允许重新演示。
- 跳过/关闭：隐藏引导，展示“重新打开引导”入口，避免形成死路。
- 方案切换：更新 URL 的 `variant` 参数并重置新方案的步骤。
- 非法 `variant`：回退到方案 A。
- 本原型无真实异步行为，因此不模拟网络失败；正式实现必须另行设计持久化失败与状态同步。

## 4. 视觉方案

### 产品与受众

- 产品：本机 LLM Agent 控制平面。
- 受众：需要管理模型供应商、Agent 和路由的 AI 工程师。
- 页面单一任务：让第一次进入的用户知道下一步该做什么。

### 设计 Token

- 画布 `#F4F6FA`、表面 `#FFFFFF`、主文字 `#182133`、次文字 `#738096`。
- 运行信号 `#5368E8`、成功 `#1B8A5A`、警示 `#A96A12`、边框 `#E1E6EF`。
- 标题/正文使用 IBM Plex Sans，步骤编号与端点使用 IBM Plex Mono。
- 8–12 px 控制圆角；阴影只用于弹窗、聚光灯提示和原型切换器。

### 识别性元素

方案 A 使用与 “Token Station” 名称一致的站点线路：三个真实操作是三个站点，线路上的信号脉冲只在
步骤变化时移动。它承担本原型唯一的强视觉记忆点，其余界面保持克制。

### 结构草图

```text
A 站点路线图       B 聚光灯讲解       C 快速开始面板
┌─────────────┐    [真实页面高亮]      ┌────页面────┬────┐
│ 线路/进度 │ 内容 │       ↑ 提示卡       │            │清单│
│ ●──○──○  │ 预览 │                     │            │步骤│
└─────────────┘                     └────────────┴────┘
```

## 5. 响应式、键盘和可访问性

- 桌面优先，适配 900×600；窄屏时双栏弹窗改为单栏，底部操作区可换行。
- 所有交互使用原生 `button`，提供清晰 `focus-visible`。
- 左右方向键切换方案；方案内按钮可通过 Tab 访问。
- `Escape` 关闭当前引导；“重新打开引导”可恢复。
- 进度变化通过 `aria-live="polite"` 告知辅助技术。
- 遵守 `prefers-reduced-motion`，减少线路脉冲、弹层入场与聚光灯移动。

## 6. 公开测试边界、验收标准和真实检查项

本原型是独立、一次性视觉验证页面，不进入产品公开接口，因此不新增正式自动化测试。手工验收边界：

1. `?variant=a|b|c` 能直接打开对应方案，非法值回退 A。
2. 底部左右按钮与键盘左右键可循环切换三个方案。
3. 每个方案均能完成完整步骤、关闭并重新打开。
4. 页面刷新后不保留任何操作状态。
5. 900×600 和常见宽屏下无内容不可达；Tab 焦点可见；减少动态效果设置生效。
6. 浏览器控制台无错误，页面无需网络即可打开。

## 7. 实现落点、遗留项和发布要求

- 实现仅落在独立 HTML：`apps/desktop/prototypes/first-run-onboarding-prototype.html`。
- 原型使用内联 CSS/JavaScript，双击即可运行，不依赖项目开发服务器。
- 正式实现前必须由用户选定方案，并重新编写生产设计、公开行为测试和状态持久化策略。
- 本轮不修改 `apps/desktop/src` 或构建配置，不影响可执行行为，因此不安装本地桌面 App。
- 本轮不提交 commit；待用户选择方案并授权正式接入后，按项目交付流程提交。
