# shadcn/ui 桌面端重设计

- 日期：2026-08-03
- 状态：第五轮细节修正已实现并完成本机验收
- 范围：`apps/desktop`
- 视觉原型：`/Users/liuwenhao/Desktop/2026-07-31-桌面端重设计原型.html`
- 组件基线：[shadcn/ui](https://ui.shadcn.com/)

## 1. 问题

当前桌面端已经具备完整的路由、Agent、供应商、用量、日志和设置能力，但一级信息架构仍以
“主页 + Agent 侧栏 + 右上角图标入口”为主：

- 主页同时承载路由、供应商和最近请求，用户不能先获得系统运行全貌再决定下一步操作。
- saved revision、running revision、草稿与应用状态散落在按钮、横幅和说明文字中，没有形成稳定的运行状态模型。
- 供应商、用量和日志虽然功能完整，但入口层级不一致，不利于持续监控。
- 现有 `App.css` 体积大，基础控件样式和业务组件样式混合，继续扩展会加重层叠冲突。
- 通用按钮、弹窗、抽屉、表格、标签、提示和键盘交互尚未统一到明确的组件基线。

用户已经确认独立 shadcn/ui 高保真预览，可以进入真实项目改造。

## 2. 目标

1. 建立“概览、路由、Agent、供应商、用量、日志、设置”七个稳定一级入口。
2. 将 `草稿 → 已保存 → 已应用/运行中` 的 revision 关系作为全局状态主线。
3. 使用官方 shadcn/ui 作为通用组件基础，同时保留 Token Station 的领域组件和真实状态语义。
4. 重组现有页面，不丢失 Agent 接入、供应商生命周期、额度优先、请求回执、自救模式、中英文等能力。
5. 在 1040×720 默认窗口和 900×600 最小窗口中保持高密度、可扫描、可键盘操作。
6. 保持 Tauri、React 与现有 Rust/IPC 契约不变；仅在概览需要组合现有只读数据时增加前端读取。

## 3. 范围

### 3.1 本轮范围

- 接入 Tailwind CSS v4 和官方 shadcn/ui CLI 生成的 Radix 基础组件。
- 建立 Token Station 颜色、字体、圆角、控件高度和暗色主题 Token。
- 重做 `AppShell` 为顶部一级导航与运行状态区。
- 新增只读“概览”页，组合当前运行态、路由快照、Agent/供应商数量和本地用量摘要。
- 将现有主页收敛为“路由”页。
- 将供应商管理和最近请求/请求日志拆成独立一级页面。
- 保留 Agent 详情、添加供应商、免费供应商、实时额度和设置二级页面。
- 将新壳层与新增页面的通用控件迁移到 shadcn/ui。

### 3.2 非目标

- 不改变智能路由算法、阈值、关键词优先级或额度优先选择逻辑。
- 不重写 Rust 后端或 Tauri command。
- 不增加通知中心；原型中的铃铛不进入真实 App。
- 不复制原型中的假 macOS 红绿灯和窗口阴影；真实 App 继续使用 Tauri 原生窗口装饰。
- 不在本轮把所有历史业务组件一次性改写为 Tailwind；已有复杂领域组件允许保留语义化 class，逐步收敛。
- 不改变免费供应商目录、Provider 分层测试、插件、自救导出等既有产品范围。

## 4. shadcn/ui 使用边界

“必须使用 shadcn/ui”定义为：

- 项目包含官方 `components.json`，schema 指向 `https://ui.shadcn.com/schema.json`。
- 通用 `Button`、`Badge`、`Card`、`Tabs`、`Separator`、`Progress`、`Sheet`、`Dialog`、
  `AlertDialog`、`Tooltip`、`DropdownMenu`、`ScrollArea`、`Table`、`Input`、`Select`、`Switch`
  等组件由官方 CLI 从 shadcn registry 生成到 `src/components/ui/`。
- 页面和业务组件通过这些基础组件组合；Agent 接入、三档路由、额度计划、请求回执等领域组件继续自定义。
- 不引入第二套通用 UI 组件库。

shadcn/ui 是源码分发组件，不要求每个 DOM 元素都来自组件目录。布局、数据可视化和领域组件必须按
Token Station 的任务设计，不能退化成 shadcn 默认模板。

## 5. 视觉系统

### 5.1 产品对象与页面任务

- 产品对象：本机 LLM Agent 控制平面。
- 主要用户：需要同时管理多 Agent、多供应商和本地路由状态的 AI 工程师。
- 单一核心任务：确认当前系统实际在运行什么，并安全地改变下一版配置。

### 5.2 颜色

### 5.3 字体与密度

- 正文、标题与交互：IBM Plex Sans，系统字体作为回退。
- Revision、端点、Request ID、模型和数据：IBM Plex Mono。
- 普通按钮高 32 px，输入框高 34 px，表格行高 38–44 px。
- 基础圆角 8 px，卡片圆角不超过 10 px，避免大圆角 SaaS 模板感。
- 阴影仅用于弹出层和窗口层级；常规卡片主要依赖边框。

### 5.4 识别性元素

唯一重点视觉元素是 Revision 运行链：

```text
草稿 rev 15  →  待应用 1 项  →  运行中 rev 14
已保存 rev 14  →  已应用同步  →  运行中 rev 14
```

链条必须由真实 `draft_revision`、`saved_revision`、`config_dirty`、`serve.phase` 和
`running_revision` 推导，不能使用装饰性假数据。

## 6. 信息架构

```text
Token Station | 概览 | 路由 | Agent | 供应商 | 用量 | 日志 | 设置 | 运行状态
--------------------------------------------------------------------------------
                               当前页面内容
```

### 6.1 概览

只读展示：

- 代理运行状态、监听地址和连续状态信息。
- Revision 运行链。
- 当前时间范围的请求数、成功率、p95 和待处理信号；数据不可用时展示明确的不可用/空状态。
- 当前三档路由快照。
- Agent 已接入/待接入数量和供应商数量。
- 最近请求摘要；点击进入日志页或请求详情。

概览不允许直接修改路由，不读取请求正文，不展示 API Key。

### 6.2 路由

沿用现有 `HomePage` 的真实能力：

- 三档智能路由与额度优先模式。
- 策略组保存、删除和应用到全部 Agent。
- 关键词路由、本地优先和云端回退。
- 配置错误、草稿、saved revision 和保存并应用反馈。

从该页面移除供应商列表和最近请求，避免主任务混杂。

### 6.3 Agent

- 一级 Agent 页展示 Registry 中允许显示的 Agent 及其发现/接入状态。
- 点击 Agent 进入现有详情和独立路由页。
- 隐藏 Agent 偏好继续由设置控制。
- 重新扫描行为保持单飞和代际保护。

### 6.4 供应商

- 独立展示当前供应商、模型数量、状态和回收站。
- 添加供应商进入现有目录/向导，不把 API Key 放入 URL、日志或本地预览状态。
- 删除继续先展示影响预览，正常删除失败时不提供未经说明的强制路径。

### 6.5 用量与日志

- 用量页保留趋势、分组、预算和定价能力。
- 请求日志成为独立一级入口，复用现有分页、状态筛选和 Receipt 详情。
- 日志详情优先使用 shadcn `Sheet`；Escape 关闭后焦点返回触发行。
- 用量和日志均只读取本地无正文元数据。

### 6.6 设置

保留通用设置、虚拟密钥、外观、Agent 显示、语言、路由表、插件和关于。设置是一级页面，继续使用
全局顶部导航，不再渲染独立“返回 + CONTROL ROOM”旧壳。设置分类改为内容区顶部的二级导航，
当前分类使用选中语义；不把低频调试页提升到一级导航。

## 7. 状态与失败处理

### 7.1 Revision 状态

- `config_dirty=true`：显示草稿 revision 和未保存状态。
- `saved_revision > running_revision` 且运行态健康：显示已保存尚未应用。
- `serve.phase=starting`：显示正在应用，不提前报告成功。
- 只有运行态健康且 `running_revision === saved_revision` 才显示已应用同步。
- 应用失败继续显示后端错误，不能由动画或 Toast 覆盖。

### 7.2 只读数据

- 概览统计、最近请求或额度读取失败时，各区块独立降级；不阻断路由与设置页面。
- 自动刷新继续采用现有单飞策略，不因概览页新增读取造成并发轮询。
- 页面离开后停止该页面的定时器并忽略旧响应。

### 7.3 写操作

- 所有现有写操作继续经过 App 级 `run` 或对应领域事务。
- 视觉迁移不得引入自动保存、自动应用或自动 Agent 接入。
- 按钮文案与完成反馈保持同一动词，例如“保存并应用”成功后才报告“配置已应用”。

## 8. 安全与数据红线

- 不读取、展示、复制或传输供应商 API Key；密钥仍只显示掩码和明确用户操作。
- 不读取或记录提示词、响应正文和请求 body。
- 不修改 `token-station.state.json`、Agent 配置或 Provider 配置，除非现有明确用户操作授权。
- 不改变 Provider 回收站、恢复、Agent 快照和反向补丁语义。
- 不在前端伪造运行、额度、成本、Revision 或 Agent 接入成功状态。
- 不扩大监听地址、网络出站和本机文件访问权限。
- 本地安装只允许脚本精确替换 bundle id 为 `com.tokenstation.desktop` 的
  `/Applications/token-station.app`。

## 9. 响应式、键盘与可访问性

### 9.1 响应式

- 1200 px 以上宽屏：概览、Agent 与设置使用除固定页面边距外的全部可用宽度，不设置居中窄版
  `max-width`；Agent 卡片按可用宽度从三列扩展到四列。
- 1040×720：显示七个一级入口、运行状态和完整页面标题。
- 900×600：压缩标签间距；必要时将低频“日志、设置”放入更多菜单，但不得隐藏可达性。
- 页面内容允许纵向滚动，不允许壳层横向溢出。
- 指标区在空间不足时从四列降为两列。
- 表格使用容器滚动或收敛次要列，不能让窗口整体横向滚动。

### 9.2 键盘与焦点

- 一级导航使用语义化 tab/navigation，支持 Tab 顺序和清晰 `focus-visible`。
- Dialog、AlertDialog、Sheet、Select 和 DropdownMenu 使用 shadcn/Radix 焦点管理。
- Escape 关闭弹层并恢复触发元素焦点。
- 图标按钮必须有 `aria-label` 和 `title`。
- 当前页面使用 `aria-current` 或选中态语义。
- 动效遵守 `prefers-reduced-motion`。

## 15. 用户复验反馈与修正规格（2026-08-03）

### 15.1 反馈现象

用户在宽屏真实 App 中复验后指出：

- 概览仍被 `1120px` 最大宽度限制在画面中央，左右留白明显。
- Agent 总览固定三列且同样受窄容器限制，七个 Agent 不能充分平铺到屏幕。
- 设置仍保留旧的独立左侧目录和返回入口，与全局顶部导航重复；部分窗口状态下内容被裁切。

### 15.2 修正目标

- 一级工作区采用“全宽运维画布”：仅保留稳定的 28px 页面边距，宽屏不再限制为 1120px。
- Agent 网格在宽屏显示四列，在常规窗口显示三列，在窄窗口显示两列。
- 设置与概览、Agent 共用相同页面标题、边距和顶部导航；设置分类使用 shadcn `Button` 组成的
  横向二级导航，并允许在空间不足时换行。
- 设置内容占满剩余宽度，但表单内部继续保持可读分组；不改变设置保存、主题、语言、Agent 显示、
  路由表、插件和关于的现有业务行为。

### 15.3 非目标与红线

- 不修改任何设置值、Agent 接入状态或路由配置。
- 不因全宽布局放大字号或卡片，保持当前高密度控制台风格。
- 不引入新的页面层级、后端契约或第二套组件库。

### 15.4 复验项

- 约 1600–2000px 宽窗口中，概览卡片和 Agent 网格延伸至左右页面边距，Agent 至少四列。
- 设置页仍能访问七个分类，且不再出现独立返回按钮和重复设置壳。
- 1040×720 与 900×600 仍无整体横向滚动，设置二级导航和所有主要操作可达。

用户基于真实 App 截图确认三个视觉问题：

1. Agent 图标虽然尺寸已放大，但使用的是品牌库 `Avatar` 变体；该变体的设计就是黑色圆底配缩小标记，
   Claude Code、OpenCode、OpenClaw 仍像“没有显示图标”。
2. 概览首排摘要被代理状态中的三段 revision 链撑高，上下两层几乎等高；首排留白多，而下方路由和
   处理项承载更多信息却显得偏小。
3. 一级页面标题区同时拥有 `page-stack` gap 和自身 `margin-bottom`，形成双倍垂直间距；28px 大标题和
   62px 最小高度进一步放大了空白。

本轮目标是让工作区回到高密度桌面控制台比例：标题用于定位而非占据首屏，摘要用于快速扫视，配置和
处理内容获得更多空间。范围包括 Agent 品牌图形、共享页面标题密度、概览两层比例和对应公开测试；
不改动 Agent 显示偏好、统计、扫描、接入、路由或供应商契约。

### 21.2 视觉与布局决策

- 继续使用现有 `#f4f6fa / #ffffff / #182133 / #5368e8` 浅色基线和对应深色变量，IBM Plex Sans
  承载正文与标题，IBM Plex Mono 承载 eyebrow 和数据；不增加新字体或第二组件库。
- Agent 改用 `@lobehub/icons` 的 `Color` 品牌图形；没有 `Color` 变体的 OpenCode 使用自身 Mono
  图形，并继承当前主题前景色。图形直接置于轻量中性底，不再使用黑色 Avatar 圆底；Hermes 保留
  官方位图。
- 共享 `overview-heading` 收敛为约 46px 内容高度：H1 由 28px 降至 22px，说明文字降至 11.5px，
  删除标题自身底部 margin，依赖 `page-stack` 的单一间距。`page-title-row` 同步采用 22px 标题和紧凑
  上下间距，覆盖路由、额度和新增供应商等页面。
- 概览首排卡片目标高度约 128–136px，卡内 padding 与数字字号小幅收敛。三段 revision 链从“代理
  状态”摘要移到下方“当前路由快照”卡片，使运行卡只保留状态、revision 和监听地址。
- 下方两张主卡目标高度增至约 224px，标题、路由行和处理项适度放大，形成“紧凑摘要带 + 稳定工作区”
  的层级。Token Station 的视觉签名仍是运行状态与成本同排，而不是通用数据大屏。

布局草图：

```text
RUNTIME STATUS
概览                 管理供应商
代理运行状态、当前路由、请求与成本

┌代理 128h┐ ┌请求 128h┐ ┌Agent 128h┐ ┌供应商 128h┐
┌当前路由快照 + revision 224h──────┐ ┌下一步处理 224h───────┐
```

### 21.3 状态、失败处理与红线

- Agent 图标仅改变展示组件，不改变 registry id、可见性、状态、点击或选择行为；缺少品牌图形仍使用
  现有 fallback，图片加载失败仍回退，不请求网络资源。
- revision 链只移动展示位置，`draft/saved/running` 数据和辅助名称保持不变。
- 不自动恢复隐藏 Agent，不扫描、接管、启停代理、保存草稿或切换路由。
- 不读取或展示 prompt、response、API Key，不修改用户当前配置或统计数据。

### 21.4 响应式、键盘与可访问性

- Agent 图形为装饰内容，Agent 按钮继续通过完整名称提供可访问名称；状态不依赖图标颜色。
- 标题缩减不能改变 H1 层级、按钮焦点顺序或现有键盘行为。
- 980px 以下概览摘要允许两列，860px 以下 Agent 主从仍折叠；紧凑规则不得造成文本裁切或壳层横向
  滚动。
- 深色主题下 Mono 图形继承 `--ink`，中性图标底使用主题变量，避免黑底黑标。

### 21.5 公开测试边界与验收标准

公开 seam 已由用户截图确认：Agent 列表按钮内的可见品牌图形、概览摘要区域、路由快照和一级标题。

- Claude Code、OpenCode、OpenClaw 不再渲染带 inline 黑色背景的 Avatar 容器，仍有品牌 SVG。
- revision 状态链不再位于“系统摘要”区域，而位于“当前路由快照”卡片；辅助名称保持不变。
- 1040×720 真实 App 中标题区明显缩短，概览首排低于下方主卡；四卡仍同排且内容无裁切。
- Agent 左栏品牌标记在浅色和深色下可辨识，不再呈现空黑圆；列表固定与右侧独立滚动行为保持。
- 前端全量测试、生产构建、桌面安装审计、真实 App 验收和中文本地提交全部完成。

## 23. 第五轮细节修正规格（2026-08-03）

### 23.1 问题、目标与范围

用户基于浅色与深色真实 App 截图确认四个问题：

1. Agent 品牌图形已经可见，但不同 SVG 的 viewBox 留白不同，直接以统一宽高渲染时出现光学偏移；
   图形与外框没有稳定的共同中心。
2. Agent 详情中的“智能分档 / 额度优先”选项在浅色主题下使用了过近的底色、边框和次级文字色，未选中
   项尤其难以快速辨认。
3. 顶部“启动代理”按钮高度、横向 padding 和图标比例仍明显大于相邻主题与供应商操作，破坏顶栏平衡。
4. 设置中的“路由表”和“插件”是只读技术页面，当前产品不需要暴露，增加了导航噪声。

本轮只修正上述显示与信息架构，不改动 Agent 扫描、接入、路由策略保存、代理启停、插件加载或后端
契约。设置中删除的是用户入口与页面分支，不删除插件运行能力和路由决策实现。

### 23.2 视觉与交互决策

- Agent 图标外框继续使用主题中性底与圆角边框；内部新增固定的光学居中层，采用绝对居中而非依赖 SVG
  自身行盒。品牌图形按可见轮廓控制在 30–34px，并允许对已知不对称图形做不超过 1px 的品牌级光学校正。
- Agent 路由策略使用清晰的二选一卡片：浅色主题下容器、选中项、未选中项至少形成边框或底色层级，
  标题使用正文前景色，说明使用次级前景色；选中项额外使用信号蓝描边和轻量蓝底，不只依赖阴影。
- 顶部代理按钮降为 38px 高度，图标约 18px，监听地址保留但降为辅助字号；宽度由内容决定，不再形成
  近似主 CTA 的大色块。它仍比普通导航更醒目，并保留完整可访问名称。
- 设置分类仅保留“通用、Agent 显示、外观、语言、关于”。移除“路由表”和“插件”的导航按钮、页面
  分支及对应不可达导入；不自动改变当前用户配置。

### 23.3 失败处理、安全与数据红线

- 品牌图形加载失败继续使用现有 fallback；不通过网络下载图标。
- 路由策略视觉调整不改变 tab 值、禁用条件、键盘切换、保存动作或后端 payload。
- 删除设置入口不得删除插件目录、WASM 包、路由表数据或 CLI 能力。
- 不启动代理、不扫描或接管 Agent、不保存路由、不读取或展示 API Key、prompt、response。

### 23.4 响应式、键盘与可访问性

- 图标为装饰内容，Agent 按钮的可访问名称继续来自 Agent 名称和状态。
- 路由策略保持 `tablist/tab` 语义、可见焦点和键盘操作；浅色、深色均不以颜色作为唯一选中提示。
- 900px 以下顶栏仍可安全收缩；38px 代理按钮不得与主题或供应商按钮重叠。
- 设置移除两项后保持原顺序与单列键盘焦点流，不留下空白分组或不可达选中状态。

### 23.5 公开测试边界与验收标准

公开 seam 为用户可访问的一级导航、Agent 列表按钮、Agent 路由策略 tab 和设置分类按钮：

- Agent 列表每个品牌图形都位于固定居中容器内，品牌 SVG 不直接承担按钮内布局。

  两项标题、说明和边界均清晰可见。
- 顶部代理按钮仍显示“启动代理”和监听地址，但真实 App 中高度与相邻操作接近，不再占据过大面积。
- 设置分类中不存在“路由表”和“插件”，其余五项仍可访问并正常切换。
