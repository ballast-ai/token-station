# 主页 Agent 手动重新扫描设计

## 问题

当前桌面端只在启动时扫描一次本机 Agent。用户在 Token Station 已打开时安装、卸载或修复 Agent CLI，主页不会重新发现变化；旧版曾提供的“重新扫描”入口在主页整合过程中被移除。

## 目标

- 在主页左侧“本机客户端”卡片恢复明确的“重新扫描”按钮。
- 扫描成功后，以最新本机扫描结果更新 Agent 安装状态和默认可见列表。
- 使用项目现有组件库，不新增平行按钮样式或自定义图标实现。
- 扫描失败时保留上一次可用结果，并给出可理解的错误提示。

## 范围与非目标

范围包括主页和 Agent 详情共用的 Agent 选择列表、扫描状态、结果刷新和公开行为测试。

本次不增加自动轮询，不改变启动扫描，不修改 Agent 配置，不自动安装或卸载任何 CLI，也不把刷新入口重复放到概览页。

## 安全与数据红线

- `scan_agents` 仅用于读取本机安装事实；刷新动作不得写入或接管 Agent 配置。
- 不清除用户保存的“隐藏 Agent”或“显示未检测 Agent”偏好。
- 扫描失败不得用空列表覆盖上一次成功结果。
- 同一时刻只允许一个手动扫描请求，避免并发结果互相覆盖。

## 用户可见交互与状态

1. “本机客户端”标题栏右侧依次显示当前可见数量和“重新扫描”按钮。
2. 按钮使用现有 shadcn `Button` 的 `outline`、`sm` 规格和 Lucide `RefreshCw` 图标。
3. 点击后按钮禁用，图标旋转，文案变为“扫描中…”。完成前重复点击不产生第二个请求。
4. 扫描成功后：
   - 新检测到且未被用户隐藏的 Agent 默认出现在列表中；
   - 已不再检测到的 Agent 默认从列表移除，但用户明确设置为“显示未检测 Agent”的项目继续显示，并标记“未检测”；
   - Agent 的安装实例和状态使用新结果替换。
5. 如果当前打开的 Agent 在刷新后不再可见，返回主页的全局路由。
6. 扫描失败时恢复按钮可用状态，保留原列表，并使用既有 Toast 错误组件提示失败原因。

## 响应式、键盘与可访问性

- 标题操作区允许紧凑排列，不挤压标题；沿用卡片现有响应式宽度。
- 按钮可通过 Tab 聚焦并使用 Enter/Space 触发。
- 扫描中使用禁用状态和可见文案表达，不只依赖旋转动画；减少动态效果模式下停用旋转动画。
- 图标为装饰内容，不重复朗读；按钮文字作为无障碍名称。

## 公开测试边界与验收标准

- 启动仍只自动调用一次 `scan_agents`，主页可见“重新扫描”按钮。
- 点击按钮只新增一次扫描调用；请求期间按钮显示“扫描中…”且不可用。
- 成功返回新的安装结果后，新检测到的 Agent 出现在列表中。
- 失败时旧列表不变、按钮恢复可用且显示错误提示。
- 概览页不出现重复的“重新扫描 Agent”入口。
- 全量前端测试、前端构建、Rust 工作区测试通过。
