# Agent 主页与单独路由整合设计

- 日期：2026-08-11
- 状态：已实现并验收（2026-08-12）
- 范围：Desktop 首页/概览/供应商 UI、Agent 生命周期、Desktop 控制面契约、CLI 宿主路由配置与 Gateway
- 不涉及：DMG、发布上传、远端推送、生产切换

## 1. 问题

当前桌面端把“概览”“路由”和“Agent”作为三个顶层页面。应用先渲染 Registry
中的全部 Agent，再异步扫描并反复重扫，导致现在已经承担主页职责的 Agent 页面在启动后
持续变化。全局路由与 Agent 接入分离，也让“先选路由、再接入 Agent”的核心工作流跨页。

路由目前只有三档智能路由与额度优先。缺少一种与 CC Switch 相同的显式一对一路由：
用户选择一个供应商及其已管理模型，点击应用后，所有请求只走这一对目标。额度优先列表和
三档 pool 的顺序都具有真实路由语义，不能借用它们保存纯展示的拖拽顺序。

此外还存在以下一致性问题：

1. 代理未启动时“一键接入”被禁用，用户必须先手动启动。
2. 操作型错误散落在页面内，遮断布局且不能统一关闭。
3. 概览在最终 CSS 级联中被取消最大宽度，横屏时铺满；快捷键列与上方“已接管
   Agent”不严格左对齐；整体字号偏小。
4. 策略组删除入口已存在但藏在“存为策略”展开区；Agent 的“当前策略组”仍是原生
   `select`。
5. 额度计划已经使用统一组件，但标题、间距和说明文案仍不易读。
6. 供应商管理列表和路由下拉框没有复用添加供应商页已有的品牌图标。

## 2. 目标

1. 顶层只保留“主页、供应商、用量、设置”；点击左上角 Token Station 品牌按钮才进入
   原概览。
2. 应用默认进入合并主页。左侧第一行固定为“全局路由”，后续只列本进程启动扫描发现的
   Agent；右侧显示当前选择的全局路由或 Agent 配置。
3. 业务主页必须等启动扫描完成后一次性出现；进入主页后不再执行会改变页面成员或顺序的
   展示扫描。
4. 新增 `direct` 单独路由，位于三个路由策略的第一列，并作为新建桌面配置的默认模式。
5. 单独路由逐行列出供应商图标、名称和该供应商已管理模型的下拉框；整行选择，浅蓝高亮，
   右下角“应用”才提交。
6. 供应商行可以通过左侧盲文拖拽柄或键盘调整展示顺序；顺序永远不参与实际路由。
7. 一键接入在代理停止时自动启动代理，等待同一运行实例真正可达后再规划和应用接入。
8. 操作型/请求型错误统一显示为左下角可关闭 toast，8 秒后渐隐；字段校验和致命恢复错误
   保持就地可修复。
9. 概览恢复居中最大宽度，所有字号提高一级，快捷键列与“已接管 Agent”指标左边缘对齐。
10. 让策略组删除入口可发现、当前策略组使用统一下拉组件；额度计划文案易读；供应商菜单
    和管理列表展示品牌图标。

## 3. 范围与非目标

### 3.1 范围

- CLI 增加宿主层 Home/Agent Direct 配置，并把 Direct 编译为受约束的单成员
  `RouterConfig`；冻结的 `router-core` 不增加第三种 wire mode。
- Gateway 继续只消费 `router-core` 的 Tiered/QuotaFirst 两态，Direct 编译结果走现有
  Tiered 纯函数路径。
- Desktop 新配置模板、StateView、命令、Provider 引用保护和启动状态机。
- Desktop 启动扫描门禁、缓存快照运行态叠加、导航/首次引导、合并主页。
- Direct 路由面板、错误 toast、策略组/额度/供应商图标、概览布局与响应式。
- 对应公开行为测试、文档、构建、本地 App 安装和真实界面验收。

### 3.2 非目标

- 不删除接入事务内部的路径、版本、配置指纹与代理实例安全复核。
- 不让拖拽顺序成为故障转移、额度优先级或默认目标。
- 不把历史缺省配置静默迁移成 Direct；不自动选择第一家供应商。
- 不强制删除仍被 Agent 挂载的策略组，不增加级联删除语义。
- 不重做额度计划后端、多窗口额度模型或实时额度算法。
- 不隐藏历史统计中的已卸载 Agent；“只显示发现 Agent”只约束业务主页。
- 不新增远程图片、网络字体或新的前端组件依赖。
- 不打包或发布 DMG，不修改 Release 渠道。
- 不修改、格式化或放宽受 CI 冻结门禁保护的 `crates/router-core/**`。

## 4. 不允许触碰的安全与数据红线

1. Direct 的运行目标只能来自用户点中行、选择模型并点击“应用”提交的稳定
   `(upstream, model)`；不得由数组首项、拖拽位置或 Provider 名字排序推断。
2. Direct 决策必须 `fallbacks=[]`；非目标供应商永远不能因健康或顺序变化被尝试。
3. `local_only`、能力约束、健康状态和 Provider 出站授权继续生效；Direct 不是绕过安全
   闸门的快捷路径。
4. 历史 JSON 缺省宿主层 `routing` 时，继续从 `router.routing_mode` 派生 Tiered 或
   QuotaFirst。只有新 Desktop 模板显式写 `routing.mode: "direct"`。
5. Provider 删除、模型移除和启动草稿清理必须覆盖 Home/Agent direct target 与既有
   `quota_accounts`，不能留下悬空引用，也不能擅自改选下一家。
6. Agent 展示扫描每进程只执行一次，但 `plan_agent_connection` 与 `apply_agent_plan`
   的 TOCTOU 安全复核必须保留；安全复核不能改变前端启动时固定的 Agent 成员集合。
7. 自动启动成功而 Agent 接入失败时保留代理运行，不能自动停止并影响其他 Agent。
8. 代理 `Starting`/`Applying` 时加入同一 generation 的等待；`Stopping`、generation
   被替换、启动失败或超时必须停止接入，不能向旧实例写配置。
9. 不记录或展示 API Key、请求正文、响应正文、未脱敏配置差异或其他敏感数据。
10. 构建失败时保留当前 `/Applications/token-station.app`；安装脚本只能替换 bundle id
    为 `com.tokenstation.desktop` 的明确目标。

## 5. 需要保留兼容的事实

### 5.1 路由缺省兼容

`router-core::RoutingMode` 仍只有 Tiered/QuotaFirst，且其 Serde 缺省保持 Tiered。
CLI 新增可选宿主层 `routing`；它缺失时从既有 `router.routing_mode` 派生。新模板可以
暂时处于 `routing.mode = direct`、`direct_target` 未配置的编辑态，但保存/启动必须返回
明确错误。不能把旧配置中缺省宿主层字段解释成 Direct，因为这会静默改变现有用户的数据面。

新 App 写入顶层 `routing` 后，旧二进制因 `ClientConfig::deny_unknown_fields` 无法回读，
属于明确的向旧版本回滚风险。该行为是失败闭合：旧版不会把 Direct 静默解释成额度路由。
依赖现有配置原子写入、备份和恢复机制，不伪装成双向兼容。

### 5.2 扫描与安全复核

“启动后不再扫描”定义为：不再执行会重新生成 UI Agent 成员集合的展示扫描。Connector
写入前仍须重新确认精确安装路径、版本、配置指纹、Connector 与 proxy runtime 指纹。
这类复核属于写入授权边界，不驱动页面新增、删除或重排 Agent。

### 5.3 错误提示边界

- 操作型、请求型错误：进入左下角 toast。
- 字段校验、阻止应用的配置缺失：继续与字段/按钮相邻显示，可同时触发 toast，但不能只剩
  8 秒提示。
- Bootstrap/Recovery 致命错误：继续持久显示并保留重试入口。
- 内容区加载失败且会替代整个内容：保留内容态和重试动作；瞬时刷新失败进入 toast。

## 6. 信息架构与状态模型

### 6.1 合并主页

内部保留 `home` 与 `agent:<id>`，但二者都映射到顶层“主页”菜单：

```text
主页
┌────────────────────┬─────────────────────────────────────────────┐
│ ◉ 全局路由          │ 路由策略：单独路由 / 智能分档 / 额度优先      │
│   本机默认 · 固定首行 │ 当前策略对应的配置面板                        │
├────────────────────┼─────────────────────────────────────────────┤
│ Claude Code         │ 当前 Agent 接入与路由                          │
│ Codex               │                                             │
│ ...仅启动扫描发现项  │                                             │
└────────────────────┴─────────────────────────────────────────────┘
```

- `home` 默认选择固定的“全局路由”条目。
- `agent:<id>` 选择对应 Agent，但“主页”菜单继续高亮。
- 当前 Agent 被隐藏或失效时回到 `home`，不跳概览。
- 空扫描仍显示全局路由和稳定 Agent 空态。
- Settings 的 Agent 显示偏好继续列 Registry 支持项；主页取“启动发现集合 ∩ 未隐藏集合”。

### 6.2 启动门禁

1. 先完成现有 Recovery bootstrap。
2. 正常模式订阅 serve state。
3. 并行读取 State、Registry 和一次 `scan_agents`。
4. 三者全部成功后一次性提交 React 状态并显示主页。
5. 保存不可变 `detectedAgentIdsAtBoot`，仅含 `installations.length > 0` 的 Agent。
6. 后续 cached overlay 只更新这些 ID 的 `managed/connected/adapter_ready`，不能扩大成员集合。
7. 扫描失败停留在启动错误态并允许重试；成功进入主页后不再显示扫描按钮。

### 6.3 缓存快照运行态叠加

新增只读 `get_cached_agent_views`：复用进程内扫描快照重新读取 ownership、配置和当前
runtime overlay，不调用 DiscoveryScanner、版本探测或展示扫描。无快照返回
`scan_required`。接入、恢复和代理状态切换后通过该命令更新卡片状态。

### 6.4 自动启动门禁

新增幂等 `ensure_serve_running`：

| 当前生命周期 | 行为 |
|---|---|
| Running 且 listener 可达 | 立即返回，不保存、不重启、不增加 revision |
| Starting | 等待当前 generation |
| Applying | 等待新 generation 完成，不使用旧 runtime 规划 |
| Stopped / Failed | 发起一次启动并等待同一 generation 可达 |
| Stopping | 明确返回“代理正在停止，请稍后重试” |
| generation 替换、失败、超时 | 返回确定错误，不进入 plan/apply |

完整接入顺序：

```text
ensure_serve_running
  → plan_agent_connection（安全复核）
  → apply_agent_plan（再次复核与事务写入）
  → get_cached_agent_views（只更新运行态叠加）
```

## 7. Direct 数据与路由契约

### 7.1 公共配置

- CLI 宿主层 `RoutingMode::{Tiered, Direct, QuotaFirst}`，wire 分别为
  `tiered/direct/quota_first`；它不扩展冻结的 `router-core::RoutingMode`。
- `ClientConfig.routing: Option<HostRoutingConfig>`，包含 `mode` 与可选
  `direct_target: UpstreamModel`；缺失时兼容既有 `router.routing_mode`。
- `AgentRouteConfig.direct_target: Option<UpstreamModel>`；Agent 未显式设置时继承 Home
  direct target，显式应用后只覆盖该 Agent。
- 新 Desktop 模板显式 `routing.mode: "direct"`；历史缺省仍按原 core mode 运行。

### 7.2 路由决策

CLI 的 `compile_router_config` 把 Direct 编译为一个临时 Tiered 文档：只保留名为
`direct` 的单成员 pool，清空 rules、hints 与 heuristic，关闭 exact-model override，
恢复策略固定为 Strict，保留 local-only、cloud-fallback 与上下文窗口。Gateway 随后调用
既有 `Router::route`，因此继续复用能力、local-only 与健康约束。结果固定为：

```text
chosen   = direct_target
fallbacks = []
pool     = "direct"
decided_by = Default（避免扩大 metrics schema 迁移）
```

目标缺失、目标没有所需能力或被安全策略拒绝时直接失败，不回退到别的 Provider。
编译后的 Direct 在 core 中表现为 Tiered 单成员路由，因此 quota preamble、lease、settle
和 quota receipt 仍只在真正的 `QuotaFirst` 执行。

### 7.3 Desktop 应用命令

`set_direct_route(upstream, model, agent_id?)`：

- 先校验 Provider 与模型确实存在于已管理目录。
- Home 无 `agent_id` 时只写顶层 `routing.direct_target`。
- Agent 有 `agent_id` 时只写对应 `agent_routes.<id>.direct_target`。
- 校验或 revision 写入失败时，draft/revision/disk 均保持不变。
- 选择行、修改模型和拖拽都不能调用该命令。

Home 的“应用”执行 `set_direct_route → serve_start`；Agent 的“应用此 Agent”执行
`set_direct_route(agent) → restart_agent_route(agent)`，不得重启或改变兄弟 Agent。

### 7.4 引用保护

以下位置都必须扫描顶层 `routing.direct_target`、Agent direct target 和
`router.quota_accounts`：

- Provider 删除预览与删除门禁。
- Provider 模型替换门禁。
- 启动草稿的悬空引用清理。

Provider 不存在时清空悬空 target；Provider 存在但模型被移除时保留 Provider 并清空
模型，mode 仍为 Direct，UI 明确显示未完成。不得自动选择第一家或第一个模型。

## 8. Direct 用户交互

Direct 面板维护三个互相独立的状态：

1. 展示顺序 `providerOrder`，只存 UI preference/localStorage。
2. 当前草稿选择 `selectedProvider + modelByProvider`。
3. 后端返回的已应用 `directTarget`。

```text
单独路由 · 默认
请求固定发送给你明确选择的一个供应商和一个模型

⠿  [DeepSeek 图标] deepseek               [deepseek-chat      ▾]  ◉
⠿  [OpenAI 图标]   openai                 [gpt-5.6            ▾]  ○
⠿  [自定义首字母]   internal_gpu           [qwen3              ▾]  ○

                                                     [应用]
```

- 每个 Provider 恰好一行，模型选项只来自 `ProviderView.models`，不读 catalog cache。
- 行使用 radio 语义和可见选中标识；浅蓝色不是唯一状态信息。
- 行容器不能是包含下拉框的嵌套 button。
- 拖拽柄可鼠标拖动，并支持键盘上移/下移；React key 使用 Provider 稳定 name。
- Provider 集合变化时：去重已知顺序、丢弃删除项、把新项追加到末尾。
- 应用使用选中 Provider 的稳定 name 查找 target，绝不能读取第一行或数组 index。
- 无 Provider、无模型或目标失效时禁用应用并说明修复动作。

## 9. 视觉设计基线

### 9.1 产品、受众与单一任务

- 产品：本机 LLM Agent 路由控制台。
- 受众：管理多个 Agent、Provider 与模型的 AI 工程师。
- 合并主页的单一任务：明确“哪个 Agent 通过哪个路由运行”，并用一次显式应用改变它。

### 9.2 Token 系统

- Canvas `#f4f6fa`：工作区底色。
- Surface `#ffffff`：卡片与控件。
- Ink `#182133`：主文字。
- Muted `#738096`：辅助说明。
- Signal `#5368e8`：当前选择、焦点和应用动作。
- Signal soft `#edf0ff`：Direct 选中行浅蓝高亮。

暗色继续使用现有对应变量，不引入第二套硬编码颜色。标题/正文使用 IBM Plex Sans；
Provider ID、模型、revision 和状态 eyebrow 使用 IBM Plex Mono。概览字号在现有固定 px
层级上整体提高一级，不影响其他页面。

### 9.3 视觉签名与自检

唯一强化元素是“固定首行的全局路由 + Direct 供应商选择轨道”：左侧路线标识、右侧
盲文柄和品牌行把路由选择表现为本机控制台的物理接线，而不是通用设置表单。

没有引入渐变 hero、巨大数字或装饰性动画；拖拽、选中和应用都编码真实状态。大胆之处只
用于路由轨道，其余卡片、字体和颜色继续服从现有桌面视觉系统。

## 10. 其他用户可见调整

### 10.1 导航与概览

- 顶层菜单：主页、供应商、用量、设置。
- 品牌按钮保留中英文可访问名称，鼠标和键盘均可进入概览。
- 初始、返回 fallback、首次引导完成、隐藏当前 Agent 等程序化跳转统一回主页。
- 概览 `.overview-main-grid` 改为等宽两列，使快捷键列左边缘与四等分指标的第三列
  “已接管 Agent”严格对齐。
- 最终 CSS 级联处恢复概览 `max-width: 1120px; margin-inline: auto`。
- 概览固定字号逐项提高一级；内容不足不拉伸到两侧，内容过高继续由主容器滚动。

### 10.2 错误 toast

- 左下角固定堆叠，`role="alert"`，不抢焦点。
- 每条有“关闭错误提示”按钮；8 秒后进入渐隐并移除。
- 同一稳定错误 ID/相同 runtime error 去重，轮询不能重复堆叠。
- 导航不清空 toast；组件卸载清理 timer。
- `prefers-reduced-motion` 下取消渐隐动画，但仍在 8 秒后移除。

### 10.3 策略组

- 保留已有安全删除命令及“挂载中拒绝删除”语义。
- 删除入口迁移到可发现的策略组管理区。
- Agent “当前策略组”使用统一 Select/Combobox；选择仍调用 `mount_agent_profile`。
- 现有 UI 文案“独立路由”（实际为自定义三档）改为“自定义三档”，避免与 Direct
  “单独路由”重名。

### 10.4 额度计划

- 保持额度优先面板内的现有业务位置与 Field/Input/Select/Separator。
- 标题统一为“额度计划（可选）”。
- 中文说明拆成两句：
  - “填写供应商的额度上限和刷新周期后，Token Station 会在本机估算剩余额度。”
  - “若供应商会自动上报额度，则无需填写。”

### 10.5 供应商图标

- ProviderView 暴露只读稳定 `brand_id`，不把可重命名的 upstream name 当品牌 ID。
- Provider 管理列表、三档 Provider 下拉、额度 Provider 下拉和 Direct 行复用
  `ProviderIcon`。
- 下拉 trigger 与 option 都显示图标；图标装饰性隐藏，文本仍是可访问名称。
- 免费供应商使用目录提供的 brand alias；自定义 Provider 使用首字母 fallback。

## 11. 响应式、键盘与可访问性

- 1040×720 默认窗口保持双栏；900×600 最小窗口不得横向溢出。

## 15. 计划实现落点与遗留风险

计划实现落点见影响面地图。已知风险：

- 包含顶层 `routing` 的新配置不能由旧二进制读取，属于失败闭合的向旧版本回滚兼容边界。
- 仓库 `router-core` frozen-baseline 检查器的远端固定 SHA 已落后于当前 develop tree；本任务
  保证相对任务起点零差异并通过本地 frozen-tree 检查，但远端基线治理仍需门禁所有者处理。
