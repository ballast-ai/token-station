# 配置指纹与三方漂移检测设计

> 日期：2026-07-22
> 对应任务：第二批协作任务 #2
> 状态：实施依据
> 范围：`apps/desktop/src-tauri/src/agent_integration/**`、`apps/desktop/src/**`

## 1. 问题定义

Token Station 接管 Agent 配置后，配置文件仍可能被用户、Agent 升级器、编辑器或其它工具修改。现有系统已经有：

- Discovery 的结构形状指纹；
- 接管前加密快照；
- Ownership 中的 `before_hash`、`managed_after_hash`、owned paths 和 owned-value HMAC；
- 写入前 hash 复核及失败回滚。

但这些事实尚未形成一个用户可见的只读对账结果。Discovery 的结构形状指纹刻意忽略值，不能用于判断配置是否漂移；是否仍“已连接”也只验证 Connector 投影，不能解释外部具体改了哪些字段。

本设计增加三方对账：

```text
接管前 baseline        我们最后写入 managed        当前磁盘 current
加密 baseline snapshot  Ownership managed hash      重新只读文件并计算 hash
```

## 2. 不变量

1. 查询漂移是零写入操作：不写 Agent 配置、不更新 Ownership、不创建快照、不刷新“最后写入”事实。
2. baseline 配置和 current 配置的原始值不进入 IPC、普通日志或前端状态。
3. 前端只接收 hash、状态、结构路径、变化类型和是否属于受管字段。
4. managed 事实以 Ownership 为准，不用当前磁盘内容反向伪造。
5. owned path 使用每路径 HMAC 判断是否仍等于最后写入值；HMAC 不解密、不降级为明文。
6. current hash 等于 managed hash 才是完全无漂移；只要不同就必须显示原因或 typed error。
7. 文件缺失、不可读、不可解析、快照/keychain 不可用均单独表示，不能显示成“无漂移”。
8. 检测不触发“重新接管”或“保留外部改动”；这些是用户确认后的独立写工作流。

## 3. 状态模型

`DriftStatus`：

| 状态 | 含义 |
|---|---|
| `unmanaged` | 该精确安装没有 active Ownership |
| `in_sync` | current hash 等于 managed hash |
| `unowned_changes` | current hash 不同，但所有 owned path HMAC 仍匹配；外部只改了非受管字段 |
| `managed_changes` | 至少一个 owned path HMAC 不匹配 |
| `missing` | 接管目标文件当前不存在 |
| `unreadable` | 文件或 keychain/snapshot 无法安全读取 |
| `unparseable` | 当前文件不再符合 Connector 的结构化格式 |

每个结果包含：

```text
AgentDriftView
  agent_id
  installation_path
  target_config_path
  connector_id
  status
  baseline_hash
  managed_hash
  current_hash?
  checked_at_ms
  changes[]
  message
```

`DriftChange`：

```text
path             # 结构路径，不含值
scope            # managed / unowned
kind             # added / removed / changed / managed_projection
current_matches_managed?
```

前端不接收 baseline/current/managed 的字段值。受管敏感字段与普通受管字段采用同一“路径 + 状态”表达，避免 IPC 类型未来意外增加值容器。

## 4. 对账算法

### 4.1 事实加载

1. 调用方必须给出 `agent_id + installation_path`，并精确命中最近一次服务端扫描。
2. 从 OwnershipStore 按精确安装列出 active 记录；无记录返回 `unmanaged`，多记录逐目标返回，不猜目标。
3. 使用 `baseline_snapshot_id` 解密接管前快照，只在后端内存中保留 zeroizing bytes。
4. 用 Connector 的格式解析 baseline 和 current；复用现有文件大小、格式、重复键和 YAML/JSON5/TOML 安全边界。
5. 用 `file_revision_hash` 计算 current hash；baseline/managed hash 分别使用 Ownership 中的 `before_hash/managed_after_hash`。

### 4.2 快速路径

若 current hash 等于 managed hash，返回 `in_sync`，`changes=[]`。此时不需要把语义树送入 diff。

### 4.3 owned path 对账

对 current document 重新计算每个 owned path 的 HMAC，与 Ownership `owned_value_macs` 逐项比较：

- 相等：该受管字段仍是 Token Station 最后写入值；
- 不等：加入 `scope=managed` 的 change；存在性变化决定 added/removed，否则为 changed。

managed 的原始值不需要被恢复或持久化；Ownership HMAC 已足以回答“当前是否仍等于我们写入的值”。

### 4.4 非受管字段 diff

baseline 与 current 转为规范语义树后做递归 diff：

- object：按 key 并集递归；
- array 或 scalar：作为当前路径的一个整体变化，不展开可能高基数的数组元素；
- 进入任何 owned path 或其后代时停止，避免把 Token Station 自己的投影误报为外部改动；
- 最多返回 200 条，单路径最多 512 字节；超限时返回明确截断标记。

若 current hash 不同、所有 owned path 匹配且存在非受管 diff，状态为 `unowned_changes`。若 owned path 不匹配，状态为 `managed_changes`，同时可以附带非受管 diff，便于用户完整对账。

## 5. IPC 与 UI

新增只读命令：

```text
get_agent_drift(agent_id, installation_path) -> AgentDriftView[]
```

安全边界：

- 路径必须精确命中最近一次扫描，renderer 不能提交任意配置路径；
- target path、Connector、snapshot 和 Ownership 全由服务端关联；
- 返回类型没有任意 JSON value、配置片段或日志文本字段；
- 命令不接受“修复”“采用”或 patch 参数。

Agent 页面在精确安装诊断区增加“配置对账”只读面板：

- 三列展示接管前、最后写入、当前磁盘的短 hash 和状态；
- 展示 changed paths、受管/非受管范围和变化类型；
- `in_sync` 明确显示无漂移；
- 错误状态给下一步建议，但不自动修改；
- 多安装未选择前不查询。

## 6. 测试缝

1. 纯后端 `analyze_drift`：输入 baseline/current document、Ownership 和 key，观察 typed view；不 mock 内部 diff helper。
2. Tauri command seam：通过精确扫描记录、真实 FileOwnershipStore 和加密 FileSnapshotStore 查询，证明零写入和任意路径拒绝。
3. React Agent 页面：mock 单一只读 IPC 返回，验证三方状态与路径展示；不测试内部调用次数以外的实现细节。

关键 fixture：

- current == managed；
- 只改非受管 theme；
- 修改/删除受管 key；
- 同时修改受管和非受管字段；
- current 文件缺失；
- current 格式损坏；
- baseline snapshot/keychain 不可用；
- 200 条以上 diff 截断；
- 敏感值不出现在序列化 view、错误和日志中。

## 7. 通过条件

1. 外部修改受管或非受管字段后，面板准确列出结构路径和归属。
2. 三个 hash 来源明确，current 不能覆盖 managed 事实。
3. 查询前后目标文件、Ownership index、snapshot index 的字节和 mtime 不变。
4. IPC 序列化结果不包含 baseline/current 原始值、virtual key 或任意配置 JSON。
5. 文件缺失、格式错误、keychain/snapshot 失败均 fail-closed 且不自动覆盖。
