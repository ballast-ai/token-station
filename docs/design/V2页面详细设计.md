## 零、全局口径与设计约定

### 0.1 呈现形态

- 原型按**交付物③ 平台 SaaS + 余额计费**形态呈现（与 v1-prototype 同口径，便于直接对照看增量）。交付物②（私有部署 Team/Enterprise）共用同一套页面，差异由 license 开关矩阵控制：**Enterprise 专属能力在页面上以 `Ent` 徽章标注**，Team 档实例中这些区块呈灰置/升级引导态（详设约定：不隐藏，显示「需 Enterprise license」，作为升档转化触点）。
- 计费三模式（balance/quota/credits）P3 起为**实例级运行时配置**〔V2-P3-5〕：用户侧 billing 页按余额模式画；quota/credits 形态下充值/余额区块整体替换为配额视图（沿 V1 admin「额度」页词汇），不另出一套页面。
- 交付物①（本地客户端）**无本地 Web 界面**（CLI 是唯一本地管理面〔V2-C1-6〕）；客户端相关的云端页面 = 用户侧「设备与客户端」页（§2.14）+ 管理侧「客户端发布」页（§3.16），即业务模式 §三「控制面在云端、数据面在本地」的 Web 落点。
- V1 构建者画像（M9）平台形态默认下线，V2 页面不再出现；其导航位由「设置」接替。

### 0.2 阶段标注体系

页面与区块统一用徽章标注**首次交付阶段**，原型中以 `stage-*` 样式呈现（assets/v2.css）：

| 徽章 | 含义 | 原型配色 |
|------|------|---------|
| `V1` | V1 已有，保留直用或仅文案微调 | 灰 |
| `P1` | 决策链路 + BYOK + 接入产品化 | 靛（accent） |
| `P2` | 质量侧路由 + 路由透明 | 青（info） |
| `P3` | 多租户 + 计费产品化 + Enterprise | 琥珀（warn） |
| `P4` | Preset + 学习型路由 + 数据飞轮 | 粉 |
| `C2` | 客户端 C2 的服务端配套（随 P3 交付）| 绿（ok） |
| `Ent` | license 门槛：仅 Enterprise 档启用 | 红边描线 |

约定：页面标题旁标注该页**主体阶段**；区块（card）标题旁标注该区块阶段；同区块内晚期字段在详设表中单独注明。开发某期时，晚于该期的区块整体不渲染（不是置灰——置灰仅用于 license 门槛）。

### 0.3 视觉与组件

- 骨架、设计 token、全部基础组件沿用 `v1-prototype/assets/dash.css`（源自 V1 源码 `src/templates/dash.css`），明暗双主题不变。
- V2 新增组件**只增不改**，收敛在 `v2-prototype/assets/v2.css`：阶段徽章（`stage-*`）、决策时间线（decision-detail 逐层视图）、成本旋钮滑杆、开关矩阵表、版本历史行内 diff 提示。禁止在单页内写与 dash.css 语义重复的样式。
- 原型为静态 HTML，全部数据为模拟数据；交互（表单提交、筛选生效）以本文「交互」列的文字为准，原型只呈现视觉状态。

### 0.4 一个必须分清的口径：服务端 BYOK ≠ 客户端 BYOK

不变式 V2-NF-2 已拆成两个口径：**客户端 BYOK** key 永不上传云端；**服务端 BYOK** 是用户主动托管给 SaaS/私有部署网关、由网关代理直连的凭证。用户侧「自带上游」页（§2.5）管理的是服务端 BYOK〔V2-P1-4〕；本地客户端的 BYOK key 只存本地，云端配置 profile 里只有引用名。页面文案须显式区分（「此处录入的 key 由平台加密保管、用于服务端代理直连；本地客户端的 key 永不上传，见设备页」），避免用户误读隐私承诺。尤其注意：SaaS 服务端 BYOK 不等于平台对请求内容不可见，它只改变上游账号与结算归属。

### 1.3 关键页面间闭环

- **路由透明三件套闭环**〔V2-P2-10〕：billing「本月省 $X」→ decisions 列表 → decision-detail（原因可见）→「用规则覆写」按钮预填跳转 rules 编辑器（可覆写）→ 规则命中数回流 decisions。这是 V2 产品灵魂，四页链路在原型中可点击走通。
- **BYOK 账路闭环**〔V2-P1-6〕：byok（凭证+账路模式）→ usage（billing_route 维度）→ billing（双账路分列）。
- **客户端控制面闭环**〔V2-P3-13/C2〕：devices（绑定/报表/远程配置）↔ releases（管理侧版本与授权监控）。
- **租户治理闭环**〔V2-P3-1/2/4/7〕：org（自助）↔ org-detail（平台管理员视角同一域对象）。

### 3.10 提供商 providers.html — `/admin/providers` · 主体 V1+P1/P2

### 3.11 模型 models.html — `/admin/models` · 主体 V1+P1
