# 桌面端应用内更新设计

## 1. 背景与问题

Token Station 桌面端当前只有匿名版本检查：用户点击「检查更新」后，Rust 后端查询
GitHub Releases API，前端展示是否有新版本及发布页地址。它不会下载、验签、安装或
重启桌面 App。

目标是为后续正式发布版本提供 Tauri 2 原生应用内更新能力：用户主动检查后，可以在
App 内下载当前平台的更新包、验证发布者签名、原地安装并自动重启，不再每个版本都手动
打开 GitHub、下载 DMG/MSI 和覆盖安装。

当前已经发布的 v1.1.2 没有内置 Tauri Updater、公钥或更新端点，无法通过事后修改让
它获得自更新能力。因此首个包含本设计的版本是「引导版本」：v1.1.2 及更早版本用户仍
需手动安装一次；从引导版本升级到后续版本时，应用内更新才可用。产品文案和发布说明
必须如实披露这一边界。

### 1.1 cc-Switch 调研结论与本项目取舍

以 cc-Switch `43eaf07355af145aebfee301801779e824d4c221` 源码为准，它使用 Tauri 2
Updater：配置内置公钥与 `latest.json` 端点，`createUpdaterArtifacts=true` 生成更新
载荷，manifest 为各平台提供下载 URL 和内嵌 Minisign 签名；新版将下载、安装、平台清理
和重启串进 Rust 后端命令，避免 macOS 替换 App bundle 后继续依赖旧 WebView。它还提供
GitHub Releases 与 R2 镜像两个端点，并在启动约一秒后自动检查。

Token Station 复用“签名载荷 + 静态 manifest + 后端安装重启”这条成熟主链，但不照搬
两项做法：一是不在启动时自动联网，二是不把正式 Updater 私钥放入 GitHub Actions
Secret。前者遵守用户主动触发的隐私边界；后者遵守正式私钥只存在于离线签名环境的密钥
红线。此外，本项目不向 WebView 授予 `updater:default`，而以两个窄 Rust IPC 收口检查与
安装权限。

## 2. 目标

1. 保留用户主动触发的匿名检查，不在启动时自动联网。
2. 发现新版本后，在关于页和自救模式中提供明确的一键更新入口。
3. 更新包必须先完成 Tauri Updater 签名校验，校验失败时绝不安装。
4. 下载、验签失败时保持当前 App 和本地网关可用。
5. 安装前安全停止本地网关，排空在途请求并释放端口；新版启动后按现有持久化配置
   恢复，不改写 Provider、密钥、Agent 快照或用户业务数据。
6. 首版应用内更新只发布 macOS Apple Silicon 与 Intel 载荷，静态 `latest.json` 只声明
   `darwin-aarch64` 和 `darwin-x86_64`。
7. Updater 私钥不进入仓库、CI、联网开发机或 App；正式签名继续由离线环境完成。

## 3. 范围

### 3.1 本次范围

- macOS Apple Silicon 和 macOS Intel 桌面端。
- 关于页与数据库/前端异常自救模式的更新交互。
- Tauri Rust 后端更新检查、下载、进度、安装和重启链路。
- GitHub Release 静态 `latest.json` 分发。
- 桌面发布流水线生成待离线签名的更新载荷，并在签名齐全后发布。
- 更新状态、错误分类、并发防护和公开行为测试。
- 首个引导版本的发布说明与手工回退入口。

### 3.2 非目标

- 不在启动时、后台定时或网关运行期间自动检查更新。
- 不做静默自动安装，不允许绕过用户确认。
- 不引入 Cloudflare R2、S3、自建更新服务器或灰度渠道；第一版只用 GitHub Release。
- 不允许降级安装，不实现 beta/nightly 通道。
- 不更改 CLI 的 `manifest.json`、Ed25519 离线签名和可复现构建信任链。
- 不把 DMG 当作应用内更新载荷；DMG 继续用于首次安装和人工恢复。
- 不在首版公开桌面发布中支持 Windows。Windows MSI 发布与 Windows 应用内更新另开任务，
  首版 Desktop Release 跳过 Windows job，`latest.json` 不声明 `windows-x86_64`。
- 不在本次补齐 Linux 桌面发布；Linux AppImage Updater 留待 Linux 正式发布任务。

## 4. 安全与数据红线

1. **正式 Updater 私钥只存在于离线签名环境。** 不写入 Git、GitHub Actions Secret、
   构建日志、临时发布附件或联网开发机。
2. App 只内嵌公钥。公钥缺失、格式错误或与签名不匹配时，生产构建/发布必须失败；
   不能退化为「仍然安装」。
3. Tauri Updater 的签名校验不可关闭。HTTPS/GitHub 只是传输渠道，不是信任根。
4. 代码签名与 Updater 签名是两条独立门禁：macOS 仍必须通过 Developer ID、Gatekeeper、
   公证和 stapling；Windows 首版不发布，后续若发布 MSI，仍必须通过 Authenticode 和
   时间戳校验，且需单独补齐 updater manifest。
5. 正式 `latest.json` 只能引用同一正式 Release 中已完成系统代码签名、发布审计和
   Updater 离线签名的载荷。
6. 下载失败、验签失败、平台不支持、版本相同或 manifest 无效时，不停止网关、不覆盖
   当前 App、不删除旧安装包。
7. 下载完成并验证通过后才进入更新准备阶段。停止网关时复用现有 drain 语义，最多等待
   五秒，禁止直接杀死数据写入线程。
8. 更新过程不得读取、上传或写出 Provider 密钥、Agent 配置原文、请求正文、指标库内容
   或诊断包；更新请求只携带 Tauri/HTTP 必需的普通元数据。
9. 不扩大 WebView 权限：前端不直接获得 `updater:default` 或任意下载/安装能力，只能调用
   Token Station 自己的窄 IPC 命令。CSP 不新增外网 `connect-src`。
10. 不自动修改 Agent 接管文件。更新重启沿用正常 App 重启语义；如果现有退出模型无法
    证明不会遗留端口/进程，发布前必须阻断，而不是猜测。

## 5. 用户可见交互与状态

### 5.1 关于页

初始按钮仍为「检查更新」。用户点击后进入以下状态机：

| 状态 | 用户可见内容 | 可执行动作 |
|---|---|---|
| `checking` | 「正在检查更新…」 | 无，按钮禁用 |
| `up_to_date` | 当前版本已是最新 | 可再次检查 |
| `available` | 新版本号、发布日期、发布说明摘要 | 「下载并更新到 vX」 |
| `downloading` | 已下载字节、总字节和百分比（总量未知时显示已下载） | 无，防止重复触发 |
| `installing` | 「正在验证并安装…」及网关即将短暂停止提示 | 无 |
| `restarting` | 「更新完成，正在重启…」 | 无 |
| `failed` | 可理解的错误；说明旧版本未被替换或当前应如何恢复 | 重试检查；保留发布页链接 |
| `unsupported` | 当前构建未配置官方更新公钥或当前平台不支持 | 打开/复制正式发布页 |

发现更新后，安装前弹出确认：说明 App 将下载签名更新、网关会在最终安装阶段短暂停止、
在途请求最多等待五秒、新版会自动重启。取消不产生任何运行态变化。

### 5.2 自救模式

自救模式不能依赖业务指标库或完整 `AppStateManaged`。它保留检查功能；发现更新后可调用
同一后端安装命令。安装命令必须只依赖 `AppHandle` 和可选的最小运行态清理入口，业务库
损坏不能阻止下载、验签和替换 App。

### 5.3 并发与重复点击

- 同一进程同时只允许一个检查或安装任务。
- 安装进行中再次调用返回稳定的 `update_in_progress` 错误，不启动第二次下载。
- 检查可以在上一次检查结束后重试。
- 关闭确认框、检查无更新和失败不会留下永久 busy 状态。

## 6. 失败处理与回退

| 失败 | 行为 |
|---|---|
| GitHub/manifest 不可达 | 显示网络错误；当前 App 和网关继续运行 |
| manifest 无效或版本不可解析 | 视为不可信元数据，拒绝下载 |
| 当前平台没有载荷 | 显示不支持并提供发布页 |
| 下载中断 | 丢弃插件管理的临时数据；允许重试；不停止网关 |
| 签名不匹配 | 明确报告安全校验失败；绝不安装 |
| macOS 安装失败 | 保持旧进程和网关；提供 DMG 发布页人工恢复 |
| Windows 平台检查更新 | 首版显示不支持应用内更新，提供发布页人工下载入口 |
| 安装成功但重启失败 | 显示可恢复说明（若进程仍在）；下次手动启动应进入新版 |

首版 GitHub Release 必须继续保留 DMG，作为应用内更新失败后的人工恢复渠道。

## 7. 响应式、键盘与可访问性

1. 900px 最小宽度下关于页按钮和状态不得横向溢出；长版本号和错误文案可换行。
2. 所有动作使用原生按钮语义，可通过 Tab 聚焦、Enter/Space 触发。
3. 确认框具有焦点陷阱；默认焦点放在取消，Escape 取消；不能用只有颜色区别风险。
4. 检查、下载、失败和完成状态放在 `aria-live="polite"` 区域；安全校验失败使用
   `role="alert"`。
5. 下载进度使用可访问的 progress 语义；总量未知时不伪造百分比。
6. 安装中禁用按钮但保留可读文案，图标动画遵循 `prefers-reduced-motion`。

## 8. 公开测试边界与验收标准

### 8.1 已确认的公开边界

1. **前端页面边界**：通过关于页和自救模式可见控件观察状态，不断言内部 hook 或调用次数。
2. **IPC 契约边界**：前端只调用 `check_desktop_update`、
   `install_desktop_update_and_restart`，使用稳定请求/响应结构和错误码。
3. **Rust 更新服务边界**：以可注入的更新源/安装器系统边界测试检查、下载、进度、失败和
   安装决策，不访问真实 GitHub、不替换测试机 App。
4. **生命周期边界**：通过现有 serve 状态与端口可达性证明安装准备会排空并停止网关。
5. **发布产物边界**：脚本/工作流测试检查 macOS 两个平台载荷、`.sig`、`latest.json`
   映射和发布门禁；测试使用 fixture，不接触正式私钥。

### 8.2 必须通过的场景

- 无更新、发现更新、网络失败、manifest 无效、平台缺失。
- 下载进度、未知总量、重复点击、安装并发冲突。
- 签名失败不安装且网关保持运行。
- 成功载荷在最终安装阶段排空网关并进入重启状态。
- 关于页与自救模式都能触达更新路径；键盘与可访问状态可被查询。
- 引导版本缺少正式公钥时只允许检查/人工下载，不允许安装。
- `latest.json` 的版本、macOS 平台 URL 和内嵌签名来自同一组已审计产物。
- macOS DMG/App 继续通过代码签名、公证、stapling 和项目 DMG 验收。

### 8.3 真实 App 检查项

1. 执行 `scripts/install-local-desktop.sh`，确认旧 App 只在新构建审计通过后被替换。
2. 校验 `/Applications/token-station.app` bundle id 为 `com.tokenstation.desktop`，
   代码签名有效并能启动。
3. 关于页在中文/英文下能检查并正确展示结果；本地构建没有正式公钥时显示诚实的
   `unsupported`/人工下载状态，不能出现可安装假象。
4. 网关运行时检查更新不影响现有端口和请求。
5. 使用测试签名与测试端点的专项安装演练只能在隔离构建中进行，不能把测试公钥或不安全
   端点写入正式配置。

## 10. 实现落点

### 10.1 Rust 后端

新增独立 `desktop_update` 模块，避免继续把更新逻辑堆进 `lib.rs`。模块负责：

- 公开序列化类型：`DesktopUpdateView`、`DesktopUpdateProgress`。
- `check_desktop_update`：构建 updater、检查、返回稳定状态。
- `install_desktop_update_and_restart`：再次检查、下载、报告进度、安装、清理和重启。
- 进程级互斥，保证检查/安装不会并发重入。
- 系统边界 trait，仅用于测试替换真实网络/安装器，不向产品 API 暴露。

正式公钥通过生产构建环境变量 `TOKEN_STATION_UPDATER_PUBKEY` 编译进 Rust 后端；源代码、
本地构建和通用 Tauri config 都不携带正式公钥或私钥。Tauri 插件基础配置只保留显式空
`pubkey`，用于让本地 App 正常初始化；窄 IPC 会在构建期公钥为空时、任何联网之前返回
`unsupported`，不得尝试安装。

### 10.2 前端

关于页保留现有 `UpgradeView` 文案兼容，但更新到新的桌面更新契约。安装确认和进度直接由
公开状态驱动。自救模式复用相同 API，不依赖正常设置页加载。

### 10.3 发布

- GitHub Actions 使用一次性临时 Updater key 只让 Tauri bundler 生成 macOS updater
  payload；临时 `.sig` 不得进入 Release。Windows 首版不生成、不上传 updater payload。
- 正式 macOS updater payload 下载到离线环境后，使用正式 Tauri Updater 私钥执行
  `tauri signer sign`，生成正式 `.sig`。
- 离线/受控发布工具根据已审计 payload 与正式 `.sig` 生成静态 `latest.json`。
- `latest.json`、正式 macOS `.sig`、macOS payload、DMG 和 CLI 资产齐全后才能把 draft Release
  转为正式发布。
- 生产 App 内嵌的公钥必须与离线私钥配对；发布演练需要使用独立测试 key，不能复用正式
  私钥或把测试 key 带进正式构建。
