## 2. 决策详情与仓库对齐

### D1 视频/长耗时模型:异步方向

会议结论:视频类模型生成耗时长(30 秒到数分钟),同步接口易超时卡死;采用「异步挂起、任务入库、回调通知」的处理逻辑,并对齐 Google Veo、国内 Seedance 等主流视频模型的异步协议做**通用抽象**,不做单厂商定制对接。

与既有文档的关系:

- `docs/research/2026-07-17-Agent与API兼容拓展-M0调研.md` §6.3 曾将「同步 facade(任务基线)vs 异步 job(OpenRouter 现状)」标记为 `DECISION_REQUIRED`。**本次会议给出方向:异步。**
- 后续多模态设计文档中的正式 ADR 应引用本决策;在 ADR 落稿前,不启动任何视频相关代码。
- 调研范围:Veo、Seedance 及 OpenRouter `/api/v1/videos` job 模型(pending/in_progress/completed/failed 状态机与退避策略,M0 调研已覆盖)。

指导原则(会议原话):「要做的事情是抽象,不是对接。对接 AI 就干了,抽象得把几个用法的共性找出来。」

### D2 核心引擎层 / 用户层分界

会议结论:产品定位为**通用模型路由引擎**(语言、视频、语音、Embedding 全类型),分核心引擎层(路由引擎,含分类器)与用户层两层;核心引擎须**不做任何适配修改**即可复用至企业版(企业版能力:多客户端管理、调用审计、成本管控、数据安全)。

仓库现状:引擎已经事实上独立——`crates/`(router-core、protocol、plugin-api、plugin-runtime、metrics)+ WASM 插件对壳无感知;桌面壳以 lib 方式复用 CLI crate 里的 Gateway,证明了可嵌入性。

落地动作:把 `gateway.rs` / `server.rs` / `admin.rs` / recorder 从 `apps/cli` 提取为独立 kernel crate,使 CLI、桌面、企业服务端三个壳平等依赖。企业版新增能力全部落壳层,引擎不改。

### D3 链路容错:断连故障转移

问题:与服务商断连时,网关无兜底,直接把异常抛回 Agent,Agent 无法感知只能卡住。产品是短连接场景,处理难度可控。

设计边界(沿用 M0 调研 §5.5 已定的红线,不得放宽):

- 只有**网络类 / 服务不可用类**错误允许自动切换其他厂商;
- 鉴权、参数、能力、内容策略错误**不得**跨厂商重放;
- 首字节前才允许 fallback;首字节后 HTTP 状态已提交,只能发流内错误终止,不得静默换模型。

### D4 多客户端多路由策略(调研)

问题:当前仅支持单组路由策略,Claude Code 与 Codex 无法各用一组配置。

会议要求:先调研竞品实现,评估灵活映射的**必要性**与**配置复杂度副作用**,再决定做不做。基线规则:默认提供单组通用策略,支持按需新增自定义策略,不抬高普通用户使用门槛。功能取舍标准(会议原话):「做什么不做什么,不是因为技术做不做得到,而是你的场景、你的用户需不需要。」

### D5 配置备份与回退

范围:接入 Agent 覆盖其配置时——只覆盖已知、可识别的配置段,不认识的配置段报错(不盲写,避免损坏用户环境);记录源文件、备份路径与新配置信息;支持回退。

仓库现状:connector 已有部分约束成文(写前确认入站 Adapter 已挂载、非法配置不覆盖、保留无关字段、同目录临时文件替换、幂等,见 M0 调研 §3.2);**备份记录与一键回退尚未开发**,已入计划。

名词澄清(避免与另两个「缓存」混淆):

| 话题 | 是什么 | 状态 |
|---|---|---|
| 本条(会上的「缓存管理」) | Agent 配置覆盖前备份、可回退 | 已计划未开发 |
| WASM 编译缓存 | wasmtime 插件编译产物缓存,解决桌面端启动卡顿(`cache` feature + `Config::cache`,失效由内容哈希自动管理) | 待做,与本条无关 |
| 模型列表缓存 | `discover_with_cache`,live/cache/none 三态 | 已完成 |

### D6 研发流程规范

- **方案先行**:未完成方案共识不启动代码开发;白天做方案论证、场景调研、需求对齐,代码生成集中在夜间批量进行,避免生成后改逻辑的高成本返工。
- **提交节奏**:Rust 全量编译与测试耗时长,单模块开发完成后再提 PR 统一跑 CI,避免频繁触发全量校验。
- **测试要求**:核心模块单元测试覆盖率不低于 80%,由 AI 基于业务需求生成用例,搭配必要的人工集成测试。
- **竞品参考**:参考 cc-switch 等竞品迭代方向,不照搬非通用场景的定制化设计,优先保障核心链路简洁易用。
