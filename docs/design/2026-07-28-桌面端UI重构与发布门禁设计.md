# 桌面端 UI 重构与发布门禁设计

- 日期：2026-07-28
- 状态：PR 提交前缺陷已修复并验收，功能分支已同步 `develop`，待用户确认
- 范围：`apps/desktop`
- 关联提交：`4b21318`、`0da6fa1`、`ac4c36d`、`f6aedaa`
- 设计参考：[shadcn/ui](https://ui.shadcn.com/)

## 1. 文档定位

基础 UI 重构已经实现，这份文档用于记录设计依据、交互约束和发布门禁。2026-07-28 新增的“移除三档同步”和“已选供应商置顶”规则在实现前先更新到本文，随后完成实现和验收。后续修改桌面端界面时，应先更新本文或新建设计文档，再进入实现。

这次重构的目标是让 Token Station 更像一个可长期使用的本地工程工具。界面保持简约，减少装饰，优先保证路由配置、供应商管理和用量查看的效率。

## 2. 问题范围

改动前存在以下问题：

- 主页同时展示 Agent 概览和路由配置，信息重复，主任务不集中。
- 三档路由使用原生选择框，不同系统上的外观和行为不一致。
- 选择框菜单会被父组件的 500 ms 运行态刷新抢走焦点。
- 重复选择当前供应商仍会触发级联更新，模型可能被重置。
- “同步三档”是低频批量操作，却长期占用三档路由表的操作列，增加界面复杂度和误触风险。
- 供应商选项始终按目录顺序展示，再次打开时无法快速确认当前选择并切换到其他供应商。
- 策略组保存和删除绕过 App 级命令锁，旧响应可能覆盖新状态。
- 用量页自动刷新可能重叠，零 Token 时仍显示 50% 输入和 50% 输出。
- 900 px 到 1050 px 的响应式规则互相覆盖，侧栏和供应商卡片会被压缩。
- 部分图标按钮在折叠侧栏中失去可访问名称。

## 3. 产品与视觉原则

### 3.1 页面主任务

主页只承担一个主任务：配置所有 Agent 默认继承的三档路由。Agent 的发现、接入和独立路由留在左侧导航对应页面，不在主页重复展示。

### 3.2 视觉基线

界面采用中性、低阴影、边框主导的视觉语言：

| 角色 | 浅色 | 深色 |
|---|---:|---:|
| 画布 | `#ffffff` | `#09090b` |
| 次级表面 | `#f4f4f5` | `#18181b` |
| 主文字 | `#09090b` | `#fafafa` |
| 次级文字 | `#71717a` | `#a1a1aa` |
| 普通边框 | `#e4e4e7` | `#27272a` |
| 强边框 | `#d4d4d8` | `#3f3f46` |

字体优先使用 Geist Sans 和系统字体。说明文字、状态标签和数据采用更紧凑的字号，但可交互元素不得依赖小字传达唯一含义。

### 3.3 简约不等于减少反馈

界面可以减少装饰，但必须保留以下反馈：

- 当前选中项。
- 键盘焦点。
- 禁用原因对应的上下文提示。
- 保存状态和应用状态。
- 空数据、错误和加载状态。
- 操作是否只写草稿，是否已经应用到运行态。

## 4. 信息架构

### 4.1 左侧导航

左侧导航包含主页和 Registry 中允许展示的 Agent。主页不再展示 Agent 卡片概览。

常规窗口显示图标和文字。窗口宽度不超过 980 px 时切换为 76 px 图标侧栏。折叠后，主页、Agent 和重新扫描按钮仍必须提供 `aria-label` 或 `title`。

### 4.2 主页路由

三档路由使用紧凑表格表达：

```text
档位          供应商                 模型
上档          minimax_cn             MiniMax-M3
中档          minimax_cn             MiniMax-M3
下档          minimax_cn             MiniMax-M3
```

档位说明固定为：

- 上档：复杂推理与代码。
- 中档：日常开发任务。
- 下档：简单快速任务。

主页不提供“同步三档”按钮。用户分别配置每一档，避免一次操作覆盖其他档位已经确认的路由。

### 4.3 供应商目录

供应商目录使用卡片网格。卡片展示名称、类型和必要标签，详情在选择后进入配置流程。

响应式列数：

| 窗口宽度 | 列数 |
|---|---:|
| 大于 1050 px | 4 |
| 961 px 到 1050 px | 3 |
| 不超过 960 px | 2 |
| 不超过 560 px | 1 |

桌面 App 当前最小宽度为 900 px，因此 2 列布局必须在真实桌面窗口中可达。

### 4.4 用量页

用量工具栏使用统一的紧凑选择框，筛选顺序为 Agent、供应商、模型、自动刷新和时间范围。

筛选具有级联关系：

- 切换 Agent 时清空供应商和模型。
- 切换供应商时清空模型。
- 新统计结果不再包含当前供应商或模型时，清理失效筛选，不把旧值重新插入选项。

自动刷新采用单飞策略。已有刷新未完成时，不启动第二组统计请求，只记录一次待刷新请求。

总 Token 为零时，输入和输出轨道宽度都为零，并提供“暂无 Token 数据”的可访问说明。

## 5. 选择框交互规范

`CompactCombobox` 是桌面端统一的紧凑选择框。所有使用方遵守同一套行为。

### 5.1 展开方向与定位

- 菜单始终向下展开，不允许自动上弹。
- 菜单顶部与触发框底部保持 6 px 间距。
- 菜单使用视口固定定位，页面滚动或窗口尺寸变化时重新计算位置。
- 菜单最大高度为 360 px，内容超过高度后在菜单内部滚动。
- 选项超过 10 个时显示搜索框。
- 未搜索时最多渲染前 100 项；当前选中项不在前 100 项时，仍需保留并优先展示。
- 触发框和选项提供完整名称的 `title`，可见文字允许省略。

### 5.2 焦点与键盘

- 打开菜单时聚焦当前选项。
- `ArrowDown` 和 `ArrowUp` 在选项间循环移动。
- `Home` 和 `End` 移动到首项和末项。
- `Escape` 关闭菜单并把焦点还给触发框。
- Tab 离开组件时关闭菜单，不阻断正常焦点顺序。
- 父组件重新渲染不得重置用户已经移动到的选项。
- 同一时间只允许一个选择框菜单展开。

首次聚焦必须在 React 布局提交阶段完成，不使用延迟 animation frame，避免用户按键后焦点又被拉回。

### 5.3 状态变化

- 选择当前值时只关闭菜单，不调用 `onChange`。
- 组件在展开期间变为禁用时立即关闭菜单。
- 只读模式沿用禁用语义，不允许通过已经展开的旧菜单修改状态。
- 三档路由的供应商菜单按当前行独立排序。
- 当前已经选择的供应商排在第一项，“未选择”排在第二项，其余供应商保持目录原始顺序。
- 当前行尚未选择供应商时，“未选择”排在第一项，其余供应商保持目录原始顺序。
- 切换供应商后，该行下次打开菜单时按新选择重新排序，不改变其他档位的当前值。
- 供应商置顶只改变菜单展示顺序，不改变保存、应用和路由选择语义。

## 6. 状态一致性

### 6.1 路由档位独立更新

三档路由继续通过 `set_tier` 分别更新。移除前端“同步三档”入口、对应的 API 包装和 Tauri command，避免保留无法从界面触达的批量写入路径。

选择供应商时仍沿用现有级联规则：自动选择该供应商的第一个模型；没有模型时模型为空。重新选择当前供应商不触发写入。

### 6.2 策略组操作使用统一命令锁

策略组保存和删除通过 App 的 `run` 执行。操作期间，主页其他会改变路由状态的控件保持禁用。请求完成后只接受该命令返回的完整状态。

### 6.3 用量刷新不并发

统计请求执行期间，后续自动刷新只设置一次 queued 标记。当前请求结束后再读取最新筛选条件执行下一次刷新。旧筛选对应的响应不得覆盖新筛选状态。

## 7. 响应式和可访问性

### 7.1 断点

- 大于 1050 px：224 px 完整侧栏。
- 981 px 到 1050 px：196 px 完整侧栏。
- 不超过 980 px：76 px 图标侧栏。
- 不超过 760 px：切换为顶部紧凑导航。该规则为未来更小窗口保留。

后声明的媒体查询不得把 76 px 图标侧栏覆盖回 196 px，同时保留隐藏文字规则。修改 `App.css` 时必须检查同一选择器在所有媒体查询中的最终层叠结果。

### 7.2 可访问性

- 图标按钮必须有可访问名称。
- 选择框使用 `role="combobox"`、`aria-expanded`、`aria-controls` 和 `role="listbox"`。
- 当前选项使用 `aria-selected`。
- 仅活动选项进入 Tab 顺序，其余选项使用 `tabIndex=-1`。
- 可见焦点不能只靠颜色变化，需保留轮廓。
- 动效遵守 `prefers-reduced-motion`。

## 8. 红线

UI 改动不得扩大授权范围：

- 不读取或修改 `token-station.state.json`。
- 不读取、展示或传输供应商 API Key。
- 不自动保存或应用路由草稿。
- 不修改 Agent 配置文件，除非用户在对应接入流程中明确确认。
- 不改变路由算法、阈值和供应商选择语义。
- 不为了视觉调整删除供应商、策略组、Receipt 或其他用户数据。
- 不用宽泛路径或模糊匹配替换本地 App。

## 9. 验收标准

### 9.1 自动化

- `CompactCombobox` 覆盖父级重渲染、Escape、重复选择、禁用关闭、大列表和固定向下展开。
- 三档路由测试覆盖已选供应商置顶、未选择项位置、切换后的模型级联和“同步三档”入口不存在。
- App 测试覆盖策略组操作期间的全局串行化。
- Stats 测试覆盖零 Token 和自动刷新不重叠。

### 9.2 真实 App

至少检查以下窗口与页面：

### 9.3 本地安装

任何影响可执行行为或界面的代码改动，交付前执行：

```bash

```

该脚本必须先完成构建和产物审计，再精确替换 bundle id 为 `com.tokenstation.desktop` 的 `/Applications/token-station.app`。

纯文档改动不重装 App。

## 10. 文档先行流程

后续桌面 UI 改动按以下顺序进行：

1. 在 `docs/design` 新建或更新设计文档，写清问题、非目标、交互规则、状态边界和验收标准。
2. 确认公开测试边界，包括组件行为、Tauri API 和用户可见结果。
3. 先添加失败测试，再实现一个垂直切片。
4. 完成前端和 Rust 全量测试。
5. 构建并更新本地 App。
6. 在真实窗口中检查常规宽度、最小宽度、键盘焦点和主题。
7. 将实现差异、验收结果和已知遗留项回写文档。
8. 使用中文提交说明创建本地 commit。

## 14. PR 提交前缺陷修复设计

### 14.1 问题、目标与范围

2026-07-28 的提交前审查发现四类不能带入 Ready PR 的问题：

- 本地安装脚本先删除旧 App，再复制和校验新 App；复制、校验或并发执行失败时，
  可能丢失仍可工作的旧 App。
- 安装脚本把 `open` 返回成功当作 App 已成功启动，无法发现新进程立即退出。
- 用量页的单飞刷新在慢请求、部分失败和页面卸载场景下会失效，可能持续丢弃结果、
  重叠查询或在页面离开后继续发起请求。
- 选择框靠近视口底部时仍强制向下展开至少 120 px，菜单会被视口裁切。

本轮目标：

1. 安装过程在单进程和并发执行下都保持可恢复；新 App 未完成复制、校验和启动验收前，
   旧 App 始终可恢复。
2. 启动验收检查精确 App 可执行进程在稳定窗口内仍存活；失败时安装命令非零退出并恢复旧 App。
3. 统计刷新同一时刻最多存在一个完整请求批次；相同筛选的自动刷新只合并一次，
   新筛选替代旧筛选但不允许旧批次的剩余请求与新批次重叠；页面卸载后不再排队。
4. 选择框继续只向下展开，但打开前必须把触发框滚动到可容纳菜单的位置，并把菜单高度
   限制在真实可用空间内，保证最小窗口中选项可见、可点击、可键盘操作。

范围限于：

- `scripts/install-local-desktop.sh` 及其公开命令行契约测试。
- `apps/desktop/src/pages/Stats.tsx` 与 `Stats.test.tsx`。
- `apps/desktop/src/components/CompactCombobox.tsx` 与对应组件测试。

非目标：

- 不改变路由、供应商、预算或统计聚合语义。
- 不增加后台自动安装、自动更新或提权流程。
- 不改变“菜单只向下展开”的已确认产品规则。
- 不在本轮拆分 `App.css` 或处理主包体积告警。

### 14.2 安全与数据红线

- 安装脚本只能操作精确路径 `/Applications/token-station.app`，且旧、新、暂存、备份 App
  都必须校验 bundle id 为 `com.tokenstation.desktop`。
- 禁止通配符、前缀匹配或未解析变量参与删除。
- 安装锁必须覆盖构建、退出旧进程、复制、替换、启动验收和清理全过程。
- 暂存目录必须位于 `/Applications` 同一文件系统，使用本次进程独占的随机路径；
  任何退出路径都只能清理本次创建的暂存对象。
- 替换失败或启动验收失败时必须恢复旧 App；恢复失败要同时报告主失败和恢复失败，
  不得输出成功文案。
- 修复不得读取、复制或记录 `token-station.state.json`、API Key、Agent 配置内容或请求正文。
- Stats 页面卸载后不得继续发起新的统计查询；失败信息不得包含统计库内容。

### 14.3 用户可见行为与失败处理

安装成功：

1. 构建并审计新 App。
2. 在同卷暂存路径复制并再次校验 bundle id 与签名。
3. 将旧 App 原子移动到本次备份路径，将暂存 App 原子移动到正式路径。
4. 启动正式路径 App，确认精确可执行进程在稳定窗口内仍存活。
5. 删除备份并输出成功。

安装失败：

- 已有安装进程持锁时，立即报“已有本地桌面安装正在进行”并退出，不等待也不并发覆盖。
- 替换前失败不退出或删除旧 App。
- 替换后失败先退出新 App并恢复旧 App；恢复成功后报告安装失败但旧版本已恢复。
- 无旧 App 的首次安装失败时删除本次残留，不伪造一个可用安装。

Stats：

- 自动刷新触发时若已有同筛选批次运行，只记录一次待刷新。
- 任何一个 `getStats` 失败后，先等待同批其他请求结束，再释放单飞锁。
- 筛选变化只保留最新筛选快照；旧结果不覆盖新筛选。
- 页面离开后丢弃结果并清空队列，不再启动新批次。

选择框：

- 打开后菜单顶部仍位于触发框下方 6 px。
- 空间不足时先把触发框滚入能容纳菜单的位置，再重新定位。
