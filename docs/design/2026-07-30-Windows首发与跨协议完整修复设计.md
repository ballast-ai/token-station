## 1. 背景

本设计同时处理以下两份 Windows 真机报告：

- `2026-07-29-Windows-移植问题交接.md`：第一次 Windows 11 x64 从零构建、
  自动化与真实 Agent 测试发现的 41 个问题；
- `2026-07-30-Windows-剩余测试结果与开发问题清单.md`：后续 MSI、UI、
  标准 OpenAI SDK 和真实 Agent 补测发现的 16 个问题。

交接文档 F 组中“测试机已修”的补丁没有进入当前 `develop`。因此本次不能只处理
后续 16 条，而要以当前源码为权威，重新覆盖 Windows 权限、配置事务、发现、
打包、协议、取消、诊断和 UI 契约。

用户已确认三个产品决策：

1. Codex 必须完整支持真实的本地编码工具调用，不接受纯文本模式或静默降级；
2. Windows 第一版正式渠道只发布 x64 MSI，暂停 NSIS 和 Portable.zip；
3. Provider 凭据默认使用 Token Station 本地 store，高级用户可切换 env/file。

## 2. 目标

1. Windows 11 x64 上安装 MSI 后无需手工复制插件、修改 PATH 或配置临时绕过，
   即可发现、接入并使用正式支持的 Agent。
2. 修复 Windows 配置事务哈希、私有目录、虚拟 Key、`secrets.json`、快照和
   ownership 文件的权限边界。
3. Codex 完成文本、流式、真实工具调用、工具结果回传、多轮继续和错误终止；
   非 Function 的 Responses 工具不得静默丢弃。
4. Gemini 的 function call/result 在多轮历史中保持稳定关联，工具任务可继续。
5. OpenCode 在客户端断开、服务端排空和超时三种情况下得到各自正确的终止行为，
   不无限等待，不污染错误率。
6. Chat Completions 的 `message.content` 始终满足公开 string/null 契约。
7. 设置、About、更新检查、预算、端口错误、能力错误和 404 诊断提供结构化且可操作
   的用户反馈。
8. Windows 正式包为 per-user x64 MSI，默认安装到
   `%LOCALAPPDATA%\Programs\token-station`，不要求管理员权限，禁止降级。
9. macOS 的安装、签名、公证、目录、权限和既有业务流程不回归；Codex 的完整工具
   支持作为明确批准的跨平台能力增强。
10. 全部改动遵循“设计 → 红测 → 实现 → 全量门禁 → 本地 App → 真机验收 →
    文档回写 → 中文 commit”。

## 3. 非目标

1. 不发布 Windows NSIS、Portable.zip、x86 或 ARM64 包。
2. 不单独发布 Windows CLI；MSI 内部使用的桌面可执行组件不等同于独立 CLI 产品。
3. 不注册需要管理员权限的 Windows Service。网关继续作为当前用户会话中的本地
   进程运行。
4. 不实现 Agent 自动安装、自动升级或从远端下载可执行代码。
5. 不修改路由算法、评分、选池、fallback 或 `crates/router-core/**`。
6. 不让 Token Station 代替客户端对 404 自动重试，也不为已提交的流式响应做透明
   重放。
7. 不把 OpenAI 托管的 `web_search` 能力伪装成 DeepSeek 原生能力。客户端可执行
   工具必须完整往返；Provider 托管工具只有目标 Provider 明确声明支持时才准入。
8. 不自动迁移、删除或覆盖用户现有 Agent 配置、凭据、指标或日志。

## 4. 不允许触碰的红线

### 4.1 路由与数据面

1. `crates/router-core/**` 与冻结基线必须零差异。
2. 不为 Windows、Codex 或任何具体 Agent 增加 Router 特判。
3. 默认 loopback、默认鉴权、常量时间虚拟 Key 比较和出站禁止重定向不得弱化。
4. 请求正文、响应正文、reasoning、工具参数和工具结果不得写入 metrics、requests
   log、诊断日志或新的持久化缓存。

### 4.2 凭据与文件

1. 上游 API Key、虚拟 Key、快照明文不得进入 IPC、普通错误、argv 或日志。
2. Windows 私有目录和文件必须在敏感字节发布到最终路径前应用当前用户专属受保护
   DACL；收紧失败则删除临时文件并失败关闭。
3. Unix/macOS 继续使用既有 `0700/0600`，不得用 Windows ACL 重构改变其行为。
4. 不执行 `.cmd`、`.bat`、`.ps1` shim，不调用 `cmd /C` 或 PowerShell 绕过 argv
   约束。shim 只能作为只读入口线索。
5. Agent 接管只修改 Connector 的 `owned_paths`；未知字段、注释、其他 Provider、
   MCP、Skill 和用户配置必须保留。

### 4.3 发布与本机数据

1. Windows 打包配置只能进入 Windows 专属配置或 WiX 模板，不能改变 macOS
   `tauri.conf.json` 的 bundle、签名和公证语义。
2. 构建失败时不得删除当前已安装的 macOS App。
3. 测试优先使用隔离数据目录和临时 Agent 配置；读取 App 中现有 DeepSeek Key
   只能通过正式凭据解析路径，不打印、不复制、不写入测试 fixture。
4. 不用 mock 或 macOS 交叉编译结果冒充 Windows MSI、NTFS ACL 或 Windows Agent
   真机通过。

任一实现需要突破上述红线时，本批次立即停止该方案，记录证据并重新设计。

## 6. 平台隔离设计

### 6.1 Windows 专属实现

以下实现只能在 `cfg(windows)`、Windows 模块、Windows Tauri 配置或 WiX 模板内：

- DACL 应用与验证；
- npm shim、MSIX PackageManager 和 Windows PATH 解析；
- Windows 默认安装位置和配置路径；
- MSI target、per-user 目录、UpgradeCode、禁止降级、签名和安装测试；
- Windows 构建进程锁检查、notepad 回退、PowerShell 测试；
- Windows CI。

### 6.2 共享但向后兼容的实现

以下属于协议或产品公共契约，会同时覆盖 macOS：

- Codex/Gemini/OpenAI/OpenCode 协议修复；
- credential store/env/file 类型；
- 结构化设置错误、版本、更新结果、预算格式和诊断原因；
- cancellation 与 metrics 语义。

共享结构只允许增加有默认值的字段或明确升级 ABI；旧 fixture 和现有 Agent/
Provider adapter 必须继续通过。macOS 安装、目录和权限分支不改。

## 7. Windows 私有文件设计

建立一套共享语义、平台实现分离的 private filesystem：

1. `ensure_private_dir`：
   - Unix/macOS：真实目录且 mode 收紧为 `0700`；
   - Windows：真实目录、拒绝 reparse/symlink，应用受保护 owner-only DACL 并读回验证。
2. `write_atomic_private`：
   - 在同目录创建唯一临时文件；
   - 写入、flush、sync；
   - 在 rename 前应用私有权限并验证；
   - 原子替换；
   - 替换后再次验证，失败不把不合格文件当成成功。
3. `verify_private_file`：
   - 拒绝 symlink/reparse 和非普通文件；
   - Unix 检查 group/other 位；
   - Windows 检查 DACL 已保护，且不存在 Everyone/Users/Authenticated Users 的
     读写 ACE。
4. `virtual-key`、`secrets.json`、日志、SQLite、快照、ownership、价格缓存和
   配置文件统一复用；不得各自维护不一致的 ACL 逻辑。
5. ACL 错误只显示路径抽象和动作建议，不包含敏感文件内容。

## 8. Agent 发现与接入设计

### 8.1 npm shim

1. `.cmd` 只作为 UTF-8/系统文本读取，设置大小和行数上限。
2. 从文本提取 npm 包目录，不直接相信过期入口文件。
3. 规范化并确认包目录位于 shim 相邻 `node_modules` 内，拒绝 `..`、UNC、ADS、
   reparse 逃逸和外部绝对路径。
4. 读取包内 `package.json`，按 `bin` 的字符串或对象形状选择命令入口。
5. 入口规范化后必须仍在包目录内且为普通文件。
6. `.exe` 直接受限探测；`.js/.mjs/.cjs` 使用已发现的原生 `node.exe` 和 argv
   探测；其他扩展不执行。
7. 对最终入口执行 Agent fingerprint，避免 Claude Code 被误认为 Claude Desktop。
8. 任一步失败只生成“已发现但安装损坏/不可验证”，不得猜测、执行 shell 或写配置。

### 8.2 准入和连接后验证

- 卡片状态、按钮可用性和 `connector_id` 来自同一个 CompatibilityDecision。
- 协议适配器、版本、配置路径、认证模式和所需能力均满足后才允许预览。
- 接入写后除了字节/hash/解析验证，还运行 Agent 专属只读自检：
  - OpenCode：解析 provider/model；
  - Gemini：确认 selectedType 和网关环境生效；
  - Codex：确认 provider 配置和 Responses capability；
  - 其他 Agent：使用无正文、无上游消费的配置/版本自检。
- 自检失败自动恢复接入前 owned paths，并分别报告写入和恢复结果。

## 9. Codex 真实工具调用契约

### 9.1 真实请求证据

本机 `codex-cli 0.146.0-alpha.3.1` 的隔离捕获已确认请求包含：

- 多个客户端执行的 `type=function` 工具；
- `type=namespace` 的 `multi_agent_v1`，内部包含
  `close_agent/resume_agent/send_input/spawn_agent/wait_agent`；
- `web_search` Provider 工具声明；
- `tool_choice`、`parallel_tool_calls=false`；
- `reasoning.summary`、`include=["reasoning.encrypted_content"]`；
- `store=false`、流式输出和客户端元数据。

旧 Adapter 对非 `function` 工具直接 `filter_map` 丢弃，不能作为正式实现。第一轮实现
改为失败关闭后，真实 Codex 验收进一步证明 `namespace` 不是可选测试形状，而是
0.146 普通请求也会携带的客户端执行工具容器。

### 9.2 工具分类

1. **客户端执行 Function 工具**：完整保留 name、description、strict、parameters、
   call id、arguments 和 result；DeepSeek 通过 Chat Completions function calling
   产生调用，Codex 客户端真实执行。
2. **客户端执行的专用 Responses 工具**（例如 local shell/apply patch 形状）：
   规范化为带 wire-kind 的 ToolDef/ToolCall，Provider 侧映射为 function，回到 Codex
   时恢复原 Responses item 类型。
3. **客户端执行的 namespace 工具**：
   - 将每个内部 Function 展开为 `<namespace>__<name>`；namespace 已以 `__`
     结尾时不重复分隔符；
   - description、strict、parameters 和 call id 原样保留；
   - 在仅请求生命周期可见的扩展中保存反向映射，Provider 返回后恢复为
     `function_call.name=<name>` 与 `function_call.namespace=<namespace>`；
   - 非流式、流式增量、完成事件、历史重放和 continuation 使用同一映射；
   - 展开名碰撞、非法 namespace/name、非 Function 子工具或超过 Provider 名称
     上限时明确拒绝，不能覆盖、截断或猜测。
4. **Provider 托管工具**：
   - 禁用声明可保留为 capability metadata，不向不支持的 Provider 虚假广告；
   - 启用时只有 Provider capability 明确支持才准入；
   - 不支持时在请求前返回闭合 `provider_tool_unsupported`，绝不静默丢弃。

### 9.3 多轮与 reasoning

- Function call/output 以 call_id 强关联并保持顺序。
- reasoning text/summary 使用协议中立 reasoning part；encrypted continuation 作为
  opaque、不落盘扩展往返。
- `previous_response_id` 使用有界、仅内存、按 Agent/虚拟 Key 隔离的 continuation
  store；有 TTL、条目数和总字节上限，服务重启后返回明确的
  `continuation_expired`，不伪造空历史。
- `store=false` 不写磁盘；日志只记录是否使用 continuation 和闭合失败原因。
- forced/required tool choice 和 structured output 使用现有 typed IR，不再无条件拒绝。
- 流式必须输出 Codex 可识别的 response.created、tool item/delta/done、reasoning、
  completed/failed 终止事件。

### 9.4 通过条件

使用隔离工作目录和真实 Codex：

1. 普通文本成功；
2. 读取指定文件成功；
3. 执行受控 shell 命令成功；
4. 编辑指定测试文件成功；
5. 工具结果返回后继续第二轮并给出最终文本；
6. 流式结束不挂起；
7. 取消、上游 400/500、Provider 不支持工具均有明确终止；
8. App/网关重启后新会话可用，过期 continuation 不被误报成功；
9. 请求、工具参数、文件内容和 DeepSeek Key 不落盘。
10. Codex 0.146 默认携带 namespace 时仍能完成普通 shell 工具调用；若模型选择
    namespace 子工具，返回项必须恢复 namespace/name，Codex 能路由到对应客户端
    runtime。

## 10. Gemini、OpenAI 与 OpenCode 协议

### 10.1 Gemini

- 优先使用 Gemini 原始 functionCall/functionResponse ID。
- 无 ID 时为每个 assistant turn 维护未匹配调用队列，按 name + 出现顺序匹配结果。
- 同名并发调用必须依赖明确 ID；无法唯一匹配时返回
  `ambiguous_tool_result`，不得合成不同 ID。
- fixture 覆盖 call → response → Provider body → 后续 response 完整链。

### 10.2 OpenAI Chat Completions

- `choices[].message.content` 只输出 string/null。
- text parts 按顺序拼接；thinking 不混入公开 content。
- reasoning 放到受控兼容字段，目标 Agent/SDK 不支持时不破坏 content 类型。
- 非流式、流式、openai-python、openai-node 和严格 JSON Schema 均覆盖。

### 10.3 OpenCode 取消与排空

新增闭合原因：

- `client_disconnect`：不再向已断开客户端写响应，不计错误；
- `server_drain`：若已提交流，发送协议原生 terminal error 后关闭；未提交则返回
  标准 503/明确错误；
- `deadline`：发送 timeout terminal，计入超时而非协议转换失败；
- `upstream_failure`：保持既有失败前/失败后语义。

`StreamOutcome`、conversion report、request record、health 和 stats 从同一 settle
结果派生。客户端取消单列 cancelled，不进入 errors。

## 11. 设置、凭据和诊断契约

### 11.1 设置事务

所有保存命令采用：

```text
clone live draft
→ apply requested edit
→ materialize + field validation
→ observe revision
→ commit candidate
→ persist
```

失败时 live draft/revision/dirty/disk 均不变。IPC 返回闭合字段错误：
`field`、`reason_code`、`message`。前端设置 `aria-invalid`、关联错误文本并聚焦首个
错误字段。

### 11.2 凭据来源

- `store`：默认，写入本地 `secrets.json`；
- `env`：只保存变量名，运行时读取；
- `file`：只保存绝对文件路径，运行时读取私有普通文件；
- 不再把 store 称为 keyring；
- 切换来源时不把旧明文复制到新来源，删除 store 值需要用户明确动作；
- Windows store 在 ACL 门禁通过前不可写入。

### 11.3 结构化展示

- About：分别显示 Desktop version 和 Core version。
- 更新：`UpToDate | UpdateAvailable | NoPublishedRelease | Unavailable`。
- 预算：统一金额 formatter，极小非零值不得显示为 `0.00`。
- 端口：AddrInUse 显示 `127.0.0.1:port` 和处理建议。
- capability：闭合 reason code 和安全 detail。
- 404：记录 method、agent 和闭合 path kind；未知路径只记
  `unknown_agent_endpoint`，不持久化任意 raw path。
- threshold：显示 matched band 和 band lower bound，避免与启发式总阈值混淆。

### 19.5 PR Windows Clippy 紧急修复记录

- 现象：PR #57 的 `Windows full Rust and desktop gates` 在

  `-D warnings` 因此失败。Unix 构建需要 `mut` 调用 `DirBuilderExt::mode(0o700)`，

  调用；不改变插件包校验、复制预算、发布事务、失败清理或用户可见交互。
- 红线：不删除 Unix `mode(0o700)`，不增加 `allow(unused_mut)`，不降低
  `-D warnings`，不修改 Router、凭据、Agent 配置或任何用户数据。
- 回归：失败的 Windows Clippy job 是实现前红测；实现后本地 workspace/Desktop
  Clippy `-D warnings`、workspace 全量测试与插件安装测试均已通过。新一轮 Windows
