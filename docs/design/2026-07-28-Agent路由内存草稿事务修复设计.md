# Agent 路由内存草稿事务修复设计

> 日期：2026-07-28
> 基线：`develop@5694347`
> 状态：已实现、已验证、已安装本地 App

## 1. 问题

空主页进入 Agent 独立路由时，桌面后端会把未配置档位写成
`agent_routes.<agent>.custom_route.<slot> = null`，并直接放入全局
`AppInner.draft`。`ConfigState::observe_draft()` 只记录指纹和 revision，不执行
`ClientConfig` 结构校验，因此命令可以成功返回，但随后主页、保存和启动才暴露：

```text
配置结构不合法: invalid type: null, expected struct AgentRouteTarget
```

设置 Agent 档位时还存在“先生成草稿、后验证目标”的顺序。未知供应商或模型被拒绝后，
全局 draft 已经改变，但 revision 甚至可能尚未观察到该改变。

## 2. 目标

1. 未完成的 Agent 独立路由只存在于进程内编辑草稿，不进入可保存的全局配置。
2. 路由命令失败后，全局 draft、revision、dirty 状态和磁盘配置保持不变。
3. 普通导航返回主页后，可以继续添加供应商、配置主页三档、保存和启动。
4. 完整 Agent 三档通过一次事务提升为合法 `ClientConfig`，再按现有保存流程写盘。
5. 错误指出 Agent、档位和缺失字段，不直接向用户暴露 serde 类型错误。

## 3. 范围

### 3.1 包含

- `AppInner` 中 Agent 路由编辑草稿的生命周期。
- Agent 路由模式、档位编辑、保存、恢复主页和挂载策略组命令。
- 路由相关全局 draft 修改的候选值校验与提交。
- Provider 删除、模型更新对编辑中 Agent 路由引用的保护。
- Tauri 命令级公开行为测试和 React 导航行为测试。

### 3.2 非目标

- 不改变 CLI 的 `ClientConfig`、`AgentRouteConfig` 和磁盘 JSON 契约。
- 不持久化未完成编辑草稿；重启后回到最后一次合法配置。
- 不在本次引入新的配置文件锁、跨进程同步协议或多实例 UI。
- 不重做 Agent 路由页面视觉布局。

## 4. 安全与数据红线

1. 非法或不完整 Agent 路由不得写入 `token-station.json`。
2. 路由校验失败不得覆盖磁盘上的最后合法配置。
3. 候选配置通过完整 `ClientConfig` 物化前，不得更新权威 draft/revision。
4. Provider 凭据、请求正文、响应正文不得进入编辑草稿、错误或测试输出。
5. Provider 删除与模型移除必须同时检查已保存路由和进程内编辑路由，禁止制造悬空引用。
6. 本次不删除、迁移或自动修复用户磁盘配置。

## 5. 状态模型和交互

### 5.1 权威状态

- `AppInner.draft`：始终可以物化为结构合法的 `ClientConfig`。
- `ConfigState`：只跟踪权威 draft、saved 和 revision。
- `agent_route_drafts`：按 Agent 保存进程内编辑态，档位允许为空，不参与全局
  `config_error`、`config_dirty` 或主页保存。

### 5.2 进入独立路由

1. 已有编辑草稿时继续使用。
2. 否则优先复制该 Agent 已保存的 `custom_route`。
3. 没有已保存独立路由时，从当前主页三档生成编辑草稿；未配置档位保持为空。
4. `StateView.agent_routes[agent].mode` 展示为 `custom`，但全局 draft/revision 不变。

### 5.3 编辑档位

1. 先校验 Agent、档位、供应商和模型。
2. 校验通过后才更新进程内编辑草稿。
3. 清空档位只清空编辑草稿中的该档。
4. 失败时编辑草稿和权威状态均保持操作前状态。

### 5.4 保存独立路由

1. 检查每个待提交 Agent 的 high/mid/low。
2. 缺失时返回 `Agent <id> 的 <slot> 档缺少供应商或模型`。
3. 完整时生成候选全局 JSON。
4. 候选通过 `ClientConfig` 物化后，原子更新 draft 与 ConfigState。
5. 沿用现有原子配置写盘；写盘成功后清除对应编辑草稿。

### 5.5 返回主页、恢复和挂载

- 普通导航只切换页面，保留进程内编辑草稿，不污染主页。
- “跟随主页”清除该 Agent 编辑草稿，并事务性更新合法配置。
- “恢复主页路由”继续执行保存，成功后保持跟随主页。
- 挂载策略组成功后清除该 Agent 编辑草稿。
- “应用到全部 Agent”清除全部编辑草稿，并提交合法的 inherit 配置。

### 5.6 失败处理

- 输入或结构校验失败：丢弃候选，全局 draft/revision/disk 不变。
- revision sidecar 写入失败：候选不成为权威内存状态。
- 配置文件写入失败：保留结构合法、可重试的内存 draft；不得留下非法结构。
- 未完成编辑草稿不阻断主页保存、Provider 保存或代理启动。

## 6. 响应式、键盘与可访问性

本次不改变布局和键盘模型。现有模式选择继续使用 `role="radio"` 和
`aria-checked`；档位选择继续由可键盘操作的组合框承载。错误文本仍位于页面现有错误
区域，不新增只能通过颜色理解的状态。

## 7. 公开测试 seam

### 7.1 Tauri 命令 seam

1. 空主页切换 custom 后，返回视图显示编辑态，但全局 draft/revision/dirty/config_error
   不变。
2. 无效 Agent 目标失败后，编辑草稿和全局状态都不变。
3. “空主页 → custom → 返回主页语义 → 添加 Provider → 配置三档 → 保存”成功，
   磁盘配置合法。
4. 未完成 Agent 路由执行“保存独立路由”时返回具体 Agent/档位错误，磁盘和全局状态
   不变。
5. 完成三档后保存成功，磁盘 `custom_route` 完整且没有 `null`。
6. Provider 模型更新和删除能识别编辑草稿引用。

### 7.2 React 页面 seam

1. 进入独立路由后普通导航返回主页，不隐式调用保存或恢复命令。
2. 再进入同一 Agent 时仍展示编辑草稿。
3. 未完成编辑只禁用“保存独立路由”，不显示全局配置损坏提示。
