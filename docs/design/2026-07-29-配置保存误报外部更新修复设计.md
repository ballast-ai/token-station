# 配置保存误报外部更新修复设计

## 1. 问题、目标、范围与非目标

### 问题

桌面端启动时通过 `ClientConfig::load` 补齐默认字段，再将规范化配置保存为内存快照；保存前却把该快照的指纹与磁盘原始 JSON 指纹比较。旧配置缺少默认字段时，即使没有任何外部修改，保存也会误报“配置已被另一个 Token Station 实例或外部程序更新”。

### 目标

记录启动时磁盘文件的原始语义指纹，允许正常保存经过默认值补全的配置，同时继续拒绝真实外部修改，避免静默覆盖。

### 范围

仅涉及桌面端配置 revision 状态和保存前的指纹校验，并补充 Rust 回归测试。

### 非目标

不改变配置格式、默认值、并发写锁、外部修改时的 fail-closed 行为，也不自动合并两个不同内容的配置。

## 2. 安全与数据红线

- 真实外部修改仍必须拒绝保存。
- 不覆盖或删除外部配置，不输出密钥和完整配置内容。
- 指纹只用于比较，不写入用户配置文件；revision sidecar 继续原子更新。

## 3. 用户可见行为与失败处理

启动后保存仅因默认字段补全不再报冲突；其他程序实际改动配置内容时，仍提示重新加载后再保存。

## 4. 响应式、键盘与可访问性

本修复不改变界面布局、键盘行为或可访问性语义。

## 5. 测试边界、验收标准与真实 App 检查

- 回归测试覆盖磁盘配置缺少默认字段但首次保存成功。
- 现有外部修改测试继续通过。
- 运行桌面构建测试，安装并启动本地 App，确认保存不再误报。

## 6. 实现落点、遗留项与发布要求

实现落点为 `apps/desktop/src-tauri/src/config_state.rs`：加载时从磁盘原始 JSON 计算 `disk_fingerprint`，而内存的规范化配置继续用于 saved/draft 指纹。

已知遗留项：DMG 打包依赖本机 `bundle_dmg.sh`，若该环境仍失败，只交付签名并启动成功的 `.app`。

发布前执行相关测试、`scripts/install-local-desktop.sh`，并回写验收结果；本地 commit 使用中文说明。

## 7. 实现状态与验收结果

已实现：`ConfigState::load` 现在分别记录规范化内存配置指纹和启动时磁盘原始 JSON 指纹。新增回归测试确认默认字段补全不会触发外部更新提示，原有外部修改拒绝测试仍通过。

前端测试 197 项通过；配置状态 Rust 测试 12 项通过。桌面 Rust 全量测试中有 4 项受本机 Node 版本和未预置 WASM 插件目录影响，官方桌面构建流程会自行准备插件目录；这 4 项不是本次修改引入。

实际 App 已按官方流程编译并通过签名校验，修复版 `.app` 已启动。DMG 仍因本机 `bundle_dmg.sh` 失败未生成；当前已生成的 App 本体可运行。
