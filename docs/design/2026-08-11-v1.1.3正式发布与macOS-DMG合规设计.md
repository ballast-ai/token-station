# v1.1.3 正式发布与 macOS DMG 合规设计

## 0. 发布范围调整

2026-08-11 经用户确认，v1.1.3 本次只发布 GitHub 稳定 Release 及 GitHub 自动
生成的源码归档，不上传 CLI 二进制、DMG 或 Updater 载荷。本文的签名、公证、
DMG 与离线签名实现作为后续正式二进制发布能力合入，但不用于 v1.1.3。
未签名的本地 App、DMG 或临时 CI 载荷不得作为替代品附加到本次 Release。

## 1. 问题

`develop` 已包含 v1.1.2 之后的首次配置向导、桌面更新安全语义、错误提示和 CI
修复，但仓库中的桌面版本仍为 1.1.2，CLI 版本仍为 0.2.0。现有 Tauri 默认 DMG
也没有满足《macOS DMG 安装提示与打包要求》规定的五个根目录入口。直接创建
`v1.1.3` 标签会得到版本不一致的产物，并触发无法通过正式门禁的发布任务。

## 2. 目标

1. 把桌面 App、CLI 和发布标签统一为 `1.1.3`。
2. 为 Apple Silicon 和 Intel macOS 生成 Developer ID 签名、Apple 公证且结构合规的
   DMG。
3. 把 App bundle 的最低系统版本从 Tauri 默认的 10.13 校正为真实支持的
   macOS 11.0，避免不支持的系统误判为可安装。
4. 让 DMG 根目录包含 App、`Applications` 快捷方式、中文安装说明、可双击安装脚本和
   `AGENTS.md`。
5. 保持 CLI Ed25519 发布清单签名和 Tauri Updater 离线签名两条信任链，不把正式私钥
   放入仓库、GitHub Secrets、CI 或联网开发机。
6. 只从已合并的远端提交构建；本地配置、凭据、未跟踪文档、缓存和用户数据不得进入标签、
   构建输入或 Release 资产。
7. Release 公开前完成资产、签名、版本、校验值和真实安装检查。
8. 把发布审计中已有兼容补丁的桌面传递依赖更新到安全版本，不使用主版本跳跃或自动
   `npm audit fix`。

## 3. 范围

- 更新桌面端和 CLI 的版本元数据及锁文件。
- 新增 macOS DMG 安装说明、安装脚本、DMG 内 Agent 约束和自定义打包脚本。
- 新增静态发布门禁和最终 DMG 挂载审计。
- 调整正式二进制工作流，使其未显式启用时跳过，启用后只上传通过门禁的资产。
- 准备 v1.1.3 源码 Release notes；保留签名清单和 `latest.json` 的后续门禁。
- 创建 PR，合入 `develop` 后从精确合并提交创建并推送 `v1.1.3` 标签。
- 公开不含附加二进制资产的 GitHub Release。

## 4. 非目标

- 不向 v1.1.3 GitHub Release 上传任何二进制资产。
- 不发布 Windows 安装包或启用 Windows Updater。
- 不关闭 Gatekeeper，不修改 SIP，不降低整台 Mac 的安全设置。
- 不把正式 CLI 或 Updater 私钥迁移到 CI。
- 不修改业务配置、用户路由、Provider 数据或本地 Agent 配置。
- 不把当前工作区里的未跟踪文件作为 Release 附件。

## 5. 安全与数据红线

1. CLI 正式签名种子和 Tauri Updater 正式私钥只能存在于离线签名环境；聊天中只允许传递
   对应公钥。
2. Apple `.p12`、密码和 App Store Connect `.p8` 只能通过 GitHub Secret 的标准输入写入，
   不得出现在命令参数、日志、提交或 Release 附件中。
3. 自定义安装脚本只能操作 `/Applications/token-station.app` 及带固定 Token Station 前缀
   的临时路径和备份路径，禁止通配符和宽泛递归删除。
4. 覆盖旧 App 前必须校验源和目标 bundle id；目标不是 `com.tokenstation.desktop` 时停止。
5. 新 App 复制、签名校验、替换、二次校验或启动失败时必须恢复旧版本，并用正常中文说明
   失败发生在哪一步。
6. 只允许对 `/Applications/token-station.app` 移除 quarantine；严禁执行或建议
   `spctl --master-disable`。
7. 正式构建必须启用源码路径和 Cargo 路径重映射，产物审计不得发现开发者用户名或工作区
   绝对路径。

## 6. 用户可见交互与失败处理

DMG 根目录固定展示：

1. `token-station.app`
2. `Applications`（指向 `/Applications`）
3. `安装前必读.md`
4. `安装 Token Station.command`
5. `AGENTS.md`

推荐入口是双击安装脚本。脚本先用中文说明来源校验、安装目标、管理员密码用途和安全边界，
再等待用户输入 `y` 或 `Y`。其他输入均取消且不修改系统。`sudo` 请求密码前明确说明输入时
不会显示字符。每个失败分支必须告诉用户是来源 App、签名、目标冲突、复制、替换、启动还是
恢复失败，避免只显示退出码或工具原始报错。

手工安装路径继续保留：用户可以把 App 拖到 `Applications`，右键选择“打开”；仍失败时，
说明文档只提供针对 `/Applications/token-station.app` 的 quarantine 清理命令。

GitHub Release 页面必须说明支持的平台、签名与公证状态、CLI/Updater 验证方式、文件名和
SHA-256。任一正式签名、公证或平台资产缺失时，Release 保持 Draft，不显示为 Latest。

上述要求适用于二进制发布。v1.1.3 的源码 Release 可以显示为 Latest，但页面必须
明确说明没有附加安装包，不得声称已通过 Developer ID 签名或 Apple 公证。

## 7. 状态变化

正式二进制发布状态只允许按以下顺序前进：

`源码准备` → `PR 已合并` → `标签已推送` → `CI 资产已审计` → `离线签名完成` →
`Draft 资产完整` → `Release 已公开`

任何门禁失败都停留在当前状态，不得通过上传未签名替代品、复用旧版本资产或删除校验步骤
继续前进。修复后必须重新从同一标签构建或重新创建标签前的源码提交；禁止移动已经公开的
标签。

v1.1.3 源码 Release 的状态为：`PR 已合并` → `标签已推送` → `源码 Release 已公开`。
标签触发的正式二进制工作流在仓库变量
`TOKEN_STATION_FORMAL_ARTIFACTS_ENABLED` 不是 `true` 时必须明确跳过。

## 8. 响应式、键盘操作和可访问性

本次不修改桌面 UI 布局。安装入口使用 Finder 可见的普通文件名，可由键盘选择并打开。
终端脚本不依赖颜色、鼠标或图形控件；所有提示均有纯文本内容，确认只接受明确的单字符
输入，错误后等待回车，避免窗口立即关闭导致信息不可读。

## 9. 公开测试边界

### 9.1 静态门禁

- 三处桌面版本、CLI 包版本和目标标签必须一致。
- App bundle 最低系统版本必须是 macOS 11.0。
- 桌面锁文件中 `dompurify`、`mermaid`、`nanoid`、`postcss` 和 `undici` 必须不低于已知安全补丁版本。
- DMG 五个源入口必须存在，安装脚本必须具有可执行权限。
- 安装脚本必须包含 bundle id、代码签名、明确确认、精确目标、备份、回滚、精确
  quarantine 清理和启动步骤。
- 安装说明与脚本不得包含全局关闭 Gatekeeper 的命令。
- 发布工作流必须运行 DMG 策略检查并上传最终合规 DMG。

### 9.2 构建与挂载审计

- 最终 DMG 必须真实挂载并核对五个根目录入口。
- App bundle id 必须为 `com.tokenstation.desktop`。
- App 和 DMG 代码签名、Gatekeeper、Apple 公证及票据装订必须通过。
- `Applications` 必须精确指向 `/Applications`。
- 安装脚本可执行，且只对精确 App 路径移除 quarantine。
- 两个架构的文件名、版本和校验值必须与 Release 页面一致。

### 9.3 回归

- Rust 全工作区测试、桌面 Rust 测试、前端测试和生产构建全部通过。
- `scripts/install-local-desktop.sh` 完成当前 Mac 的本地 App 替换、签名检查和启动。
- 真实 App 关于页显示 `1.1.3`，主要页面可进入，首次配置向导和 Agent 扫描没有回归。

## 10. 验收标准

1. 发布提交只包含设计、测试、版本元数据、发布脚本、安装物料和发布文档，没有本地数据。
2. CI 对目标合并提交全部通过，正式二进制工作流在未启用时只记录跳过原因。
3. v1.1.3 Release 的附加资产列表为空，只提供 GitHub 自动生成的源码归档。
4. Release 正文明确说明本次不提供签名安装包或 CLI 二进制。
5. Release 公开后，`/releases/latest` 指向 `v1.1.3`。

以下条目是后续二进制发布的验收标准，不在 v1.1.3 源码 Release 中执行：

1. 两个 macOS DMG 都通过最终挂载审计和隔离环境首次启动检查。
2. 四个平台 CLI 归档、`manifest.json`、`manifest.json.sig` 和 `SHA256SUMS` 完整且验签通过。
3. 两个 macOS Updater 载荷及正式 `.sig` 完整，`latest.json` 验证成功且只引用同一 Release。
4. Apple 签名、公证、票据装订和 Gatekeeper 检查全部通过。
