# 桌面端缺省策略组配置回归修复设计

- 日期：2026-08-10
- 状态：已实现、已验证、已安装本地 App
- 范围：`apps/desktop/src-tauri/src/lib.rs` 的桌面配置草稿准备流程

## 问题、目标、范围和非目标

合法的 `ClientConfig` 可以省略空的 `profiles`。Desktop 加载配置后会调用
`prepare_desktop_draft` 清理悬空路由引用；该逻辑通过可变 JSON 下标读取缺失的
`profiles`，从而在内存草稿中插入 `profiles: null`。随后页面物化配置时要求
`profiles` 是映射并报错：

```text
配置结构不合法: invalid type: null, expected a map
```

CLI 直接加载同一份配置成功，因为 CLI 不执行 Desktop 草稿准备流程。目标是让缺省的
可选映射在草稿准备后继续保持缺省，同时保留对真实 `agent_routes` 和 `profiles` 的悬空
引用清理。

本次不改变 `ClientConfig` 的磁盘 JSON 契约，不修改用户现有配置，不重做策略组或路由
交互，也不扩大到 Windows 发布支持。

## 安全与数据红线

1. 不读取、记录或输出 Provider 凭据、请求正文和响应正文。
2. 不因启动时内存迁移写回、删除或自动补全用户磁盘配置。
3. 缺省映射不得被物化成 `null`；已有合法策略组和 Agent 路由不得丢失。
4. 已有悬空引用清理行为必须保留，且只作用于实际存在的映射。
5. 配置无法通过 CLI 读取时继续进入现有只读保护，不覆盖原文件。

## 用户可见行为、状态和失败处理

修复后，省略 `profiles` 的合法配置应在 App 启动、刷新模型、主页和全局路由页面正常
加载，不再显示结构错误。配置仍由现有保存操作显式写盘；仅打开 App 不产生配置变更。

已有策略组时继续清理指向已删除 Provider 或模型的悬空档位。真实非法配置仍通过现有
`config_error` 和只读保护反馈，不做静默容错。

## 响应式、键盘和可访问性

本次不改变界面结构、文本层级、键盘操作或可访问性语义。错误消失后，页面恢复使用现有
控件和焦点模型。

## 公开测试边界与验收标准

1. 脱敏合法配置省略 `profiles` 时，`prepare_desktop_draft` 不新增
   `profiles: null`，结果可反序列化为 `ClientConfig`。
2. 同时省略 `agent_routes` 和 `profiles` 时，两个字段均保持缺省。
3. 真实存在的策略组和 Agent 路由仍执行悬空引用清理。
4. Desktop Rust 定向测试、全量测试、格式检查、Clippy 和构建通过。
5. 执行 `scripts/install-local-desktop.sh`，完成 bundle id、签名、启动检查。
6. 真实 App 复查刷新模型、主页和全局路由页面，不再出现
   `invalid type: null, expected a map`。

## 实现落点、遗留项和发布要求

实现只修改 `prepare_desktop_draft` 对可选顶层映射的读取方式，使用不插入缺省值的
`get_mut` 访问，并把真实配置诊断测试替换为脱敏回归测试。完成后回写本文的实现状态、
自动化验证、真实 App 验收和遗留项，使用中文提交说明创建本地 commit。

本次不创建 DMG，不修改 Windows 或 macOS 平台发布逻辑。是否推送远端在本地修复、
自审和真实 App 验收完成后决定。
