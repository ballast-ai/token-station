# Cursor 3.13.25 实验实现补充

## 现象与目标

本机发现 `/Applications/Cursor.app`，版本为 3.13.25。CLI 不在 PATH，但桌面可执行文件和用户数据目录存在。目标是在 develop 隔离分支中验证 Cursor Agent 的 OpenAI-compatible 请求能否进入 Token Station，不改主工作树，不猜测或覆盖 Cursor 私有配置。

通过 Cursor 3.13.25 的 Models → API Keys 页面确认，桌面端实际提供 `OpenAI API Key` 和
`Override OpenAI Base URL` 两个入口。当前用户配置里的 Base URL 为
`https://open.wecoding.ai/v1`，API Key 显示为已保存状态。这个入口比猜测
`settings.json` 或 SQLite ownership 更可靠，后续真实验收应从 UI 临时切换并在结束后恢复。

## 红线

- 不读取或输出 API Key、完整提示词和图片内容。
- 不修改 `~/Library/Application Support/Cursor`。
- 不启动 Token Station App，不安装桌面 App，不占用固定 8787 端口。
- Cursor 配置格式未确认前，Agent Registry 只允许 discovery-only。

## 实现与测试边界

实验分支 `codex/cursor-compat-experiment` 已新增 Cursor scoped 协议转换：当请求来自 `cursor` Agent 且 body 使用 Responses 形 `input` 时，转换为 Canonical IR 可接受的 `messages`；扁平 function tool 转成 Chat Completions 嵌套 function。普通 OpenAI-compatible 和 WorkBuddy 不走这条分支。

Registry 加入 Cursor macOS/Windows 可执行入口和兼容目录，但暂不提供连接器。原因是 Cursor 3.13.25 的 `settings.json` 与全局状态没有发现稳定的自定义 Provider 文件契约。

已通过：agent-openai 插件单测、CLI cargo check、桌面 Registry 单测、JSON 解析和 git diff check。未完成：真实 Cursor 自定义 Provider 请求抓包、工具续轮、SSE 实际回包和配置写入验收。

## 发布要求

这是实验分支，不安装 App，不运行 `scripts/install-local-desktop.sh`，不合并到 develop。真实 Cursor 验收必须使用隔离配置和非固定端口，并在验收后回写请求 fixture 与配置 ownership 设计。
