# Windows 必须可用性最小修复设计

日期：2026-07-31

状态：实现、本机验收与本地门禁完成；等待 PR Windows 权威 runner 复验

基线：`7ffaf7a`

## 1. 问题

Windows 审计报告覆盖了大量安全、发布、供应链和长期恢复问题，但本轮只处理三个已经
由当前源码确认、并会直接破坏用户正常接入、断开或配置状态判断的问题：

1. Gemini CLI 的主配置是 Dotenv，companion `settings.json` 是 JSON；ownership
   没有持久化 companion 格式，正常断开或恢复会按 Dotenv 解析 JSON。
2. 桌面端把配置中声明的 Agent adapter 当成已加载成功，未使用 Gateway 的实际
   ready/skipped 结果；adapter 加载失败时仍可能允许接入。
3. “保存并应用”只根据 `starting -> running` 相变显示成功，没有同时核对目标
   revision 与 apply error；旧实例恢复运行时可能误报新配置已应用。

## 2. 目标

1. Gemini 新旧 ownership 均能用 Connector 声明的 companion 格式安全生成断开与
   快照恢复计划。
2. Agent 接入资格来自当前运行 Gateway 实际加载成功的 adapter。
3. 只有目标 revision 确实运行且没有 apply error 时才显示“已应用”。
4. macOS/Linux 现有路径、权限、安装、签名、路由和正常交互保持不变。

## 3. 范围

### 3.1 本轮修改

- Agent ownership 的 companion 格式字段及旧记录兼容解析。
- Gateway 到桌面 Runtime Supervisor 的实际 Agent adapter readiness 只读接口。
- 前端应用成功横幅的 revision/error 判定及行为测试。

### 3.2 非目标

- 不修复审计报告中的其他 P0/P1。
- 不修改 Router、选池、评分、fallback、local-only 或免费 Provider 行为。
- 不修改 Provider 凭据存储、备份恢复全集、插件签名、SQLite、成本和响应上限。
- 不修改 Windows 高 DPI、NSIS、Portable、独立 Windows CLI 或发布流水线。
- 不修改 Hermes Windows 路径。当前仓库的产品、指南、fixture 与生产 Registry
  均锁定 `%LOCALAPPDATA%/hermes/config.yaml`；Connector 的 `${HOME}` metadata
  不参与生产目标选择。没有相同版本 Windows 真机或官方源码的反证前不得改写合同。
- 不补 macOS Agent 搜索路径、ACL、xattr 或签名公证。

## 4. 不允许触碰的安全与数据红线

1. `crates/router-core/**` 必须与基线保持零差异。
2. 不改变任何 Router 输入候选、评分、选池、fallback 或错误语义。
3. 不放宽本地监听、virtual key、Provider URL、Header、插件或 Agent 准入边界。
4. 不记录、导出或新增持久化请求正文与凭据明文。
5. 不删除既有 ownership、snapshot、Agent 配置或用户数据。
6. Gemini 旧 ownership 缺少格式时，只能使用对应 Connector 的显式 companion
   合同；不得根据扩展名或内容猜测。无法确定时必须失败关闭且零写盘。
7. 不修改任何 Hermes Registry、Connector、fixture 或文档路径合同。
8. 不修改 macOS bundle、entitlement、目录、Unix mode、签名或安装脚本语义。

## 5. 用户可见交互与状态

### 5.1 Gemini

- 新建连接时，ownership 为每个 companion 持久化 `document_format`。
- 旧 ownership 若没有该字段，由 Gemini Connector 对已声明的
  `settings.json` companion 返回 JSON 格式。
- 普通断开与快照恢复继续只恢复 owned paths，保留用户后来修改的非 owned 字段。
- Connector 无法确认旧 companion 格式时，展示可操作错误，保留 ownership 与快照，
  不执行任何文件写入。

### 5.2 Adapter readiness

- 当前 Gateway 实际加载成功对应 adapter 时，Agent 才允许生成连接计划。
- 配置声明存在但加载失败时，Agent 页面显示 adapter 未就绪，新接入按钮禁用；后端生成
  计划仍独立失败关闭，不改写 Agent 配置。
- 页面只显示无路径、无凭据的通用未就绪说明；插件加载的详细诊断不新增跨层 UI 合同。
- Gateway 重启或应用新 revision 后，readiness 随实际运行实例更新，不读取草稿冒充。

### 5.3 应用成功

- 记录用户发起 apply 时的目标 saved revision。
- 只有运行态满足以下全部条件时展示成功：
  - `phase == running`；
  - `running_revision == target_revision`；
  - `apply_error == null`。
- 旧实例恢复运行、revision 不符或存在 apply error 时，不展示成功横幅，既有错误状态继续
  可见。

## 6. 失败处理

1. 所有 Agent 计划失败发生在写盘前。
2. readiness 缺失默认按未就绪处理，不能乐观放行。
3. 旧 ownership 兼容失败不得自动升级、删除或覆盖记录。
4. 前端轮询失败不得凭 phase 推导成功。
5. 任一实现若需要修改 Router、候选集或 fallback，本轮立即停止并缩小范围。

## 7. 响应式、键盘与可访问性

本轮不改变页面布局、断点或导航结构。

- 现有按钮角色、Tab 顺序、焦点与键盘操作保持不变。
- readiness 和 apply error 继续通过现有文本状态与 banner 呈现，不只依赖颜色。
- 新错误信息必须使用现有可读错误区域，不新增自动聚焦或抢焦点行为。
- 中英文状态文案必须同时保持准确。

## 8. 公开测试边界

### 8.1 Gemini

1. 真实 TransactionEngine 完成 Connect 后再 Disconnect：
   Dotenv 主文件与 JSON companion 均正确恢复。
2. companion 的非 owned JSON 字段在断开后保留。
3. 旧 ownership 无格式字段时使用 Connector 显式合同。
4. 未知旧 companion 失败关闭，目标文件、ownership、snapshot 均不变。
5. Snapshot restore 覆盖同一矩阵。

### 8.2 Adapter readiness

1. 配置声明 adapter、Gateway 实际 skipped：连接计划被拒绝。
2. Gateway 实际 ready：保持现有连接行为。
3. applying 状态使用仍在服务的旧实例实际 readiness。
4. 新实例成功切换后 readiness 随实例更新。

### 8.3 应用状态

1. 目标 revision 成功运行且无错误时展示成功。
2. `starting -> running` 但运行的是旧 revision 时不展示成功。
3. 存在 apply error 时不展示成功。
4. 普通首次启动不被误认为一次 apply 成功。

## 12. 实现与验收记录

### 12.1 实现结果

1. Gemini companion
   - `CompanionOwnership` 新增可选 `document_format`，新连接按每个 companion 的真实格式
     持久化；未提升 schema，旧记录继续可读。
   - Gemini 只对主配置同目录的精确 `settings.json` 声明旧记录 JSON 合同；Claude
     Desktop 对既有 metadata/deployment companion 保留相同兼容合同。
   - 普通断开、快照恢复和强制断开统一使用持久化格式或 Connector 显式旧合同；未知路径
     在任何写盘前失败关闭。成功恢复会把旧记录升级为带格式记录。
2. Adapter readiness
   - Gateway 保存实际加载成功的 adapter package，并提供不可变只读查询。
   - Desktop 在 `Running` 或 `Applying.old` 上查询正在服务实例，不再从配置名称推断。
   - Agent 扫描结果新增 `adapter_ready` 事实；未就绪时不再显示已接入，新接入按钮禁用，
     既有接管仍允许用户执行恢复。
   - serving `instance_id` 变化会触发一次去重重扫，确保 `Applying.old → Running(new)`
     没有 ready gap 时，页面也会切换到新实例的 readiness。
3. 应用状态
   - 前端只为用户显式“保存并应用”记录目标 revision。
   - 仅在目标 revision 运行且 `error == null` 时显示成功；失败回退旧实例时继续显示
     `serve.error`。
   - 迟到的旧 revision 轮询不会清空待确认目标；普通首次启动不会生成成功横幅。
