# 凭据下拉与额度应用门禁修复设计

## 1. 问题、目标、范围与非目标

### 1.1 问题

1. “添加供应商 → 高级凭据来源”仍使用浏览器原生 `<select>`，与当前桌面端
   shadcn/Radix 控件的视觉、焦点和弹层行为不一致。
2. 额度优先行可以只选供应商、不选模型便点击“保存并应用”。前端会静默
   丢弃不完整行，Desktop 命令也接受空列表，路由核心随后把空列表解释为
   “所有候选模型均参与”。这违反用户显式选择和最小授权原则。

### 1.2 第一性原则

1. **显式性**：路由目标必须来自用户完整选择，空值不得推导出更大范围。
2. **原子性**：一行账户只有在“供应商 + 模型”都完整时才是可提交单元；不得
   把用户看得见的不完整行静默转为另一份配置。
3. **纵深防御**：UI、Desktop 命令和路由核心各自守住边界，任一层失效都不能静默
   扩大路由范围。

### 1.3 目标与范围

- 凭据来源改用项目现有 `components/ui/select.tsx` 控件。
- 额度面板至少有一个完整账户，且不存在不完整行时，才能保存并应用。
- 不完整行就地显示可操作提示，并与模型下拉建立可访问性关联。
- Desktop `set_quota_accounts` 拒绝空列表和任何不完整行，失败时不修改草稿。
- 路由核心对空额度账户列表 fail closed，不使用任何候选模型。

### 1.4 非目标

- 不改变已完整额度账户的排序、余额计算、会话粘性或故障转移。
- 不改变凭据的存储方式、参考值语义或供应商保存协议。
- 不处理请求日志页、日志数据或相关样式。
- 不为空额度列表增加自动选择、自动修复或隐式回退。

## 2. 安全与数据红线

1. 不读取、展示、记录或转移 API Key 值；仅切换凭据来源枚举。
2. 校验失败不得写草稿、不得保存配置、不得重启 Gateway。
3. 空额度列表不得等价为“全选”或任何其他扩大权限的语义。
4. 已完整且有效的账户仍须经 `validate_route_target` 校验；精确重复项可继续
   去重并保留首次顺序。

## 3. 用户可见交互、状态与失败处理

### 3.1 凭据来源

- 触发器、弹层、选中勾和键盘行为由组件库 `Select` 统一提供。
- 选项仍为“本地存储（默认）/环境变量/凭据文件”；切换时继续清空不再适用的
  Key 或参考值，不修改保存协议。

### 3.2 额度账户

- 无任何账户行：“保存并应用”禁用，提示至少添加一个模型。
- 某行只选供应商、模型为空：按钮禁用，该行显示“请选择模型”，模型控件
  标记无效并关联提示。
- 存在完整行和不完整行：仍禁止应用，不静默丢弃不完整行。
- 所有行完整且至少一行：可保存并应用，传递用户看到的完整列表。
- 绕过 UI 提交空或不完整列表：Desktop 命令返回稳定错误，原配置保持不变。
- 旧配置或其他路径令路由核心收到空列表：当次路由返回不可用，不命中任何
  候选模型。

## 4. 响应式、键盘操作与可访问性

- 凭据 `SelectTrigger` 占满字段宽度，900×600 最小窗口不产生水平滚动。
- 凭据下拉支持 Tab 聚焦、Enter/Space 打开、方向键选择、Escape 关闭，并保留
  可见焦点。
- 额度模型触发器通过 `aria-invalid` 暴露错误，通过 `aria-describedby` 关联该行提示。
- 总体提示使用 `role="status"`/`aria-live="polite"`，不仅依赖颜色。
- 禁用按钮保留明确的相邻文字，说明修复动作。

## 8. 额度行校验态对齐修正（2026-08-14）

### 8.1 问题、目标与范围

模型未选择时，模型列会多出一行就地校验文案。额度行当前对所有网格单元整体垂直居中，导致没有
校验文案的供应商控件按整列高度居中并向下偏移，供应商与模型下拉顶部不齐。目标是让一行中的交互
控件始终按顶部基线对齐，校验文案只向模型控件下方扩展，不反向移动其他控件。

本次仅修改额度账户行的布局和对应公开结构测试；不改变校验触发条件、按钮门禁、账户数据、排序、
保存行为或后端契约。不得为对齐而隐藏错误文案或预留永久空白。

### 8.2 交互、响应式与可访问性

- 供应商和模型控件顶部在正常态与校验态均对齐。
- 优先级序号和移除按钮相对下拉控件首行垂直居中，不随错误文案高度移动。
- `aria-invalid`、`aria-describedby`、错误文案 `role="status"` 和键盘顺序保持不变。
- 既有响应式列布局不变，不引入固定行高或横向滚动。

### 8.3 测试与真实 App 验收

- 公开组件测试确认带模型错误的账户行使用顶部对齐布局标记，且无效态关联仍存在。
- 前端全量测试、生产构建、Rust 回归测试和本地 App 安装通过。
- 真实 App 在“只选供应商、未选模型”状态确认两个下拉顶部对齐，提示仍位于模型下方；不点击
  “保存并应用”，验收后移除临时编辑行，不修改持久化配置。
