# 安全审计问题核验与修复设计

## 1. 背景与问题

外部审计报告 `token-station-security-audit.md` 以提交
`7d5bf8aaa14b8467fb94e95d3e55a6b45cc33e1c` 为基线，提出 TS-01～TS-16
共十六组安全、资源、持久化、性能和隐私声明问题。

本次工作以当前 `develop` 的 `e752c24f9e31fb29889009d0ad1d0d1a3a669dce`
为真实核验对象。审计基线之后的改动主要是桌面 UI、发布门禁和代理兼容测试；
在开始本设计时，TS-01、TS-03～TS-10 对应的核心安全模块没有得到系统性修复。

不能把审计报告中的“已确认”直接当成事实。本次先从安全不变量、入口、调用链和
最终 sink 逐条复核；只有能给出具体触发输入、现有 guard 缺口和可观察失败行为的
结论才进入实现。

## 2. 目标

1. 对 TS-01～TS-16 逐条给出“存在、部分存在、已不存在、证据不足或已受控接受”
   的结论和当前源码证据。
2. 优先闭合可由不可信输入触发的路径、凭据、鉴权、并发和渲染层信任边界。
3. 对资源和长期增长问题建立默认非零总量上限，避免用单实例局部上限冒充进程预算。
4. 对持久化操作采用一致快照、预验证、staging、原子替换和可恢复失败语义。
5. 对暂时不能在本批次安全完成的架构迁移，提供 fail-closed 的边界或明确受控遗留，
   不保留误导性“已验证”“完全本地”等声明。
6. 每个行为修复先补公开接口上的回归测试，旧实现必须能让该测试失败。

## 3. 范围

### 3.1 本批次范围

- 插件清单身份、fixture 相对路径、安装、删除、递归复制、receipt 和 package digest。
- Provider endpoint 解析、路径授权、出站 header、入站 HeaderDigest。
- HTTP 鉴权、请求体上限、`spawn_blocking` 前的总量准入和默认并发配置。
- 插件 manifest/WASM/fixture/ABI 输出和实例数量的资源边界。
- 虚拟 key、Provider secret 文件、CLI 密钥交互和外部字符串日志。
- 桌面 `ServeView`、只读管理数据获取、浏览器管理降级行为和 Tauri CSP。
- SQLite backup/restore、统计查询、receipt 查询、成本回填和模型目录缓存。
- 通用敏感文件写入、更新下载/哈希和 README 隐私声明。

### 3.2 非目标

- 不在本批次把同步 `ureq` 全量迁移为异步 HTTP 客户端；先用准入、连接/实例上限和
  有界读取闭合资源风险。
- 不自动删除用户历史数据；retention 需要独立产品策略和显式用户授权。
- 不在没有可信发布者根、公钥分发和轮换方案时伪造“发布者签名已验证”。本批次必须
  先保证 conformance 测试字节与安装字节一致，并把“本机兼容性通过”和“发布者身份”
  分成不同状态。
- 不自动修复或移除受控的 `RUSTSEC-2024-0429` 例外。保留其 owner、暴露评估和到期
  fail 门禁；依赖链升级另开设计。
- 不实施会静默改变或删除历史指标的数据库迁移。
- 不增加远程管理能力。浏览器模式在独立短期、只读、可撤销 admin token 设计完成前
  必须 fail closed。

## 4. 不允许触碰的安全与数据红线

1. 默认监听 loopback、默认开启鉴权、常量时间 key 比较和出站禁止重定向不得弱化。
2. 插件提供的路径不能逃出已打开的插件根；不允许用字符串前缀、通配符或模糊匹配
   保护递归删除。
3. 插件安装失败不得留下可被 discovery 扫描的半成品；旧插件不得在新插件完全验证
   和原子提交前被覆盖。
4. 通过 conformance 的 manifest、WASM 和 fixture 必须与最终安装及 receipt 绑定的
   字节完全一致。
5. Provider 凭据只能附加到标准解析器规范化后仍位于已配置 origin 和 API 根之下的
   URL；授权和发送不得重新解释不同的原始字符串。
6. `Host`、framing、hop-by-hop、proxy 和未声明的出站头不得由插件控制。
7. 鉴权和进程级总量准入必须发生在请求体聚合、blocking 任务和 Provider WASM 实例
   创建之前。
8. 桌面 renderer 不得通过状态快照、模块全局变量或 `localStorage` 持有完整虚拟 key；
   Agent 配置仍由 Rust 后端直接写入。
9. Provider secret 和虚拟 key 不得进入日志、错误、argv、浏览器存储或非显式展示
   路径。
10. backup/restore 失败后只能观察到完整旧状态或完整新状态；不得留下 config/DB
    混合状态。
11. 不把提示正文写入 SQLite、JSONL、诊断日志或新增缓存。云 Provider 请求仍只发送
    给用户配置后最终选中的上游。
12. 不清理、不移动、不覆盖工作区中与本任务无关的未跟踪用户文件。

## 5. 第一性原理安全不变量

| 不变量 | 公开判定 |
|---|---|
| 根目录约束 | 任意清单、CLI 名称、symlink 或并发替换都不能使读写/删除落到插件根之外 |
| 字节身份 | conformance 输入、package digest、receipt 和最终运行输入必须绑定同一 staging 快照 |
| 出站授权 | 授权器与 HTTP 客户端消费同一个规范化 URL；dot、编码分隔符和反斜杠 fail closed |
| 前置准入 | 无效 key、超额请求和超限 body 在分配大 body、blocking worker、连接或 WASM 前失败 |
| 总量预算 | 所有由不可信输入扩张的维度都有默认非零上限和稳定的超限错误 |
| 渲染层最小权限 | renderer 只得到展示所需状态，不得到可消费上游额度的 bearer secret |
| 崩溃一致性 | 每个写入/恢复阶段被中断时，旧状态可恢复且不会发布半成品 |
| 隐私陈述一致 | 文档只声明代码和测试能证明的“不持久化”和“选定上游发送”语义 |

## 6. 最终核验矩阵

以下结论来自当前源码调用链、公开行为测试、恶意输入测试和真实 App 验收。报告中的
复合表述被拆成“能否触发”和“影响是否无界”分别判断，避免把有硬上限的实现继续描述成
无界 DoS，也不把本机 conformance receipt 描述成发布者签名。

| ID | 当前结论 | 主要证据与触发 | 本批次处理 |
|---|---|---|---|
| TS-01 | 存在 | `manifest.name` 和 CLI `name` 直接 `join` 后进入 copy/remove；fixture 仅检查非空 | 安全组件类型、相对路径验证、no-symlink 有界 staging、根约束删除 |
| TS-02 | 存在 | 先对可变 source 做 conformance，后再次复制；receipt 只绑定 manifest/WASM；报告把本机兼容性 receipt 与发布者身份混为一谈 | staging 快照先于测试、完整递归 digest、原子发布、receipt 绑定最终包；发布者签名保持“未验证” |
| TS-03 | 存在，具体利用依赖 HTTP 客户端重解释 | `ProviderEndpoint::permits` 明确允许 dot-segment，授权器与发送端对原始路径的解释边界不清 | 拒绝 raw/encoded dot、编码分隔符、反斜杠、重复斜杠、控制字符和异常 `%`；发送端只消费已验证 URL |
| TS-04 | 存在 | handler 先提取 body 再 `spawn_blocking`；global admission 在 worker 内；默认 `0=unlimited` | 前置异步 semaphore、默认非零、worker/stream/实例总量绑定 |
| TS-05 | 存在 | 浏览器降级从 `localStorage.ts_key` 读取 bearer；CSP 为 `null`；报告没有给出可利用 XSS 证据 | 浏览器不再读取/持有 key，管理调用 fail closed；桌面默认状态不含 key，显式 reveal/copy 只走 typed IPC；启用严格 CSP |
| TS-06 | 存在 | Axum `Bytes` extractor 在 handler 内鉴权前完成；框架默认与网关 10 MiB 不一致 | parts-only 鉴权、准入后有界 `to_bytes`、显式 10 MiB 行为与 413 |
| TS-07 | 存在 | loader 无上限读 manifest/WASM；Store 仅限制单 memory；ABI 错误可原样扩张 | 文件/fixture/ABI/实例/表/内存上限，错误截断与诊断标识 |
| TS-08 | 存在 | `SafeHeaders` 仅拒绝已知 credential，gateway 透传其他全部 header | Provider 出站值白名单和系统/逐跳头硬拒绝 |
| TS-09 | 存在于恶意 Agent 插件威胁模型 | `HeaderDigest` 对非已知 credential 的所有值放行，恶意插件可读取并外传；没有证据表明官方插件已经这样做 | 名称全保留用于协议判断；值仅对闭合协议目录开放，credential 值永不进入 envelope |
| TS-10 | 部分存在 | 首次虚拟 key 写 stderr；TTY `read_line` 回显；model/guest error 原样进入日志；“所有上游响应体都原样记录”不成立 | 首次只报路径、TTY 关闭回显、日志使用稳定错误；官方 Provider 既有的有界响应处理保留 |
| TS-11 | 存在 | CLI backup 直接 `fs::copy` 活跃 DB；restore 依次替换两个文件 | online backup、staging 校验、恢复 journal、回滚和目录 fsync |
| TS-12 | 部分存在 | stats 全量装载排序和成本回填全量 Vec + 长事务成立；receipt 最多返回 5 条，N+1 有界但会阻塞 async worker | stats 精确扫描限制 100,000 条并移出 async worker；成本按 500 条短事务回填；receipt 查询移出 async worker，保留最多 5 条硬上限 |
| TS-13 | 存在且覆盖不一致 | Agent 模块部分路径已有安全写入器，CLI receipts/key/cache/log 与若干桌面缓存没有统一权限和原子语义；真实机器还存在历史 0755/0644 数据 | 私有原子写入器覆盖敏感落点；启动时校验/迁移已知历史目录和文件为 0700/0600，拒绝 symlink/特殊文件 |
| TS-14 | 存在 | cache 无读取上限，removed 模型永久保留，全文件重复解析 | 文件/模型数/ID 长度上限、removed TTL/保留上限、单次加载 |
| TS-15 | 存在，公钥空值当前为 fail closed | 下载和 `sha256_file` 整件缓冲；最终文件可能先覆盖/删除；RustSec 例外有治理但仍活跃 | metadata/signature/artifact 分别限额，私有临时文件流式下载+增量哈希+fsync，create-if-absent 发布不覆盖既有文件；空公钥继续拒绝升级 |
| TS-16 | 存在 | README 同时声称提示不离机并展示云 Provider；`local=true` 未强制 loopback | 文案改为“不持久化；仅发往选定上游；strict local-only 才不离机”，并强制 local Provider endpoint 为 loopback |

## 7. 用户可见交互、状态变化与失败处理

### 7.1 插件 CLI

- `plugin install <path>` 对非法名称、越界 fixture、symlink、超深/超大包返回固定类别错误，
  不创建最终插件目录，不写 receipt。
- 安装先复制到私有随机 staging；只有完整 digest、conformance 和 receipt 准备成功后
  才原子 rename。
- `plugin list/info` 分开展示：
  - `conformance_passed`
  - `publisher_signature_verified`
  - `package_digest`
- `plugin remove <name>` 只接受安全单组件名称；任何 `..`、斜杠、反斜杠、绝对路径、
  控制字符或超长输入在访问文件系统前失败。

### 7.2 HTTP 数据面

- 无效/缺失 key：保持协议相容的 `401`，且不读取 body。
- 进程总量已满：立即 `429 concurrency_limit`，不创建 blocking worker。
- body 超过 10 MiB：已认证且已获准请求返回 `413`；10 MiB 内请求不再被 Axum 隐式
  2 MiB 上限提前拒绝。
- Provider URL 或 header 越界：在解析 credential 前返回稳定内部边界错误，不发网络。
- 日志只记录规范化 model token、固定 error code、长度和 diagnostic hash，不输出不可信
  原文或控制字符。

### 7.3 密钥 CLI

- 首次生成只输出指纹/文件位置，不输出完整 key。
- `key set`：
  - 交互 TTY 使用不回显输入；
  - 管道模式必须显式 `--stdin`；
  - 密钥不得从 argv 读取。
- 完整本地虚拟 key 只通过显式 `key reveal --confirm` 在真实 TTY 展示；重定向时 fail
  closed。

### 7.4 桌面 App

- 默认状态仅显示鉴权是否开启和 key 是否存在，不携带完整 key。
- 用量、receipt、路由、插件和 egress 全部走现有 typed Tauri IPC。
- “显示/复制完整虚拟 key”只允许在桌面 Tauri 环境中由用户显式触发；返回值不写模块
  全局、状态快照或浏览器存储。代理停止时相关按钮禁用。
- 纯浏览器管理在独立 scoped admin token 完成前显示“不受支持”，不读取
  `localStorage.ts_key`。
- CSP 拒绝远程脚本、任意连接、frame 和 object；只开放 Tauri IPC、打包资源和现有内联
  样式所需最小集合。

### 7.5 备份、统计和缓存

- backup 生成一致 SQLite 快照；源 DB 活跃写入时仍可恢复。
- restore 在切换前完成 config 校验、schema 检查和 `integrity_check`；任一步失败保留当前
  状态。
- 查询超过同步管理上限时返回可解释错误，不让 UI/Tokio worker 无界阻塞。
- 模型缓存超限时丢弃最老的 removed 记录；不删除仍在配置中的模型。

## 8. 响应式、键盘和可访问性

- 本批次唯一直接 UI 变化是虚拟 key 卡片和浏览器管理失败提示。
- 桌面窄宽度下指纹、说明和命令提示必须换行，不能扩大现有最小窗口要求。
- 所有操作继续使用原生 `button`，键盘 Tab 可达，Enter/Space 可触发。
- 移除 reveal/copy 后不得留下不可用按钮；状态变化使用文本和现有 status chip，不只依赖
  颜色。
- 命令提示使用可选择的 `<code>`，并带明确可访问标签；错误提示进入现有错误/恢复层。
- CSP 不得阻断主题、语言、图标和焦点样式。

## 9. 公开测试边界

审计报告已明确要求补充插件文件系统、URL/HTTP 差异、资源耗尽、恶意 WASM、持久化和
大库测试；本设计把以下现有公开接口确定为测试 seam：

| seam | 测试位置 | 必须先失败的行为 |
|---|---|---|
| `AdapterManifest::validate` JSON 契约 | `crates/plugin-api` tests | 非安全插件名和 fixture 路径被接受 |
| `plugins::install/remove` CLI 库接口 | `apps/cli/tests/plugin_install.rs` | 越界、symlink、TOCTOU 或超限包可落盘/删除 |
| `plugin_package_digest` | `crates/release` tests | 递归文件未绑定、symlink/特殊文件被跟随 |
| `ProviderEndpoint` + `ProviderConfig::authorize` | `crates/protocol` tests | dot/编码分隔符/默认端口差异通过 |
| `SafeHeaders` / `HeaderDigest` serde 契约 | `crates/protocol` tests | system header 或未知私有值进入插件 |
| 真实 Axum listener | `apps/cli/tests/proxy.rs` | 未认证 body 被读取、2～10 MiB 被错误拒绝、worker 前不拒绝超额 |
| `PluginRuntime` / loader | `crates/plugin-runtime` tests | 超大输入/输出/实例逃出预算 |
| CLI clap + 子进程 stdin/stdout/stderr | `apps/cli` tests | 首启泄露、TTY/pipe 交互不安全、原始日志未约束 |
| `backup/restore` + 真实 SQLite | `apps/cli` tests | 活跃 DB 快照不一致、失败产生混合状态 |
| `stats` / `SqliteStore` 公共查询 | `apps/cli` tests | 无界装载、receipt N+1、回填不可分批 |
| Tauri command + `StateView` serde | `apps/desktop/src-tauri` tests | renderer 状态包含完整 key |
| React `api.ts` / Settings 页面 | `apps/desktop/src` tests | Tauri 路径仍 fetch bearer、浏览器读取 `ts_key`、UI 暴露 key |
| 模型目录 public command | `apps/desktop/src-tauri` tests | 超限 cache/removed 记录单调增长 |
| 更新下载/哈希函数 | `apps/cli`、`crates/release` tests | 哈希要求整件内存读取 |
| README 精确隐私语义 | 文档一致性 grep/test | 仍声称云路径下提示不离机 |

测试只在系统边界 mock 外部 Provider/网络、时间和故障注入，不 mock 仓库内部模块。

## 10. 实现落点与最小顺序

### Phase A：直接安全边界

1. `crates/plugin-api`：`PluginName`、`SafeRelativePath` 验证和 serde 入口。
2. `apps/cli/src/plugins.rs`：有界 no-symlink staging、同字节 conformance、原子安装和
   根约束删除。
3. `crates/release`：递归规范 package digest 和增量文件 hash。
4. `crates/protocol`：标准 URL、规范路径授权、出站 header allowlist、入站值 allowlist。
5. `apps/cli/src/server.rs`：parts-only auth、前置 semaphore、有界 body 聚合。
6. `apps/cli/src/admission.rs` / config：非零安全默认值和拒绝显式零值。
7. `crates/plugin-runtime`：输入/输出/错误/Store/实例预算。

### Phase B：凭据和 renderer

1. `apps/cli/src/virtual_key.rs`、`secrets.rs`、`main.rs`：安全文件读取、显式 reveal、
   隐藏输入、日志最小化。
2. `apps/desktop/src-tauri`：默认 `ServeView` 不返回 key；后端继续持有 key 并用于
   Agent 配置，显式 reveal/copy 通过独立 typed command 完成。
3. `apps/desktop/src/api.ts`：浏览器分支删除 `localStorage.ts_key`；Tauri 管理查询和
   显式 key 操作只走 IPC。
4. `SettingsHub.tsx`：key 卡片默认隐藏，代理停止时禁用 reveal/copy。
5. `tauri.conf.json`：启用严格 CSP。

### Phase C：持久化与长期资源

1. CLI `secure_fs`：私有目录、no-follow 有界读取、临时文件、flush/fsync、原子 rename。
2. `backup.rs`：online SQLite snapshot、staging、校验、journal、原子切换和回滚。
3. `stats.rs` / `store.rs`：聚合下推或有界分批、receipt 批量子查询、成本分批回填。
4. `model_catalog.rs`：缓存上限、removed TTL/数量上限和单次加载。
5. `upgrade.rs`：下载直写私有临时文件并增量 SHA-256。
6. README 与用户文档：回写精确隐私、插件信任和资源限制语义。

## 11. 验收标准

### 11.1 安全行为

- 审计报告列出的路径穿越样例和同类 Windows/Unicode/符号链接输入均在触盘前失败。
- 安装中并发替换 source 不改变 staging 内已测试字节；最终 digest 与测试快照一致。
- `/v1/../admin`、编码 dot/slash、反斜杠、userinfo、默认端口差异不能获得凭据。

## 14. 已知遗留项与现有控制

| 遗留 | 现有控制与风险 | 触发条件与下一步 |
|---|---|---|
| 同步 `ureq` 到异步 HTTP 的架构迁移 | 全局/Agent/Provider 并发默认非零，worker 在 body 前准入，stream component 进程级最多 64；因此不是无界扩张，但阻塞线程的效率风险仍在 | 需要更高并发或取消传播时另立设计迁移，不在安全修复中仓促改传输栈 |
| 浏览器管理 token | 浏览器管理 fail closed，不读取 bearer；风险是纯浏览器模式暂不可管理，而不是凭据泄露 | 产品确认远程/浏览器管理需求后，设计短期、只读、可撤销 scoped token |
| 发布者信任根 | package digest 和 conformance receipt 绑定最终安装字节，但不证明发布者身份 | 在存在可信根、轮换、撤销和 UI 语义后再实现签名；此前保持 `publisher_signature_verified=false` |
| receipt 子查询 | 最多 5 条且已移出 async worker，不构成报告所称无界 DoS；仍有固定 N+1 成本 | receipt 展示规模扩大前改为批量查询 |
| 精确 stats | 最多扫描 100,000 条，超限返回窄化筛选错误；不会无界占用，但大窗口仍有固定成本 | 若产品需要超大窗口精确分位数，新增数据库聚合/预聚合设计 |
| retention/归档 | 本批次不静默删除用户指标；磁盘长期增长仍由用户数据规模决定 | 产品确定保留期、导出和删除授权后另立迁移设计 |
| Windows 运行时路径行为 | Windows/reparse 防护代码已编译和静态门禁，当前只在 macOS 真实运行验收 | Windows 发布前补 NTFS junction/reparse/hardlink 真机矩阵 |
| RustSec 在线新鲜度 | 离线缓存审计通过，当前环境无法连接代理刷新索引；既有 `RUSTSEC-2024-0429` 例外仍按治理文件受控 | CI/有网络环境必须执行在线门禁；依赖链可升级时移除例外 |
| 前端 bundle 体积 | production build 通过，Vite 报约 964 KiB chunk 警告；不影响本次安全行为 | 性能预算工作中拆分 chunk，不与安全修复混合 |
