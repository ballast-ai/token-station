# 操作反馈统一 Toast 收口

- 日期：2026-08-12
- 状态：已实现；自动化、构建和本地安装已通过；真实点击因锁屏未执行
- 范围：Desktop 操作反馈组件、顶层代理生命周期反馈、各页面一次性成功/失败反馈
- 不涉及：Recovery 信息架构、字段校验规则、首屏/整块内容错误页、后端命令与数据契约

## 1. 问题

当前 Desktop 已把大部分请求失败放入左下角错误 Toast，但反馈系统只支持 `error`。
成功反馈仍由多套页面内横条承担。点击顶栏“启动代理”时，`serve_start` 返回
`phase=starting`，`App.tsx` 会在内容顶部渲染 `.global-banner`，并把普通启动误写成
“正在应用配置…”。这是用户看到顶部细横条的直接原因。

残留的一次性页面内反馈包括：

1. 顶层保存并应用、策略组增删、应用到全部 Agent、供应商增删/恢复和添加供应商。
2. Agent 接入、断开、挂载策略组、保存路由、应用主页路由和恢复跟随主页。
3. 通用设置保存、预算保存/删除、模型价格版本保存/删除。
4. Provider 模型保存等由顶层 `showState(next, message)` 承接的成功结果。
5. 发布链接、虚拟 API Key 和请求 ID 的复制失败此前未捕获，会误报“已复制”或产生未处理
   Promise rejection。
6. Agent 显示、主题和语言属于显式偏好操作；偏好写入或原生主题同步失败时不能静默吞掉，
   但当次界面切换仍应保持生效。

这些反馈的呈现位置、语义、关闭方式和存活时间不一致，导航还会提前清掉顶层消息。

## 2. 判断边界

“所有提示都放 Toast”若按字面包含字段错误、首载失败、恢复原因和下载进度，会导致用户在
8 秒后失去修复入口或持续状态。因此本次统一的是**一次性操作反馈**，不是把所有状态文本
机械搬到左下角。

### 2.1 必须进入左下 Toast

- 用户触发命令的进行中反馈：启动代理、停止代理、保存并应用。
- 用户触发命令的成功结果：创建、保存、删除、恢复、接入、断开、应用、启动和停止。
- 用户触发命令的非字段失败，以及后台刷新/监听等瞬时请求失败。
- 正常 App 内的复制操作失败；复制成功仍可留在触发按钮内作微反馈。
- Agent 显示、主题、语言等偏好持久化与原生同步失败。

### 2.2 必须保留原位

- 字段/表单校验和对应焦点、`aria-invalid`、字段说明。
- 启动页、整块内容首载失败及重试入口。
- Recovery/只读保护的原因、操作结果和恢复入口。
- About 更新结果、版本说明、下载进度等需要持续阅读或操作的内容。
- 路由配置错误、revision、代理健康、预算预警、目录来源等持续状态。
- 首次接入差异卡片；它是一次性但需要用户阅读并确认，不是短暂反馈。
- 复制按钮自身的短时“已复制”标签；这是控件内确认，不产生布局横条。

## 3. 目标与非目标

### 3.1 目标

1. 删除业务页面顶部 `.global-banner`，普通启动不再出现“正在应用配置…”。
2. 提供 `info`、`success`、`error` 三种统一左下 Toast，均支持 X 关闭和 8 秒渐隐。
3. 代理启动/停止只在用户点击时产生进行中 Toast；应用启动时恢复到 `starting` 不冒出操作
   Toast。
4. 保存并应用只在显式应用动作下显示“正在应用配置…”，并仅在目标 revision 确实运行后
   显示成功。
5. 同一动作使用稳定 ID 更新 Toast；从进行中变为成功/失败时重启 8 秒寿命，不堆叠旧消息。
6. 页面导航不清除 Toast；页面中的一次性成功横条全部移除。
7. 偏好写入失败不得回滚本次界面选择；必须提示“本次已生效，但可能无法在下次启动时保留”。

### 3.2 非目标

- 不修改 Tauri 命令、代理状态机、revision 判定或接入事务顺序。
- 不把持续状态伪装成短暂通知。
- 不新增 Toast 依赖或远程资源。
- 不调整 Recovery 页；它位于正常 App Provider 之外且必须持续显示修复结果。

## 4. 安全与数据红线

1. Toast 只展示现有已脱敏人话错误，不得显示 API Key、配置内容、请求/响应正文或本机路径。
2. Toast 不能作为命令成功的依据；成功仍由后端返回状态或运行 revision/可达性判定。
3. 普通代理启动不得被标记为“配置已应用”；保存并应用不得在旧 revision 或回退实例运行时
   报成功。
4. 接入成功后的偏好写入失败不得反转接入结果；应独立显示错误 Toast。
5. 去重不能吞掉新结果；同 ID 的类型/文案变化必须更新并重置渐隐计时。

## 5. 用户可见交互与状态

### 5.1 代理启动与停止

```text
点击启动代理
  → info Toast「正在启动代理…」
  → 返回 running 且 listener 可达：同 ID 更新为 success「代理已启动」
  → 返回 starting：保留 info；后续 serve event 达到可用终态后更新为 success
  → 请求或 runtime 失败：error Toast

点击停止代理
  → info Toast「正在停止代理…」
  → stopped：同 ID 更新为 success「代理已停止」
  → 失败：error Toast
```

首次进入 App 时即使读到 `starting`/`stopping`，也只由顶栏运行态控件表达，不主动弹 Toast。

### 5.2 保存并应用

- 点击后以 `config-apply` ID 显示 info Toast「正在应用配置…」。
- 后端立即抛错时更新为 error。
- 返回 `starting` 后继续等待现有目标 revision 判定。
- 目标 revision 运行且无错误时更新为 success「配置已应用 · revision N」。
- 旧 revision、失败回退或非运行终态不得显示 success。

### 5.3 其他操作

- 一次性成功结果直接显示 success Toast。
- 一次性非字段失败显示 error Toast。
- 按钮 busy 文案和禁用态继续表达局部进行中状态，不额外制造重复 Toast，除代理生命周期和
  保存并应用这两个跨页面/跨事件动作。

## 6. 视觉与可访问性

产品对象是本地 AI Agent 网关控制台，主要用户是需要快速判断操作是否生效的工程用户；
Toast 的唯一任务是说明“哪个动作处于什么结果”，不承担配置说明。

- 位置：复用固定左下 viewport，宽度 `min(380px, 100vw - 36px)`，纵向堆叠。
- 字体：沿用 IBM Plex Sans 与现有 12px / 1.45 行高，不引入新字体。
- 色彩：`info` 使用 `--signal`，`success` 使用 `--success`，`error` 使用 `--danger`；底色均
  以现有 surface 混合，深浅主题自动适配。
- 结构：统一 48px 最小高度、类型图标、正文和关闭按钮。类型差异同时由图标、语义和颜色
  表达，不只依赖颜色。
- error 使用 `role=alert` / assertive；info、success 使用 `role=status` / polite。
- Toast 出现不抢焦点；关闭按钮可键盘操作，名称统一为“关闭提示”。
- 7 秒开始渐隐、8 秒移除；`prefers-reduced-motion` 下取消动画但仍按时移除。

## 8. 公开测试边界

1. Toast 组件：三种类型、语义角色、稳定 ID 更新、计时重置、X 关闭、8 秒渐隐、不抢焦点。
2. App：点击启动/停止后顶部无 `.global-banner`；info/success 位于左下 viewport；初始
   `starting` 不显示“正在应用配置”。
3. App 应用：info 只由显式保存并应用触发；旧 revision/错误无 success；目标 revision
   成功时 success 位于 viewport。
4. App 顶层策略、Provider 等操作成功位于 viewport，导航后仍存在。
5. Agent：接入、断开、路由保存成功位于 viewport，页面内无成功横条；前置配置缺失错误
   进入 error Toast。
6. Settings/Stats/Pricing：操作成功进入 viewport；字段校验继续在字段附近且不产生全局横条。
7. 既有错误 Toast、瞬时后台刷新、Recovery、首载和持续状态测试继续通过。
8. 复制失败只进入 viewport，不误显示“已复制”，不泄露虚拟 Key，也不产生未处理 Promise。
9. 偏好存储或原生主题同步失败时，当次 UI 仍更新，并在 viewport 显示稳定 ID 错误 Toast。

## 10. 实现与验收结果

实现完成：

- 普通启动不再渲染顶部 `.global-banner`；显式启动、停止、保存并应用用同一稳定 ID 在左下
  Toast 中从 `info` 更新为 `success` 或 `error`。
- 策略组、Provider、Agent 接入/恢复/路由、设置、预算、价格等一次性成功与非字段失败已
  收口；页面导航不再清除 Toast。
- 发布链接、虚拟 API Key、请求 ID 仅在剪贴板写入成功后显示“已复制”；失败进入 Toast。
- Agent 显示、主题、语言偏好写入失败，以及 macOS 主题同步失败，均保留当次界面状态并
  进入 Toast。
- 恢复官方配置成功后的缓存刷新失败使用独立错误 ID，不再反转已完成的恢复结果。
- 公开价格查询失败进入 Toast；Provider Base URL 解析失败按字段错误留在字段附近，并提供
  `aria-invalid` 与可访问描述。
- 公开价格查询失败后允许对同一模型重试；重试成功会关闭旧错误，查无公开价格会明确提示
  并允许再次查询。Provider 字段错误使用实例安全 ID，不受供应商名中空格或中文影响。
