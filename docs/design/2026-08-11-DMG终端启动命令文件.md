# DMG 终端启动命令文件设计

## 1. 问题、目标、范围与非目标

### 问题

当前 v1.1.3 未签名测试 DMG 会被 macOS Gatekeeper 阻止首次启动。DMG 已包含可双击执行的 `安装 Token Station.command` 和详细的 `安装前必读.md`，但部分用户更习惯从说明文件复制一条终端命令。现有 Finder 布局中没有一个名称直接、打开后即可复制命令的入口。

### 目标

- 在未签名、未经 Apple 公证的测试 DMG 根目录新增 `终端启动命令.txt`。
- 文件说明先把 `token-station.app` 拖入 Applications，再复制一条完整命令到终端。
- 命令只移除 `/Applications/token-station.app` 的 quarantine 属性；成功后立即启动同一个 App。
- Finder 打开 DMG 时能直接看到该文件，且六个底部辅助入口不重叠、不被窗口裁切。
- 打包审计必须验证文件存在、内容安全、命令目标精确和 Finder 布局位置。

### 范围

本次修改 macOS 自定义 DMG 的静态载荷、组装脚本、挂载审计、Finder 布局和公开产物测试。只影响 `--unsigned-test` 生成的未签名测试 DMG。

### 非目标

- 不修改中英文 README。
- 不修改桌面 App 的界面、运行逻辑、bundle id 或用户数据。
- 不给已完成 Developer ID 签名和 Apple 公证的正式 DMG 添加 Gatekeeper 绕过命令。
- 不关闭系统级 Gatekeeper，不修改 SIP。
- 本任务不自动上传或替换 GitHub Release 资产；发布仍需单独授权。

## 2. 安全与数据红线

1. 终端命令只能作用于固定路径 `/Applications/token-station.app`，不得使用通配符、父目录、用户主目录或动态模糊匹配。
2. 禁止出现或执行 `spctl --master-disable`，不得降低整台 Mac 的安全设置。
3. 文案必须要求用户只对 Token Station 官方 GitHub Releases 下载的 DMG 执行命令。
4. 文案必须要求先把 App 拖入 Applications；如果 Finder 提示目标已存在，应选择替换，不能保留名为 `token-station 2.app` 的并行副本。
5. `sudo` 密码只能由用户直接输入系统终端。文案说明输入时不会显示字符；项目和 Agent 不读取、保存、打印或转发密码。
6. 使用 `&&` 连接 `xattr` 与 `open`；quarantine 移除失败时不得继续启动 App。
7. 保留现有可双击安装脚本及其 bundle id、代码签名、备份和回滚检查；文本命令只是用户明确要求的备用路径。

## 3. 用户可见交互、状态与失败处理

1. 用户挂载未签名测试 DMG，在 Finder 根目录看到 `终端启动命令.txt`。
2. 用户先把 `token-station.app` 拖到 Applications。
3. 用户双击文本文件，阅读来源限制和密码提示，复制其中唯一的命令行。
4. 用户打开终端并粘贴执行：

   ```bash
   sudo xattr -dr com.apple.quarantine "/Applications/token-station.app" && open "/Applications/token-station.app"
   ```

5. 终端请求密码时，用户输入当前 Mac 的管理员密码；输入过程无回显。
6. `xattr` 成功后执行 `open`。App 不存在、路径错误或权限失败时，shell 保留原始错误且不执行 `open`。
7. 若用户不愿执行终端命令，仍可使用 `安装 Token Station.command` 或 `安装前必读.md` 中的右键打开流程。

## 4. Finder 布局、键盘操作与可访问性

- 正式 DMG 保持原有 `920×600` Finder 窗口和布局不变。
- 未签名测试 DMG 因增加第六个底部入口，窗口扩为 `1080×600`。App 与 Applications 保持顶部主视觉关系，底部六个入口按固定间距排列。
- `终端启动命令.txt` 放在底部中间区域，文件名无需打开其他文档即可理解用途。
- 文本文件使用 UTF-8 纯文本，命令独占一行，支持键盘选择与复制；来源、密码和失败行为不依赖颜色或图标表达。
- Finder 图标继续启用预览；审计读取 `.DS_Store` 中的窗口尺寸、视图、图标大小和每个入口位置，防止自动排列或裁切回归。

## 5. 公开测试边界、验收标准与真实检查

### 自动化边界

- 静态公开行为测试先断言打包脚本、审计脚本、布局脚本和命令文件契约，再实现代码。
- 挂载审计使用真实生成的 DMG，验证根目录精确文件集、命令文件内容、App、架构、签名状态和 Finder 布局。
- 自动化不得执行 `sudo xattr`、不得请求管理员密码，也不得对当前 `/Applications` 内容移除 quarantine。

### 验收标准

1. 未签名测试 DMG 根目录精确包含新增的 `终端启动命令.txt`，正式 DMG 不包含该文件。
2. 文本包含唯一的 canonical 命令、官方来源限制、先拖入 Applications、密码无回显和失败短路说明。
3. 文本、README、安装脚本均不包含全局关闭 Gatekeeper 的执行步骤。
4. `scripts/audit-macos-dmg.sh` 会拒绝缺文件、命令被篡改、路径扩大或布局不一致的 DMG。
5. 未签名布局为 `1080×600`，六个底部入口完整可见；正式布局仍为 `920×600`。
6. 公开测试、shell/AppleScript 语法检查、真实 DMG 生成与挂载审计通过。
7. 挂载最终只读 DMG 后进行真实 Finder 截图检查，确认文件名、间距和顶部拖拽关系。
8. 桌面 App 源码没有变化；仍按工程约定执行本地 App 安装流程并确认 bundle id、代码签名和启动结果。

## 6. 实现落点、遗留项与发布要求

### 实现落点

- `packaging/macos/终端启动命令.txt`：用户可复制的纯文本入口。
- `scripts/package-macos-dmg.sh`：仅在 `--unsigned-test` 时复制文件。
- `scripts/audit-macos-dmg.sh`：验证挂载内容、安全文案与 Finder 布局。
- `packaging/macos/configure-dmg-layout.applescript`：为未签名布局增加图标并扩展窗口。
- `packaging/macos/dmg-layout-unsigned.dsstore.base64`：保存未签名测试包独立的 `1080×600` Finder 布局；正式包继续使用原有模板。
- `tests/unsigned-test-dmg.mjs`、`scripts/check-macos-dmg-packaging.mjs`：公开行为和结构回归测试。
- `docs/release/macOS-DMG安装提示与打包要求.md`：补充未签名测试 DMG 的可复制命令入口要求。

### 已知遗留项

这条命令只是未签名测试版本的局部放行方案。长期正确方案仍是完成 Developer ID 签名、Apple 公证和票据装订，使普通用户无需终端即可双击启动。

### 发布要求

本任务可以生成本地测试 DMG 作为验收证据，但不得自行上传或覆盖 GitHub Release。后续发布者必须重新核对版本、架构、源码提交、打包提交、SHA-256 和 Release 说明，并获得明确发布授权。
