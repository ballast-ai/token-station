# 配置详解

token-station 的主配置集中在**一个 JSON 文件**里（默认 `token-station.json`，用
全局 `--config` 覆盖）。每个命令读它，编辑类命令原子重写它——被拒的编辑让
文件逐字节不变。凭证、日志、指标和本地虚拟 Key 位于独立的数据目录，不写入
主配置。

字段定义以 [apps/cli/src/config.rs](../../apps/cli/src/config.rs)（`ClientConfig`
及各子结构）为准。完整示例见
[apps/cli/example-config.json](../../apps/cli/example-config.json)。

## 顶层结构

```jsonc
{
  "version": 1,
  "server":   { ... },   // 监听与鉴权
  "data":     { ... },   // 本地数据层（可选，有默认）
  "health":   { ... },   // 上游健康摘除（可选，有默认）
  "plugins":  { ... },   // 插件目录与方言绑定
  "upstreams":{ ... },   // 各上游
  "router":   { ... }    // 路由表，即 router-core 的 RouterConfig
}
```

> `router` 段就是 `router-core` 的 `RouterConfig` 原样嵌入——其形状、校验与
> 失败语义都在那个 crate 里，client 与 gateway 不能各自分叉。字段含义见
> [路由机制.md](路由机制.md)。

## server

```jsonc
"server": { "listen": "127.0.0.1:8787", "auth": true }
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen` | 必填 | 如 `127.0.0.1:8787`。**必须回环**；非回环地址在启动时直接拒绝，不是警告。 |
| `auth` | `true` | 每个端点都要求本地虚拟 key。**默认开**：回环是对网络的边界，不是对本机其他进程的。 |

用 `token-station-cli config set server.auth on|off` 翻这个开关。

## data

```jsonc
"data": { "dir": "token-station-data", "metrics": true }
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `dir` | `token-station-data` | 存 `requests.log`（含轮转）、`metrics.sqlite`、`virtual-key` 和 `secrets.json`。 |
| `metrics` | `true` | 指标库默认开、仅本地；关掉只剩文件日志（文件日志**始终**写）。 |

用 `token-station-cli config set data.metrics on|off` 翻。两种记录都**不含**
prompt / response 内容，只有用量、延迟、路由元数据。

## health

```jsonc
"health": { "eject_after": 3, "cooldown_ms": 30000 }
```

上游健康摘除，可省略（用默认）。字段含义见
[路由机制.md](路由机制.md#上游健康与摘除)。

## plugins

```jsonc
"plugins": {
  "dir": "plugins-dist",
  "agent": "agent-openai",
  "providers": { "openai-compatible": "provider-openai-compatible" }
}
```

| 字段 | 说明 |
|---|---|
| `dir` | 插件包目录，每个包一个子目录（`manifest.json` + `adapter.wasm`）。启动时扫描，每个 manifest 声明的 provider 方言自动注册。 |
| `agent` | 拥有入站协议的 agent adapter 包名。 |
| `providers` | 显式的「方言 → 包名」映射。可预声明一个尚未在 `dir` 里的包，但不能与已发现的 manifest 冲突。写在这里是运营者意图，无需 conformance 回执即绑定。 |
| `allow_unsigned` | 默认 `false`。是否让**未通过** `plugin install` conformance 的已发现包接流量。默认关：把文件丢进插件目录不足以让它收请求。 |

插件的信任模型与开发链见 [插件体系.md](插件体系.md)。

## upstreams

每个上游一个条目，键是上游名（池会引用它）。

```jsonc
"upstreams": {
  "openai_personal": {
    "provider": "openai-compatible",
    "base_url": "https://api.openai.com/v1",
    "auth": { "slot": "provider_api_key", "env": "OPENAI_API_KEY" },
    "models": [
      { "model": "gpt-5.5", "tool": true, "vision": true, "json_schema": true, "context_window": 400000 }
    ]
  },
  "ollama_local": {
    "provider": "openai-compatible",
    "base_url": "http://127.0.0.1:11434/v1",
    "models": [ { "model": "llama3.3", "tool": true, "context_window": 128000 } ]
  }
}
```

| 字段 | 说明 |
|---|---|
| `provider` | 该上游说的 provider 方言，如 `openai-compatible`；必须在插件注册表里能解析。 |
| `base_url` | 基址。经 `ProviderEndpoint` 校验：**不能有 userinfo、不能有 query**——那正是 API key 最容易被塞进 URL 的两处。 |
| `auth` | 无鉴权上游（如本地 Ollama）省略；否则见下。 |
| `models` | 该上游提供什么。`tool` / `vision` / `json_schema` / `context_window` 声明能力。adapter 可细化它，但因无网络不能替换它。 |

### 凭证与 auth

`auth` 只说凭证的**值在哪里**，**从不是值本身**：

```jsonc
"auth": {
  "slot": "provider_api_key",   // provider adapter 看到的槽名
  "store": true,                // 从本地私有凭证文件读（默认）
  "env": "OPENAI_API_KEY",      // 或从环境变量读
  "file": "/path/to/keyfile"    // 或从文件读（去空白）
}
```

三种来源（用其中一种）：

- **`store: true`**：从数据目录下的明文 `secrets.json` 读取，
  `token-station-cli key set` 写入。文件使用仅当前用户可访问的权限或平台 ACL，
  但没有静态加密。旧配置中的 `keyring: true` 仍作为兼容别名读取，保存时会
  规范化为 `store: true`。
- **`env: <VAR>`** — 请求时从该环境变量读。
- **`file: <PATH>`** — 请求时从该文件读（去首尾空白），文件权限由使用者负责。

凭证在请求时按 slot 名解析，注入单个 header，随请求出作用域——不进日志、
不进错误、不进插件。

## 编辑配置

```bash
token-station-cli config edit    # 用 $VISUAL/$EDITOR 打开，校验通过才应用
```

也可直接改文件后重启 `serve`；结构校验在加载时进行，路由可达性在构建 gateway
时进行，两条错误通道各自独立（不可读的文件 vs 不可路由的表，需要不同的修法）。

## 桌面端 Agent 配置投影

Agent 接入配置不属于上述 `token-station.json`，也不会修改其中的 `router`。点击
“一键接入”后，桌面端会生成内部计划并立即把本机回环代理 endpoint 投影到目标 Agent
自己的配置文件。首次接入的改动字段会在写入完成后展示：

| Agent | 默认目标 | 格式 |
|---|---|---|
| Claude Code | `~/.claude/settings.json` | JSON |
| Claude Desktop | `~/Library/Application Support/Claude-3p/configLibrary/<id>.json` | JSON |
| Codex | `~/.codex/config.toml` | TOML |
| Gemini CLI | `~/.gemini/.env` | dotenv |
| OpenCode | `~/.config/opencode/opencode.json` | JSON/JSONC |
| OpenClaw | `~/.openclaw/openclaw.json` | JSON5 |
| Hermes Agent | `~/.hermes/config.yaml` | YAML |
| WorkBuddy | `~/.workbuddy/models.json` 或 `~/.workbuddy-ai/models.json` | JSON |

环境覆盖和 Windows 路径由内置 Registry 推导，前端不能自行指定目标路径。每个 Connector 只
拥有少量 declared owned paths，其他字段与注释保留。写入前生成由本地私有
`snapshot-master.key` 保护的 AES-256-GCM 快照，随后原子替换并写后自检；用户修改受管值、配置歧义或 revision
变化都会停止写入并要求重新扫描。具体机制见
[桌面 App Agent 接入机制](../contributing/桌面App-Agent接入机制.md)。

Cursor 不使用上述通用 Connector。macOS 与 Windows 上，用户退出 Cursor 后可以执行专用
一键接入；该路径先备份两条原设置，再直接更新 Cursor 的本地 SQLite。它当前不具备通用
Connector 的字段归属和应用内断开流程，用户也可以改为手动配置。
