# 路由机制

token-station 的路由决策全部发生在本机，由**四层**顺序求值，**第一个给出
答案的层胜出**。路由内核（`router-core`）是纯函数：不读时钟、不用随机、不做
IO，因此本地 client 与服务端 gateway 对同一请求给出完全相同的路由。

选池逻辑集中在 [crates/router-core/src/route.rs](../../crates/router-core/src/route.rs)
的 `select_pool`。下文结合示例配置
[apps/cli/example-config.json](../../apps/cli/example-config.json) 讲解。

## 触发路由：`auto` 与具体模型

- 客户端请求模型 `auto` → 路由器按下面四层决策该去哪个池。
- 客户端请求具体模型 → 直接给你那个模型（若某个已配置上游能提供它）。

## 四层，按优先级从高到低

### 第 1 层 · Rules（运营者写的规则，最高优先级）

遍历 `router.rules`，某条规则的匹配器命中即返回它的 `route_to`。这是你写死
的强制规则。

```jsonc
"rules": [
  { "id": "long-context", "when": { "estimated_input_tokens_at_least": 32000 }, "route_to": "sota" },
  { "id": "tool-calls",   "when": { "requires_tools": true },                    "route_to": "sota" }
]
```

> 输入 token 估计达到 32000 → 走 `sota` 池；需要工具调用 → 走 `sota` 池。

### 第 2 层 · Agent hints（调用方声明的意图）

遍历 `hint_routes`，当某个 hint 的 `kind` 与 `value` 同时等于配置项时命中。
持久化到决策记录里的是**配置里的 value** 而非 header 传来的原文——agent 无法
把自己的文本写进你的决策记录。

```jsonc
"hint_routes": [
  { "kind": "step_type", "value": "planning",  "route_to": "sota" },
  { "kind": "step_type", "value": "summarize", "route_to": "cheap" }
]
```

> Agent 声明这一步是 `planning` → 走 `sota`；是 `summarize` → 走 `cheap`。

### 第 3 层 · Heuristic（打分对阈值）

对请求特征打分，`score >= threshold` 取 `above` 池，否则 `below` 池。分数为
整数运算，保证 client 与 gateway 不会因浮点末位分歧。

```jsonc
"heuristic": {
  "weights": {
    "tokens_per_point": 100, "per_tool": 20, "json_schema": 10,
    "image": 15, "per_code_block": 8, "per_extra_turn": 3
  },
  "threshold": 40, "above": "sota", "below": "cheap"
}
```

> 每 100 token 计 1 分，每个工具 +20，JSON schema +10，每张图 +15，每个代码
> 块 +8，每多一轮对话 +3；总分 ≥ 40 走 `sota`，否则 `cheap`。

### 第 4 层 · Default（兜底池）

前三层都没命中时，返回 `default_pool`。

```jsonc
"default_pool": "cheap"
```

## 选定池之后：能力过滤与排序

选出池后，`rank` 再在池内按**能力**过滤并按健康度稳定排序：

- 能力匹配（`satisfies`）：请求要求 tools / vision / json_schema、以及所需
  上下文窗口，候选模型必须都满足。
- `assumed_context_window`（示例为 `8192`）：当某 adapter 未报告上下文窗口
  （窗口为 0）时的兜底假设。
- 健康度排序：被摘除的上游排到后面（见下）。

## 上游健康与摘除

连续失败达到阈值的上游被临时摘出轮转，冷却期后自动恢复。配置在
`health` 段（[apps/cli/src/config.rs](../../apps/cli/src/config.rs) `HealthConfig`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `eject_after` | `3` | 连续可计失败多少次后摘除该上游。 |
| `cooldown_ms` | `30000` | 摘除后停留在轮转外的时长（毫秒）。 |

路由会自动绕开被摘除的上游；冷却结束后它重新进入排序。

## 查看当前路由表

```bash
token-station-cli rule list
```

按求值顺序逐层打印你当前的路由表，便于确认某个请求会落到哪个池。
