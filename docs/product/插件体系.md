# 插件体系

provider / agent adapter 都是**沙箱 WASM 插件**，只做协议翻译：把入站协议
归一为系统内部的规范类型，再把内部请求翻成上游认识的协议。它们**没有网络、
拿不到明文密钥**——安全边界由运行时（`plugin-runtime`）构造，见
[../contributing/架构总览.md](../contributing/架构总览.md#插件沙箱边界)。

本文讲**使用者**要知道的：插件从哪来、凭什么被信任、怎么做一个自己的。

## 两类 adapter

| 类型 | 职责 | 官方包 |
|---|---|---|
| **agent adapter** | 拥有**入站**协议：把客户端发来的 JSON 归一为内部 `ChatRequest`，抽取 agent hints，最后把响应渲染回客户端要的形状。配置里 `plugins.agent` 指定它。 | `agent-openai`（OpenAI Chat Completions） |
| **provider adapter** | 拥有**出站**协议：把内部请求翻成某个 provider 方言的 HTTP 请求，解析（含流式）响应。一个 `upstream` 的 `provider` 字段选它。 | `provider-openai-compatible`（`openai-compatible` 方言） |

官方 manifest 里 `permissions` 全是 `network: false`、`filesystem: false`，
provider 只声明 `secrets: ["provider_api_key"]`——它能请求对该 slot 签名，
但拿不到值。

## 三层分发

插件方言注册表按此顺序合并来源
（[apps/cli/src/plugins.rs](../../apps/cli/src/plugins.rs)）：

1. **Builtin（内置）** — 官方包由发布流水线编进二进制（`--features
   builtin-plugins`）。普通 `cargo build` 没有；**官方发布二进制**即使插件
   目录为空也能服务 `openai-compatible`。
2. **Discovered（发现）** — `plugins.dir` 下每个子目录一个包
   （`manifest.json` + `adapter.wasm`），按 manifest 声明的每个方言注册。把
   包放进目录就是全部的「注册」动作。
3. **显式 `plugins.providers`** — 配置文件里的运营者意图，即使包目录还不存在
   也生效（gateway 在加载时报告缺失的包）。

同层冲突**拒绝而非仲裁**（两个本地包抢同一方言、显式条目与已发现 manifest
矛盾，都是必须让运营者看到的配置错误）。跨层 **builtin 胜**：本地包劫持不了
`openai-compatible`。

## 信任模型：注册 ≠ 能接流量

把包放进目录只是进了目录清单，**不足以接流量**。一个已发现的包只有在下列
三者之一为它背书时，才绑定它的方言：

- 它是 **builtin**（装在签名二进制里）；
- **`plugin install`** 跑过 conformance 套件，并留下一条与它当前
  `adapter.wasm` 哈希匹配的回执（Receipt）；
- 运营者**明确写下**——`plugins.providers` 条目，或对整个目录开
  `plugins.allow_unsigned = true`。

回执存在**数据目录**而非包目录里，所以下载来的包无法自带批准。

## 安装一个第三方插件

```bash
token-station-cli plugin install <path>   # 目录含 manifest.json / adapter.wasm / fixtures/
token-station-cli plugin list             # 看它是否注册、被谁背书
token-station-cli plugin info <name>      # 身份 / 信任 / 方言 / 声明的密钥
token-station-cli plugin remove <name>    # 有上游经它路由时被拒
```

`install` 会先跑该包的 conformance 套件，**通过才**复制进插件目录并记录批准。
不通过的包被存为草稿，永不进入运行时注册表。

## 开发一个自己的 provider adapter

面向第三方作者的开发链（`plugin new / build / test`）：

```bash
token-station-cli plugin new provider-acme [--dialect acme] [--dir <parent>]
cd provider-acme
# 改代码……
token-station-cli plugin build        # cargo build --target wasm32-wasip2，adapter.wasm 就位
token-station-cli plugin test         # 跑与 install 完全相同的那套 conformance
```

- `new` 的脚手架**不是空壳**：它是官方 OpenAI 兼容 adapter 改了身份名——一上来
  就能编译、就能过 conformance。开发就是「让这个能工作的翻译改说别的话」，每
  改一步 `plugin test` 都告诉你真相。
- `build`：`cargo build --target wasm32-wasip2` 后把 `adapter.wasm` 放到
  manifest 旁边，于是项目目录可直接 `plugin install`。
- `test`：跑的是 `plugin install` 用的**同一套** conformance——本地通过即安装
  时通过。

adapter 作者也可以在自己的原生构建上实现 `ProviderAdapter` trait、在自己 CI
里跑同一套 conformance，**无需 WASM 工具链**——这条「缝」的设计见
[贡献者文档](../contributing/架构总览.md)。
