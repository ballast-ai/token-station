# Token Station 桌面端动态模型目录设计

日期：2026-07-16

## 1. 背景与目标

桌面端当前在 `apps/desktop/src/catalog.ts` 中维护供应商与建议模型。静态预设已经出现实际失效：Moonshot Kimi 的首选模型 `kimi-k2-0711-preview` 持续返回 HTTP 404，而同一 Key 下的 `moonshot-v1-8k` 可以正常访问。由于三档路由都指向该失效模型，Claude Code 最终只展示为“模型不存在或无权限”，用户无法直接判断是客户端模型名、API Key、路由还是上游模型 ID 出错。

本次目标：

1. 桌面 App 能从不同厂商动态获取当前账号可访问的模型。
2. 动态获取失败时仍可使用内置建议模型和手动输入，不阻断配置。
3. 已添加供应商可以刷新并管理模型，无需删除后重新添加。
4. 模型目录请求不触发大模型推理，不产生输入/输出 Token。
5. 保持 API Key 只在 Tauri 后端与 macOS Keychain 中流转。
6. 模型较多时仍保持紧凑、清晰、可搜索的界面。

## 2. 方案比较

### 方案 A：只更新静态预设

改动最小，但模型清单会再次过期，不能解决长期维护问题，不采用。

### 方案 B：每次启动自动刷新全部供应商

目录最及时，但启动依赖多个外部接口，容易产生延迟、鉴权错误和限流噪声，不采用。

### 方案 C：动态发现 + 本地缓存 + 静态兜底

添加供应商时可获取一次；已添加供应商可手动刷新；启动时读取缓存，不主动访问外网。失败时继续展示缓存、内置建议和手动模型。该方案兼顾实时性、稳定性与可维护性，采用此方案。

## 3. 交互设计

### 3.1 新增供应商

保留现有供应商选择、Base URL、API Key 和自定义模型能力。模型区域调整为：

- 标题行左侧显示“模型”，右侧显示目录来源与状态：`内置建议`、`正在获取…`、`已同步 18 个`、`使用缓存`或`获取失败`。
- API Key 输入完整并失焦后自动尝试获取一次；同时提供“刷新模型”按钮，便于显式重试。
- 动态结果与内置建议、自定义输入按模型 ID 去重合并。
- 动态获取不会自动全选所有模型；保留已经选中的建议模型，用户明确勾选后才写入供应商配置。
- 模型不超过 12 个时使用现有紧凑 chip；超过 12 个时显示搜索框，并让模型区在固定高度内滚动。
- 已选模型优先排列，避免刷新后选中状态被大量结果淹没。

### 3.2 已添加供应商

供应商卡片增加“管理模型”入口，展开后复用同一模型选择组件：

- 展示已配置模型、缓存模型与最新发现模型。
- 支持刷新、搜索、勾选和手动添加。
- “保存模型”只更新该供应商的 `models`，不修改 Base URL、Key 或其他供应商。
- 若三档路由正在使用某模型，禁止在保存时移除该模型，并明确指出受影响档位。

### 3.3 视觉约束

- 不新增弹窗；在现有卡片内渐进展开，维持页面上下文。
- 状态采用低饱和文字与小圆点，不用大面积警告色。
- 错误提示靠近模型目录区域，包含厂商返回状态和可执行建议。
- 模型列表限定高度，避免供应商返回大量模型时破坏页面节奏。
- 刷新期间按钮只显示局部 loading，不阻塞整个页面。

## 4. 后端设计

### 4.1 Tauri 命令

新增两个命令：

```text
discover_provider_models(name?, base_url, api_key?) -> ModelDiscoveryView
update_provider_models(name, models) -> StateView
```

`discover_provider_models` 支持两种鉴权来源：

- 新增表单传入一次性 `api_key`，仅在该次请求内使用，不记录日志、不写磁盘。
- 已添加供应商不传 Key，由后端按供应商名称从 macOS Keychain 解析。

无鉴权供应商可同时省略 Key。

`update_provider_models` 复用当前配置校验与保存路径，确保空模型列表、重复模型和仍被路由引用的模型无法写入无效状态。

### 4.2 发现策略

第一阶段使用 OpenAI-compatible 通用协议：

```http
GET {base_url}/models
Authorization: Bearer <provider key>
```

解析标准响应：

```json
{
  "data": [
    { "id": "model-id" }
  ]
}
```

供应商可能不实现该接口，或者返回非标准结构。此时返回结构化失败，不猜测模型 ID，也不清空已有模型。后续可在独立映射表中增加供应商专用发现器；本次不为每家厂商引入不可验证的抓取规则。

动态目录可能包含 embedding、audio、image 等非 Chat Completions 模型。第一阶段不通过名称启发式静默删除模型，避免误删新型号；界面明确标注“请选择支持 Chat Completions 的模型”，内置建议仍承担推荐作用。

### 4.3 缓存

缓存文件位于：

```text
<data.dir>/model-catalog-cache.json
```

每个供应商缓存：

- `base_url`
- 已发现模型 ID
- 获取时间
- 结果来源

缓存不包含 API Key、请求头或错误响应正文。Base URL 变化时旧缓存失效。缓存采用临时文件写入后原子替换，损坏时忽略并回退到内置建议。

## 5. 数据流

```text
用户选择供应商并填写 Key
  -> React 调用 Tauri discover_provider_models
  -> Tauri 选择一次性 Key 或 Keychain Key
  -> GET provider /models
  -> 校验状态码与 OpenAI-compatible 响应
  -> 规范化、去重、排序模型 ID
  -> 成功结果写入无密钥缓存
  -> React 合并缓存 / 动态 / 内置 / 手动模型
  -> 用户明确选择并保存
  -> ClientConfig 校验
  -> 更新供应商模型，保留合法路由引用
```

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| 401 / 403 | 显示“Key 无效或无模型目录权限”，保留缓存和内置建议 |
| 404 | 显示“该厂商未提供标准模型目录”，允许手动输入 |
| 429 | 显示“请求过于频繁”，不自动重试 |
| 超时 / 网络错误 | 显示网络错误，保留缓存 |
| 非标准 JSON | 标记协议不兼容，不覆盖缓存 |
| 空模型列表 | 视为有效空结果，但不清除已配置模型 |
| 移除路由使用中的模型 | 阻止保存并指出上档、中档或下档引用 |

所有错误仅保留必要状态，不记录 Key 或完整上游响应正文。

## 7. 内置预设修正

动态能力不能替代安全兜底。本次同时：

- 移除已经真实验证为 404 的 `kimi-k2-0711-preview` 默认首选。
- 根据厂商官方文档更新少量稳定建议模型，避免把快照型号和短期 preview 放在首位。
- 保留每个供应商的 Base URL、是否需要 Key 和自定义模型入口。
- OpenRouter、Ollama 等目录高度动态的供应商以动态发现结果为主，内置清单只作示例。

官方资料基线：

- Moonshot Kimi：<https://platform.moonshot.cn/docs/introduction>
- 阿里云百炼模型清单：<https://help.aliyun.com/en/model-studio/text-generation-model/>
- Groq 模型目录：<https://console.groq.com/docs/models>

## 8. 测试与验收

### 8.1 Rust 单元测试

- 标准 `/models` 响应解析、去重和稳定排序。
- 401、404、429、超时、非 JSON、空列表映射。
- 缓存读写、损坏降级、Base URL 变化失效。
- Key 不进入缓存和错误字符串。
- 更新供应商模型时保护三档路由引用。

### 8.2 React 测试

- 获取状态与缓存/内置/手动结果合并。
- 大量模型时搜索、滚动和已选优先。
- 刷新失败不清空选择。
- 已添加供应商展开管理与保存状态。

### 8.3 构建与真实验收

- `cargo test --workspace --all-targets`
- `cargo fmt --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- 桌面前端构建与 Tauri release 构建
- 使用当前已配置账号验证：
  - Kimi 失效预设不再作为默认首选；
  - `moonshot-v1-8k` 探测成功；
  - `qwen-max` 探测成功；
  - DeepSeek 原有链路不回归；
  - 动态目录不产生推理 Token 记录；
  - 目录失败时缓存、内置建议和手动输入仍可用。

## 9. 范围边界

本次不实现后台定时刷新，不在 App 启动时批量请求所有供应商，不自动判断任意模型的完整能力矩阵，也不把动态目录等同于模型可调用性。模型目录成功只证明“厂商公开或授权返回该模型 ID”；真实 Chat Completions 可用性仍由现有 upstream probe 与端到端调用验证。

## 10. 迁移到稳定性分支的实施约束

动态模型目录当前实现位于独立工作树 `token-station-desktop-integration` 的未提交修改中。迁移到 `feat/claude-code-anthropic-adapter` 时采用逐文件重放，不合并整个分支，也不覆盖当前分支已经通过回归的稳定性修复。

### 10.1 必须迁移

- Tauri 模型目录模块、发现命令和供应商模型更新命令。
- React 模型选择器、供应商模型管理器及对应 API 类型。
- 模型目录与管理区域样式。
- 动态目录所需的最小 Rust 依赖与锁文件更新。
- 已验证失效或过期的静态建议模型修正。

### 10.2 冲突处理

- 保留损坏配置的 `load_error` 只读保护；发现、更新和其他写命令不得绕过 `ensure_editable`。
- 保留配置备份、临时文件加原子替换的写入路径；供应商模型更新失败必须恢复内存草稿。
- 保留 React `busyRef` 防重复操作和初始加载失败“重试”入口；模型目录刷新使用局部 loading，不得解除全局操作保护。
- 网络请求期间不得持有全局 App 状态锁；Key 只能用于请求头，不得进入缓存、错误文本、日志或前端持久状态。
- 模型缓存临时文件必须避免并发写冲突，保存失败不得破坏已有缓存。

### 10.3 明确排除

- `.superpowers/brainstorm` 运行时文件和其他临时产物。
- 集成分支中与动态模型目录无关的提交、文档和包配置差异。
- 网页端迁移、后台定时刷新、启动时批量联网和自动能力推断。
- `crates/router-core`、`crates/protocol`、`crates/release`、Provider 出站实现、WASM 权限及正式 Tauri 标识。

### 10.4 迁移验收

- 对模型解析、状态码、缓存命中/损坏/并发写、凭证不泄漏和路由引用保护执行 Rust 单元测试。
- 执行桌面 Rust 测试、格式检查、Clippy、前端 TypeScript/Vite 构建和 workspace 门禁。
- 使用真实供应商 Key 验证 `/models` 成功、失败降级和不产生推理指标；随后复测 Claude Code、Codex、OpenCode 主链。
- 提交前后对红线路径执行精确 diff，结果必须为空。
