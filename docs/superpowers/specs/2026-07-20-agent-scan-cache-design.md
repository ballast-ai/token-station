# 第一阶段：Agent 扫描缓存与按需复核设计

日期：2026-07-20

状态：第一阶段实施范围已确认并完成，代码提交 `29dc9d9`

> 本阶段仅解决 Agents 页面扫描与切换卡顿，不处理“启动代理”操作的耗时和界面阻塞；后者由独立 Spec 处理。

## 1. 背景

当前桌面端只在 `tab === "agents"` 时挂载 Agents 页面。页面挂载后立即调用 `scan_agents`，离开页面时组件销毁，因此每次重新进入都会再次执行完整本机探测。

完整探测包含：

- 遍历内置 Agent Registry；
- 搜索 PATH 与已知安装位置；
- 对已发现程序逐个执行版本命令；
- 检查候选配置文件的结构指纹；
- 读取兼容目录并生成版本准入结论；
- 读取 Token Station 的接入归属状态。

本机只读实测中，一次完整探测约需 1.35 秒。这个工作不应由普通页面切换反复触发。

## 2. 目标

1. 打开 App 后，每个 App 进程最多自动执行一次完整 Agent 探测。
2. 点击 Agents 页面时立即展示 Registry 和本次会话已有结果，不触发完整探测。
3. 用户点击“重新扫描”时才主动执行新的完整探测。
4. Registry 数量来自内置 Registry，不通过文件系统或进程探测计算。
5. 接入、断开和恢复等写入动作生成计划前必须重新复核真实状态，不能信任展示缓存。
6. 扫描和复核不得阻塞 Tauri 窗口事件线程。
7. 不修改 `crates/router-core/**`，不改变路由算法、评分、选池、排序或核心契约。

## 3. 非目标

- 不把探测结果持久化到磁盘并跨 App 重启复用。
- 不增加常驻文件监听器、进程监听器或定时轮询。
- 不自动安装、升级、修复或启动第三方 Agent。
- 不放宽未知版本、阻断版本和实验版本的准入规则。
- 不在本设计中处理代理启动时的 WASM 编译性能；该问题独立收敛。

## 4. 核心原则

将“展示数据”和“写入授权证据”分开：

- **展示缓存**用于快速渲染，可以暂时过期，并明确展示扫描时间和刷新状态。
- **写入复核**用于生成接入、断开或恢复计划，每次都读取真实路径、版本、配置 revision 和兼容目录状态。

缓存只能提升界面响应速度，不能成为绕过安全检查的授权依据。

## 5. 数据模型

### 5.1 轻量 Registry 视图

增加只读命令 `list_agent_registry`，只返回已经在内存中解析完成的 Registry 元数据：

- `agent_id`
- `display_name`
- `icon_key`
- `admission`
- 本地 Connector 能力摘要

这个命令不搜索 PATH、不读取 Agent 配置、不执行版本命令、不访问远程兼容目录。Registry 新增 Agent 后，桌面列表可自动展示，不需要前端维护固定数量或名称。

### 5.2 会话级扫描状态

前端 App 根组件持有唯一的 `AgentScanState`：

```text
phase: idle | scanning | ready | error
agents: AgentView[]
last_success_at_ms: number | null
error: string | null
generation: number
```

- `agents` 保存本次 App 运行期间最后一次成功结果。
- 扫描失败时保留最后一次成功结果，同时显示错误和“结果可能已过期”。
- `generation` 防止较早发出的请求覆盖较新的手动扫描结果。
- 不写 localStorage、IndexedDB 或磁盘。

## 6. 数据流

### 6.1 App 启动

1. App 读取现有桌面状态。
2. 读取轻量 Registry 元数据并立即建立 Agent 列表。
3. 首屏完成后，在后台发起本进程唯一一次自动完整扫描。
4. 扫描期间页面仍可切换；Agents 页面展示 Registry 行和“后台扫描中”。
5. 扫描完成后，按 `agent_id` 合并安装、版本、兼容和接入状态。

自动扫描失败不循环重试，也不阻止其他页面使用。用户可以点击“重新扫描”。

### 6.2 点击 Agents 页面

Agents 页面改为纯展示组件：

- 从 App 根组件接收 Registry、扫描结果、扫描阶段和刷新回调；
- 页面挂载时不调用 `scan_agents`；
- 离开再进入时直接展示相同的会话缓存；
- Registry 数量直接使用 `registry.length`，不使用硬编码 `5`，也不通过完整探测计算。

### 6.3 手动重新扫描

用户点击“重新扫描”后：

1. 将状态标记为 `scanning`，但继续展示旧结果；
2. 后台执行完整扫描；
3. 成功后原子替换展示缓存并更新时间；
4. 失败时保留旧结果，显示可重试错误；
5. 同一时刻只允许一个展示扫描在途。

### 6.4 接入、断开与恢复

用户点击“预览接入”“预览断开”或“恢复”后，后端必须先执行强制复核：

1. 重新发现所选安装实例；
2. 重新执行版本探测；
3. 重新读取配置结构和 revision；
4. 重新计算兼容结论；
5. 确认路径仍唯一且仍属于选中的 `agent_id`；
6. 复核通过后才生成有期限、绑定 revision 的确认计划。

应用计划前继续保留现有二次复核。任一复核失败都必须 fail closed，并提示用户重新扫描，不能退回展示缓存继续写入。

## 7. 线程与并发

`scan_agents` 和新增了真实复核的计划命令必须在 Tauri 后台阻塞线程池执行，不得作为同步命令占用窗口事件线程。

后端扫描遵循以下约束：

- 不在执行外部版本命令或读取配置时持有会话 Mutex；
- 扫描完成后只在提交新快照时短暂加锁；
- 展示扫描使用单飞控制，避免启动扫描和手动扫描重复运行；
- 写入前复核不与展示缓存共享授权结果；
- 若扫描结果返回顺序变化，按 `agent_id` 和 canonical path 稳定排序。

第一版不并行执行多个 Agent 版本命令。先移除重复扫描和主线程阻塞；只有新鲜性能证据表明仍有必要时，再单独设计有限并发。

## 8. 界面行为

Agents 页面需要明确区分四种状态：

| 状态 | 展示行为 |
|---|---|
| 尚未完成首次扫描 | 展示 Registry 列表和“后台扫描中”，不宣称未安装 |
| 扫描成功 | 展示安装、版本、兼容、接入状态及扫描时间 |
| 手动刷新中 | 保留旧结果并显示“正在重新扫描” |
| 扫描失败 | 保留旧结果并显示“扫描失败，结果可能已过期” |

“未扫描”与“未安装”必须是不同语义。只有成功扫描后没有发现安装实例，才能显示“未安装”。

## 9. 错误与安全边界

- Registry 读取失败属于应用构建或初始化错误，应明确报错，不能伪造固定五项。
- 自动扫描失败不清空最后成功结果。
- 没有成功扫描时，快照查看可按现有能力展示；所有写入计划保持禁用或由后端拒绝。
- 未知版本、无法执行、配置解析失败和多安装冲突仍按现有规则禁止直接接入。
- 日志不得记录 Agent 配置原文、API Key、快照密文或版本命令的未截断输出。
- 兼容目录远程结果仍只能收紧或准入现有 Connector，不能下发代码或命令。

## 10. 测试与验收

### 10.1 前端测试

- App 启动只自动调用一次 `scan_agents`。
- 在主页与 Agents 页面之间往返，不增加扫描调用次数。
- 点击“重新扫描”恰好增加一次扫描调用。
- 刷新期间继续展示旧结果。
- 较旧请求晚返回时不能覆盖较新的结果。
- 扫描失败时保留最后成功结果并显示过期提示。
- Registry 增加第六个 Agent 后，列表和数量不需要修改前端常量。

### 10.2 Rust 测试

- `list_agent_registry` 不调用 ProbeRunner，也不读取 Agent 配置。
- 自动/手动扫描仍覆盖五类现有 Agent 的发现矩阵。
- 计划生成前必须触发新探测；路径、版本或 revision 变化时拒绝生成计划。
- 应用计划前的现有二次复核继续生效。
- 后端只允许一个展示扫描任务在途；重复请求返回 `scan_in_progress`，前端保留当前扫描并忽略该错误。
- `crates/router-core/**` 红线检测继续为零差异。

### 10.3 人工验收

1. 启动 App 后立即连续切换主页和 Agents，窗口应保持可交互。
2. 首次扫描完成后往返 Agents 十次，不应再次执行版本命令。
3. 安装或升级一个测试 Agent 后，点击“重新扫描”应更新版本状态。
4. 扫描后修改测试配置，再点击“预览接入”，写入前复核必须发现变化并拒绝使用旧证据。

## 11. 完成标准

- 页面切换不触发 `scan_agents`。
- 每个 App 进程只有一次自动展示扫描，额外扫描只来自用户手动操作。
- Registry 数量完全来自后端 Registry 元数据。
- 所有完整扫描均不阻塞 Tauri 窗口事件线程。
- 所有写入计划均使用新鲜复核结果，展示缓存不能授权写入。
- 自动化测试、构建、红线脚本通过，且 `crates/router-core/**` 零修改。
