# 桌面 App 主页与 Agent 独立路由界面设计

- 日期：2026-07-21
- 状态：视觉方案已确认，等待规格评审
- 范围：`apps/desktop` 控制面及支持该交互所需的非 `router-core` 边界

## 1. 背景

Token Station 当前桌面端以顶部标签组织主页、Agents、路由表、用量、插件、设置和关于。主页已经具备可用的三档路由与供应商管理，但 Agent 接入和路由配置分散在不同页面，虚拟 API Key 也长期占据主界面空间。

本次设计借鉴 [CC Switch](https://github.com/farion1231/cc-switch) 的 Agent 上下文切换、独立设置页和主题状态组织方式，但不复制其页面结构、样式、组件或实现。Token Station 保留自身的核心心智模型：本地代理、上中下三档路由、全局供应商模型库和安全接入。

## 2. 目标

1. 使用左侧 Agent 侧轨组织主页和五个 Agent：Claude Code、Codex、OpenCode、OpenClaw、Hermes。
2. 主页继续使用当前“档位说明 + 供应商下拉 + 模型下拉”的三档界面，并作为全局默认路由。
3. 每个 Agent 页面复用相同的三档控件，可跟随主页或使用独立路由。
4. Agent 接入不再展示二次确认弹窗；一次明确点击完成安全接入。
5. 保留“恢复主页路由”和“恢复 Agent 原始配置”两种不同的恢复能力。
6. 将虚拟 API Key 移入设置，默认打码并支持复制。
7. 用量作为右上角独立入口，不放入设置。
8. 将路由表、插件、关于收纳到设置。
9. 支持浅色、深色和跟随系统主题。
10. 将“添加供应商”放在右上角，并使用独立页面完成添加。

## 3. 非目标与红线

### 3.1 本次非目标

- 不改变供应商、模型和三档路由的业务含义。
- 不重做模型发现、Keychain、用量聚合、插件发现或版本检查内核。
- 不自动安装、升级或修复第三方 Agent。
- 不照搬 CC Switch 的视觉、代码、组件层次、图标组合或交互细节。

### 3.2 绝对红线

- 不修改 `crates/router-core/**`。
- 不改变路由算法、规则匹配、hint、评分、阈值、选池、候选排序、fallback 或 `Decision` 结构。
- 不把时间、随机数或 IO 引入路由纯函数。
- 不让指标或日志获得承载 prompt/response 内容的字段。
- 不放宽凭据解析、出站目的地校验、WASM 沙箱或虚拟 Key 鉴权。
- 不因减少 UI 确认步骤而跳过 Agent 版本准入、配置指纹复验、加密快照、ownership、原子写入、写后校验或失败回滚。

实现阶段必须运行 `scripts/check-router-core-redline.sh <base> <head>`，并将 `crates/router-core/**` 零改动作为合并门槛。

## 4. 已确认的信息架构

### 4.1 左侧 Agent 侧轨

侧轨固定显示：

1. 主页；
2. Claude Code；
3. Codex；
4. OpenCode；
5. OpenClaw；
6. Hermes；
7. 底部重新扫描入口。

每个 Agent 使用图标、短名称和状态点表达发现/接入状态。当前页面使用背景和左侧色条标识，同时保留文本状态，不能只依赖颜色。

### 4.2 顶部操作区

顶部右侧依次放置：

- 代理运行状态及启动/停止操作；
- 用量入口；
- 设置入口；
- “添加供应商”主按钮。

“添加供应商”在主页和 Agent 页面都可见。进入添加页后保留用量和设置入口，但隐藏重复的添加按钮。

### 4.3 页面集合

```text
主页
Agent 页面 × 5
用量
设置
  ├─ 通用与虚拟 API Key
  ├─ 路由表
  ├─ 插件
  ├─ 外观
  └─ 关于
添加供应商
```

路由表、插件和关于只是移动入口，不改变原有数据来源或行为。用量保持独立页面。

## 5. 主页设计

### 5.1 默认三档路由

主页保留当前三列结构：

| 档位 | 供应商 | 模型 |
|---|---|---|
| 上档 | 供应商下拉 | 该供应商的模型下拉 |
| 中档 | 供应商下拉 | 该供应商的模型下拉 |
| 下档 | 供应商下拉 | 该供应商的模型下拉 |

档位颜色、说明和“保存并应用”语义沿用现状。供应商变化时，模型默认选择该供应商的首个可用模型；模型缺失时保持不完整草稿，不写入有效配置。

主页增加两个不同操作：

- **保存并应用**：保存主页默认路由，不修改正在使用独立路由的 Agent。
- **应用到全部 Agent**：将五个 Agent 的活动模式切换为“跟随主页”。已有独立路由草稿暂存但不生效，避免误删用户配置。

### 5.2 Agent 摘要

三档面板上方显示五个 Agent 的接入状态和路由来源：跟随主页、独立路由或未接入。点击摘要跳转到对应 Agent 页面。

### 5.3 供应商列表

主页只展示和管理现有供应商，不再内联展开添加表单。列表继续支持模型管理和删除。

## 6. Agent 页面设计

五个 Agent 页面使用同一组件骨架，差异来自 Registry 元数据、安装实例、版本兼容结果和 Connector。

### 6.1 页面头

显示：

- Agent 名称、版本和规范化安装路径；
- 未发现、可接入、已接入、未知版本或阻断版本状态；
- 接入/恢复原始配置操作。

### 6.2 一键接入

“接入”按钮的一次明确点击就是用户授权，不再打开差异确认弹窗。前端仍按顺序调用现有 plan/apply 两阶段边界：

```text
用户点击接入
  → 刷新扫描并复验版本/安装路径
  → 生成短时计划和确认令牌
  → 立即应用该计划
  → 加密快照
  → 原子写入
  → 写后校验
  → ownership 提交
```

未知版本、阻断版本、多实例未选择、Adapter 未就绪、配置损坏或代理未运行时，按钮必须禁用并展示原因。UI 简化不能转化为安全校验简化。

“恢复 Agent 默认配置”只恢复 Token Station ownership 范围内的原始配置，保留用户无关字段。失败时使用现有快照和事务回滚语义。

### 6.3 路由模式

每个 Agent 有两种模式：

- **跟随主页**：只读展示当前主页三档；主页保存后自动生效。
- **独立路由**：使用与主页完全相同的三档供应商/模型下拉，可独立保存。

“恢复主页路由”只把该 Agent 切回跟随模式，不断开 Agent，也不恢复 Agent 原始配置。这一操作和“恢复 Agent 默认配置”必须使用不同位置、文案和视觉危险等级。

## 7. 每 Agent 路由的数据边界

### 7.1 配置模型

桌面控制面维护：

```text
home_route: 三档默认配置
agent_routes:
  <agent_id>:
    mode: inherit | custom
    custom_route: 可选三档配置
```

供应商、凭据和模型目录仍是全局单一来源。Agent 路由只引用 `(upstream, model)`，不复制 Base URL 或 API Key。

### 7.2 入站身份

当前多个 Agent 可能共享 OpenAI 入站协议，仅靠协议无法可靠区分 OpenCode、OpenClaw 和 Hermes。实现独立路由时，Connector 必须为每个 Agent 写入稳定的本地命名空间，例如：

```text
http://127.0.0.1:8787/agents/codex/v1
http://127.0.0.1:8787/agents/opencode/v1
http://127.0.0.1:8787/agents/openclaw/v1
```

服务器在进入路由前解析并校验 `<agent_id>`：

- 已知命名空间：选择对应的不可变路由配置；
- 无命名空间的现有请求：使用主页默认路由，保持向后兼容；
- 未知命名空间：拒绝请求，不猜测 Agent。

Adapter 仍按路径后缀认领协议。选定配置后继续调用现有 `router-core` 纯函数，不在核心内增加 Agent 分支。该边界允许在 `apps/cli` 网关/服务层和桌面配置层实现多配置编排，同时保持 `crates/router-core/**` 不变。

实现计划开始前必须先做 Connector 能力验证，确认五个客户端都能接受带命名空间的本地 Base URL；任一客户端不支持时，不得用不可靠的 header 或进程猜测绕过。

## 8. 添加供应商页面

点击右上角“添加供应商”进入独立页面。页面复用当前能力：

1. 选择供应商预设；
2. 自动带出名称和 Base URL；
3. 输入 API Key；
4. 获取、搜索、勾选或手动添加模型；
5. 保存到全局供应商模型库。

API Key 默认打码，保存至系统钥匙串。创建成功后返回来源页面，新供应商立即出现在主页和五个 Agent 的供应商下拉中。失败时保留非敏感表单数据；API Key 不写入日志、URL、配置文件或浏览器持久化存储。

## 9. 设置、用量和主题

### 9.1 虚拟 API Key

虚拟 Key 移入设置的“通用”区域：

- 默认显示固定掩码；
- 提供复制按钮；
- 不要求先明文显示才能复制；
- 可选短时显示，离开页面或超时后重新打码；
- 不写入剪贴板以外的新持久化位置。

### 9.2 用量

用量保持右上角独立入口，继续读取本地只读指标数据面。主页可显示少量摘要，但完整筛选、聚合和明细只在用量页出现。

### 9.3 主题

设置提供浅色、深色和跟随系统三种模式。主题通过全局语义色变量控制页面、面板、输入、边框、状态和对话框；禁止再次出现单页独立主题。主题选择可本地持久化，并同步 Tauri 原生窗口主题。

## 10. 组件边界

建议拆分为：

- `AppShell`：窗口、侧轨、顶栏和页面容器；
- `AgentRail`：主页、五个 Agent 和扫描状态；
- `TopActions`：代理、用量、设置和添加供应商；
- `TierRouteEditor`：主页与 Agent 共用的三档编辑器；
- `AgentRoutePage`：Agent 状态、接入和路由模式；
- `ProviderList`：现有供应商管理；
- `AddProviderPage`：独立添加流程；
- `SettingsPage`：设置子导航及现有页面收纳；
- `ThemeProvider`：全局主题状态。

`TierRouteEditor` 只接收路由草稿、供应商模型目录和回调，不感知 Agent 接入、Tauri 或持久化细节。主页和 Agent 页面因此不会复制三档逻辑。

## 11. 错误与状态处理

- 初始状态加载失败：显示可重试错误页，不渲染可编辑空配置。
- 路由草稿不完整：允许继续编辑，但禁用有效保存并明确缺失档位。
- 供应商删除后被路由引用：沿用后端校验并阻止产生悬空引用。
- Agent 接入失败：不乐观标记已接入，展示失败阶段并保留可重试入口。
- Agent 写入中断：使用现有事务回滚；界面重新扫描真实状态。
- 独立路由命名空间缺失或未知：已命名但未知时拒绝；无命名空间时使用主页默认。
- 主题切换：所有页面同步变化；系统主题变化只在“跟随系统”模式响应。
- 添加供应商失败：保留名称、URL 和模型选择；敏感 Key 只保留在当前内存输入生命周期。

## 12. 测试与验收

### 12.1 前端

- 侧轨在主页和五个 Agent 之间正确切换。
- 主页与 Agent 页面复用同一个 `TierRouteEditor`。
- “保存主页”不覆盖独立路由；“应用到全部 Agent”切换全部为跟随模式。
- Agent 独立路由只修改目标 Agent。
- 两类恢复操作文案、调用和结果互不混淆。
- 用量独立，路由表/插件/关于进入设置。
- 添加供应商从右上角进入独立页面，成功后返回来源页。
- 虚拟 Key 默认打码且可复制。
- 浅色、深色、系统主题覆盖全部页面。

### 12.2 Tauri 与 Agent 接入

- 一键接入仍经过 plan token、扫描绑定、版本准入和运行时绑定复验。
- 未知/阻断版本、配置损坏、多实例未选择时零写入。
- 接入、断开和恢复均保留加密快照、ownership 和原子事务。
- 计划过期、令牌错配或配置指纹变化时拒绝应用。

### 12.3 网关与红线

- 五个已验证 Connector 的命名空间 Base URL 真实可用。
- 已知 Agent 命名空间选择正确路由配置。
- 无命名空间请求继续使用主页默认配置。
- 未知命名空间被拒绝。
- 同一 Router 实现对不同不可变配置给出确定性结果。
- 指标记录不新增 prompt/response 字段。
- `scripts/check-router-core-redline.sh` 通过，`crates/router-core/**` 零改动。

## 13. 实施顺序约束

1. 先验证五个 Connector 的命名空间 Base URL，不改 UI。
2. 再设计非 `router-core` 的多路由配置物化和网关选择边界。
3. 为上述边界补齐测试并通过红线检查。
4. 实现共享 `TierRouteEditor` 和页面状态模型。
5. 重构 App Shell、侧轨、顶栏和页面入口。
6. 接入一键连接、独立添加供应商、设置收纳和主题。
7. 完成真实 Tauri E2E、构建和视觉验收。

若第 1 步无法为某个 Agent 建立可靠身份，必须暂停该 Agent 的独立运行时路由能力并回到设计评审，不得修改 `router-core` 或使用不可靠启发式补洞。
