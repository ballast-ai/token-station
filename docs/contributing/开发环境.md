# 开发环境

从零到「能编译、能跑测试、能起服务」。

## 工具链

- **Rust stable**，`edition = "2024"`，MSRV **1.95**。仓库有
  [rust-toolchain.toml](../../rust-toolchain.toml)（channel `stable`，附
  `rustfmt` + `clippy`），进目录 rustup 自动切。
- **WASM target `wasm32-wasip2`** — 编 CLI 本身**不需要**；但**跑测试需要**，
  因为 `plugin-runtime` 的测试会把 `tests/guests/*` 编成真实 WASM 组件。

  ```bash
  rustup target add wasm32-wasip2
  ```

> 发布用的是**钉死版本**的工具链（`scripts/build-release.sh` 里
> `RELEASE_TOOLCHAIN`，当前 `1.96.0`），那是可复现构建的口径；开发口径跟随
> stable 即可，两者刻意分开。

## 系统依赖

- **Linux 桌面端**：Tauri / WebKit 和当前 CI 基线需要：

  ```bash
  sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev \
    librsvg2-dev patchelf libdbus-1-dev pkg-config
  ```

- **凭证存储**：三个平台统一使用本地 `secrets.json`，不依赖 OS 钥匙串或
  Linux Secret Service。文件使用仅当前用户可访问的权限或平台 ACL。

### Windows 11 x64

Windows 开发和 MSI 构建的固定基线：

- Windows 11 x64；
- Visual Studio 2022 Build Tools，安装“使用 C++ 的桌面开发”和 Windows 11 SDK；
- Microsoft Edge WebView2 Runtime；
- Rust stable（不得低于 1.95）及
  `wasm32-wasip2`、`x86_64-pc-windows-msvc` targets；
- Node.js 22.23.1，与 CI 一致；
- Git for Windows。正式 MSI 脚本从 Git Bash 运行；日常 App 开发可直接用
  PowerShell 5.1 或 7。

PowerShell 初始化：

```powershell
rustup target add wasm32-wasip2 x86_64-pc-windows-msvc
npm --prefix apps/desktop ci
node scripts/check-windows-release-config.mjs
```

开发态桌面 App 必须使用官方入口，不能直接运行 `npx tauri dev`：

```powershell
npm --prefix apps/desktop run tauri:dev
```

该入口先按锁文件构建五个官方 adapter，再使用 `bundled-plugins` 启动 Tauri；
不要求在 `%APPDATA%` 或 `%LOCALAPPDATA%` 手工复制插件。第一次启动需要编译 WASM，
后续由 Wasmtime 内容寻址缓存复用；插件或 Wasmtime 版本变化时会自动重编。

本地 x64 MSI 从 Git Bash 构建：

```bash
scripts/build-desktop.sh --local --target x86_64-pc-windows-msvc
```

正式渠道只接受 per-user x64 MSI。安装目录固定为
`%LOCALAPPDATA%\Programs\token-station`，不构建 NSIS、Portable.zip 或独立
Windows CLI。生产构建还必须提供 Authenticode 证书 thumbprint 和 RFC 3161
时间戳 URL；local 包不冒充已签名正式包。

## 构建

```bash
git clone https://github.com/GlimpseEngine/token-station
cd token-station

# 只编 CLI（最常用）
cargo build -p token-station-cli
# 或 release
cargo build --release -p token-station-cli
```

普通 `cargo build` **没有 builtin 插件层**——`--features builtin-plugins` 只
在发布流水线里用于把官方插件编进二进制（`apps/cli/build.rs`），不是产品分档
开关。日常开发用外部插件目录即可（见下）。

## 起一个本地实例

```bash
# 1. 从示例配置起步
cp apps/cli/example-config.json token-station.json

# 2. 加一个上游（这里用本地 Ollama，无需 key）
./target/debug/token-station-cli upstream add ollama_local \
  --provider openai-compatible --base-url http://127.0.0.1:11434/v1 \
  --model "llama3.3,tool,ctx=128000" --pool cheap

# 3. 起服务（首次打印一次虚拟 key，保存它）
./target/debug/token-station-cli serve
```

另开终端验证：

```bash
export TS_KEY='启动时打印的 ts-...'
curl http://127.0.0.1:8787/v1/models -H "Authorization: Bearer $TS_KEY"
```

> 示例配置的 `plugins.dir` 指向 `plugins-dist`。开发态若没有内置插件层，需要
> 一个装了官方 adapter 的插件目录：用 `scripts/build-release.sh` 产出的
> `dist/` 里带 `plugins-dist/`，或用 `plugin build` + `plugin install` 自己
> 装。一个完整的端到端上手例子见
> [../guides/GLM-5.2-本地启动指南.md](../guides/GLM-5.2-本地启动指南.md)。

## 桌面 App 开发

```bash
npm --prefix apps/desktop ci
npm --prefix apps/desktop run tauri:dev
```

这个入口同时适用于 macOS 和 Windows，并保证开发 App 实际内嵌五个官方插件。
仅调前端可使用 `npm --prefix apps/desktop run dev`。正式产物用
`scripts/build-desktop.sh`，脚本会执行最终可执行文件的只读插件自检；只在
二进制中搜索插件字符串不能作为通过证据。

## 本地门禁（提交前跑一遍）

CI 会跑同样的检查，本地先过省来回：

```bash
scripts/check-rust-format.sh
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

lint 口径写在 workspace 里：`unsafe_code = "forbid"`，clippy `all` + `pedantic`
都是 `warn`（CI 用 `-D warnings` 提级为错）。详见 [测试指南.md](测试指南.md)
与 [贡献流程.md](贡献流程.md)。

格式门禁会检查所有可修改 workspace crate、官方插件和桌面后端；
`crates/router-core/**` 按当前冻结 tree 做零差异校验，不用新版 rustfmt 对冻结
代码产生机械改动。

## 常用路径速查

| 你想改… | 去… |
|---|---|
| 路由逻辑 / 打分 / 规则匹配 | `crates/router-core/src/` |
| 请求数据面 / 流式 / 凭证注入 | `apps/cli/src/gateway.rs` |
| 配置结构 / 校验 | `apps/cli/src/config.rs` |
| CLI 命令与参数 | `apps/cli/src/main.rs` + 对应模块 |
| 规范协议类型 / 外泄闸门 | `crates/protocol/src/` |
| WASM 沙箱 / 加载门 | `crates/plugin-runtime/src/loader.rs` |
| 一致性套件 | `crates/conformance/src/` |
| 指标记录词汇 / schema | `crates/metrics/src/lib.rs` |

各 crate 职责与数据流全貌见 [架构总览.md](架构总览.md)。
