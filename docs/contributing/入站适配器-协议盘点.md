# 入站适配器协议盘点（M4 更新）

- 初版日期：2026-07-15
- M4 复核日期：2026-07-16
- 对应需求：FR-3、FR-4、M0
- 当前范围：Claude Code 已完成；M4 实现 Codex、OpenCode、OpenClaw

## 1. 核心结论

首批四个 Agent 不应“一工具一适配器”，而应按实际入站线协议复用适配器：

| Agent | 当前可用入站协议 | 主要推理入口 | 指向 token-station 的方式 | 适配器决策 | 本轮状态 |
|---|---|---|---|---|---|
| Claude Code | Anthropic Messages | `POST /v1/messages` | `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` | 新增 `agent-anthropic` | M1–M3 实现 |
| Codex | OpenAI Responses（当前仅保留 Responses wire API） | `POST /v1/responses` | 隔离 `CODEX_HOME/config.toml` 中的 `model_provider` / `base_url` / `wire_api` | 新增 `agent-openai-responses` | M4 实现/验证 |
| opencode | 可选 OpenAI Chat Completions、OpenAI Responses、Anthropic 等 | 由 provider SDK 决定 | `provider.<id>.options.baseURL` + 对应 SDK | Chat Completions 复用 `agent-openai`；Responses 复用未来 `agent-openai-responses`；Anthropic 复用 `agent-anthropic` | M4 配方/验证 |
| OpenClaw | 可配 `openai-completions`、`anthropic-messages` 等；官方 OpenAI 路线还使用 Responses | 由 `models.providers.<id>.api` 及 provider runtime 决定 | `models.providers.<id>.baseUrl` / `api` / `apiKey` | 按选定协议复用已有适配器；不新建 OpenClaw 专属协议 | M4 配方/验证 |

需求文档中的 `openclow` 按用户已确认的官方项目名 **OpenClaw** 处理。
本轮范围只包含 Codex、OpenCode、OpenClaw；开放性的其他 Agent 调研不并入
本轮实现或验收。

## 2. 逐项说明

### 2.1 Claude Code

- Claude Code 的 LLM Gateway 入口是 Anthropic Messages API；改写
  `ANTHROPIC_BASE_URL` 即可把请求指向本地代理。
- 必需接口是 `/v1/messages`，流式为 SSE。`/v1/messages/count_tokens`
  和 `/v1/models` 是可选能力，不应被 `match_inbound` 误判为推理请求。
- 官方网关协议会携带 `anthropic-version` 和 `anthropic-beta`；入站层
  需容忍并识别这些头，但是否转换为上游参数仍由被选中的 provider
  adapter 决定。`/v1/messages?beta=true` 表明匹配必须基于
  path，不能把整个 URI 当成固定字符串。
- 本机验证版本为 Claude Code `2.1.170`。

结论：新增 `agent-anthropic`，实现 Anthropic Messages 与 Canonical IR 的双向翻译。

### 2.2 Codex

- Codex 支持自定义 model provider，关键配置是 `base_url`、`env_key` 和
  `wire_api`。M4 使用独立 `CODEX_HOME`，不修改用户真实配置。
- 官方自定义 provider 与 Azure 示例均明确使用
  `wire_api = "responses"`；Responses 与 Chat Completions 形状不同。
- 当前 `agent-openai` 只声明 `openai-chat-completions`，不能将其直接
  当作 Responses 适配器。
- 本机验证版本为 `codex-cli 0.144.2`。

结论：M4 新增 `agent-openai-responses`，支持文本、图片输入、function
call/output、usage、错误和 Codex 所需 SSE；reasoning 内容、computer call 和
hosted tool 明确拒绝并走 IR 变更请求。Responses `text.format` 的
`json_schema` / `json_object` 结构化输出同样明确拒绝，不声称支持。

### 2.3 opencode

- opencode 可为任意 provider 配置 `options.baseURL`。
- 官方自定义 provider 文档明确区分：
  - `@ai-sdk/openai-compatible` 调用 `/v1/chat/completions`；
  - `@ai-sdk/openai` 用于 `/v1/responses`；
  - Anthropic provider 也可单独覆盖 `baseURL`。
- 因此 opencode 是“可选协议客户端”，不是一种新的入站线协议。

结论：M4 先用 Chat Completions 复用 `agent-openai` 产出最小接入配方；
Responses 路线可复用 `agent-openai-responses`，但本轮验收固定使用 Chat
Completions，以证明现有 `agent-openai` 可直接覆盖 OpenCode。该路径只覆盖普通文本
输出，`response_format` 结构化输出明确拒绝。

### 2.4 OpenClaw

- OpenClaw 的自定义 provider 由 `models.providers` 配置，协议由
  `api` 选择。官方示例已给出 `openai-completions` 和
  `anthropic-messages`。
- OpenClaw 官方 OpenAI provider/runtime 还使用 Responses 路径；选用该
  路径时与 Codex 一样需 Responses 适配能力。
- 该工具已有多 provider 模型，因此 token-station 不应根据
  `openclaw` 这个 Agent 名称新建专属 adapter。

结论：M4 固定选择 `openai-completions` 复用 `agent-openai`，不新建
OpenClaw 专属 adapter；其他协议路线不纳入本轮验收。与 OpenCode 相同，当前不承载
`response_format` 结构化输出。

## 3. 适配器数量决策

基于当前盘点，首批 Agent 需要的协议 adapter 集合是：

1. `agent-openai`：现有，OpenAI Chat Completions。
2. `agent-anthropic`：本轮新增，Anthropic Messages。
3. `agent-openai-responses`：M4 新增，覆盖经评审确认的 Responses 子集。

不为 Claude Code、opencode 或 OpenClaw 加入厂商专属路由分支。
模型厂商只由 token-station 的 provider/upstream 配置决定。

## 4. 证据与可变边界

| 对象 | 官方证据 | 本次使用点 |
|---|---|---|
| Claude Code | [LLM Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol) | Base URL、`/v1/messages`、SSE、headers、可选 endpoints |
| Codex | [Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced) | 自定义 provider、`base_url`、`wire_api="responses"`、项目级限制 |
| opencode | [Providers](https://opencode.ai/docs/providers/) | `baseURL`、Chat Completions / Responses SDK 分流 |
| OpenClaw | [Model providers](https://docs.openclaw.ai/concepts/model-providers) | `models.providers`、`api`、OpenAI/Anthropic 协议示例 |

这些外部工具可持续变化。M4 开始前应重新核对当时版本的官方文档
与实际请求，不将本盘点当作永久不变的协议契约。
