# 测试指南

## 前置：装 WASM target

多数集成测试会**在测试内**用子进程 `cargo build --target wasm32-wasip2` 编出
真实的 WASM 组件。缺 target 时这些测试会明确提示你补：

```bash
rustup target add wasm32-wasip2
```

Linux 还需 `libdbus-1-dev`（keyring 后端），见 [开发环境.md](开发环境.md#系统依赖)。

## 跑测试

```bash
cargo test --workspace            # 全量
cargo test -p token-station-cli   # 只跑 CLI 的
cargo test -p token-station-router-core
```

首次跑较慢：wasmtime + tokio + sqlite 全量重编约 7 分钟，且测试要现编 WASM
guest。之后增量很快。

## 测试是分层的、且不 mock 关键路径

这个项目的集成测试刻意**跑真东西**——真实 WASM 组件、真实路由、真实钥匙串
交互——而不是打桩。按 crate 看：

### plugin-runtime：加载门与沙箱

- [`tests/wasm_provider.rs`](../../crates/plugin-runtime/tests/wasm_provider.rs)
  —— 用一个诚实的小 provider guest（`tests/guests/test-provider`，编成真实
  `wasm32-wasip2` 组件）验证三道加载门与沙箱边界。
- [`tests/official_plugins.rs`](../../crates/plugin-runtime/tests/official_plugins.rs)
  —— 把**官方**两个插件当真实组件走完每道门。

guest 由测试用子进程 cargo 构建（`tests/guests/*` 是 workspace 排除成员，各带
自己的 `target/`，被 `.gitignore` 忽略）。

### apps/cli：端到端数据面

- [`tests/proxy.rs`](../../apps/cli/tests/proxy.rs)（最大，~940 行）—— C1#1 验收
  标准：OpenAI 方言客户端 → 回环代理 → 经**官方 WASM 插件**路由 → mock 上游，
  断言到底什么（连凭证一起）到达了上游。**不 mock 管线**：agent 插件、路由器、
  provider 插件都是真的，只有最远端的上游是 mock。
- [`tests/plugin_install.rs`](../../apps/cli/tests/plugin_install.rs) ——
  `plugin install` 端到端：conformance 跑在真实组件上，回执落数据目录，注册表
  随后服务该方言——**装的字节一变就立刻停止服务**。
- [`tests/plugin_devchain.rs`](../../apps/cli/tests/plugin_devchain.rs) ——
  第三方开发链全程：`plugin new → build → test → install`，注册表随后服务新
  方言。脚手架一旦不再过自己的套件，就在这里挂。
- [`tests/upgrade.rs`](../../apps/cli/tests/upgrade.rs) —— 升级信任链：一个
  脚本化的「GitHub」用测试 key 签发布，客户端**只在每一环都成立时**接受，任一
  环被切断即拒。

### conformance：一致性套件本身

`conformance` crate 刻意**不知道 WASM**——套件写在 `AgentAdapter` /
`ProviderAdapter` trait 上。这条「缝」意味着插件作者可以在**原生构建**上实现
trait、在自己 CI 里跑同一套套件，无需 WASM 工具链。运行时把这些 trait 实现在
WASM 组件之上，于是同一套件既管住原生也管住 WASM。

## CI 门禁

CI（[.github/workflows/ci.yml](../../.github/workflows/ci.yml)）三个 job：

**`rust`** — 装 `libdbus-1-dev`、`wasm32-wasip2`，然后：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

`cargo doc -D warnings` 也是硬门禁——本地一直在跑它，CI 缺了它就只是个约定。

**`deny`** — [cargo-deny](../../deny.toml)：license 允许清单、RustSec 通告、
依赖来源。

**`audit`** — cargo-audit，只读 `Cargo.lock`。与 deny 的 advisories 有重叠但
分开跑：deny 的依赖图构建坏掉时 audit 仍在把关，两者失败信号也各自更可读。

## 提交前自查

跑一遍本地门禁四连（见 [开发环境.md](开发环境.md#本地门禁提交前跑一遍)），
外加与你改动相关的 `cargo deny check`（若动了依赖）。绿了再发 PR，省 CI 来回。
