# 测试指南

## 前置：装 WASM target

多数集成测试会**在测试内**用子进程 `cargo build --target wasm32-wasip2` 编出
真实的 WASM 组件。缺 target 时这些测试会明确提示你补：

```bash
rustup target add wasm32-wasip2
```

Linux 还需 `libdbus-1-dev`（keyring 后端），见 [开发环境.md](开发环境.md#系统依赖)。

## 跑测试

```bash
cargo test --workspace            # 全量
cargo test -p token-station-cli   # 只跑 CLI 的
cargo test -p token-station-router-core
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
npm --prefix apps/desktop run test -- --run
npm --prefix apps/desktop run build
```

首次跑较慢：wasmtime + tokio + sqlite 全量重编约 7 分钟，且测试要现编 WASM
guest。之后增量很快。

## 测试是分层的、且不 mock 关键路径

这个项目的集成测试刻意**跑真东西**——真实 WASM 组件、真实路由、真实钥匙串
交互——而不是打桩。按 crate 看：

### plugin-runtime：加载门与沙箱

- [`tests/wasm_provider.rs`](../../crates/plugin-runtime/tests/wasm_provider.rs)
  —— 用一个诚实的小 provider guest（`tests/guests/test-provider`，编成真实
  `wasm32-wasip2` 组件）验证三道加载门与沙箱边界。
- [`tests/official_plugins.rs`](../../crates/plugin-runtime/tests/official_plugins.rs)
  —— 把**官方**两个插件当真实组件走完每道门。

guest 由测试用子进程 cargo 构建（`tests/guests/*` 是 workspace 排除成员，各带
自己的 `target/`，被 `.gitignore` 忽略）。

### apps/cli：端到端数据面

- [`tests/proxy.rs`](../../apps/cli/tests/proxy.rs)（最大，~940 行）—— C1#1 验收
  标准：OpenAI 方言客户端 → 回环代理 → 经**官方 WASM 插件**路由 → mock 上游，
  断言到底什么（连凭证一起）到达了上游。**不 mock 管线**：agent 插件、路由器、
  provider 插件都是真的，只有最远端的上游是 mock。
- [`tests/plugin_install.rs`](../../apps/cli/tests/plugin_install.rs) ——
  `plugin install` 端到端：conformance 跑在真实组件上，回执落数据目录，注册表
  随后服务该方言——**装的字节一变就立刻停止服务**。
- [`tests/plugin_devchain.rs`](../../apps/cli/tests/plugin_devchain.rs) ——
  第三方开发链全程：`plugin new → build → test → install`，注册表随后服务新
  方言。脚手架一旦不再过自己的套件，就在这里挂。
- [`tests/upgrade.rs`](../../apps/cli/tests/upgrade.rs) —— 升级信任链：一个
  脚本化的「GitHub」用测试 key 签发布，客户端**只在每一环都成立时**接受，任一
  环被切断即拒。

### conformance：一致性套件本身

`conformance` crate 刻意**不知道 WASM**——套件写在 `AgentAdapter` /
`ProviderAdapter` trait 上。这条「缝」意味着插件作者可以在**原生构建**上实现
trait、在自己 CI 里跑同一套套件，无需 WASM 工具链。运行时把这些 trait 实现在
WASM 组件之上，于是同一套件既管住原生也管住 WASM。

## 覆盖率

主 workspace 明确不包含桌面 Tauri crate，必须分别统计；含 WASM guest 子构建的
workspace 需要 `--coverage-host-only`，避免把 host 覆盖率插桩参数传给
`wasm32-wasip2`：

```bash
cargo llvm-cov --workspace --coverage-host-only --summary-only
cargo llvm-cov --workspace --coverage-host-only --summary-only --fail-under-lines 80
cargo llvm-cov --manifest-path apps/desktop/src-tauri/Cargo.toml \
  --lcov --output-path target/desktop-agent.lcov --fail-under-lines 90
node scripts/check-coverage-thresholds.mjs \
  target/desktop-agent.lcov apps/desktop/src-tauri/src/agent_integration 90
npm --prefix apps/desktop run test:coverage
```

最终门槛已经启用：主 workspace 行覆盖率不低于 80%，desktop Rust crate 与
`agent_integration/**` 分别不低于 90%，frontend 行覆盖率不低于 80%。不得把主
workspace 的报告当作桌面 Rust 覆盖率，也不得仅用 desktop 聚合数字替代
`agent_integration/**` 的 LCOV 路径校验。

覆盖率测试只使用临时目录、mock endpoint 和内存密钥。普通 CI 不访问开发者真实
Agent 配置或钥匙串，不安装、升级或启动 Claude Code、Codex、OpenCode、OpenClaw、
Hermes。真实 Agent E2E 只能在受控验收环境显式执行，并把版本、隔离目录和结果写入
`docs/verification/`。

## CI 门禁

CI 分为主 workspace、desktop Rust、frontend、依赖审计和独立核心红线门禁。
核心红线由
[`router-core-redline.yml`](../../.github/workflows/router-core-redline.yml)
从受信任的目标分支执行，候选 PR 只提供 Git 对象，绝不执行候选脚本。

**`rust`** — 装 `libdbus-1-dev`、`wasm32-wasip2`，然后：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

`cargo doc -D warnings` 也是硬门禁——本地一直在跑它，CI 缺了它就只是个约定。

**`deny`** — [cargo-deny](../../deny.toml)：license 允许清单、RustSec 通告、
依赖来源。

**`audit`** — cargo-audit，只读 `Cargo.lock`。与 deny 的 advisories 有重叠但
分开跑：deny 的依赖图构建坏掉时 audit 仍在把关，两者失败信号也各自更可读。

桌面 lockfile 另跑 `cargo audit -D unsound`。无法通过官方支持版本升级消除的
通告只能登记在
[`rustsec-exceptions.json`](../security/rustsec-exceptions.json)，必须包含负责人、
证据、上游跟踪和到期日；CI 先校验登记，再按精确 advisory ID 放行。过期或锁定
版本变化都会失败，禁止使用无期限的全局 ignore。

**`agent-platform-targeted`** — 在 macOS 与 Windows runner 上只跑平台路径 fixtures、
Windows `PATH`/shim 解析以及 OS keychain 密钥字节解码边界。测试不调用第三方安装器，
也不创建、删除真实 keychain 条目；Linux/WSL 路径语义由常规 desktop 全量测试覆盖。

## 提交前自查

跑一遍本地门禁四连（见 [开发环境.md](开发环境.md#本地门禁提交前跑一遍)），
外加与你改动相关的 `cargo deny check`（若动了依赖）。绿了再发 PR，省 CI 来回。
