# 架构总览

面向要**维护、开发、测试** token-station 的人。读完你应能回答：代码分成哪些
crate、一次请求怎么在系统里流动、安全边界由谁保证、改动该落在哪里。

> **设计文档在别处。** 详细设计 / 规划 / research 在私有文档仓
> `token-station-doc`。本仓 `docs/` 只保留面向用户的 `product/`、`release/`、
> `guides/` 与本贡献者目录。本文引用的 file:line 是当前源码的锚点，改代码时
> 请以源码为准。

## 仓库布局

这是一个 Cargo workspace（`edition = "2024"`，MSRV `1.85`）。

```
apps/cli/                社区版 client：回环、OpenAI 兼容的代理二进制
crates/
  protocol/              系统共享的规范协议类型（Canonical IR）
  router-core/           四层路由内核（纯函数，client 与 gateway 共用）
  metrics/               "一次请求留下什么"的记录词汇 + SQLite schema 版本
  plugin-api/            稳定的 adapter ABI：WIT worlds + manifest schema
  plugin-runtime/        WASM 宿主运行时：加载 adapter 并约束在沙箱内
  conformance/           一致性测试运行器：.wasm 进请求路径前的关卡
  release/               发布信任链：Ed25519 签名的版本化 manifest
plugins/official/        官方 adapter（workspace 之外，各自 target）
  agent-openai/          agent adapter：OpenAI Chat Completions
  provider-openai-compatible/  provider adapter：openai-compatible 方言
scripts/                 build-release.sh / verify-release.sh
```

`plugins/official/*` 与 `crates/plugin-runtime/tests/guests/*` 是 workspace
**排除**成员：它们的目标是 `wasm32-wasip2`，不能进主构建图，由 plugin-runtime
的测试用子进程 cargo 各自构建（见 [Cargo.toml](../../Cargo.toml)）。

## 各 crate 职责

| Crate | 职责 | 关键锚点 |
|---|---|---|
| **protocol** | 定义整个系统共享的规范协议类型（`ChatRequest/ChatResponse`、`HttpRequestDescriptor`、`ProviderConfig` 等）。宿主只认识这些类型，入站 / 出站协议由 adapter 翻译进出。用类型系统强制边界：凭证不进 IR、URL 不能夹带 key、`authorize` 拦越界请求。 | [protocol/src/lib.rs](../../crates/protocol/src/lib.rs) |
| **router-core** | 路由内核，本地 client 与服务端 gateway 共用同一份，防止两条产品线对同一请求给出不同路由。`Router::route` 是纯函数（无时钟 / 随机 / IO），`Decision` 不能携带请求内容。 | [router-core/src/lib.rs](../../crates/router-core/src/lib.rs) |
| **metrics** | 定义"一次代理请求留下什么"的记录词汇 `RequestRecord`（client 与 gateway 存储同构），含 `SCHEMA_VERSION` 版本门。字段几乎全是数字 / 闭合枚举 / 来自配置的字符串，内容进不了记录。 | [metrics/src/lib.rs](../../crates/metrics/src/lib.rs) |
| **plugin-api** | 稳定的 adapter ABI：WIT worlds 与 `manifest.json` schema。adapter 跨边界传的是 JSON 文档而非 WIT record；刻意**不**依赖 protocol，只知文档的名字不知其内容。 | [plugin-api/src/lib.rs](../../crates/plugin-api/src/lib.rs) |
| **plugin-runtime** | WASM 宿主运行时：加载 adapter 并把它约束在沙箱内。`ProviderPlugin::load` 按序跑三道门（manifest 门 → import 扫描 → identity 门），对每个 store 施加内存上限与调用超时。 | [plugin-runtime/src/lib.rs](../../crates/plugin-runtime/src/lib.rs) |
| **conformance** | 一致性测试运行器：第三方 `.wasm` 进请求路径前的全部关卡。三道门（`accepts_manifest` → `reported_identity_matches` → `run_*_suite`）。刻意**不**知道 WASM——测试写在 `AgentAdapter` / `ProviderAdapter` trait 上。 | [conformance/src/lib.rs](../../crates/conformance/src/lib.rs) |
| **release** | 发布信任链：Ed25519 签名的、含制品哈希的版本化 manifest。签名侧是 `ts-release` 二进制（私钥不在仓库），验证侧是 `upgrade`（公钥编译进去）。签名覆盖 manifest **原始字节**，无规范化步骤。 | [release/src/lib.rs](../../crates/release/src/lib.rs) |
| **apps/cli** | 社区版 client。分层：`server`（async 门面）→ `gateway`（同步数据面）→ `config`/`secrets` → `manage`/`stats`。库 crate，`main.rs` 只是薄参数解析。 | [apps/cli/src/lib.rs](../../apps/cli/src/lib.rs) |

## 一次 LLM 请求的数据流

数据面（`gateway`）**全同步**：WASM 运行时是同步的，所以数据面也是，async
止于服务器门面。axum 在阻塞线程上跑它，把流经 channel 桥回。入口是
`Gateway::chat`（[apps/cli/src/gateway.rs](../../apps/cli/src/gateway.rs)）。

```text
入站 JSON ──▶ agent 插件（归一 + 抽 hints）   [sync wasm]
          ──▶ router.route()                   [纯函数]
          ──▶ provider 插件（构造 HTTP 请求）  [sync wasm]
          ──▶ ProviderConfig::authorize        [外泄闸门]
          ──▶ 注入凭证，经 ureq 发送            [sync IO]
          ──▶ 解析 / 流式解析 + 渲染            [sync wasm]
```

1. **入口 / 记录开始** — `Gateway::chat` 建 `RequestRecord::begin`，保证每次
   调用恰好落一条记录（`gateway.rs:419 / 431 / 442`）。
2. **agent 归一（sync wasm）** — `agent.normalize_inbound` 把入站 JSON 归一为
   `ChatRequest` 并抽 hints（`gateway.rs:484`）。
3. **路由（纯函数）** — `router.route(&request, &hints, &candidates)`
   （`gateway.rs:492`；实现 `router-core/src/route.rs:97`，四层选池
   `select_pool` 在 `route.rs:125-177`）。
4. **写路由记录** — `RoutingRecord::from(&decision)`（`gateway.rs:503`，
   `metrics/src/lib.rs:112`）。
5. **provider 构造请求（sync wasm）** — `plugin.build_http_request` 产出
   `HttpRequestDescriptor`（`gateway.rs:576-578`；进 WASM，经
   `plugin-runtime/src/provider.rs`）。
6. **外泄闸门** — `upstream.config.authorize(&descriptor)`
   （`gateway.rs:582-585`；实现 `protocol/src/provider.rs:217`）。**此前不解析
   任何凭证。**
7. **注入凭证 + 发送（sync IO）** — `Gateway::send` → `send_with`
   （`gateway.rs:614 / 624`）；凭证由 `resolve_auth` 解析后写入单个 header，
   随请求出作用域，不进日志 / 错误 / guest（`gateway.rs:685 / 610-613`）。
8. **解析 / 流式渲染（sync wasm）** — 非流式 `plugin.parse_response` +
   `agent.render_response`（`gateway.rs:599-601`）；流式 `relay_stream` 用
   `plugin.stream_parser()` 逐块解析（`gateway.rs:717 / 724`）。
9. **指标写入** — `usage` 在解析 / 流事件处填入（`gateway.rs:600 / 765`），
   记录经 `recorder.record(&record)` 落盘（`gateway.rs:442`；`Recorder` trait
   定义 `metrics/src/lib.rs:130-131`）。

> 这个模块**从不**记录内容：它每请求只打一行路由决策，而决策按 `router-core`
> 的构造本就无内容。

## 插件沙箱边界

安全边界（无网络、无文件、限内存 / 时间）是**运行时**构造的属性，conformance
**不**假装能验证它（`conformance/src/lib.rs:31-38`）——「安全由谁保证」的答案是
`plugin-runtime`。

**adapter 拿不到什么：**

- **网络** — 编译后的组件若 import `wasi:sockets/` 或 `wasi:http/` 直接被拒
  （`FORBIDDEN_EVERYWHERE`，`plugin-runtime/src/loader.rs:32`）。这是「拒之门外」
  而非「给空实现」：连**请求**网络的插件都不是合法协议 adapter。import 扫描门
  在 `loader.rs:205-224`。
- **文件系统 / 环境 / stdio** — `Ctx::new` 用 `WasiCtxBuilder::new().build()`：
  无预打开目录、无环境变量、无参数、无继承 stdio（`loader.rs:63-72`）。
- **密钥值** — provider world 只 import `host.sign`（签名而非取值）；agent
  adapter 连 `host` 接口都不许 import（`FORBIDDEN_FOR_AGENTS`，`loader.rs:40`）。
  `host.sign` 的实现先查 `secret_ref` 是否在 manifest `permissions.secrets` 内，
  未声明直接拒（`provider.rs:48-62`）。
- **资源** — 每个 store 有内存上限（默认 64 MiB）与调用超时（默认 2s，epoch
  中断），`plugin-runtime/src/runtime.rs:8-30`。

**外泄闸门（exfiltration gate）**：adapter 开不了 socket，但它**选 URL**、
**指名凭证 slot**——两者合起来即可把 key 外泄到任意主机。`ProviderConfig::authorize`
（`protocol/src/provider.rs:217`）**先查 URL 再查凭证**，四种拒绝
（`DescriptorError`，`provider.rs:243-259`）：`UrlOutsideEndpoint`、
`UndeclaredCredential`、`UnexpectedCredential`、`MissingCredential`。

## 改动该落在哪里（upstream-first）

- 公共地基（protocol IR、plugin-api ABI、router-core、conformance）的改动
  **先落开源仓**，服务端仓依赖只许闭源 → 开源单向。
- 官方插件每个是独立审计边界，独立 `CODEOWNERS` 行（见 [.github/CODEOWNERS](../../.github/CODEOWNERS)）。
