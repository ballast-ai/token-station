# 贡献流程

## 分支与提交

- 从 `main` 切分支，命名 `type/kebab-name`，如 `feat/plugin-discovery`、
  `docs/migrate-internal-docs`、`chore/ci-cache`。
- 提交信息用 **Conventional Commits + 中文描述**：`type(scope): 中文描述`。
  常见 type：`feat` / `fix` / `docs` / `chore` / `refactor`。scope 一般是
  crate 或子系统名（`cli` / `release` / `ci` …）。
  - 例：`feat(cli): plugin install/remove/info 与未验收默认拒绝（三层分发 B2）`
- 走 **Pull Request** 合并到 `main`，不直接推 `main`。

## PR 前本地过门禁

CI 会跑同样的检查，本地先绿省来回：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

动了依赖再加 `cargo deny check`。测试细节见 [测试指南.md](测试指南.md)。

桌面安全检查还必须使用以下入口。普通 `cargo audit` 会跳过 path 包，不能替代 glib
精确回补校验及恢复原 registry 身份的审计；来源和边界见
[glib 回补记录](../security/glib-0.18.5回补.md)。优化回归需要本机 GLib 开发库和 pkg-config，缺失应报告未运行。

```bash
node --test tests/glib-backport.mjs
node scripts/check-rustsec-exceptions.mjs
node scripts/audit-desktop.mjs
scripts/run-glib-regression.sh
cargo deny --manifest-path apps/desktop/src-tauri/Cargo.toml --config apps/desktop/src-tauri/deny.toml check
```


## 代码风格与硬约束

写在 workspace 里，不是口头约定：

- **`unsafe_code = "forbid"`** —— 整个 workspace 禁 unsafe。
- **clippy `all` + `pedantic` = warn**，CI 用 `-D warnings` 提级为错。写代码
  按 pedantic 标准来。
- **`rustfmt`** —— 见 [rustfmt.toml](../../rustfmt.toml)，提交前 `cargo fmt`。
- **文档注释也是门禁** —— `cargo doc -D warnings` 必须过，公开项要有文档。

匹配现有风格：模块顶部的 `//!` 注释承载「为什么这么设计」，改动时保持这种
密度，别把它们删成裸代码。

## 依赖策略

新增依赖会被三道供应链门审：

- **[deny.toml](../../deny.toml)** —— license 允许清单、来源限制、RustSec
  advisories。加的 crate license 不在清单里、或来源不被允许，`deny` job 直接
  红。
- **cargo-audit** —— `Cargo.lock` 里有已知漏洞就红。
- workspace 依赖尽量走 `[workspace.dependencies]` 统一版本。

加重依赖前先想清楚是否必要——这是个「内容不离开本机」的项目，依赖面越小越好
审计。

## 改动落点与边界（重要）

- **upstream-first**：公共地基（`protocol` IR、`plugin-api` ABI、
  `router-core`、`conformance`）的改动**先落这个开源仓**。闭源服务端仓依赖只
  许「闭源 → 开源」单向，不能反向。
- **官方插件是独立审计边界**：`plugins/official/*` 每个包有独立 `CODEOWNERS`
  行（[.github/CODEOWNERS](../../.github/CODEOWNERS)），改动会请对应 owner 审。
- **不改路由语义的两处一致性**：`router-core` 被 client 和服务端 gateway 共用、
  `metrics` 的记录词汇两端同构——改这两个 crate 的公开形状时，记住它有第二个
  消费者。
- **别把设计 / 规划文档写进本仓**：它们在私有文档仓 `token-station-doc`。本仓
  `docs/` 只放面向用户的 `product/` / `release/` / `guides/` 与本贡献者目录。

## 安全相关改动

任何触及下列面的改动，PR 描述里要说清**为什么仍然安全**：

- 凭证解析 / 注入（`apps/cli/src/gateway.rs`、`secrets.rs`）——凭证不得进日志 /
  错误 / 插件。
- 外泄闸门（`crates/protocol/src/provider.rs` 的 `authorize`）——URL 先于凭证
  检查的顺序不能反。
- WASM 加载门与沙箱（`crates/plugin-runtime/src/loader.rs`）——禁用 import 清单
  不能放松。
- 指标 / 日志记录词汇（`crates/metrics/src/lib.rs`）——不能新增能装下 prompt /
  response 内容的列。

这些边界的原理见 [架构总览.md](架构总览.md#插件沙箱边界)。
