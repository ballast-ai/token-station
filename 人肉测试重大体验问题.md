## Latest Retest Result

There are no known unresolved major experience issues in the current version.

This cycle closed UX-005, UX-006, and UX-007:

- A local inbound conversion failure now states that the request was not sent upstream. It no longer conflicts with `attempts=0` by describing the failure as an upstream rejection.
- Anthropic server tools on a non-native provider now fail before an upstream request with an explicit capability error. They are no longer silently converted into empty functions without an executor. Native Anthropic routes continue to pass these tools through unchanged.
- The OpenCode connector writes the safe `limit` and pricing that the current effective route can prove. Real validation with Wecoding `glm-5.2` used `context=257550`, `output=32768`, `input=0.2`, `output=0.6`, and `cache_read=0.04`. The proxy `/models` response contained the same data.
- A legacy `profiles: null` value now recovers as an empty map, so an app restart no longer enters read-only protection. Reconnecting OpenCode also repairs a legacy `provider.tokenstation: null` value safely.

Automated validation included the full Rust workspace test suite, 287 desktop frontend tests, 257 desktop Rust tests, the production build, the official local desktop build, and the artifact audit. Real-app validation also covered quitting and reopening the app, restarting the proxy, opening global routing, refreshing the model catalog, reconnecting OpenCode, and reading metadata from `/agents/opencode/v1/models` after the restart.

Automatic OpenCode compaction near the threshold still requires observation during a real long-running conversation. The previous zero-context-window condition that blocked proactive compaction has been removed. This is now a follow-up runtime observation instead of a known product defect.
